# 하수도 맵 제작 공통규칙

최신 확정본: 2026-09-21. 과거 프롬프트의 누적 설명을 대신한다. 숫자의 권장값·조건부 기준을 절대 법칙으로 바꾸지 않는다.

## 1. 작업 범위와 게임 규칙

- 2D 흑백 퍼즐 플랫포머. 접촉 지형색과 플레이어색이 다르면 사망. 안 칠한 바탕도 아트의 흑백색으로 판정한다. 회색 지형은 만들지 않는다. 장치별 예외는 실제 코드를 확인한다.
- 색 규칙 출처: `docs/색판정_규칙_2026-08-30.md`, `scripts/스마트월드/색규칙.gd`. 저장고도 색 접촉 판정 대상이다. ‘장치이니 무조건 안전’이라고 추정하지 않는다.
- 새 맵: 시작/도착/방향/형태/규모/학습할 기믹을 먼저 확정. 사용자에게 위임받거나 이미 답한 항목은 재질문하지 않는다.
- 외관 교체: 기존 이동 외곽·장치 연결·진행 경로를 유지. 레벨 개편은 승인 범위 내에서 별도 설계한다.
- 스테이지1·집·메인 로비·챕터표는 별도 요청 없이 수정하지 않는다. 편집된 씬을 build_*로 재생성하지 않는다.

## 3. 설계 의도와 분기

- 장치 개수보다 구간별 학습 목적을 먼저 정한다. 기본 이해 → 기믹 둘 결합 → 종합 순서. 장애물이 없는 걷기 구간은 정답 경로에서1500px 이하를 기존 목표로 사용한다.
- 기존 분기형 프로필: 갈림길2~3곳, 보통2갈래(마지막3갈래 가능), 갈래 시작 색과 플레이를 다르게. 첫 갈림길은 진행방향1화면 이내, 두 갈래 끝은 한눈에 드러나지 않게 가린다.
- 기본 분기 문법은 F1 의미 있는 막다른 길, F2 빙 돌아가는 정답 길, F3 조건을 맞춰 여는 지름길. 사용자가 ‘지름길 없음’ 등 다른 구성을 정했다면 해당 맵 요구가 우선한다. 출구 통로는 기본1개다.
- 막다른 길 끝에 관찰 보상·체크포인트·다른 갈래를 바꾸는 장치·페인트 회수 등의 의미를 둔다. 다른 갈래에 영향을 주는 장치는 최소1곳. 복귀는 다른 길, 왕복 부담을 줄여 복귀시간≤진입의 절반 목표.
- 가로형·3층 왕복·10000px 폭을 모든 맵에 강제하지 않는다. 방향/형태/규모는 해당 맵 사용자 합의가 우선한다. 기존 분기 목표와 충돌하는 사용자 요구는 맵 작업 문서에 예외로 기록한다.
- 기존 밀도 목표: 장애물6~10개,4종 이상, 같은 장치3연속 금지, 각 갈래1개 이상/출구 전 종합. 짧은 학습 맵이나 사용자 지정 규모에는 기계적으로 개수를 채우지 말고 적용 범위를 기록한다.
- 기존 색 비율 목표 검65:흰35(±5)는 **노출 테두리 길이** 지표다. 면적으로 잘못 검사하지 않는다. 외관만 교체할 때 비율을 맞추려고 동선을 바꾸지 않는다.
- 흰 덩어리는 기존 목표3~5곳·각1화면 이내. 내부 장식색은 플레이 접촉색 비율과 구분한다. 새 장치는 안전하게 관찰할 수 있는 곳에서 소개한다.
- 기존 톱 기준: 왕복≥2초,1~3개, 검정/타이밍 구간 우선, 왕복 양끝 대기 공간. 색 판단과 빠른 타이밍을 처음부터 겹치지 않는다.
- 과거 보류 장치를 새로 쓰거나 제안된 조합을 구현 완료로 간주하지 않는다. 사용자 요청과 현재 기믹 상태를 확인한다. **바닥 벽돌 잔해는 보류.**

연속된 같은 플랫폼은 SS2D 하나. 색 영역·독립 이동·떨어진 선반만 이유를 적어 분리한다. Scale=1, 점으로 크기 변경. 점/저장 콜리전/실행 콜리전 일치. 같은 부모에서 공유 경계를 역순 사용: 틈0·겹침0.

얕은 윗면의 가운데가 실제 발 접촉선(위아래 약4px). 뒷면이 안으로 들어가는 사다리꼴 끝마감. 플레이어/콜리전을 장식 때문에 옮기지 않는다. 마감돌을 정수 개수로 맞추며, 직선 중간 점에 끝돌/홈을 만들지 않는다. 옆면 마감은 노출된 곳만, 다른 벽 안으로 윗면이 관통하거나 내부에 띠가 남으면 실패.

공중 선반은 얇은 상면과 깨진 밑면/끝 실루엣. 두꺼운 직사각 벽 조각으로 대체하지 않는다. 지지대/쇠사슬은 기존 장식 키트를 필요할 때 사용한다.

edge에 AtlasTexture를 쓰면 원본 atlas RID가 그려지는 문제가 있다. 전용 단독 텍스처를 사용한다. v01/trim_atlas나 구형 WALL을 새 외관 기본값으로 되돌리지 않는다.

## 5. 내부 무늬와 실제 색 경계

`scenes/지형/하수도/색조합/`의 내부 무늬2종·가로/세로 경계4종 사용. 검정 안 흰색/흰색 안 검정, 검흰검/흰검흰 모두 가능.

- **내부 무늬:** `하수도_내부벽돌.gd` 전용. 로컬 Rect2 최대16행, 실제 줄눈에 맞춤, 모든 외곽/구멍/오목부에서24px 이상 여유. 별도 충돌 없음. 페인트 전에 바탕만 합성해 칠하면 덮이고 회수하면 복구.
- 내부 무늬는 시작상태0, 바탕흰색과 재질 일치, 무색일때_통과=false, 안칠한_바탕도_색이다=true. 전용 기본_아트색()이 접촉색을 정한다. 일반 흰 지형에 시작상태0만 복사하지 않는다.
- 에디터 inlay_rects/count와 실행 내부_벽돌영역은 수동 편집 시 둘 다 갱신. 공유 재질을 직접 수정하지 않는다.
- **실제 경계:** 각 색은 실제 SS2D/색 판정. 반 장~두 장 깊이로 불규칙하게 맞물림. 지퍼 반복/회색 블렌딩 금지. 가로도 실제 줄눈을 따르며 세로 모듈90도 회전으로 대체하지 않는다.
- 내부 색 경계는 틈0. 통행 색 전환의 틈 규칙과 구분한다. 내부 줄눈에16px/최소변90px를 강제하지 않는다. 색 경계를 통행 외곽으로 확장하면 접촉색·착지 여유 재검증.
- 절대 UV 재질을 다른 맵으로 옮길 때 점/무늬/UV 기준 함께 변환. 부모만 달라져도 이웃 마감 탐색이 끊길 수 있다.

## 6. 물·호퍼·저장고 퍼즐

- **호퍼 유입 정렬(2026-09-23):** 단일 공급은 물줄기 중심과 호퍼 중심 x를 일치시킨다. 두 공급은 꺼진 줄기도 포함해 좌우 배치를 유지하며, 한쪽 밸브를 닫았다고 나머지를 자동으로 가운데로 이동시키지 않는다.
- 입구 감지는 윗면 위84px부터 시작하므로 감지 성공만으로 그림이 연결됐다고 판정하지 않는다. 현재 주철 기존배치 호퍼의 유입 끝은 `호퍼.y-높이+12`로 맞춰 끝 흐림을 입구 안에 숨긴다. 유입 유체의 `호퍼_유입=true`로 바닥 착수 물보라를 끄고 호퍼를 물보다 앞에 그린다. 공급 시작점 이동 시 상류 배관 접속·통행·퍼즐 우회는 별도 확인한다.

물별 기록: 노드/물색/바닥색/우회허용/필수장치/설정폭/실효판정폭/출발착지높이/우회/검증상태.

- **장치 외관 기준(2026-09-22):** world_2_클로드 전 스테이지 물줄기는 `유체_흰물v2.gd`(이름과 달리 흰/회/검 공용), 웅덩이는 `웅덩이_흰물v2.gd`. 기존 프리팹 인스턴스의 script 오버라이드를 유지한다. 새 빌더가 옛 스크립트 외관으로 되돌리지 않게 검사한다.
- 호퍼는 기존 배치 교체 시 `호퍼_주철_기존배치.gd`로 입구/출구 원점을 보존한다. 신규 배치는 `호퍼_주철_직하/좌하/우하.tscn`을 사용하되 출구_포트에 유체를 맞춘다. 좌우 곡선 출수/판정은 별도 검증 전 구현 완료로 간주하지 않는다. 원형 밸브는 `제어레버.gd`의 주철 손잡이를 사용한다.
- 압력 발판/직선 레버는 승인된 주철 부품 `assets/textures/obstacles/switch/cast_iron_v1/parts.png` 사용(2026-09-23). `압력버튼.gd` 상판은 최대3px 아래로 눌리고 표시창은 출력 활성 상태를 표시한다. `제어레버.gd` 직선형은 고정 받침+회전 손잡이, 초기 갈래 방향 표시. 공통 스크립트로 기존 배치에도 적용되며 연결·감지·충돌·좌표는 보존한다. 실제 엔진 검수 전에는 실행 확인으로 간주하지 않는다.


- 얇은 물은 점프 중2회 색 전환 기술로 통과하도록 허용 가능. 필수형은 장치 전에는 그 방법으로 못 넘고 작동 후 통과해야 한다.
- 동일 높이·추가 이동 없음일 때 너비448px는 초기 후보일 뿐 보장값 아님. 모든 프레임 실루엣, 몸이 지나는 높이, 낮은 착지/높은 출발, 판정여유, 중간발판/물 아래 빈틈을 확인한다.
- 바닥 칠해 걷기, 회색 혼합, 플랫폼·낙하 우회, 저장고 회수로 공급 끄기도 검사한다. 레버를 강제하려고 임의로 색 전환/색칠을 금지하지 않는다.
- 폭 조정은 호퍼 `출구_물줄기_폭`에서 통일하거나 -1로 유체값 유지. 기본64 덮어쓰기 주의. 과한 늘림 대신 적절한 아트를 사용하고 충돌만 넓히지 않는다.
- 필수 장치는 물을 끄기 전 도달 가능. 물을 넓혀 레버/체크포인트/준비 공간을 덮지 않는다. 꺼진 물의 그림/위험/총알 감지를 함께 검사한다.
- ★**꺼진 물은 그 자리에 아무 감지도 남기지 않는다** (2026-09-21 확정 · 도형). 밸브(원형 레버)나 저장고로 끈 물 자리는 **총알이 그대로 지나가야** 하고, 그림도 위험도 호퍼 입구 감지도 없어야 한다.
  엔진 규칙: `유체.gd`·`웅덩이.gd`의 `_켜짐_반영()`이 끄면 `collision_layer 0` + `monitorable false`로 만들고, `총알.gd`는 `총알_막나()`가 false면 통과시킨다(같은 색·회색·꺼진 물 전부).
  맵 쪽 규칙: ① 물을 끄는 레버/저장고를 둔 자리마다 "끈 뒤 총알이 지나가 뒤의 표적을 칠할 수 있는가"를 공략(`하수도_주행검사.gd`의 `레버` → `칠`)에 넣는다. ② 꺼진 물 자리에 다른 Area(웅덩이·연기)를 겹쳐 두어 '보이지 않는 벽'을 만들지 않는다.
  ③ 회귀 검사 `godot --headless --path . -s res://tools/test_유체_끄면_총알통과.gd`(8 항목)가 통과해야 한다 — 유체/총알/웅덩이 코드를 손대면 반드시 돌린다.
- 장치 하나의 공급값에 여러 제어자가 서로 다른 값을 쓰지 않도록 소유 관계를 적는다. 호퍼/저장고/레버 연결은 외형 배관만 붙여 성립하지 않는다.
- 복합 조합은 기본 이해 이후: 공급색 선택 → 호퍼 전달/혼합 → 물속에서도 색 유지하는 통과플랫폼. 저장량·자동문 등 미구현 기능은 별도 구현 항목으로 구분한다.

## 7. 배경·성능·검수

- 배경은 하수도 다층 패럴럭스. 먼층 느리게/가까운층 빠르게, 가로·세로 모두 적용. 배경의 큰 반복 구멍/기둥을 격자로 빽빽하게 깔지 않는다. 지형보다 대비를 낮춰 분리한다.
- 외벽300px나 카메라리밋만으로 화면 밖 공백이 가려진다고 가정하지 않는다. 실제 줌/화면비/앞보기/흔들림/대각 모서리까지 화면 범위를 채우고 플레이 충돌면은 보존한다.
- `_CachedTrim_*`는 변경 시 생성하는 마감. owner를 붙여 저장하지 않는다. 본체 cached_draw_mode=1, 좁은 마감=2. 옛0.5초 전체 이웃 재검색/큰 본체의 경계 루프를 되살리지 않는다.
- 정적: 참조/연결/공유선/콜리전/면적/무늬 여유. 엔진 허가 후: 파싱 오류→실제 도약·착지→두색 색칠/회수/사망→퍼즐 정답/우회→재시작·재로드→실제줌 화면→프레임 시간.
- 과거132검사나 정적 샘플 통과를 새 코드의 실행 통과로 간주하지 않는다. 엔진 실행 전에는 미실행으로 보고한다. 검사는 생략하지 않고 출력만 성공요약/실패상세로 줄인다.
- loaded node owner 재설정 금지, 새 노드만 owner 지정. 내부 resource ID는 ASCII 영숫자/밑줄. shader 안 한글 금지. 변경 코드에는 한글 이유 주석.

규칙 변경은 이 파일에 한 번만 반영하고 맵 문서에는 해당 맵의 선택/예외만 기록한다. 과거 전체 문서는 보관 폴더에서 근거가 필요할 때만 읽는다.
