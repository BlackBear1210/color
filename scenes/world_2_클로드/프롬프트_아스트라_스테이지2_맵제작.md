## 0. 맵 제작 전에 사용자에게 먼저 묻기

**사용자가 "맵 만들어"라고 하면 구조를 임의로 확정하지 말고 다음 항목을 묻는다.** 이미 이번 대화에서 답한 항목은 다시 묻지 않는다. 답을 기다리는 동안 자료는 읽어도 되지만, 시작·도착·동선을 임의로 정한 씬을 먼저 작성하지 않는다. 사용자가 명시적으로 맡긴 항목은 제안해 진행할 수 있다.

1. **플레이어 시작 위치:** 왼쪽 중간 / 왼쪽 위 / 아래 중앙 / 오른쪽 / 기타 원하는 자리?
2. **도착 위치:** 위 중앙 / 왼쪽 위 / 오른쪽 위 / 아래 중앙 / 오른쪽 중간 / 오른쪽 아래 등 어디? 목적지 후보가 여러 개면 **그중 하나**를 선택한다.
3. **주 진행 방향:** 좌→우 / 우→좌 / 아래→위 / 위→아래 / 대각선 / 여러 방향으로 왕복하며 순환?
4. **맵의 전체 틀:** 가로로 긴 형태 / 세로로 긴 형태 / 평행사변형 / 사다리꼴 / 꺾인 형태 / 비정형 중 어떤 느낌? PPT 몇 장 또는 어떤 도형을 참고할지 함께 묻는다.
5. **규모와 플레이 느낌:** 목표 플레이 시간·규모, 갈림길과 우회 비중, 대각선 경사 지형의 비중, 원하는 주요 장치나 난이도?

질문은 시작·도착, 방향·형태, 규모·장치처럼 묶어서 답하기 쉽게 제시한다. 답을 받은 뒤 **시작 / 도착 / 방향 / 외곽 형태 / 규모 / 주요 기믹** 표와 동선 설계에 반영한다. 가로형, 좌측 아래 시작, 우측 위 출구로 자동 결정하지 않는다.

## 게임 규칙 (이걸 모르면 맵이 성립하지 않는다)

- 2D 흑백 퍼즐 플랫포머. 플레이어는 **검정 또는 흰색** 중 하나. 물감총으로 지형을 칠한다.
- ★**몸에 닿은 지형이 내 색과 다르면 즉사.** 회색(물·웅덩이에만 있음)만 누구에게나 안전.
- ★**안 칠한 지형은 검정이다.** 흰 플레이어는 안 칠한 바닥·벽·천장 어디에 닿아도 죽는다.
- ★**지형에 회색은 없다**(2026-09-06 도형 지시). 지형은 검정·흰색 둘뿐. Shift 는 언제든 눌리지만 **바꾼 순간 닿아 있는 지형이 반대색이면 죽는다** → 안전하게 바꿀 수 있는 곳은 **공중(점프 중)** 과 **회색 물·웅덩이 위**뿐. 그래서 **색이 바뀌는 경계마다 폭 ≥ 80px 틈**을 둔다(2-1 방식). 턱만 두면 반대색 옆면에 부딪쳐 죽는다.
- 모든 지형은 `칠하기_허용 = true`(= `칠하기_방식 = 전체칠_가능`). 벽·천장도 색 규칙에 참여한다 → **한 구간의 바닥·벽·천장은 반드시 같은 색.**
- 물리: 점프 높이 160px · 점프 거리 320px · 올라갈 수 있는 단차 ≤ 110px · 가로 간격 ≤ 260px · **치명 낙하 520px** · 플레이어 콜리전 50×47 · 발판 위 머리 공간 ≥ 52px · 걸어 오를 수 있는 경사 ≤ 45°(권장 30°).
- 물(웅덩이·유체)은 색이 맞으면 **낙하를 받아 준다.** 색이 다르면 즉사.
- 화면 1920×1080 · 줌 0.85 → **플레이어가 보는 범위는 약 2259×1271px.** 맵은 이보다 훨씬 커야 한다.

## 이 스테이지의 목표 (한 문단)

한 스테이지 = **출구 통로 하나**(`연결통로.tscn`). 플레이어는 **맵 전체를 한 화면에서 볼 수 없다.** 길이 **여러 갈래**로 갈리고 플레이어가 하나를 골라 간다. **잘못된 길**은 끝까지 가면 **되돌아와야** 하고, **올바른 길**이라도 **크게 빙 돌아야** 하는 것이 있다. 되돌아오는 길은 **왔던 길을 그대로 되밟지 않게(고리)** 만든다. 참고 원본은 **Fireboy and Watergirl (Forest Temple)** — 3~4층, 좌우 두 갈래가 색으로 갈리고 중간에 한 번 교차, 막다른 선반, 대각선·사다리꼴 지형. 단, 두 캐릭터 협동은 우리 게임에서 **"흰색일 때 준비해 두고 검정으로 바꿔 통과"** 라는 **순서**로 치환한다.

## 반드시 지킬 규칙

### A. 갈림길 문법
1. 갈림길 **2~3곳.** 종류 세 가지를 **모두** 넣는다:
   - **F1 막다른 길**: 올바른 길처럼 보이는데 막혀 있다. 끝까지 가면 돌아온다.
   - **F2 빙 도는 길**: 올바르지만 크게 돌아 목적지 근처로 되돌아온다.
   - **F3 지름길**: 짧지만 색·탄약·장치가 맞아야 통과. 처음엔 못 간다.
2. 첫 갈림길은 **시작에서 진행 방향 기준 1화면 이내.** 기준 줌에서 수평 약 2259px, 수직 약 1271px를 참고하고 실제 카메라 시야로 판단한다.
3. 갈림길 한 곳의 갈래는 2개(마지막 갈림길만 3개 허용). 두 갈래는 **다른 색**으로 시작(왼쪽 흰·오른쪽 검 처럼).
4. 갈림길에서 **두 갈래의 끝이 모두 화면 밖**이어야 한다. 수평 맵의 1,300px는 참고값이며, 수직·대각선 맵은 실제 시야와 가림 구조로 판단한다. 경로 길이만 길게 늘여놓고 끝이 화면에 보이면 조건을 충족하지 못한다.
5. **F1 의 끝에는 반드시** 다음 중 하나 이상: ⓐ 체크포인트 ⓑ 출구·레버가 **보이는 창**(창문 Template) ⓒ **반대 갈래의 문/발판을 움직이는 압력버튼(`한 번 누르면 유지`)** 또는 **물줄기를 반대 갈래로 돌리는 제어레버** ⓓ 칠해 둔 발판을 되돌아오며 회수(E)하게 하는 배치. **ⓒ 는 스테이지에 최소 1곳.**
6. 되돌아오는 길은 **왔던 길과 다른 길**(예: ≤ 400px 낙차로 아래층 복귀). 되돌아오는 시간 ≤ 갔던 시간의 절반.
7. 금지: 끝에 아무것도 없는 막다른 길 · 내려가기만 하고 못 올라오는 낙차(소프트락) · 두 갈래가 같은 색·같은 모양 · 가짜 길이 진짜 길보다 눈에 띄게 예쁜 배치.

### B. 구조·크기
- **시작 위치·도착 위치·주 진행 방향·전체 외곽 형태는 §0의 사용자 답으로 정한다.** 수평·수직 상승·수직 하강·대각선·순환 동선 모두 허용한다. 도착점은 위 중앙이나 아래쪽도 가능하다.
- 층 3~4개는 분기 배치의 참고 구조다. 평행사변형·사다리꼴·수직 갱도·대각 회랑 등 선택한 형태에 맞게 층과 구역을 배치한다. 직사각형 3층 왕복 구조를 반복하지 않는다.
- **규모는 사용자와 정한 플레이 시간·탐색 밀도·주축 길이로 결정한다.** 기존 폭 10,000px·경로 25,000px는 가로형 대형 맵의 참고값이며 모든 맵의 하한이 아니다. 세로형 맵을 맞추려고 불필요하게 가로로 늘이지 않는다. 맵 전체가 한 화면에 드러나지 않고 갈림길 선택과 우회가 성립할 공간은 확보한다.
- 시야 가리기 3법을 섞어 쓴다: 두꺼운 벽(≥ 300px) · 꺾인 통로(ㄱ자·ㄷ자) · 층 슬래브(≥ 140px).
- 층 간격은 헤드룸 ≥ 440 + 슬래브 ≥ 140 = **≥ 580px** 로 잡히므로 치명 낙하(520)를 넘는다 → **층에서 층으로 바로 떨어지면 무조건 죽는다.** **층 사이 구멍은 아래에 색 맞는 물이 있거나 ≤ 400px 중간 선반이 있어야** 한다. 그 외 구멍은 전부 "죽는 구멍" 이고, 죽는 구멍은 **520px 보다 확실히 깊게**(어중간 금지) 판다.

### B-1. 맵 외곽에서 스테이지 밖 빈 공간이 보이지 않게

- 플레이어가 **맨 위·맨 아래·왼쪽 끝·오른쪽 끝·모서리**에 가거나 그 자리에서 점프해도 화면에 외벽 뒤의 빈 배경, 지형 밑의 잘린 단면 틈이 드러나면 안 된다. 사용자가 제보한 시작 바닥 아래의 삼각형 빈 공간도 이 규칙에 포함한다.
- **플레이 가능 영역과 화면을 채우는 외곽 영역을 함께 설계한다.** 외벽·천장·바닥을 바깥 방향으로 충분히 연장하고 접합부를 메운다. 플레이어 쪽 충돌면·색 전환 틈·퍼즐 통로는 유지한다. 의도된 내부 방이나 구덩이를 외부 빈 공간과 혼동해 막지 않는다.
- 카메라 리밋만 설정했다고 해결된 것으로 보지 않는다. **가장 넓게 보이는 실제 줌, 화면 비율, 추적 오프셋·앞보기·흔들림·전환 중 이동**까지 포함해 화면이 차지하는 범위를 구한다. 기준 1920×1080 / 줌 0.85라면 반시야 약 **1130px × 636px**에 카메라 이동 여유가 추가된다. 벽 두께 300px를 외곽 가림의 충분조건으로 쓰지 않는다.
- 평행사변형·사다리꼴·대각 외곽은 비스듬한 변과 모서리 주변까지 채운다. 사각 카메라 리밋 안에 들어 있다는 이유로 대각선 밖의 삼각형 공백을 방치하지 않는다.
- 설계도에 **외곽 마감 범위와 카메라 범위**를 표시한다. 정적 확인과 실제 화면 확인을 구분해 보고한다. 엔진 실행이 허용된 경우 네 방향 끝·모서리·시작·도착에서 서 있기/점프/카메라 이동을 확인하고 외부 빈 공간 노출이 없어야 한다.

### B-2. ★색 비율 — 검정이 기준 (도형 지시: "검정 6.5 : 흰색 3.5")
- 지형 **면적** 기준 **검정 65 % · 흰색 35 %**(±5). 빌더가 면적을 합산해 `검정 %% · 흰색 %%` 를 로그로 찍고, 60~70 % 를 벗어나면 굽기를 **실패**시켜라.
- 시작 구간·출구 구간·큰 벽·천장·기둥은 **검정.** 플레이어 시작 색도 **검정.**
- 흰색은 **사이사이**: 갈래 하나 · 중간 층의 섬/선반 · F3 지름길 · 장치가 있는 방. 스테이지당 **흰 덩어리 3~5개**, 한 덩어리 **≤ 1화면(2259px)**, 각 덩어리 앞뒤에 **≥ 80px 틈**(공중에서 색 전환). 흰 구간이 두 화면 이상 이어지면 안 된다.

### B-3. ★장애물 — 중간에 반드시 배치
- 스테이지당 **6~10개**(체크포인트·출구·조명 제외) · **4종 이상** · 같은 것 3개 연속 금지.
- 정답 경로에서 **장애물 사이 걷기만 하는 구간 ≤ 1,500px.**
- 각 갈래에 최소 1개 · 교차점에 장치(압력버튼 또는 제어레버) 1개 · F1 끝에 장치 또는 창 · 출구 직전에 종합 1개.

### C. 지형 모양 — 직사각형만 쓰지 마라
- 사용자가 원하면 **대각선 경사 지형을 많이 배치해도 된다.** 맵의 외곽 형태와 내부 진행 경로를 함께 변형한다. 걷는 경사로의 각도·점프 한계와 하강 경로의 낙하 안전 규칙은 지킨다.
- SS2D 는 임의 다각형이다. **직사각형 · 사다리꼴 · 역사다리꼴(매달린 선반) · 평행사변형(경사 슬래브) · 직각삼각형(경사로, ≤ 30°) · ㄱ자 · ㄷ자 · 오각형(지붕꼴) · 계단 Template · 쐐기** 를 섞는다.
- **한 화면 안에 모양 3종 이상.** 경사로·평행사변형이 **층 이동의 절반 이상**을 맡긴다.
- **곡선 금지**(테두리 45° 지점에 틈이 생기는 알려진 이슈). 길이 **90px 미만 변 금지**(코너 조각 90px). 두께 ≥ 140px(권장 180). 계단은 폭 180 × 높이 110.
- FBWG 의 "기둥에서 뻗은 가지" = 기둥(직사각형) + 좌우 짧은 역사다리꼴 선반.

### D. ★SS2D 붙이기 — 겹치지 말고 딱 붙여라 (사람이 나중에 손으로 고친다)
**[사용자 추가 지시] 하나의 연속된 플랫폼은 SS2D 노드 하나로 만든다.** 평지→오르막→평지→내리막을 4개의 SS2D로 조립하지 않는다. **한 SS2D의 꼭짓점(편집 점)을 추가해** 굴곡 전체와 아랫면을 하나의 닫힌 폴리곤으로 표현한다. 여기서 점 추가는 씬 노드를 여러 개 추가하라는 뜻이 아니다. 사용자가 나중에 플랫폼 전체를 한 번에 선택·이동·수정할 수 있어야 한다.

- 단순히 만들기 편하다는 이유로 같은 플랫폼을 잘게 나누지 않는다. 기본 단위는 **물리적으로 하나인 플랫폼 = SS2D 하나**다.
- 색이 달라 반드시 틈을 둬야 하는 구간, 따로 움직이는 문, 서로 떨어진 발판처럼 **독립 동작이 필요한 경우만** 별도 SS2D로 둔다. 설계도에 분리 이유를 적는다.
- 빌더의 경사·평지 헬퍼는 노드를 각각 생성하는 대신 한 플랫폼의 점 목록을 구성한다. 최종 노드 생성은 플랫폼마다 한 번만 한다.

1. **이웃한 두 지형은 꼭짓점을 공유한다.** A 의 오른쪽 변 두 점 = B 의 왼쪽 변 두 점, **같은 숫자.**
2. **겹침 0 · 틈 0.** 겹치면 텍스처가 두 겹이 되고 점 하나를 옮기면 옆 지형과 어긋난다.
3. T 자 접합은 긴 변 **직선 위**에 짧은 쪽 두 점을 정확히 놓는다.
4. **모든 꼭짓점을 16px 격자**에 둔다. 경사면 양 끝점도.
5. 한 플랫폼의 바닥·경사·굴곡과 연결된 벽은 **SS2D 하나의 폴리곤(ㄱ자·ㄷ자 등)**으로 만든다. 단 **색이 갈리는 곳은 반드시 나누고 전환 틈을 둔다**(`시작상태` 는 노드당 하나).
6. **Scale 은 항상 1.** 크기는 점으로만.
7. 빌더에서 폴리곤 표를 적을 때 **이웃끼리 같은 점 상수를 참조**하게 하라. 숫자를 두 번 적지 마라.
