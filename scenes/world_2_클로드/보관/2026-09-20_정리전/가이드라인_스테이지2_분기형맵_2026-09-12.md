## 제작 전 질문과 PPT

사용자가 새 맵 제작을 요청하면 **시작 위치 / 도착 위치 / 주 진행 방향 / 전체 외곽 형태 / 규모·주요 장치**를 먼저 묻고 답을 반영한다. 이미 받은 답은 다시 묻지 않는다. 아직 답하지 않은 핵심 항목은 임의로 확정하지 않으며, 사용자가 명시적으로 맡긴 항목만 판단해 제안한다. 질문 양식과 슬라이드별 표는 [제작 프롬프트 §0](프롬프트_아스트라_스테이지2_맵제작.md#0-맵-제작-전에-사용자에게-먼저-묻기)을 따른다.

참고 파일은 [맵 기본 구조 틀.pptx](<맵 기본 구조 틀.pptx>)이다. 1~4장은 서로 다른 시작 위치와 목적지 후보의 조합이고, 실제 출구는 후보 중 하나를 선택한다. 5장은 대각 모서리를 자른 형태·가로형·세로형·사다리꼴의 전체 모양 예시다. PPT의 그림을 유일한 배치로 고정하지 않는다.

사용자가 허용한 구조: **세로로 길게 상승, 위에서 아래로 하강, 수평 이동, 대각선 이동, 평행사변형·사다리꼴·비정형 외곽, 위 중앙 목적지**. 대각선 지형을 많이 배치해도 된다. 실제 보행면의 경사각과 낙하 안전 조건은 그대로 지킨다.

기존 씬을 사용자가 직접 수정하겠다고 한 경우 다시 굽거나 덮어쓰지 않는다. Godot 실행은 별도 명시 요청 전까지 하지 않고, 엔진 검사 결과는 미실행으로 기록한다.

## 0. 왜 바꾸나 — 지금 맵의 문제 (한 줄씩)

| 문제 | 근거 |
|---|---|
| **일자다.** 왼쪽에서 오른쪽으로 걷기만 하면 끝난다 | 맵분석 §4-6 "단면이 일곱 판 내내 똑같다" · §4-7 "걷기만 하는 시간이 길다" |
| **선택이 없다.** 갈림길이 없으니 "잘못 갔다 → 돌아온다" 는 경험이 0 이다 | 2-1~2-7 전부 단일 경로 |
| **직사각형뿐이다.** 모든 지형이 축 정렬 사각형이라 화면이 같아 보인다 | 2-8 빌더 `_사각()` 하나로 전부 찍음 |
| **다 보인다.** 한 화면 안에서 다음 관문까지 보이니 긴장이 없다 | 카메라 줌 1.0 · 시야 1920×1080px |

FBWG 는 정반대다: **한 화면 = 한 판**인데도 지루하지 않다. 길이 얽혀 있고, 모양이 다양하고, 갈림길에서 고르게 만들기 때문이다.
우리는 FBWG 의 **얽힘·모양·선택**을 가져오되, **화면은 일부만 보여 주는** 쪽으로 간다 — 그러면 "저 위에 뭐가 있지?" 가 하나 더 생긴다.

## 1. 목표 정의 (이 한 문단이 전부다)

> 한 스테이지 = **목적지 하나**(출구 통로 하나).
> 플레이어는 **한 화면 안에서 맵 전체를 볼 수 없다.**
> 길이 **여러 갈래**로 갈리고, 플레이어가 하나를 골라 간다.
> **잘못된 길**은 끝까지 가면 결국 **되돌아와야** 하고,
> **올바른 길**이라도 **크게 빙 돌아야** 하는 것이 있다.
> 되돌아오는 길은 **처음 온 길을 그대로 되밟지 않게** (고리 구조) 만든다.

## 3. 카메라와 맵 크기 — "다 안 보여 주기"

| 값 | 수치 | 출처 |
|---|---|---|
| 화면 | 1920×1080 | `project.godot` |
| 기준 줌 | **1.0** (2026-09-14 확정 · 씬 루트 `카메라_줌` 에 명시) | 월드.gd 기본 0.85 는 집 챕터 값 |
| **실제 시야** | **1920 × 1080 px** · 반시야 960 × 540 | |

규칙:
- **전체 형태와 규모는 사용자 답으로 정한다.** 폭 10,000px·경로 25,000px·3~4층은 기존 가로형 대형 맵의 참고값이다. 모든 맵의 필수 하한으로 강제하지 않는다. 세로형이면 높이와 수직 동선, 대각형이면 그 주축과 구역 배치를 기준으로 탐색 규모를 확보한다.
- **갈림길에서는 두 갈래의 끝이 모두 화면 밖**이어야 한다. 한쪽 끝이 보이면 선택이 아니다.
  → 수평 갈래 1,300px는 참고값. 수직·대각선 갈래는 실제 시야와 차폐를 확인한다. 경로 길이만 길어도 끝이 보이면 선택의 긴장감이 생기지 않는다.
- 시야를 가리는 방법 3가지 (섞어 쓴다):
  1. **두꺼운 벽**(≥ 300px) 으로 옆방을 가린다
  2. **통로를 꺾는다** — ㄱ자·ㄷ자 통로는 코너를 돌기 전엔 안 보인다
  3. **층을 가른다** — 위층 바닥이 곧 아래층 천장. 슬래브 두께 ≥ 140px
- 반대로 **일부러 보여 주는 것**도 쓴다: 막다른 길 끝에서 **출구가 보이는데 못 가는** 창(§4-3 ⓑ) — 이건 좋은 좌절이다.

### 3-1. 외곽의 빈 공간 방지

플레이어가 맨 위·맨 아래·양쪽 끝·각 모서리에 서거나 점프해도 **스테이지 외벽 뒤나 지형 밑의 빈 배경이 노출되지 않도록** 마감한다. 시작 바닥 아래의 삼각형 공백처럼 잘린 단면이 보이는 경우도 포함한다.

- 플레이 가능한 안쪽 경계와 이를 둘러싸 화면을 채우는 외곽 영역을 별도로 표시한다. 외벽·바닥·천장을 바깥으로 연장하고 연결부를 메운다. 안쪽 충돌면과 색 전환 틈, 의도된 내부 공간은 보존한다.
- 실제 최저 줌·화면 비율·카메라 오프셋·앞보기·흔들림·전환 이동을 포함해 화면 범위를 구한다. 기준 반시야는 960×540px(줌 1.0)이며 여기에 카메라 이동 여유가 추가된다. 내부 차폐용 300px 벽만으로 외곽을 충분히 가렸다고 판단하지 않는다.
- 카메라 리밋만으로 완료 처리하지 않는다. 특히 평행사변형·사다리꼴 외곽은 사각 리밋 안에서도 대각선 바깥의 삼각형 공백이 보일 수 있다. 모든 비스듬한 변과 모서리 주변까지 채운다.
- 설계도에 외곽 마감·카메라 범위를 표시한다. 정적 확인과 실제 화면 검사를 구분하며, Godot 실행이 명시적으로 허용된 경우에만 네 방향 끝·모서리·시작·도착에서 화면을 확인한다.

## 4. 갈림길 문법 (이 스테이지 라인의 핵심)

### 4-1. 갈림길 종류 — 한 스테이지에 셋 다 넣는다

| 코드 | 이름 | 무엇 | 플레이어 경험 |
|---|---|---|---|
| **F1** | 막다른 길 (가짜) | 올바른 길처럼 보이는데 끝이 막혀 있다. 끝까지 가면 **돌아와야** 한다 | "속았다 → 그래도 뭔가 얻었다" |
| **F2** | 빙 도는 길 (진짜) | 올바른 길인데 **크게 돌아** 목적지 근처로 되돌아온다 | "멀리 왔는데 아까 그 자리네 → 이제 열렸다" |
| **F3** | 지름길 (조건부) | 짧지만 **색·탄약·장치**가 맞아야 통과. 처음엔 못 간다 | "저기로 가면 빠른데… 나중에 다시 오자" |

### 4-2. 배치 규칙

1. **갈림길은 스테이지당 2~3곳.** 더 많으면 미로가 되어 색 퍼즐이 죽는다.
2. **첫 갈림길은 시작에서 진행 방향 기준 1화면 이내.** 수평 1920px, 수직 1080px(줌 1.0)를 참고하고 실제 카메라 시야로 확인한다. 튜토리얼 없이 "골라야 한다"를 바로 가르친다.
3. 갈림길 한 곳의 갈래는 **2개**. 3개는 마지막 갈림길에서만.
4. 각 갈래는 **다른 색**으로 시작하게 한다 (왼쪽 흰색·오른쪽 검정). 색이 곧 안내판이다.
5. **고리(loop) 구조.** F1 의 끝에서 되돌아오는 길은 **왔던 길과 다른 길**이어야 한다
   (예: 위로 갔다가 낙하지대 아닌 400px 이하 낙차로 아래층에 떨어져 시작 근처로 복귀).
   같은 길을 그대로 되밟게 하면 그냥 벌칙이다.
6. **되돌아오는 시간 ≤ 갔던 시간의 절반.** 낙차·승강기·통로로 빨리 돌려보낸다.

### 4-3. 막다른 길(F1)에는 반드시 하나 이상

- ⓐ **체크포인트** — 헛걸음이 저장은 되게
- ⓑ **정보** — 출구·버튼·다음 방이 **보이는 창**(벽 사이 틈, 창문 Template). "저기가 목적지구나"
- ⓒ **장치** — 여기서 누른 **압력버튼(`한 번 누르면 유지`)** 이 **다른 갈래**의 발판·문을 움직이거나, **제어레버**가 물줄기를 다른 갈래로 돌린다 → 사실은 헛걸음이 아니었다 (FBWG 의 협동 치환). ⚠ 제어레버는 **물 전용**이라 발판·문은 못 움직인다
- ⓓ **탄약 회수 기회** — 칠해 둔 발판을 되돌아오며 회수(E)하게 해 탄약 이코노미를 굴린다

**ⓒ 를 스테이지당 최소 1곳.** "막다른 길이 실은 열쇠" 가 이 구조의 가장 큰 재미다.

### 4-4. 금지

- 막다른 길 끝에 **아무것도 없는** 배치
- 막다른 길에 **내려가기만 하고 못 올라오는** 낙차 (소프트락 — `레벨검사.gd` 가 잡는다)
- 갈림길 두 갈래가 **같은 색·같은 모양** (구분이 안 되면 선택이 아니라 동전 던지기)
- 가짜 길이 **진짜 길보다 훨씬 예쁘거나 눈에 띄는** 배치 — 속임수가 아니라 **그럴듯함**이어야 한다

## 5. 지형 모양 어휘 — 직사각형만 쓰지 않는다

모든 지형은 **SS2D `WALL_벽체` 키트**로 찍는다 (§6). SS2D 는 임의 다각형이므로 아래 모양이 전부 가능하다.
**곡선은 금지**(테두리 45°/135°/225°/315° 에 틈이 생기는 알려진 이슈 `CLOSED-LOOP-TAPER-01`).

| 코드 | 모양 | 쓰는 자리 | 수치 규칙 |
|---|---|---|---|
| **S1** | 직사각형 | 바닥 슬래브·벽·기둥 | 두께 ≥ 140px (권장 180) |
| **S2** | **사다리꼴** (윗변 < 아랫변) | 층을 받치는 받침대·제단 모양 발판 | 옆면 기울기 ≤ 45° |

## 6. SS2D 붙이기 규칙 — 겹치지 말고, 딱 붙인다 (★수정 가능성 때문)

**[사용자 추가 지시] 연속된 플랫폼 하나는 SS2D 하나로 만든다.** 평지·경사·평지·내리막을 4개 노드로 조립하지 않고 **한 노드 안의 꼭짓점(편집 점)을 늘려** 닫힌 폴리곤 하나로 표현한다. 씬 노드를 늘리라는 뜻이 아니다. 작업자가 플랫폼 전체를 한 번에 선택·이동·수정할 수 있어야 한다.

독립된 색 구간(전환 틈 포함), 움직이는 문, 떨어져 있는 발판처럼 분리가 필요한 경우에만 별도 노드를 쓴다. 플랫폼 생성 헬퍼는 여러 노드를 만들지 않고 점 목록을 모아 마지막에 노드 하나를 생성한다. 분리 이유는 설계도에 기록한다.

> 도형 지시: "겹치게 만들면 내가 수정하기 힘들다. 딱 SS2D 경계선이 달라붙게."

### 6-1. 원칙

1. **이웃한 두 지형은 꼭짓점을 공유한다.** A 의 오른쪽 변 두 점 = B 의 왼쪽 변 두 점 (좌표가 **같은 숫자**).
2. **겹침 0, 틈 0.** 겹치면 안쪽 텍스처가 두 겹으로 그려지고 점 하나를 옮기면 옆 지형과 어긋난다.
3. **T 자 접합**은 긴 쪽 변 위에 짧은 쪽의 두 점이 정확히 놓이게 한다 (긴 쪽에 점을 추가하지 않아도 된다 — 직선 위이므로).
4. **모든 꼭짓점을 16px 격자**에 둔다. 경사면도 양 끝점을 격자에 두면 이웃과 맞는다.
5. 한 덩어리로 보이는 지형(바닥 + 그 위 벽)은 **가능하면 폴리곤 하나(ㄱ자·ㄷ자)** 로 만든다 — 조각이 적을수록 수정이 쉽다.
   단, **색이 갈리는 곳**은 반드시 나눈다 (`시작상태` 는 노드당 하나).

### 6-2. 에디터에서 찍을 때

- SS2D 노드 선택 → 툴바 SS2D 스냅 메뉴 → **"격자 스냅 사용" 켜기 · "상대적인 스냅" 끄기** · 스냅 구성 Step = 16
- Godot 자체 ⊞ 스냅은 **노드 이동에만** 작동한다. 점 편집은 SS2D 스냅이 담당.
- Template 을 꽂고 **Scale 은 1 로 둔다.** 축척하면 재질이 늘어나고 이웃과 점이 안 맞는다. 크기는 **점을 끌어** 바꾼다.

### 6-3. 빌더 스크립트로 찍을 때 (권장 — 좌표가 표로 남는다)

- `tools/build_하수도_2-8.gd` 의 `_지형(층, 템플릿, 이름, 월드점들, 칠가능, 시작, 유령)` 을 그대로 복사해 쓴다.
  월드 좌표로 점을 주면 노드 중심을 잡고 로컬로 바꿔 `SS2D_Point_Array` 를 만든다. **Scale 을 안 건드린다.**
- 폴리곤 표를 먼저 적고, **이웃 지형끼리 같은 점 상수를 참조**하게 한다 (숫자를 두 번 적지 않는다).

## 7. 색 규칙이 맵 구조에 거는 제약 (잊기 쉬운 것)

- **안 칠한 지형 = 검정.** 흰 플레이어는 안 칠한 바닥·벽·천장 어디에 닿아도 죽는다.
  → **한 구간의 바닥·벽·천장은 같은 색.** 흰 구간을 검정 천장으로 덮지 않는다.
- ★**지형에 회색은 없다**(2026-09-06 도형 지시 — `build_하수도_2-1.gd` 머리 주석). 지형은 검정·흰색 둘뿐, 회색은 물·웅덩이·호퍼에만.
  Shift 는 언제든 눌리지만 **바꾼 순간 닿아 있는 지형이 반대색이면 죽는다** → 안전하게 바꿀 수 있는 곳은 **공중(점프 중)** 과 **회색 물 위**뿐.
  → **색이 바뀌는 경계마다 폭 ≥ 80px 틈**을 둔다(2-1 이 구간 4→5·5→6·8→9 에 그렇게 했다). 턱만 두면 검정인 채로 흰 턱 옆면에 부딪쳐 죽는다.
  → 주행검사에서는 `["뛰기색", …]`(공중 전환) 으로 건넌다.
- **모든 지형 `칠하기_허용 = true`** (규약 4). 벽도 칠할 수 있다 = 벽도 위험하다.
- 갈래 색 배치: **왼쪽 갈래 흰색 · 오른쪽 갈래 검정** 처럼 갈림길에서 색이 갈리면 "어느 색으로 갈까" 가 곧 선택이 된다.
- 층 간격은 헤드룸 ≥ 440 + 슬래브 ≥ 140 = **≥ 580px**. ★[2026-09-14] 치명 낙하가 **1500** 으로 바뀌어 층에서 층으로 떨어져도 죽지 않는다. 구멍은 ① 되돌아올 길이 있거나 ② 바닥에 가시·반대색 웅덩이를 둔 죽는 구멍, 둘 중 하나여야 한다(못 올라오는데 안 죽는 구멍 = 소프트락).

## 7-1. ★색 비율 — 검정이 기준, 흰색은 사이사이 (2026-09-12 도형 지시)

> "맵은 검은색 타일이 기준이다. 검정 플랫폼이 주를 이루고 중간에 흰색이 있는 느낌. **검정 6.5 : 흰색 3.5**."

| 규칙 | 값 |
|---|---|
| 지형 **면적 비율** | **검정 65 % · 흰색 35 %** (±5) |
| 기본색 | 시작 구간·출구 구간·큰 벽·천장·기둥은 **검정** |
| 흰색이 오는 자리 | **갈래 하나**(FBWG 의 "파란 길") · 중간 층의 **섬**·선반 · F3 지름길 · 장치가 있는 방 |
| 흰색 덩어리 크기 | 한 덩어리는 **1화면(1920px) 이하**. 흰 구간이 두 화면 이상 이어지지 않는다 |
| 흰색 덩어리 수 | 스테이지당 **3~5 덩어리**, 서로 떨어져 있고 각 덩어리 앞뒤에 **≥ 80px 틈**(공중 색 전환) |
| 플레이어 시작 색 | **검정** (기본 지형과 같으니 시작부터 죽지 않는다) |

왜 검정이 기준인가: 안 칠한 지형 = 검정이라, 검정 플레이어는 **아무것도 안 칠하고도** 대부분을 걸을 수 있다. 흰 구간이 "칠하거나 색을 바꿔야 하는 문제"가 되고, 그 문제가 **드문드문** 있어야 리듬이 생긴다. 흰색이 절반을 넘으면 문제가 아니라 배경이 된다.

빌더에서: 지형 표에 색을 적은 뒤 **면적을 합산해 비율을 로그로 찍는다**(`검정 %.0f%% · 흰색 %.0f%%`). 60~70 % 범위를 벗어나면 굽기를 실패시킨다.

## 9. 한 판의 뼈대 (상승형 예시 — 사용자 선택에 맞춰 변형)

아래 그림은 **아래 시작 → 우측 상단 도착을 선택했을 때의 한 예시**다. 기본 배치로 자동 적용하지 않는다. 다른 시작·목적지·형태를 선택하면 그에 맞춰 주 동선과 갈림길을 다시 설계한다.

```
									[출구 통로]  ← L4  (마지막 층, 오른쪽 끝)
		┌─ S3 역사다리꼴 선반 ─┐         ▲ 승강기(버튼 B · 박스로 유지)
 L3 ═══╧═══[F1 막다른 길·창·버튼 A]═╧═ 80px틈 ═╧═════[버튼 B]═════
		▲ S5 경사로(흰)      ▼ 중간 선반 2단(≤400씩)   ▲ S9 계단(검)
 L2 ════[흰 갈래]══════[교차점·움직이는 다리(버튼 A)]══════[검 갈래]════
		▲ S2 사다리꼴 받침                          ▲ F3 지름길(검정 웅덩이 — 흰색은 못 감)
 L1 ═[시작·검정]═══════╦═ 80px틈 ═ 첫 갈림길 ═╦═══════════════
					  흰 ↑(공중 전환)        ↑ 검
```

정답 흐름(예): 시작(**검정**) → 첫 갈림길 80px 틈에서 공중 전환해 **왼쪽(흰)** → L2 → L3 **막다른 길** 끝에서 창으로 출구 확인 + **버튼 A(한 번 누르면 유지)** → L2 교차점의 **움직이는 다리**가 열림 → **중간 선반 2단(각 ≤ 400)** 으로 L2 복귀(고리 · 560 을 한 번에 떨어지면 죽는다) → 틈에서 공중 전환해 **검정** → 오른쪽 갈래 → 계단 → L3 **버튼 B** 에 박스를 올려 유지 → 승강기(`움직이는발판` `이동거리 = 0` + 버튼 대상) → L4 출구.
**F3 지름길**(검정 웅덩이 위 짧은 길)은 처음엔 흰색이라 못 가고, 검정이 된 뒤 되돌아올 때 쓰인다.

물감 이코노미(가이드 §2): S(정답 최소 발수) 4~6 · 반대색 함정(조준선 위에 반대색 발판이 겹쳐 실수로 덮어쓰게 유도) 1~2 · FIFO 깊이 1~2 (하수도 5~12 난이도대).
⚠ `레벨디자인_가이드.md` §2 의 "회색 함정" 은 옛 규칙이다 — 지금은 **반대색을 쏘면 회색 혼합 없이 덮어쓴다**(`페인트_코어.gd` 머리 주석). 회색은 장애물 상호작용으로만 생긴다.
