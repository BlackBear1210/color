## 2. 왜 빌더로 찍나

에디터에서 SS2D 점을 끄는 것도 가능하다(`README_지형찍기.md` 가 그 방법이다). 그런데 하수도는 이렇게 만들었다:

1. **구간이 색으로 갈린다.** `시작상태` 는 노드당 하나뿐이라, 회색 전환 띠 하나를 만들려면 바닥을 조각내야 한다. 2-1 만 지형 노드가 **37 개**다. 손으로 37 개를 일관되게 찍는 것보다 표 하나를 적는 게 빠르고 안 틀린다.
2. **모든 값이 서로 물려 있다.** 바닥 높이를 120 올리면 천장·물줄기 길이·유령 발판·출구 선반이 전부 따라 움직여야 한다. 빌더는 **바닥에서 파생**시키므로 한 곳만 고치면 된다.
3. **되풀이 가능하다.** 검사에서 걸리면 숫자 하나 고치고 다시 굽는다. 손으로 찍었으면 37 개를 다시 옮겨야 한다.

그래서 **구간의 바닥·벽·천장은 반드시 같은 색**이다. 빌더는 구간표의 색 하나로 셋을 다 칠한다.

이 제약이 오히려 좋은 신호가 됐다 — **벽 색 = 여기서 있어야 하는 색.** 플레이어가 들어서기 전에 보고 안다.

## 4. 단면·좌표 규약

```
        천장 윗면  y = 140  ← 모든 천장이 공유. 여기서 아래로 두께가 붙는다
        ─────────────────────────────
              (통로 480 / 챔버 800)
        ─────────────────────────────
        바닥 윗면  y = 기복 생성기가 정함 (980 · 1100 · 1220)
              바닥 두께
        바닥 아랫면 y = 가장 낮은 바닥 + 260  ← 모든 바닥이 공유
```

- **천장 아랫면 = 그 구간 바닥 − 480**(일반 통로) · **− 800**(관문 4·5 챔버).
  천장이 바닥을 따라다니므로 굴곡을 넣어도 바닥·천장이 늘 한 화면에 들어온다.
- 바닥 조각은 **전부 같은 아랫면까지** 내려간다. 공중에 뜬 조각을 안 만들려는 것이다.

### ⚠ 설계도의 "통로 높이 960" 은 못 쓴다 — 실측으로 480 으로 고쳤다

`TEMPLATE_WALL_SOLID` 의 기본 높이(960)에 맞춘 값이었는데, **카메라가 플레이어 중심**이라 줌 1.0 에서 보이는 것은 **바닥 기준 위로 594 · 아래로 486** 뿐이다. 960 을 쓰면 천장이 화면 밖으로 나가고, 그러면 *"물줄기가 어디서 오는지 화면에 보이는가"*(제작계획 §9 체크리스트)가 깨진다.

점 배열은 어차피 빌더가 직접 찍으므로 **템플릿 기본 높이를 맞출 이유가 없다.**

> **설계도와 빌더가 어긋나면 빌더가 맞다.** 설계도는 "무엇을 만들까", 빌더는 "실제로 성립하는 값".

## 5. 빌더 읽는 순서

### 5-1. 구간표 — x 범위와 색만 적는다

```gdscript
## [x0, x1, 색, 챔버인가]   ← 높이는 안 적는다
const 구간표 := [
    [300.0, 1240.0, 검정, false],     # 0 시작
    ...
    [2980.0, 3360.0, 회색, false],    # 5 전환 띠 — 색을 바꿀 수 있는 유일한 자리
    [4560.0, 5080.0, 흰색, false],    # 9 흰 구간
    ...
]
```

같은 색을 여러 조각으로 쪼갠 곳이 많다. **퍼즐은 그대로 두고 걷는 리듬만 넣으려고** 그렇게 한 것이다.

### 5-2. 높이는 기복 생성기가 정한다

```gdscript
_높이 = 기복.굴곡(구간표.size(), 씨앗, {
    "기준": 1100.0, "단": 120.0,
    "위로": 1, "아래로": 1,      # 기준 ±1칸 = 980 · 1100 · 1220 세 높이
    "평지": [11],                # 구덩이 착지는 도약대와 같은 높이라야 한다
    "직진_최대": 2,              # 같은 높이 3연속 금지 = 일자 맵 금지
    "머물_확률": 0.22,
})
var 문제 := 기복.검산(_높이, 단)   # 못 오르는 턱이 있으면 빌드를 멈춘다
```

**씨앗 숫자 하나만 바꾸면 맵의 리듬이 통째로 바뀐다.** 몇 개 뽑아 보고 마음에 드는 것을 상수로 박는다.

#### ★★ 랜덤인데 왜 매번 같은 맵인가 — 일부러 그렇게 만들었다

빌드마다 맵이 바뀌면 ① 레벨검사를 통과해도 다음 빌드에서 깨지고 ② 관문 좌표를 적어 둔 설계도가 매번 거짓말이 되고 ③ 버그가 재현이 안 된다. `AGENTS.md §5` 의 **"도구는 멱등이어야 한다"** 가 바로 이것이다.

#### 생성기가 대신 지켜 주는 것

| 규칙 | 왜 |
|---|---|
| 한 턱은 **±120** 뿐 | 안전 오름단차가 **128**(`지형규칙.gd`)이라 120 이면 점프 없이 걸어서 **양방향** 오르내린다. 더 크게 잡으면 죽고 체크포인트로 돌아온 뒤 못 올라가는 **일방통행**이 생긴다 |
| 높이는 **띠 안**에 갇힌다 | 안 그러면 계단이 한 방향으로만 쌓여 스테이지가 통째로 기운다 |
| 같은 높이 **3연속 금지** | 이게 "일자 맵 금지" 다 |
| `평지` 로 못 박기 | 구덩이 착지처럼 높이가 어긋나면 안 되는 자리 |

### 5-3. 나머지는 전부 바닥에서 파생된다

| 만드는 것 | 기준 |
|---|---|
| 천장 아랫면 | 그 구간 바닥 − 480 (또는 −800) |
| 유령 발판 윗면 | `기준x` 자리 바닥 − `올림칸 × 120` |
| 출구 선반 윗면 | 바닥 − 120×3 (사다리 셋째 칸) |
| 물줄기 아랫면 | `"바닥"` / `"발판"`(그 자리 유령 발판 윗면) / `"통로"`(바닥 − 340) |
| 물줄기 윗면 | 그 자리 **천장 아랫면** (물이 천장 배관에서 나와야 읽힌다) |
| 낙사 y · 카메라 리밋 | 가장 낮은 바닥에서 계산 |

**그래서 씨앗을 바꿔도 오름 단차 120 과 관문 5 의 "물 아래 통로 340" 은 저절로 지켜진다.**

## 6. ★★ 실제로 터진 함정들 — 여기부터 꼭 읽을 것

전부 이번에 한 번씩 터뜨리고 고친 것이다. 2-2 를 찍을 때 **똑같이 터진다.**

### ① 흰 물 4줄기가 조용히 회색으로 구워졌다 — `GEN_EDIT_STATE_INSTANCE`

`PackedScene.instantiate()` 의 기본값(`GEN_EDIT_STATE_DISABLED`)은 **인스턴스 상태를 안 들고 온다.** 그러면 `pack()` 이 "이 값을 씬에 적을까" 를 **스크립트 기본값**과 비교해서 정한다.

`유체.gd` 의 기본색이 **흰색**이라, 흰 물을 넣으면 *"기본값과 같네"* 하고 **안 적는다.** 로드할 때는 `유체.tscn` 에 저장된 **회색**이 나온다. F4·F6·F7·F8 네 줄기가 전부 회색이었다. 에러도 경고도 없다.

```gdscript
var 물: Node2D = 씬.instantiate(PackedScene.GEN_EDIT_STATE_INSTANCE)   # ← 이렇게
```

> 장치 씬(`유체` · `배관` · `가시` …)을 꽂을 때는 **항상 이걸 쓴다.**
> 지형 Template 은 점 배열을 어차피 갈아 끼우므로 기본 `instantiate()` 로도 된다.

### ② 조각 경계마다 폭 32 · 깊이 500 짜리 **세로 슬롯**이 생긴다

SS2D 는 `collision_size`(24)만큼 콜리전을 **안쪽으로 깎는다.** 그래서 x 를 딱 맞춰 두면 조각 사이에 폭 ~32 틈이 생기고, 조각이 전부 같은 아랫면까지 내려가 있으니 그게 깊이 500 짜리 슬롯이 된다.

바닥이 평지일 때는 선반이 하나로 합쳐져 **안 보였다.** 굴곡을 넣자마자 레벨검사가 계단마다 *"낙차 밑이 없음"* 으로 **19 곳**을 잡아냈다.

**고치는 법 — 짧은 조각을 긴 조각 밑으로 48px 밀어 넣는다** (`_겹치기()`).
두 조각은 한쪽 면을 공유하므로(바닥은 아랫면, 천장은 윗면), 그 면에서 덜 뻗은 쪽이 짧은 쪽이다. 짧은 쪽을 늘리면 겹친 부분이 **긴 쪽 안에 통째로 묻혀 화면에는 아무 변화가 없다.**
⚠ 반대로 긴 쪽을 늘리면 낮은 바닥 위로 **턱이 삐져나온다.**
⚠ 구덩이처럼 **원래 떨어져 있는 경계는 건드리면 안 된다** — 늘리면 구덩이가 메워진다.

### ③ 유령 발판이 바닥을 파고들어 통로를 막았다

관문 5 사다리를 `윗면 940 · 높이 180` 으로 잡았더니 아랫면이 1,120 이 되어 바닥(1,100)을 20px 파고들었다. 그 조각이 통로를 막아 레벨검사가 **도달 불가**로 잡았다. 오름 단차도 160 이라 안전 오름단차 128 을 넘었다.

→ 사다리 칸은 전부 **오름 단차 120**, 바닥에 얹히는 칸은 **높이 = 120** 으로 맞춘다.

### ④ 32px 짜리 주머니에 빠지면 못 나온다

출구 선반을 유령 발판 오른끝(8,160)에서 40px 띄워 8,200 에서 시작했더니, 바닥에 폭 32 짜리 주머니가 생겼다. 거기 떨어지면 양옆이 360 벽이라 못 나온다 → **소프트락**.

→ 선반 왼끝을 발판 오른끝에 **붙였다.**

### ⑤ 흰 지형은 반드시 `_WHITE` Template 을 쓴다

검정판에 `시작상태 = 흰색` 만 주면 **에디터 화면에서는 검게 보인다**(칠하는 셰이더가 실행 중에만 돈다). 배치하다 반드시 헷갈린다. `README_지형찍기.md` §3 에도 같은 경고가 있다.

- 흰 바닥 → `TEMPLATE_CEMENT_SOLID_WHITE` · 흰 벽/천장 → `TEMPLATE_WALL_SOLID_WHITE`
- **회색은 짝이 되는 Template 이 없다.** 검정판 + `시작상태 = 회색` 으로 둔다(에디터에선 검게 보인다).

### ⑥ enum 값을 헷갈리면 조용히 다른 색이 나온다

```gdscript
# 지형.gd   enum 상태  { 무색 = 0, 검정 = 1, 흰색 = 2, 회색 = 3 }
# 유체.gd   enum 물색_ { 검정색 = 0, 흰색 = 1, 회색 = 2 }        ← 순서가 다르다!
```

**지형의 2 는 흰색이고 유체의 2 는 회색이다.** 빌더는 이걸 상수로 따로 박아 뒀다(`검정`/`흰색`/`회색` vs `물_검`/`물_흰`/`물_회`).

### ⑦ `tools/screenshot_scene.gd` 는 카메라가 안 따라온다

플레이어 x·y 를 줘도 **카메라가 시작 지점에 머문다.** 그래서 관문 2~5 는 스크린샷으로 확인이 안 됐고, 좌표·색은 임시 점검 스크립트로 데이터를 찍어서 확인했다.

→ 중간 구간을 눈으로 보려면 카메라를 직접 옮기도록 도구를 고치거나, 에디터에서 씬을 열어 본다.

### ⑧ 레벨검사의 "도달 불가" 는 대부분 정상이다

천장·끝벽의 **윗면**은 아무도 안 밟으므로 늘 도달 불가로 나온다(2-1 은 17 개). `README_지형찍기.md` §19 에도 *"장식으로 일부러 띄워 둔 것이 도달 불가로 나오는 건 정상"* 이라고 적혀 있다.

**진짜로 봐야 하는 것은 `소프트락` 과, 밟아야 하는 지형이 도달 불가에 끼어 있는지다.**

### ⑨ `build_*.gd` 를 다시 돌리면 에디터 편집분이 날아간다

`AGENTS.md §4`. 씬을 에디터에서 손본 뒤 빌더를 다시 돌리면 그 값이 전부 사라진다.
그리고 **그 씬이 에디터에 열려 있으면 빌드 뒤 반드시 "씬 → 저장된 씬 다시 불러오기"** 를 해야 한다. 안 하면 에디터가 옛 내용으로 덮어쓴다.

> **결론: `stage_2-1.tscn` 을 직접 고치지 마라. 빌더를 고치고 다시 구워라.**

### 순서

1. `tools/build_하수도_2-1.gd` 를 **복사**해서 `build_하수도_2-2.gd` 로 만든다.
2. `내씬` · `루트.name` · `스테이지_이름` 을 바꾼다.

### 2-2 「구멍 난 바닥」 — 통과 플랫폼 · 수직 갱도

- 새 장치: `통과플랫폼.tscn` (크기 224×26 · 필요횟수 2 · **물이 페인트를 못 지운다**)
- ★**수직 갱도**라 지금 기복 생성기를 그대로 못 쓴다. 가로 굴곡이 아니라 **갱도 폭**이나 **층 높이**에 적용해야 한다.
  `지형기복.굴곡()` 은 그냥 숫자 배열을 주는 함수라, 갱도 좌우 벽의 x 를 만드는 데도 쓸 수 있다(기준 = 갱도 중심 x, 단 = 벽이 들쭉날쭉한 폭).
- 갱도 폭은 **640** 으로 잡았다(설계도). 통과플랫폼 224 를 좌우 번갈아 두면 수평 간격이 86 이라 점프 거리 160 안에 든다. **폭을 800 이상 벌리면 간격이 246 이 되어 못 건넌다.**
- `scripts/스마트월드/카메라공간배치.gd` 를 붙여 세로 구도로 전환한다.

### 2-3 「관을 따라서」 — 배관 + 호퍼

- 새 장치: `호퍼.tscn` (폭 120 · 높이 56 · **밟을 수 있다** · 색 규칙 밖)
- 핵심 문법: **흑 + 백 = 회색.** 두 물줄기를 한 호퍼에 모으면 출구가 회색이 되고, 회색은 누구도 안 죽인다.

## 9. 이 챕터를 지배하는 색 규칙 (코드에서 확인한 것)

맵을 찍기 전에 이 넷을 외우고 시작한다.

1. **안 칠한 바닥은 검정이다.** 무색 지형도 판정은 검정(`색규칙.위험한가` 의 `기본색 = BLACK`). → **흰색 플레이어는 안 칠한 바닥 위에서 죽는다.**
2. **회색만이 둘 다에게 안전하다.** 그래서 **색을 바꿀 수 있는 자리 = 회색 바닥 위**다. 이 설계의 모든 색 전환 지점은 회색 띠 위에 있다.
3. ★**물은 "내가 칠한 것" 만 되돌린다.** `유체.gd` → `지형.되돌리기()` → `_원래대로()` 는 **`시작상태` 로** 되돌린다. 시작상태가 검정인 바닥에 흰 물을 부어도 **다시 검정**이다.
   → **물로 길을 여는 설계는 성립하지 않는다. 물은 길을 닫는다.**
4. **벽도 색 규칙 안에 있다**(규약 4). 구간의 벽·천장·바닥은 전부 같은 색.

### 덤으로 찾은 버그 (아직 안 고쳤다)

`유체.gd:494` → `페인트_코어.부분_자동회수()` 가 **조건 없이 `_환급(1)`** 한다. 그런데 `_회수줄_감소()` 는 그 지형이 회수줄에 없으면 아무것도 안 하고 돌아온다. 즉 **한 번도 칠하지 않은 시작상태 검정 바닥에 흰 물이 닿기만 해도 탄약 1발이 생긴다**(지형당 1회 · 최대 12 상한).

→ 탄약 예산은 이 환급을 **0 으로 놓고** 셌다. 고치려면 `_회수줄_찾기(대상) < 0` 일 때 환급하지 않으면 된다.
