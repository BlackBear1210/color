# Claude Opus 작업 프롬프트 — 하수도 쇠사슬·삼각 지지대 장식 키트

작성: 2026-09-14 · 아스트라

이 문서를 읽고 아래 범위의 재사용 가능한 2D 장식 부품과 시험 씬을 구현하라. 문서만 다시 요약하고 끝내지 말고, 사용자에게 맡겨진 범위의 실제 파일을 만들고 검증 결과와 사용법을 제출하라. 다만 이 문서 자체가 엔진 실행·기존 맵 재생성·커밋·푸시 권한을 부여하지는 않는다. 해당 세션의 사용자 지시와 저장소 규약을 따르라.

## 0. 이번 작업을 한 문장으로 정의

**하수도 플랫폼이 건축물이나 기계에 매달리거나 고정되어 보이도록, 길이 조절 쇠사슬과 좌우형 삼각 지지대·고정구를 만든다. 기존 플레이 지형의 충돌·색칠·사망·승강기 운반 기능은 유지한다.**

참고 이미지: 같은 폴더의 `참고_쇠사슬_삼각지지대.png`.
이미지의 빨간 표시를 에셋에 포함하지 않는다. 왼쪽은 천장에서 승강기 양쪽으로 내려오는 두 쇠사슬, 오른쪽은 벽돌 발판 밑의 삼각 철제 받침이다. 배경·톱·물·플레이어 전체를 재제작하라는 요청이 아니다.

## 1. 목적과 사용자의 확정 의도

GRAY는 검정·흰색 기반 2D 퍼즐 플랫포머다. 하수도 배경에 벽돌 플랫폼만 띄워 놓으면 공간과 연결되지 않아 조립 부품처럼 보인다. 다음 단서로 설치 이유를 보여 주려는 작업이다.

- 쇠사슬: “이 발판은 천장 기계에 매달려 움직인다.”
- 삼각 지지대(까치발/브래킷): “이 발판은 뒤쪽 벽에 볼트로 고정되어 있다.”
- 고정구: 체인 끝이나 철재가 허공에서 갑자기 끝나지 않고 구조물에 연결되었다는 단서.

사용자 확정:

1. 3D가 아닌 2D 고정 시점으로 충분하다. 카메라 위치에 따라 옆면이 바뀌지 않는다.
2. 실제 연속 플랫폼 하나는 SS2D 하나다. 모양을 바꾸려면 점을 추가한다.
3. 벽돌 채움·상면·모서리처럼 반복 부품을 조합한다. 긴 이미지 하나를 마구 늘리지 않는다.
4. 검정 지형 전체에 고정 흰 테두리를 붙이지 않는다. 지형의 약한 근접 반사는 이미 별도 구현되어 있다.
5. 배경은 비교적 밝고 저대비이며, 플레이 지형과 깊이를 구분한다.
6. 이번 쇠사슬·지지대는 **우선 충돌 없는 장식**이다. 밟기·매달리기·타고 오르기·체인 끊기 퍼즐은 이번 범위가 아니다.

## 2. 구현 범위와 제외 범위

### 반드시 만들 것

- 길이를 조절하는 반복 쇠사슬 장식 1종.
- 고정 천장점과 움직이는 플랫폼 연결점을 참조하는 쇠사슬 연결 기능.
- 쇠사슬 한 줄/두 줄을 사용할 수 있는 조합 예시.
- 좌향/우향 삼각 지지대. 별개 그림을 두 벌 관리하기보다 하나의 구조와 방향 옵션을 우선 검토한다.
- 천장 체인 고정구와 벽면 브래킷 고정 볼트/플레이트.
- 고정 SS2D 발판 조합과 기존 상하 승강기 조합 시험 씬.
- 설정 안내, 배치 예시, 검증 결과표, 알려진 제한.

### 이번에 하지 않을 것

- 고리마다 RigidBody2D·관절을 만들어 실제로 매다는 물리 체인.
- 체인 장력이 승강기를 끌어올리거나 지지대가 하중 계산을 하는 시스템.
- 파괴·플레이어 매달리기·등반·흔들림 퍼즐.
- 기존 장애물 디자인 전면 변경, 공용 색 규칙 변경, 다른 팀원의 스테이지1 수정.
- 기존 stage_2 맵 전체에 자동 배포, 기존 맵 재굽기, 챕터표 변경.
- 외부 에셋이나 생성 결과를 확인하지 않고 완성품이라고 부르기.

낮은 비용의 흔들림/물방울은 후속 확장 후보로만 문서화한다. 필수 부품이 안정화되기 전에 넣지 않는다.

## 5. 쇠사슬의 동작 계약

### 5-1. 길이를 바꾸는 원리

고리 몇 개가 연결된 **반복 단위 텍스처**를 일정한 크기로 이어 그린다. 체인 전체의 Scale.y를 늘려 고리가 납작하거나 길쭉해지는 방식은 사용하지 않는다.

세로 반복 경계에서 고리가 자연스럽게 이어지도록 텍스처를 준비한다. 좌우 배경은 진짜 알파0이어야 한다. 체커보드가 그려진 이미지나 흰 배경 JPG를 투명 에셋으로 쓰지 않는다.

가능한 구현은 여러 개다. 반복 UV를 쓰는 단일 메시/그리기 방식, 반복 텍스처 선 그리기 등을 현재 Godot API와 에디터 미리보기에서 확인해 하나를 선택하라. **매 프레임 고리 수만큼 노드를 생성/삭제하는 방식은 금지**한다.

선택 이유를 사용 안내에 짧게 남긴다. 고리 간격, 끝단 클리핑, 텍스처 필터링이 안정적인지를 우선한다. Node를 써야 한다면 길이 변경 시만 갱신하고 수를 제한한다.

### 5-2. 두 끝점

- 시작점 A: 천장 고정점. 플랫폼과 함께 이동하면 안 된다.
- 끝점 B: 플랫폼 연결점. 플랫폼 이동을 따라간다.
- 길이 L = distance(A,B). 길이0 또는 아주 짧은 구간은 나눗셈/정규화 전에 처리한다.
- 월드 좌표로 두 Marker2D 위치를 얻은 후 **체인 노드의 로컬 좌표로 변환**해 그린다. 로컬 좌표와 월드 좌표를 섞지 않는다.
- 부모 Node2D를 옮겨도 연결이 유지되어야 한다. 부모 스케일은 기본(1,1)을 권장하고, 비균일/음수 스케일 지원 여부를 명확히 한다.

### 5-3. 모드

1. **고정 장식 모드:** 인스펙터의 로컬 시작/끝 좌표나 길이로 배치한다. 이동이 없으면 상시 업데이트하지 않는다.
2. **대상 추적 모드:** 시작 Marker2D와 끝 Marker2D를 NodePath로 지정한다. 최소한 끝점 추적은 지원한다. 대상 위치가 바뀔 때만 그리기 데이터를 갱신한다.

두 모드가 동시에 서로 덮어쓰지 않도록 어떤 값이 우선하는지 명시한다. 인스펙터 값의 저장/재로드 결과도 같아야 한다.

### 5-4. 승강기와 함께 움직일 때

천장 Marker는 승강기 바깥에 둔다. 끝점 Marker는 승강기의 자식으로 둔다. 승강기가 올라가면 체인 길이가 짧아지고 내려가면 길어진다. 체인이 천장 장치로 감기는 연출이다.

텍스처 반복 위상은 한 기준으로 고정한다. 예를 들어 플랫폼 연결점에 위상을 고정하면 끝 고리가 발판에 붙어 있고, 위쪽 고리가 천장으로 들어가는 것처럼 읽힌다. 길이가 고리 간격을 넘을 때 전체 체인이 갑자기 한 칸 튀지 않아야 한다.

기존 승강기 위치 갱신 순서와 렌더링 위치를 확인한다. 물리 프레임과 화면 프레임의 차이로 연결점이 한 프레임 늦거나 떨리면 장식 쪽 갱신 시점/보간을 맞춘다. 이를 해결하려고 기존 승강기의 물리를 끄지 않는다.

체인 연결 노드가 승강기의 position을 변경하거나 이동속도를 결정해서는 안 된다. **체인은 이동 결과를 읽기만 한다.**

수직 체인 시험에서는 좌우 끝점 각각의 x를 맞춘다. 승강기가 천장 위로 올라가는 잘못된 배치는 체인을 뒤집어 그리며 숨기지 말고 경고한다. 수평 이동도 계산상 대각선 연결은 가능하지만, 실제로 늘어나는 체인처럼 보일 수 있다. 수평 승강기의 기계적 연출은 별도 설계 범위로 기록한다.

## 6. 노드 구성 예시 — 부모를 잘못 잡지 말 것

아래는 역할 예시다. 엔진 클래스/API 이름은 실제 프로젝트 버전에 맞춰 확인한다.

```text
시험구간 (Node2D)
├─ 천장고정점_L (Marker2D)
├─ 천장고정점_R (Marker2D)
├─ 체인_L (장식 전용 Node2D)
├─ 체인_R (장식 전용 Node2D)
└─ 승강기 (기존 움직이는발판.tscn 인스턴스)
   ├─ 체인연결점_L (Marker2D)
   └─ 체인연결점_R (Marker2D)
```

두 체인은 각각 천장 Marker와 승강기의 Marker를 참조한다. 천장까지 승강기 자식에 넣으면 두 점이 같이 움직여 길이가 변하지 않으므로 잘못된 구성이다.

기존 승강기에 새 SS2D StaticBody2D를 중첩하여 충돌을 두 겹으로 만들지 않는다. 승강기 외관 교체가 필요해도 기존 AnimatableBody2D가 충돌을 담당하도록 분리하고, 이번 범위에서 필요 없으면 승강기 본체 외관은 보존한다.

## 7. 삼각 지지대의 동작 계약

### 7-1. 구조와 고정 의미

가로 철재 + 세로 철재 + 대각 철재 + 벽 고정 볼트로 구성한다. 뒤쪽 하수도 벽에 세로 철재가 고정되고, 가로 철재가 플랫폼 아랫면을 받치는 형태다.

독립된 섬처럼 떠 있는 플랫폼 아래에 지지대만 붙여 놓으면 지지대도 같이 공중에 뜬다. 뒤쪽 벽·벽 플레이트·매입 흔적 등 고정의 근거가 화면에 있어야 한다. 배경 레이어의 시차가 큰 벽에 직접 고정된 것처럼 그리면 카메라 이동 때 고정구가 미끄러져 보인다. **고정구/근접 벽 장식은 플랫폼과 같은 월드 좌표계**에 두고 먼 배경과 구분한다.

### 7-2. 그림 방식

기본은 투명 배경의 브래킷 한 장으로 구현해도 된다. 관리가 쉽고 볼트·모서리 명암을 유지할 수 있다. 최소 하나의 완성된 형태를 먼저 만든다.

크기 조절이 필요한 경우:

- 전체 비율을 유지하는 균일 확대/축소는 제한된 범위에서 허용한다.
- 폭만2배·높이만0.5배 같은 변형으로 볼트가 타원형이 되거나 철재 두께가 달라지면 안 된다.
- 넓은 플랫폼은 같은 지지대를 두 개 배치한다. 하나를 플랫폼 전체 너비까지 늘이지 않는다.
- 다양한 폭/높이가 꼭 필요하면 가로/세로/대각 철재와 볼트를 분리해 조립한다. 철재 단면 두께와 볼트 크기를 일정하게 유지한다. 처음부터 불필요하게 복잡한 범용 건축 편집기를 만들지 않는다.

좌우 방향은 내부 Sprite의 flip 또는 계산 좌표 반전으로 제공한다. 게임 지형의 Scale.x를 -1로 바꾸는 방식은 금지한다. 명암 방향까지 뒤집혀 어색하면 별도 좌우 그림 또는 중립적인 명암을 사용한다.

### 7-3. 부착 기준점

브래킷 원점은 플랫폼 하단 부착 위치로 잡는다. 삽입 시 원점을 어디에 맞춰야 하는지 안내한다. 금속 가로대가 벽돌 하단 뒤로 조금 들어가 접합부가 가려지게 한다.

플랫폼을 이동하면 부착된 지지대도 따라가야 한다. 다만 움직이는 플랫폼에 벽 고정 브래킷을 붙이면 “벽에 박혀 있는데 이동”하는 모순이 생긴다. 기본 브래킷은 **고정 발판용**이다. 승강기에는 체인 연결구나 이동 가이드가 맞으며 벽 브래킷을 자동으로 붙이지 않는다.

경사 발판에 수평 브래킷을 붙이면 빈틈이 생길 수 있다. 첫 버전에서 경사 부착을 지원할지 명시한다. 미지원이면 수평 하단 지점에만 배치하고, 자동 각도 보정이 완성된 것처럼 보고하지 않는다.

## 8. 충돌·색칠·사망과의 경계

장식 루트는 Node2D 중심으로 구성한다. 체인/브래킷/볼트에 StaticBody2D·Area2D·CollisionShape2D를 만들지 않는다. 필요하지 않은 플레이어 감지 영역도 추가하지 않는다.

다음 게임 그룹/계약에 등록하지 않는다: `칠할수있음`, `스마트지형`, `player`. `명중`, `현재색` 같은 게임용 메서드를 장식 기능 이름으로 흉내 내지 않는다. 기존 지형.gd를 장식에 붙이지 않는다.

검정 장식을 흰 플레이어가 통과해도 죽지 않는 것이 이번 설계다. 그러나 검정 그림이면 위험한 지형으로 오해할 수 있으므로 다음 시각 기준을 적용한다.

- 플레이 가능한 상면보다 낮은 대비와 선명도.
- 플랫폼 뒤쪽에 배치하고 실제 착지면을 가리지 않음.
- 발판처럼 보이는 두꺼운 수평 선반을 만들지 않음.
- 안전을 뜻하는 별도 회색 충돌 지형으로 바꾸지 않음. 명암은 장식의 깊이 표현이며 게임 색 상태가 아님.
- 체인이 조준선을 가리거나 페인트가 맞을 것처럼 오해되지 않도록 크기·대비를 검토.

장식에 쏜 탄은 장식을 통과한다. 뒤에 실제 지형이 있으면 그 지형에 맞는 것이 정상이다. 장식 통과 자체를 총알 충돌 버그로 기록하지 않는다.

플랫폼을 흰색으로 칠해도 지지대는 기본 금속 외관을 유지한다. 그것이 색 상태 불일치 버그는 아니다. 반대로 **실제 SS2D 상면/옆면이 이전 색으로 남는 것**은 버그일 수 있다. 이 차이를 사용 안내와 검사표에 명시한다.

근접 반사를 장식에 복사하려고 지형 페인트 셰이더를 붙이지 않는다. 장식 전용 조명 반응은 후속 작업으로 분리한다.

## 9. 아트 제작 기준

스타일: 오래된 하수도 철재, 어두운 금속, 절제된 마모·습기, 좁은 하이라이트. 주황 녹·강한 파랑·금색 등 새로운 강조색을 임의로 넣지 않는다. 검정·흰색 게임의 시선을 빼앗지 않는다.

체인은 고리 구멍이 읽히고, 반복해도 줄무늬 막대처럼 보이지 않아야 한다. 모든 고리에 강한 흰 윤곽을 둘러 화면에서 발판보다 튀지 않게 한다.

브래킷은 가로/세로/대각 부재 연결과 볼트 위치가 읽혀야 한다. 대각 부재가 가로대 밖으로 튀어나오거나 하중과 무관한 장식 삼각형만 남지 않게 한다.

픽셀 해상도는 실제 표시 크기를 기준으로 결정한다. 에셋만 확대해서 예쁜 것보다 줌1.0에서 읽히는지가 중요하다. 텍스처 필터링·알파 가장자리·밉맵 선택은 기존 아트와 함께 확인한다. 검정/밝은 배경 두 곳에서 흰 테두리 같은 알파 오염이 없는지 본다.

이미지 생성 도구를 사용할 수 있다면 투명 배경·반복 단위·정면 고정 시점·게임 부품만 생성하도록 요청한다. 전체 참고 이미지를 한 장으로 생성해 잘라 쓰면 배경과 조명이 섞여 재사용성이 떨어질 수 있다.

도구가 없거나 결과 품질이 부족하면 기능 검증용 임시 그림임을 명시한다. “정식 아트 완료”라고 하지 않는다. 무관한 플러그인을 설치하거나 유료 작업을 임의로 요청하지 않는다. 외부 에셋이면 출처·라이선스를 asset_notes.md에 기록한다. 생성 에셋이면 사용 도구·날짜·핵심 프롬프트를 기록한다.

## 10. 인스펙터와 에디터 사용성

프로그래머가 아닌 맵 제작자가 설정할 수 있어야 한다. 공개 속성을 다음처럼 적은 수의 그룹으로 정리한다. 이름은 제안이며 실제 선택을 사용 안내에 적는다.

| 체인 속성 | 의미 | 주의 |
|---|---|---|
| 모드 | 고정/대상 추적 | 우선순위가 명확해야 함 |
| 시작점·끝점 경로 | 참조 Marker2D | 비어 있거나 끊어지면 경고 |
| 고정 시작/끝 좌표 | 고정 모드용 로컬 좌표 | 월드 좌표와 구분 |
| 체인 폭·고리 간격 | 반복 크기 | 길이와 별개 |
| 끝단 겹침 | 고정구 뒤로 숨길 양 | 과도하게 짧아지지 않게 제한 |
| 텍스처·색조 | 아트 참조 | 전체 화면 밝기 규칙 유지 |

| 브래킷 속성 | 의미 |
|---|---|
| 방향 | 왼쪽/오른쪽 |
| 크기 프리셋 또는 균일 배율 | 지원 범위를 문서화 |
| 부착 오프셋 | 플랫폼 아랫면에 맞추는 미세 이동 |
| 색조/텍스처 | 공유 원본 변경과 인스턴스 변경을 구분 |

가능하면 @tool 미리보기를 제공한다. 에디터에서 체인 길이와 방향을 볼 수 있어야 한다. @tool이 에디터에서 플레이용 로직·저장·노드 중복 생성을 실행하지 않도록 한다.

참조가 없어도 월드 원점까지 긴 체인을 그리지 않는다. 표시를 숨기거나 로컬 미리보기로 제한하고 명확한 경고를 한 번 표시한다. 매 프레임 동일 경고를 찍지 않는다.

리소스 setter에서 초기화 순서 때문에 자식이 아직 없을 수 있다. 에디터 로드 중에도 오류 없이 동작하도록 한다. 리소스 수정이 다른 인스턴스까지 전파되는 경우와 로컬 설정인 경우를 구분한다.

## 11. 수명·예외·성능

- 참조 플랫폼이 삭제되거나 재시작으로 교체되면 유효성을 확인한다. 해제된 인스턴스를 접근하지 않는다.
- 씬을 나갔다 다시 들어오면 옛 체인·신호 연결이 남지 않아야 한다.
- 신호를 사용하면 중복 연결하지 않는다. 해제 규칙을 명확히 한다.
- 시작점=끝점, 길이0, 짧은 길이, 매우 긴 길이, 잘못된 NodePath, 텍스처 없음, 대상 삭제를 시험한다.
- 최대 지원 길이를 정하고, 초과 시 동작을 명시한다. 무한 루프나 수만 개 고리 노드 생성을 허용하지 않는다.
- 정적 체인은 값이 바뀔 때만 갱신한다. 동적 체인도 텍스처를 매 프레임 로드하거나 ImageTexture를 매번 만들지 않는다.
- 플랫폼 수가 늘어날 때 비용을 측정할 수 있도록 대표적인 수량의 시험 배치를 준비한다. 예: 정적20줄·동적4줄. 이 숫자는 게임 요구량이 아닌 측정 예시다.
- FPS 평균 하나만으로 결론 내리지 말고, 장식 켬/끔·같은 카메라·같은 렌더러에서 CPU/프레임 시간과 노드 수 증가를 비교한다. 측정하지 않았으면 미측정이라고 쓴다.

## 12. 시험 씬 구성

별도 시험 씬을 만든다. 기존 SS2D 시험 씬과 실제 맵을 덮어쓰지 않는다.

최소 구성:

1. 검정 고정 발판 + 왼쪽 브래킷.
2. 흰색 고정 발판 + 오른쪽 브래킷.
3. 넓은 고정 발판 + 같은 크기 브래킷 두 개.
4. 짧은 체인과 긴 체인 비교. 고리 크기는 같아야 한다.
5. 기존 상하 승강기 + 천장점 두 개 + 체인 두 줄. 위/중간/아래에서 연결 유지.
6. 이동된 부모 Node2D 아래의 같은 체인 조합. 좌표 변환 검사.
7. 잘못된 참조/길이0 검사. 플레이 씬과 구분해 오류 조건임을 표시.

실제 플레이어·월드·페인트코어가 필요한 기능 검사는 기존 시험 씬 구조를 참고하되, 공용 스크립트를 임의로 교체하지 않는다. 시험용 카메라 순간이동은 시각 검사에만 사용하며 주행 완료로 집계하지 않는다.

시험용 텍스트 라벨은 최종 장식 프리팹에 포함하지 않는다. 사용자가 실제 맵에 넣을 때 “TEST” 글자가 따라오면 안 된다.

## 14. 버그 판정 기준

- 체인은 움직이는데 고정점이 같이 움직인다 → 부모/참조 구조 오류.
- 플랫폼이 멈췄는데 체인이 한 프레임씩 튄다 → 좌표 갱신/보간 순서 확인.
- 고리가 길쭉해진다 → 반복 대신 텍스처/노드 스케일을 늘린 것인지 확인.
- 길이 임계값에서 고리가 갑자기 튄다 → 반복 위상·끝단 처리 오류.
- 벽 고정 브래킷이 승강기와 이동한다 → 부품 선택/연출 설계 오류.
- 장식에 닿아 사망한다 → 불필요한 충돌/게임 그룹/지형 계약 연결 확인.
- 장식이 지형과 함께 흰색으로 안 변한다 → 기본 설계상 정상. 실제 지형 면이 안 변하는 경우와 구분.
- 총알이 체인을 통과한다 → 기본 설계상 정상. 뒤의 실제 지형까지 통과하면 별도 버그.
- 이미지가 예쁘지만 받치는 벽이 없다 → 기능 오류는 아니지만 배치/시각적 설득력 불합격.
- 노드 수가 왕복할수록 증가한다 → 생성/정리 수명 버그.
- exit0인데 ERROR가 있다 → 테스트 통과가 아니다.

버그 기록: 씬/노드, 설정, 재현 순서, 기대/실제, 위치/색, 로그/캡처, 수정 원인, 재검증을 적는다. 실패를 없애기 위해 충돌·색 사망·승강기 운반 검사를 끄지 않는다.

## 15. 맵 제작자가 사용하는 절차를 문서로 남겨라

최종 사용 안내에는 코드 지식 없이 따라 할 수 있는 다음 절차가 있어야 한다.

### 고정 발판 지지대

1. 기존 SS2D 발판을 배치한다.
2. 삼각지지대.tscn을 장식 자식으로 넣는다.
3. 지지대 원점을 발판 하단 부착점에 맞춘다.
4. 방향/허용 크기를 선택한다. 넓으면 두 개를 배치한다.
5. 고정 볼트 뒤에 같은 월드 좌표의 벽 고정 단서가 있는지 확인한다.
6. 게임을 실행해 플레이어가 지지대에 걸리지 않고 실제 발판 충돌은 유지되는지 본다.

### 체인 승강기

1. 기존 움직이는발판.tscn을 배치하고 상하 이동을 설정한다.
2. 승강기 밖에 천장 Marker2D 두 개를 만든다.
3. 승강기 안에 체인 끝 Marker2D 두 개를 만든다.
4. 체인 두 줄에 각각 시작/끝 경로를 지정한다.
5. 천장과 발판 고정구가 체인 끝을 조금 덮도록 정렬한다.
6. 위/아래 끝에서 장력 연출이 자연스럽고 천장 위로 플랫폼이 넘어가지 않는지 확인한다.

최종 속성 이름과 실제 스크린샷으로 위 절차를 갱신한다. “적당히 설정” 같은 문구로 필수 설정을 생략하지 않는다.

## 16. 추후 유지보수와 확장

- 동작 코드와 아트 리소스를 분리한다. 그림을 바꿔도 플랫폼 이동 코드가 바뀌지 않아야 한다.
- 폭·간격·알파 가장자리·부착 원점의 의미를 asset_notes.md에 기록한다.
- 원본 그림은 보존하고 새 아트는 버전/변경 이유를 기록한다. 같은 이름의 공유 에셋 교체가 모든 맵에 미치는 영향을 확인한다.
- NodePath나 공개 속성 이름 변경 시 기존 씬 마이그레이션 목록을 만든다. 빈 참조로 조용히 변하지 않게 한다.
- 장식 변경 후 최소 C03/G01/G03/G05/S01 검사를 재실행한다. 체인 알고리즘 변경이면 C01~C07도 재검사한다.
- 흔들림·파괴·등반을 추가하는 날에는 현재의 “충돌 없는 장식”과 별도 기능으로 설계한다. 기존 장식 전체에 갑자기 충돌을 추가하지 않는다.
- 여러 맵에 배포하기 전 실제 사용 수량에서 성능과 저장 안정성을 확인한다.

## 17. 작업 순서와 제출

1. 관련 코드와 원화 확인 → 기존 구현 재사용 여부 결정.
2. 파일 구성·동작 계약·미지원 범위를 짧게 기록.
3. 체인 정적 반복과 브래킷 기본형 구현.
4. 체인 끝점 추적과 실제 승강기 조합 구현.
5. 에디터 미리보기, 저장/재로드, 예외 처리.
6. 기능/회귀 검사 → 실제 렌더링 캡처 → 그림을 열어 확인.
7. 사용 안내·유지보수 안내·작업기록 작성.

Godot 실행 허가가 있으면4.6.3의 확인된 실행 경로를 사용하고, 저장소 안전 규약대로 실행한다. 실행 허가가 없으면 정적 확인까지 진행하고 엔진 검사를 미실행으로 보고한다. 기존 맵 빌더를 실행해서 시험 환경을 만들지 않는다.

제출 보고에는 다음을 포함한다.

- 새로 만든 실제 파일 경로와 각 역할.
- 체인 길이/끝점/지지대 방향을 어떻게 설정하는지.
- 테스트 ID별 결과와 실제 실행 로그.
- 움직이는 체인의 위/중간/아래 캡처 또는 짧은 영상.
- 임시 아트 여부, 미지원 배치, 미실행 검사, 남은 버그.
- 기존 공용 SS2D 기능이 유지되었는지.

완료는 “그림이 나왔다”가 아니다. **길이가 바뀌어도 고리가 유지되고, 움직임을 따라가고, 저장이 유지되고, 플레이를 방해하지 않으며, 다른 맵 제작자가 문서만 보고 재사용할 수 있는 상태**를 뜻한다. 측정하지 않은 성능 수치나 실행하지 않은 검사를 지어내지 않는다.
