# 하수도 맵 제작 시작 — 모델 공통

2026-09-20 정리. 오퍼스·아스트라 모두 이 파일로 시작한다. 경로는 저장소 루트 기준.

1. 적용되는 AGENTS.md/CLAUDE.md와 현재 사용자 요청을 확인한다. 사용자가 이미 정한 범위·시작·도착·방향은 다시 묻지 않는다.
2. [공통규칙](맵제작_공통규칙.md)을 읽는다. 같은 작업에서 내용이 바뀌지 않았다면 반복해서 전문을 읽지 않는다.
3. `작업/stage_2-N_작업.md`를 읽는다. 없으면 [서식](작업/맵작업_서식.md)으로 해당 맵 문서만 만든다. 설계가 미정인 핵심 항목만 사용자에게 확인한다.
4. [장치 요약](장치_요약.md)에서 이번 맵이 사용하는 항목만 읽는다. 코드 해시가 달라졌거나 버그·새 연결을 다루면 관련 함수만 확인한다.
5. 씬은 `python tools/summarize_sewer_scene.py scenes/world_2_클로드/stage_2-N.tscn`으로 먼저 요약한다. 특정 노드는 `--node 호퍼`, 더 보려면 `--limit 60`. 기본 출력은 최대20노드이며 생략을 표시한다. 이 도구는 직접 저장값만 읽는 인덱스다. 상속/런타임 상태·도달성·충돌의 정확성을 판정하지 않는다.
6. 짧은 대표 구간을 제작·검사하고 확대한다. 완료 시 맵 작업 문서의 변경 노드/검증/미완료만 갱신한다. 작업기록은 저장소 규약에 따라 별도로 남긴다.

## 짧게 읽되 생략하면 안 되는 것

- 파일 수를 줄이려고 씬·코드·문서를 한 파일에 합치지 않는다. rg로 함수/절을 찾고 해당 범위만 읽는다.
- 메시·텍스처 배열·성공 로그 전체를 출력하지 않는다. 성공은 요약, 실패는 노드·좌표·기대/실제 값과 재현 조건을 출력한다.
- 출처가 다른 확정 규칙을 반복 복사하지 않는다. 공통규칙을 수정하고 맵 문서는 예외/고유 설계만 기록한다.
- 요약의 불확실함을 없애려고 추측하지 않는다. 실제 코드 변경 여부를 확인하고 필요한 부분을 읽는다.
- 검사는 줄이지 않는다. 정적 통과와 실제 게임 실행 통과를 구분한다. 엔진 실행은 현재 사용자 허가/저장소 규약에 따른다.
- 현재 사용자 지시 > 최신 확정 공통규칙 > 해당 맵 설계 > 과거 기록. 코드와 규칙이 충돌하면 실제 동작과 의도를 분리해 기록하고, 의도에 없는 규칙을 만들어 맞추지 않는다.
