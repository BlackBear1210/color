# 흰물 모듈 v1

실제 PNG와 시간 기반 셰이더 애니메이션을 갖춘 **시각 전용 프리팹**. 기존 맵 교체 및 게임 판정 연결은 아직 하지 않았다.

- 프리팹: `res://scenes/장식/유체/흰물_디자인.tscn`
- 비교 씬: `res://scenes/테스트/흰물_디자인_비교.tscn`
- `preview.html`: 파일을 브라우저에서 열면 외부 서버 없이 6가지 애니메이션과 크기 슬라이더를 사용할 수 있다.
- 원본: `flow_white.png`. 내장 image_gen 생성. 별도 유료 Higgsfield 요청 없음.

## 조절

노드 Scale은 (1,1). `크기`로 너비·높이를 지정한다. `무늬_크기` 기본 128px는 그대로 두면 물 크기에 상관없이 텍스처 밀도를 유지한다. 거울 반복 UV로 원본 경계에서 색이 불연속적으로 튀는 현상을 피한다. 일반 주기 타일의 완전 무봉제 여부를 주장하지 않는다.

`형태` 0 가는 물줄기 / 1 넓은 물막 / 2 배관 출수 / 3 수면·웅덩이 / 4 충돌 물보라 / 5 잔물·물방울.

물줄기와 물막은 같은 몸통 모듈의 폭 차이다. 물보라는 별도 인스턴스로 붙인다. 모드 4의 바닥은 로컬 y=높이-5 부근이므로 바닥 착수 위치에 맞춰 배치한다. 모드 2의 너비는 출수 곡선의 수평 이동량이다. 출수 두께는 최대 36px로 유지되므로 대형 관의 출수 두께까지 자유롭게 조절하는 기능은 후속 사항이다.

웅덩이 원점은 앞쪽 수면 중앙. 뒤쪽 수평 면 y=-4..0px, 모따기 3px. 기존 `하수도_마감메시.gd`의 4px 후방 윗면과 3px 모따기 기준이다. 24px는 수평 윗면이 아닌 아래쪽 마감 띠이므로 수면 깊이를 24px로 늘리지 않는다. width가 늘어도 깊이와 모따기는 늘지 않는다. 실제 벽에 맞닿는 끝은 통합 시 지형으로 가리는 처리가 필요하다.

`흐름속도`는 몸통/출수 텍스처의 px/s, `애니메이션`은 모든 모드의 재생 여부, `위상`은 시간 오프셋이다. 물보라와 물방울의 개수·크기는 상수이며 실제 파티클 노드를 생성하지 않는다. 프리팹은 CPU _process가 없고 셰이더 TIME을 사용한다. 화면 밖 비용 및 성능 수치는 Godot 프로파일링 전까지 미검증이다.

## 판정 연결 전 주의

기존 `유체.gd`는 animated_v4 이미지에서 구운 프레임별 충돌 폴리곤을 쓴다. **새 그림만 덮어씌우면 보이는 물과 판정이 달라질 수 있다.** 이 프리팹 자체에는 충돌·혼합·페인트·사망 로직이 없다. 기존 유체를 숨겨 놓고 새 그림만 띄우는 식으로 적용하지 말 것. 실제 적용 시 켜짐, 색 변화/회색 혼합, 크기/차오름, 물방울 장식과 위험 몸통 분리, 새 실루엣 판정을 함께 연결하고 검증해야 한다. 흰 물만 완성한 현 단계에서 회색/검정색 유체까지 이 재질로 강제 교체하지 않는다.

## 생성 프롬프트

내장 image_gen. 단일 정사각형 불투명 흰 물 내부 텍스처, 전체 영역을 채운 미세한 수직 흐름과 길쭉한 액체 주름, 중성 회색조 #E8E8E8 중심·#FAFAFA 하이라이트·얕은 회색 음영. 배관·물보라·문자·테두리·원근·배경·투명 구멍 제외. 가로와 세로 반복 사용 의도. 원본 이미지는 수정하지 않고 셰이더에서 반복·밝기·실루엣·애니메이션을 처리했다.

## 검증

WebGL2에서 Godot 셰이더의 water/detail 함수 본문을 그대로 사용한 브라우저 미리보기 6종 표시 확인. 물막 448px·웅덩이 480px 너비 변경 확인. Godot 실행·파서·실제 게임 판정·프레임 측정은 사용자 안전 규칙에 따라 미실행. 브라우저 확인이 Godot 전체 검증을 대체하지 않는다.
