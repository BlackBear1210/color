## 1. zone2 경계 시스템 재구축 (`docs/경계_색구역_시스템.md` 적용)

### 무엇이 바뀌었나
- **폐기**: SwitchZone(밝은 사각형) + `world_lab.gd` 의 감시-되돌리기 잠금
  (`_watch_switch_lock`, `_in_switch_zone`, `_prev_color`, `_reverting`) — 전부 삭제.
- **도입**: `ColorZone`(scenes/경계/color_zone.gd) 2개를 build_world 가 직접 조립.
  - `Zone2White`: 경계 위 (y −352 ~ **236**) — 들어오면 자동 白
  - `Zone2Black`: 경계 아래 (y **264** ~ 520) — 들어오면 자동 黑
  - 구역 밖(회색 복도·다리)에서는 예전처럼 키보드 자유 전환.
- 기존 TintTop/TintBottom 폴리곤 삭제 — ColorZone 이 스스로 틴트를 그린다.
- 백 발판 3(y2)을 무색 1발로 교체 — 백 구역 안 "칠해서 길 만들기" 퍼즐 추가.
- 우측 벽을 y8~13 으로 낮춰 상층에 회색 다리(y6)를 놓아 zone3 로 연결.

### ★중립 틈 28px 규칙 (이번 작업의 핵심 설계)
플레이어 충돌 크기는 64×128 × scale(0.795, 0.368) ≈ **51×47px** (Player.tscn 실측).
두 ColorZone 을 딱 붙이면 몸이 항상 양쪽에 걸쳐 "마지막 진입 우선" 스택이 매 프레임
다투게 된다. 그래서 회색 전환 발판 윗면 **S** 기준으로:

```
위쪽 구역 아랫변 = S − 20   (회색 위에 선 몸(S−47~S)의 머리와 27px 겹침 → 강제 발동)
아래 구역 윗변   = S + 8    (회색 위에 선 몸과는 안 겹침 / 두 칸 아래 발판(S+64)에
                            선 몸(S+17~)과는 겹침 → 강제 발동)
```

- 틈 28px < 키 47px → 경계를 지나는 중에 **색 공백이 없다** (항상 한쪽에 걸침).
- 발판에 가만히 서 있을 때는 반대편 구역에 닿지 않는다 → **히스테리시스**로 깜빡임 방지.
- 회색(중립) 발판 위 = "다음 밴드 색"이 이미 강제된 상태 → 회색이라 어느 색이든 안전.
  **경계는 반드시 회색 발판에서 넘는다**는 기존 레벨 문법이 그대로 유지된다.

### 게임플레이 변화
| 이전 (SwitchZone) | 이후 (ColorZone) |
|---|---|
| 전환 존 안에서만 Shift 허용 | 경계를 넘으면 색이 **저절로** 바뀜 |
| 존 밖 Shift → 강제 되돌림 메시지 | 구역 안 Shift → 같은 프레임 자동 교정 (문서 §3.3) |
| 반대색 사망이 주 위협 | 구역이 색을 맞춰 주므로 지형 사망은 거의 불가능해지고, 퍼즐 축이 "무색 발판 칠하기"로 이동 |

※ 단독 테스트 씬 `zone_02.tscn` + `zone02_lab.gd` 는 **구 방식 그대로 보존** (프로토 참조용
+ test_color_death 가 사용). world_1 만 새 방식이다.

## 2. ZONE 3 — 수직 도시 (신규)

기획서 스테이지 3 "도시(판자촌 → 고층, 위로 상승)"의 그레이박스 구현.

### 구조 (tools/build_world.gd 가 생성)
- **연결**: zone2 백 상층(y6) → 회색 다리(y6, x105~117) → 탑 내부로 낙하 진입 → 판자촌 바닥(y13).
- **탑**: 좌벽 x113(다리 높이 y4~5 개방) / 우벽 x152 / 폭 약 1200px / 높이 약 1400px.
- **등반**: 발판 20개 지그재그 상승 (수평 간격 ≤3칸·수직 2칸 — zone1/2 와 같은 점프 문법).
- **색 밴드 4개** (ColorZone, 위로 갈수록 흑↔백 반전):

| 밴드 | 범위(y px) | 색 | 발판 구성 |
|---|---|---|---|
| A | 40 ~ 470 | 黑 | 흑 발판 + 무색 1발·2발 |
| B | −344 ~ 12 | 白 | 백 발판 + 무색 1발·2발 (왼쪽으로 지그재그) |
| C | −728 ~ −372 | 黑 | 흑 발판 + **무색 3발**(최고 난도) + 1발 |
| D | −960 ~ −756 | 白 | 백 발판 + 옥상(골인) |

- 밴드 사이마다 **회색 전환 발판 G1(S=32)/G2(−352)/G3(−736)** + 발광 구슬 + 이중 경계선.
  중립 틈 공식은 zone2 와 동일 (S−20 / S+8).
- **골인**: 옥상(y−27) 위 ExitZone — 진입 시 "WORLD 1 CLEAR" → 흰 잉크 와이프 → 로비.
- **카메라**: `REGION_3 = Rect2(3520, −1080, 1456, 1768)` (세로로 긴 리밋) + 줌 0.9.
  경계 x=3500(다리 중반) ± 히스테리시스 60px. 체크포인트 = 다리 위 (3400, 189) —
  회색이므로 어느 색 리스폰도 안전.

### 연출 의도
- 다리(회색)가 zone2 백 구역을 빠져나와 밴드 A(흑) 범위 안까지 이어져 있어,
  건너는 동안 색이 白→黑으로 자연스럽게 넘어간다 (완충 지대).
- 하늘 그라데이션이 **아래(판자촌)는 어둡고 위(옥상)는 밝다** — "위로 = 희망" 톤.
- 판자촌(판잣집 실루엣·가로등) → 고층(창문 불빛 실루엣) → 옥상(차가운 달빛)으로
  높이에 따라 배경 밀도와 광원이 바뀐다.

## 3. 일러스트 프롭 + 노멀맵 라이팅 ("레인월드 룩")

### 리서치 근거
레인월드는 방 이미지를 **30장 깊이 레이어**로 나눠 픽셀 채널에 깊이/조명 정보를 인코딩하고
셰이더 팔레트 룩업으로 즉석 계산한다(사전 노멀맵 없음). Godot 2D 에서 같은 인상을 내는
정석 대응물은 **CanvasTexture(디퓨즈+노멀맵) + Light2D + CanvasModulate** — 이미 프로젝트에
있던 기반(zone_visuals.gd)을 프롭·정적 광원으로 확장하는 쪽을 택했다.
- 참고: [Rain World Palettes (모딩 위키)](https://rainworldmodding.miraheze.org/wiki/Palettes),
  [Rain World Shader Documentation](https://gist.github.com/EtiTheSpirit/655d8e81732ba516ca768dbd7410ddf4)

## 5. 디버깅 기록 (발견한 문제와 해결)

1. **신규 SVG 가 노멀맵 생성에서 SKIP** — 헤드리스 스크립트 실행은 새 에셋을 임포트하지
   않아 `ResourceLoader.exists()` 가 false. → **`--headless --import` 를 먼저 1회 실행**
   후 생성기를 돌리는 순서로 해결. (새 에셋 추가 시 항상 이 순서)
2. **셰이더 코드에 GDScript 숫자를 문자열로 박는 방식의 파싱 위험** — `"%s" % 1681.0` 은
   `"1681"` 로 찍혀 `uniform float x = 1681;` 이 되는데 Godot 셰이더 언어는 int→float 암시
   변환에 엄격하다. → 물웅덩이 `streak_x` 를 **`set_shader_parameter` 유니폼 전달**로 변경.
3. **스크린샷 2장이 zone2 로 찍히는 문제** (zone3 밴드B·옥상) — 원인 분석:
   워프 좌표가 발판 표면과 6~10px 로 너무 가까워, ColorZone 이 색을 교정하기(물리 우선
   순위 10) 전에 착지 → 색 사망 판정(우선순위 0)이 먼저 걸려 사망 → 다리 체크포인트
   리스폰 화면이 찍힘. **실제 플레이에서는 경계를 항상 점프/낙하 중(공중)에 넘으므로
   공중에서 교정이 끝나 발생하지 않는다** (test_world_flow 5·6·9·10·11 로 검증).
   → 스크린샷/테스트의 워프는 **발판 위 80px 이상 공중**에 넣는 규약으로 해결하고
   test_world_flow.gd 머리말에 규약을 명시.
   ※ 남는 이론적 경계 사례: 하강 시 "구역 진입 → 1프레임 뒤 교정" 사이에 착지하려면
   진입선(S+8)과 발판(S+64) 사이 56px 를 1프레임(최대 낙하 ~23px)에 통과해야 하므로 불가능.
4. **등반 발판 가로등(z=2)이 캐릭터 앞을 가림** — 스크린샷 검증에서 발견.
   → 가로등 프롭 z=−1(플레이어 뒤)로 수정 후 재생성·재캡처로 확인.
