## 2. 짚어야 할 점 (3건)

### 2-1. ⚠ 문서가 모르는 것 — `stage_transition.gd`가 이미 존재함

Part 1은 4.2에서 "지금은 SceneManager 구현 금지"라고 옳게 말했지만, **이 프로젝트엔 이미 씬 전환
최소 버전이 있다**: `scripts/proto/stage_transition.gd` (`StageTransition.change_scene(from, path)`
한 줄, autoload 불필요, 잉크 와이프 연출까지 포함). world_1의 ExitZone→로비 복귀도 이걸로 처리 중.

- 시사점: 문서가 이걸 몰라서 "SceneManager 만들지 마라"고 한 건데, 결과적으로 **이미 딱 그 수준의
  헬퍼가 있으니 방침은 맞다.** 다만 나중에 스테이지가 늘어나 "클리어 기록→다음 잠금 해제" 로직이
  필요해질 때, SceneManager를 새로 만들 게 아니라 **이 `stage_transition.gd`를 확장**하는 방향이 맞다.
  (문서의 조언을 따르되, 출발점이 0이 아니라는 것만 기억.)

### 2-2. ⚠ "첫 autoload = EffectManager"는 아키텍처를 살짝 바꾸는 결정

4.6이 EffectManager를 autoload 1순위(★★★★★)로 추천한다. **논리 자체는 타당**하다 —
Paint FX / Camera FX / Screen Flash / 전역 Tween 같은 "화면 전체에 걸리는 연출"은 존(zone)마다
새로 만들기보다 전역 싱글톤 하나로 두는 게 Godot 관용구다.

**단, 알고 결정할 것**: 이 프로젝트는 지금까지 **autoload를 0개로 유지**하고, 모든 걸 `zone_lab.gd`
런타임 조립 + `ColorZone`의 static 스택으로 처리해 왔다(그래서 어제 감사에서 코드 꼬임이 거의 안 나온
것이기도 함). EffectManager를 넣으면 **이 프로젝트 최초의 autoload**가 되고, `project.godot`를
수정해야 한다(= 팀 공유 파일 변경).

- **도형 권장안**: 곧바로 autoload를 만들지 말고, **먼저 `scripts/proto/`에 EffectSpawner를 일반
  컴포넌트로** 만들어(zone_lab가 런타임 부착) FX 파이프라인을 검증한 뒤, 정말 "화면 전역 FX"가
  여러 곳에서 필요해질 때 그때 autoload로 승격하는 게 지금까지의 패턴과 일관된다. 4.3(PackedScene
  EffectSpawner ★★★★★)이 사실상 이 "먼저 만들 것"에 해당하고, 4.6 EffectManager는 그 다음 단계로
  보면 순서가 자연스럽다. **project.godot 변경(첫 autoload 등록)은 팀에 한 번 알리고 진행 권장.**

### 2-3. ⚠ FX 스폰 위치 함정 (4.3 예시 코드)

4.3의 `spawn_fx` 예시는 `add_child(fx)`로 스포너 자식에 붙인다. 이 프로젝트는 **Player 스케일이
비균등(0.795, 0.368)**이라, FX를 플레이어/스포너 자식으로 붙이면 이펙트가 찌그러지거나 위치가
어긋난 전례가 여러 번 있었다(과거 페인트 클립·발광 오버레이 버그). 그래서:

- **Paint Splash·Landing Dust 같은 월드 FX는 반드시 씬 루트(존 루트) 좌표계에 스폰**하고
  `global_position`을 명시해야 한다(스포너를 스케일 없는 노드로 두거나 `top_level = true` 사용).
  기존 `stage_transition.gd`(CanvasLayer)·`zone_visuals.gd`(플레이어 광원 top_level)가 이미
  이 함정을 우회하는 방식으로 짜여 있으니 참고하면 된다.

## 3. 어제(12·13차) 우선순위와의 정합성 — 매우 잘 맞음

Part 1은 어제 두 번의 검토에서 나온 "진짜 빈 곳" 목록에 **구현 방법(how/where)을 얹어주는** 역할을 한다:

| 어제 뽑은 "빈 곳" (12·13차) | Part 1이 제시한 그릇 |
|---|---|
| Paint Splash / Landing Dust | 4.3 PackedScene EffectSpawner (★★★★★, 바로 적용) |
| Camera Shake | 4.6 EffectManager의 "Camera FX" (단, 구현은 `proto_camera.gd`에 trauma 방식이 정석) |
| Hit Stop | 문서엔 명시 안 됐지만 EffectManager에 `Engine.time_scale` 순간 정지로 얹으면 자연스러움 |
| 사운드 인프라 | 4.6 AudioManager 2순위 (사운드 제작 시작 시) — 순서 타당 |

→ **서로 다른 방식(코드 감사 / Ch3 대조 / Ch4 대조)이 같은 결론에 수렴** = 이 방향이 맞다는 신호.
어제 내가 1순위로 꼽은 **Hit Stop**만 문서에 이름이 빠져 있는데, EffectManager에 얹기 가장 쉬운
항목이므로 그대로 최우선 후보로 유지한다.

## 4. 정리된 "실제 착수 순서" 제안 (Part 1 + 어제 결론 종합)

1. **`proto/effect_spawner.gd` (PackedScene 스포너) 신규** — Paint Splash / Landing Dust용.
   §2-3 함정(월드 좌표 스폰) 지키기. `paint_system.gd`의 `hit_feedback`/`gray_created` 시그널에
   리스너로 연결(리스너 자리가 이미 비어있음 — 13차에서 확인). **바로 착수 가능, player.gd 무관.**
2. **Camera Shake** — `proto_camera.gd`에 trauma 변수 추가(파일은 도형 소유 proto라 자유 수정).
3. **Hit Stop** — 사망/착탄 순간 `Engine.time_scale` 짧은 정지. 1·2를 묶어 관리할 EffectManager를
   만들 시점이면 여기에 얹는다(이때가 첫 autoload 등록 시점 = 팀 통지).
4. **AudioManager** — 사운드 에셋이 준비되면(2순위). M2(7/26) 전 자리만 잡아두기 권장.
5. **SaveManager / SceneManager / ItemManager = 지금 만들지 않음**(문서 "현재 만들지 말 것"에 동의).

## 5. 기타 관찰

- 4.5(Signal) "Player가 직접 호출하지 않는다"는 이미 지켜지고 있음(어제 확인). `paint_system.gd`가
  시그널 3종을 이미 쏘고, `brush_cursor_ui.gd`가 `hit_feedback`을 이미 구독 중 — 문서가 그리는
  `ProtoGun → PaintSystem → ZoneVisual → Effect` 흐름의 앞 절반은 이미 완성돼 있고, 뒤쪽
  `→ Effect` 리스너만 §4-1로 채우면 된다.
- Claude Prompt가 또 "Godot 4.4 기준"이라고 적혀 있다(실제는 **4.6.3**). 큰 문제는 아니지만,
  문서의 코드 예시를 그대로 복붙할 때 4.4↔4.6 API 차이(거의 없지만)는 한 번 확인.
- 4.4(Resource)의 "지금은 남용 금지, M3 이후 PaintData/StageData"는 타당. 현재 물감 규칙 상수가
  `paint_system.gd`에 하드코딩돼 있는데, 스테이지가 늘어 발판 내구도·색 규칙을 데이터로 빼고 싶어질
  때 그때 Resource로 옮기면 된다.
