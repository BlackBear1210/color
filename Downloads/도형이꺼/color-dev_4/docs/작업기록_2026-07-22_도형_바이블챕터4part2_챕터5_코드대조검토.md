## 1. ★ 가장 중요한 발견 — Chapter 5의 사실 오류

**Chapter 5.2 표**는 `Jump Buffer(★★★★☆, 🟡)`, `Coyote Time(★★★★☆, 🟡)`을 "앞으로 추가할, 팀
협의가 필요한" 게임필 항목으로 올려놨고, **5.8 "팀 협의 필요"** 목록에도 둘을 다시 넣었다.

**그러나 `scripts/player.gd`에 둘 다 이미 완전히 구현돼 있다:**

```gdscript
const COYOTE_TIME:      float = 0.12  # 절벽 끝 낙하 후 점프 가능 시간   (player.gd:12)
const JUMP_BUFFER_TIME: float = 0.12  # 착지 직전 점프 입력 유지 시간   (player.gd:13)
```
그리고 `_physics_process`(40~55줄)가 점프 버퍼·코요테 타이머를 매 프레임 굴리고 있다. 가변 점프
높이(점프 키를 떼면 상승 감속, `JUMP_CUT_MULTIPLIER`)·비대칭 중력(`FALL_GRAVITY_MULTIPLIER`)까지
들어가 있어, **점프 손맛 3종 세트가 이미 셀레스트급으로 갖춰져 있다.**

- **시사점**: 이 항목들을 "할 일"로 착수하면 **이미 있는 걸 다시 만드는 헛수고**가 되고, 하필
  `player.gd`(팀 무수정 대상)를 건드리게 돼 위험까지 겹친다. → **Chapter 5.2 표와 5.8에서 이 두
  항목은 지워도 된다. 이미 완료.** (Chapter 3에서 `player_anim.gd`를 못 봤던 것과 같은 패턴 —
  문서가 실제 파일 내용을 안 읽음.)

## 2. ★ 지금 가장 가치 높은 실착수 항목 — 조준 궤적 가시성 개선 (Chapter 5.3)

이건 반대로 **문서가 제대로 짚었다.** 게다가 **도형님이 맨 처음 ChatGPT에 던진 불만("좌클릭 색칠,
우클릭 포물선인데 잘 안 보여")과 정확히 같은 문제**라, 개발 바이블 다섯 챕터를 통틀어 "사용자 본인이
직접 느낀 실제 페인 포인트"에 가장 가까운 항목이다.

**현재 코드 상태(`proto_gun.gd`)를 확인한 결과 — 조준 시스템은 이미 있고, "일부러" 흐리다:**

```gdscript
## "너무 잘 보이지 않고 흐릿하게" — 중간 회색 + 낮은 알파               (proto_gun.gd:29~32)
const TRAJ_COLOR: Color = Color(0.5, 0.5, 0.5, 0.32)
const TRAJ_ALPHA_END: float = 0.10   # 진행할수록 0.10까지 더 옅어짐
```

즉 포물선 궤적(발사와 동일 물리로 시뮬, 지형에 닿으면 그 지점에서 끊김, 탄착점 살짝 크게)은 **이미
잘 작동**하는데, **디자인 의도가 "은은하게"라서 알파가 0.32→0.10으로 매우 낮다.** 그래서 배경에
묻히는 것이다. Chapter 5.3의 개선 목록과 현재 상태를 대조하면:

| Chapter 5.3 추천 | 현재 `proto_gun.gd` | 판정 |
|---|---|---|
| 착탄 지점 마커 | 이미 있음(마지막 점 반지름 1.6배) | ✅ 있으나 알파 0.22로 흐림 |
| 지형 충돌 시 끊김 | 이미 있음(레이캐스트로 자름) | ✅ 완성 |
| Gradient(멀수록 변화) | 알파 페이드만 있음 | 🟡 색 그라데이션 추가 여지 |
| 충돌 시 빨간색 표시 | 없음 | ❌ 신규 — 착탄점을 빨갛게 |
| Glow / 점선 애니메이션 | 없음 | ❌ 신규 |

- **결론**: "Line2D로 조준 시스템을 새로 만들어라"(5.9 Claude Prompt)는 **틀린 처방**이다 — 이미
  `draw_circle` 기반으로 잘 도는 시스템이 있다. 필요한 건 **신규 제작이 아니라 가시성 튜닝**:
  기본 알파 상향(예 0.32→0.6), 탄착 마커를 또렷하게 + 충돌 시 빨간색, 필요하면 점선 흐름 애니메이션.
  전부 **`proto_gun.gd`(도형 소유 proto, 자유 수정) 안에서 상수·`_draw()` 몇 줄만 손보면 끝**이고
  `player.gd`와 완전히 무관하다. → **오늘 바로 착수 가능한 최우선 후보.**

## 4. ⚠ 문서 간 오디오 우선순위가 엇갈림 — 정리

- Chapter 4 **Part 1**: AudioManager = autoload **2순위**(사운드 제작 시작 시)
- Chapter 4 **Part 2**: Audio = **M4**(제출 직전)
- Chapter 5: Paint Feedback에 Sound 포함(🟢 지금)

세 군데가 서로 다르다. **도형 판단**: 색 반전=즉사 장르(Ikaruga/OVIVO식)는 **오디오 피드백이
반응속도에 시각보다 크게 기여**한다(어제 리서치). 사운드를 M4까지 미루면 M2·M3 내내 "감이 안 오는"
상태로 개발하게 된다. → **최소 사운드(발사·색전환·색사망·착지) 4종은 M2 후반~M3 초에 넣는 걸 권장.**
거창한 AudioManager autoload 없이도, EffectSpawner에 `AudioStreamPlayer` 재생을 함께 얹는
방식으로 가볍게 시작할 수 있다(첫 autoload 도입 시점을 늦추는 §Part1 논의와도 일관).

## 5. ⚠ 반복되는 신호 — "Godot 4.4" 표기 & "새로 만들어라"체 프롬프트

- 두 챕터의 Claude Prompt가 또 "Godot **4.4** 기준"(실제 4.6.3)이고, **이미 있는 것을 "만들어줘"**
  라고 지시한다(5.9 조준 시스템, 4.10 카메라 LookAhead). 그대로 실행하면 중복 제작 위험.
- **원칙 재확인**: 바이블의 Claude Prompt는 **그대로 복붙하지 말 것.** 항상 "이미 있는지" 먼저
  확인하고, 있으면 "새로 제작"이 아니라 "기존 proto 파일 튜닝"으로 바꿔서 나(Claude)에게 시킬 것.

## 6. 종합 착수 순서 (5개 챕터 전체 검토 최종본)

어제~오늘 다섯 번의 코드 대조가 수렴한 **실제 우선순위**:

1. **조준 궤적 가시성 개선** — `proto_gun.gd` 튜닝(§2). 사용자 본인 페인 포인트 + player.gd 무관 +
   상수 몇 줄. **최우선·최저비용.**
2. **EffectSpawner + Paint Splash / Landing Dust** — `proto/` 신규(Ch4 Part1 §4·Ch5 5.4/5.5).
   이미 비어있는 시그널 리스너에 연결.
3. **Camera Shake(trauma) / Landing Zoom** — `proto_camera.gd`에 추가(도형 소유).
4. **Hit Stop** — 사망/착탄 `Engine.time_scale` 순간 정지(EffectManager 도입 시점에 얹기).
5. **최소 사운드 4종** — §4대로 M4 아니라 M2 후반~M3 초 권장.
- **팀 협의/보류**: player.gd·gun.gd·bullet.gd 수정, FSM, SceneManager, SaveManager.
- **이미 완료(착수 금지)**: Jump Buffer, Coyote Time, Look Ahead, 기본 애니(land/death), 씬 전환 헬퍼.
