# 색칠 표현 방식 비교 — 셰이더(zone_04) vs VFX(zone_05)

> 작성: 도형 + Claude / 2026-07-24
> 목적: **"색칠할 때 어떤 느낌이 우리 게임에 어울리는가"를 팀이 눈으로 보고 고르기 위한 문서.**
> 실행: 로비 → 챕터 1 → `ZONE 4` / `ZONE 5` 를 번갈아 보면 된다.

---

## 0. 왜 두 개를 만들었나

오픈AI(ChatGPT) 상담에서 나온 두 제안 —

- **Ink Spread Shader**: 브러시 중심에서 노이즈로 가장자리가 자연스럽게 퍼지는 효과, 시간에 따라 번지는 애니메이션, 젖은 느낌의 하이라이트
- **Paint Drip System**: 벽에 닿은 위치에서 일정 확률로 물감 방울 생성, 중력 방향으로 흘러내리며 길이가 늘고, 일정 시간 뒤 사라지거나 굳음

— 은 **서로 배타적인 선택지가 아니다.**
`Ink Spread` 는 "색칠 자체를 어떻게 보여줄까"이고, `Paint Drip` 은 "그 위에 얹는 연출"이다.

그래서 실제로 갈리는 선택은 이것이다:

> **색칠된 면적을 무엇으로 그릴 것인가 — 셰이더 마스크인가, 누적되는 얼룩 스프라이트인가?**

두 방식을 각각 zone_04 / zone_05 로 만들었다.
**물감 흐름(Drip)·스플래시·카메라 킥은 두 존 모두에 똑같이 들어간다** (그건 선택지가 아니라 기본).

### ⚠ 비교의 공정성

- 두 존은 **지형 배치가 픽셀 단위로 동일**하다 (`build_stages.gd` 의 `_실험실()` 한 함수가 둘 다 찍어냄).
- **게임 규칙도 완전히 동일**하다. `PaintPlatform.표현_모드` 한 값만 다르다.
- 그래서 차이 나는 것은 **오직 "보이는 방식"** 뿐이다.

## 1. 방식 A — 잉크 번짐 셰이더 (zone_04)

**파일**: `shaders/ink_spread.gdshader`

### 어떻게 동작하나

```
명중 → 그 지점의 로컬 UV 를 씨앗(seed)으로 기록 (최대 8개)
     → CPU 가 씨앗마다 반지름을 부드럽게 키운다
     → 셰이더가 "가장 가까운 씨앗까지의 거리 − 반지름" 을 계산
     → fbm 노이즈로 그 경계를 흔든다 → 원이 아니라 번진 잉크 모양
     → 경계 근처에 젖은 광택 띠 (0.8초에 걸쳐 마름)
```

### 장점

| | |
|---|---|
| **드로우콜** | 플랫폼 1개 = **1회**. 몇 번을 칠하든 늘지 않는다 |
| **노드 수** | 색칠 때문에 생기는 노드 **0개** |
| **경계 품질** | 픽셀 단위로 부드럽고, 확대해도 깨지지 않는다 |
| **저장/되돌리기** | 씨앗 좌표 + 반지름 몇 개면 상태가 완전히 복원된다 |
| **일관성** | 어떤 크기·재질의 플랫폼에서도 같은 문법으로 퍼진다 |

### 단점

| | |
|---|---|
| **물성 표현** | "물감이 튀어서 얼룩졌다"는 **거친 질감**은 표현이 약하다. 매끄럽고 깔끔한 쪽 |
| **수정 비용** | 느낌을 바꾸려면 셰이더 코드를 고쳐야 한다 (아티스트가 직접 못 만짐) |
| **씨앗 상한** | 유니폼 배열이 8개로 고정. 넘으면 오래된 씨앗을 밀어낸다 |

### 보이는 느낌 (스크린샷 `tools/_shots/z4_wall.png`)

> **깔끔하고 조용하다.** 물감이 종이에 스며드는 쪽. LIMBO / INSIDE 같은 절제된 톤과 잘 맞는다.
> 벽 전체가 매끈하게 흰색으로 덮이고, 가장자리만 미세하게 일렁인다.

## 2. 방식 B — VFX 얼룩 스탬프 (zone_05)

**파일**: `scripts/proto/paint_fx.gd` (`_스탬프_찍기` / `_얼룩` / `_얼룩_텍스처`)

### 어떻게 동작하나

```
명중 → 그 지점 주변에 얼룩 스프라이트 5장을 흩뿌려 찍는다
     → 각 얼룩은 0.14초에 걸쳐 "찰싹" 하고 커지며 나타난다 (TRANS_BACK)
     → 얼룩은 플랫폼 그림의 자식이고, clip_children 으로 실루엣 밖으로 안 삐져나간다
     → 마지막 한 발에서 남은 틈을 전부 덮는다
```

얼룩 텍스처는 **코드로 생성**한다(각도별 반지름을 흔든 64×64 이미지) — 아트 에셋 의존 0.

### 장점

| | |
|---|---|
| **물성 표현** | **"물감을 던져 맞혔다"는 타격감**이 훨씬 강하다. 얼룩 하나하나가 보인다 |
| **아트 친화** | 나중에 디자이너가 그린 얼룩 PNG 로 **텍스처만 갈아끼우면** 느낌이 통째로 바뀐다 |
| **변주** | 회전·크기 랜덤이라 같은 자리를 두 번 칠해도 모양이 다르다 |
| **읽기 쉬움** | 한 발 = 얼룩 한 뭉치라 **"몇 발 맞혔는지"가 눈으로 세어진다** |

### 단점

| | |
|---|---|
| **노드 수** | 명중 1회 = 스프라이트 5개. 8칸 플랫폼 완성에 **40~70개**. 스테이지 전체로는 수백 개 |
| **드로우콜** | 얼룩마다 1회. `clip_children` 은 추가 비용이 더 붙는다 |
| **저장/되돌리기** | 얼룩 위치를 전부 기억하거나, 복원 시 다시 찍어야 한다 |
| **경계 품질** | 얼룩 텍스처 해상도(64px)에 묶인다. 큰 플랫폼에서 확대하면 뭉개질 수 있다 |
| **지저분해질 위험** | 회수(E)·재칠을 반복하면 얼룩이 계속 쌓인다 (지금은 회수 시 전부 지우게 해뒀다) |

### 보이는 느낌 (스크린샷 `tools/_shots/z5_wall.png`)

> **거칠고 시끄럽다.** 물감을 던져 벽에 처바르는 쪽. 스플래툰 / 잉크 아트에 가깝다.
> 완성 전에는 얼룩이 듬성듬성 남아 "아직 덜 칠했다"가 아주 잘 보인다.

| 항목 | A 셰이더 (zone_04) | B VFX 스탬프 (zone_05) |
|---|---|---|

| 톤 | LIMBO · INSIDE | 스플래툰 · 잉크 아트 |

## 4. 도형(Claude)의 추천 — **A 를 기본, B 를 위에 얹기**

### 이유

1. **이 게임의 정체성은 "퍼즐"이다.**
   도형님이 명시한 방향 — *"색을 칠하는 재미보다, 색을 칠하며 장애물을 피해 스테이지를
   클리어하는 퍼즐적 희열감"* — 에서 색칠 표현은 **주인공이 아니라 피드백**이다.
   피드백은 **읽기 쉽고 조용해야** 한다. 화면이 얼룩으로 시끄러우면 "지금 이 발판이 무슨 색인가"라는
   **핵심 정보가 묻힌다.** (이 게임은 발판 색을 잘못 읽으면 즉사한다)

2. **성능 예산.** 스테이지 5 는 발판 12개 + 장애물 9개다.
   B 만 쓰면 색칠이 끝난 시점에 얼룩 노드가 수백 개 남는다. 30구역 규모로 가면 문제가 된다.

3. **B 의 장점은 "한 발의 타격감"인데, 그건 셰이더를 버리지 않고도 얻을 수 있다.**
   이미 두 존 모두에 들어가 있는 **스플래시 파티클 + 물감 흐름 + 카메라 킥 + 히트스톱**이
   그 역할을 한다. 실제로 zone_04 에서도 한 발 쏠 때의 손맛은 충분하다.

### 구체적 제안

```
기본             : A (셰이더 번짐)
명중 순간        : 스플래시 파티클 (이미 있음)
벽·아랫면 명중   : 물감 흐름 (이미 있음)
★완성되는 순간   : B 의 얼룩 스탬프를 2~3장만 "축하 폭죽"처럼 추가
회색화되는 순간  : B 의 얼룩을 회색으로 크게 한 장 (되돌릴 수 없다는 무게감)
```

= **평상시엔 조용하고, 결정적인 순간에만 거칠어진다.**

### 다만 이건 취향의 영역이다

- 게임 톤을 **더 밝고 장난스럽게** 가져가고 싶다면 B 가 맞다.
- 팀에서 **"색칠 자체가 이 게임의 놀이"** 라고 보면 B 쪽으로 기울어야 한다.
- 그래서 **직접 두 존을 번갈아 보고 정하는 게 맞다.** 코드는 어느 쪽이든 한 줄(`표현_모드`) 이다.
