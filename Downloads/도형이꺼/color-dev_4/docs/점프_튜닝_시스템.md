# 점프 튜닝 시스템 — 문서

> **작성일**: 2026-07-26
> **대상 파일**: `scripts/player.gd` (팀 공용 — world_1·zone_04/05·모든 테스트 씬이 같이 씀)
> **한 줄 요약**: 점프 높이·거리를 **px가 아니라 "타일 칸 수"**로 입력하면, 실제 물리값
> (`jump_velocity`·`gravity`)을 자동으로 역산해주는 시스템.

---

## 1. 왜 만들었나

기존에는 `jump_velocity`(-600)·`gravity`(1200) 같은 물리값을 직접 Inspector에서 만졌는데,
이 숫자만 보고 "점프가 몇 칸을 넘을 수 있는지"를 가늠하기 어려웠다.
그래서 **"칸 수"를 입력하면 물리값이 자동으로 계산되는 방식**으로 바꿨다.

---

## 2. Inspector에서 만지는 값 5개

씬에서 **`Player` 노드**를 선택하면 Inspector에 이 5개가 보인다:

| 필드 | 코드 위치 | 기본값 | 의미 |
|---|---|---|---|
| `move_speed` | `player.gd:7` | 390.0 | 좌우 이동 속도 (px/초) |
| `타일_크기` | `player.gd:27` | 16.0 | 이 씬에서 타일 한 칸이 몇 px인지 |
| `점프_높이_칸` | `player.gd:31` | 4.0 | 최고점까지 몇 칸 높이 오르는가 |
| `점프_거리_칸` | `player.gd:35` | 5.0 | 최고점 찍고 원래 높이로 착지할 때까지 수평으로 몇 칸 이동하는가 |
| `상승_배수` | `player.gd:42` | 1.0 | 상승 구간의 체감 속도 (크면 훅 튀었다 멎음 / 작으면 둥실 떠오름). 높이·거리는 그대로 유지됨 |

### ⚠ 씬마다 타일 크기가 다르다

`player.gd`는 world_1(32px 타일)부터 우리 테스트 씬(16~24px 타일)까지 전부 같이 쓰는 공용 파일이다.
그래서 **씬에 놓인 각 `Player` 인스턴스마다 `타일_크기`를 그 씬 기준으로 따로 맞춰야** "칸 수"가 정확해진다.

---

## 3. 코드에서만 수정 가능한 값 4개 (Inspector에 없음)

`scripts/player.gd`를 직접 열어서 텍스트로 고쳐야 하는 상수(`const`)들 — 조작감의 미세 튜닝용이라
일부러 Inspector에 안 뺐다:

| 이름 | 코드 위치 | 기본값 | 의미 |
|---|---|---|---|
| `COYOTE_TIME` | `player.gd:15` | 0.12초 | 절벽 끝에서 떨어진 후에도 점프 가능한 유예시간 |
| `JUMP_BUFFER_TIME` | `player.gd:16` | 0.12초 | 착지 직전 점프 입력을 미리 눌러도 기억해두는 시간 |
| `FALL_GRAVITY_MULTIPLIER` | `player.gd:17` | 2.4 | 하강이 상승보다 몇 배 빠른지 |
| `JUMP_CUT_MULTIPLIER` | `player.gd:18` | 0.4 | 점프 버튼을 짧게 뗐을 때 상승 속도를 몇 %로 깎을지(숏홉) |

---

## 4. 절대 직접 손대면 안 되는 값 2개

- **`jump_velocity`**, **`gravity`** (`player.gd:11-12`)

이 둘은 위 5개 입력값으로부터 **매번 자동으로 다시 계산되는 결과값**이다.
Inspector에도 노출 안 시켜뒀고(2026-07-26 숨김 처리), 코드에서 직접 숫자를 바꿔도
`_점프_재계산()`이 다음번에 실행될 때(`_ready()` 또는 다른 필드 편집 시) **그대로 덮어써져서 소용없다.**

---

## 5. 수정 방법 — Inspector vs 코드

### A. Inspector 값 (5개) 수정 절차

1. 씬 열기 → Scene 트리에서 `Player` 노드 선택.
2. Inspector에서 값 입력.
3. ⚠ **바로 반영 안 됨** — `player.gd`가 `@tool`이 아니라서, 에디터에서 값만 바꿔서는
   재계산 코드가 실행되지 않는다.
4. **F6(또는 F5)로 씬을 실행**해야 `_ready()`에서 자동으로 재계산돼 실제로 반영된다.
5. 저장하고 싶으면 Ctrl+S.

워크플로: **"값 바꾸기 → 실행해서 확인 → 마음에 안 들면 다시 바꾸기"** 반복.

### B. 코드 상수(4개) 수정 절차

1. `scripts/player.gd` 파일을 스크립트 에디터로 열기.
2. 숫자만 원하는 값으로 고치기 (예: `const FALL_GRAVITY_MULTIPLIER: float = 2.4` → `3.0`).
3. 저장(Ctrl+S) → Godot이 자동으로 스크립트 재로드 → 실행해서 확인.

### 요약표

| 뭘 바꾸고 싶나 | 어디서 | 즉시 반영? |
|---|---|---|
| 점프 높이/거리/속도/상승 느낌 | **Inspector** (`Player` 노드) | F6 실행해야 반영 |
| 코요테·버퍼·낙하배수·점프컷 | **코드** (`player.gd` 직접 편집) | 저장 후 재실행 |
| `jump_velocity`·`gravity` | ❌ 아무 데서도 직접 수정 안 함 | - |

## 6. 공식 (`_점프_재계산()`, `player.gd:47-52`)

```
높이 = 점프_높이_칸 × 타일_크기
거리 = 점프_거리_칸 × 타일_크기

k = 1/√상승_배수 + 1/√FALL_GRAVITY_MULTIPLIER

gravity        = 2 × 높이 × move_speed² × k² / 거리²
jump_velocity  = -√(2 × gravity × 상승_배수 × 높이)
```

기본값(높이 4칸×16=64px, 거리 5칸×16=80px, `move_speed=390`, `상승_배수=1.0`) 기준:
- `gravity ≈ 8236.71`
- `jump_velocity ≈ -1026.79`

검증된 성질: `상승_배수`를 뭘로 바꾸든 `k` 공식이 자동 보정해서, 실제 도달 높이·거리는
항상 그대로 유지되고 오직 상승 구간의 체감 속도만 달라진다 (헤드리스 테스트로 확인 완료).

## 7. 매 물리 프레임 적용 (`_physics_process`, `player.gd:67-103`)

**중력 — 상승/하강 각각 다른 배수**
```
공중 + 낙하 중(velocity.y > 0)  → 가속도 = gravity × FALL_GRAVITY_MULTIPLIER(2.4)
공중 + 상승 중(velocity.y < 0)  → 가속도 = gravity × 상승_배수(기본 1.0)
velocity.y += 가속도 × delta
```

**점프 컷 (숏홉)**
```
점프 버튼 뗐고 아직 상승 중이면: velocity.y *= JUMP_CUT_MULTIPLIER(0.4)
```

**점프 버퍼**
```
점프 버튼 누르는 순간 → _jump_buffer_timer = JUMP_BUFFER_TIME(0.12초)
```

**코요테 타임**
```
바닥에 있으면 → _coyote_timer = COYOTE_TIME(0.12초)로 리셋
공중이면      → 매 프레임 delta만큼 감소
```

**점프 실행 조건**
```
_jump_buffer_timer > 0 AND _coyote_timer > 0  →  velocity.y = jump_velocity
```

## 9. ⚠ 알려진 함정 — "칸"이 궤적 전체에 균등하게 안 퍼짐

상승 중력과 하강 중력이 다르다 보니, **최고점(`점프_높이_칸`)은 이동 거리의 초반이 아니라
전체 `점프_거리_칸`의 약 61% 지점에서야 찍힌다.**

예: 기본값(`gravity≈8236.71`, `jump_velocity≈-1026.79`) 기준 이륙 후 수평 이동 거리별 높이:

| 이륙 후 수평 이동 거리 | 그 시점의 높이 |
|---|---|
| 1칸 | 약 2.36칸 |
| 2칸 | 약 3.98칸 |
| 3칸 | 약 4.84칸 |
| 3.65칸 | 5칸(최고점) |

**이륙 지점 바로 근처(1~3칸 이내)에 있는 높은 장애물은, 공식이 보장하는 높이에 아직
도달하기 전이라 못 넘을 수 있다.** 이 부분은 아직 해결 방식이 결정되지 않았다
(궤적 자체를 바꿔 인접 장애물도 넘게 할지, 여유값만 크게 잡을지 — 팀 논의 필요).
