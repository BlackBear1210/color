## 1. ★zone_05 색칠 문제 — 원인 규명과 해결

도형님 표현: *"페인트칠이 벽돌에만 칠해지는 게 아니라 벽돌 옆 마스킹 테이프까지 같이 칠해지는데
그걸 그대로 플레이어가 볼 수 있고, 색칠이 전부 되지도 않고 가운데나 어떤 부분만 덜 칠해지는 게 이상하다."*

**서로 다른 버그 2개가 겹쳐 있었습니다.**

### 원인 A — "마스킹 테이프까지 칠해짐" = 그림이 콜리전 밖으로 삐져나오는 양이 크기에 비례했다

디자이너 타일셋은 한 칸이 384×384 이고 그중 실제 그림은 350×350, 바깥 17px 는 투명 여백(뜯긴 가장자리)입니다.
기존 코드는 배율을 `플랫폼크기 / 350` 으로 잡았습니다. 그러면 **투명 여백도 같은 배율로 커집니다**:

| 플랫폼 | 삐져나오는 양 |
|---|---|
| 2칸(64px) | 3px ← 자연스러운 유기적 가장자리 |
| **8칸(256px)** | **12.4px** ← 콜리전 밖에 "칠해진 띠"가 따로 생긴 것처럼 보임 |

→ **수정**: 배율을 `(플랫폼크기 + 12px) / 384` 로 변경.
**어떤 크기의 발판이든 항상 6px 만 삐져나옵니다.** (`PaintPlatform.그림_여백`)
셰이더의 UV·종횡비·9슬라이스 기준도 전부 "그림 크기"로 통일했습니다
(안 그러면 색칠 좌표와 그림이 어긋납니다).

### 원인 B — "가운데가 덜 칠해짐" = VFX 모드가 얼룩 스프라이트를 랜덤으로 흩뿌리는 방식이었다

구 방식은 명중할 때마다 **얼룩 스프라이트 5장**을 플랫폼 위에 겹쳐 찍었습니다.

1. **실루엣 이탈** — `clip_children` 은 부모의 **사각형** 기준이라 유기적 가장자리를 못 지킵니다.
   그래서 얼룩이 그림 밖 투명 여백까지 덮었습니다. (원인 A 와 겹쳐 더 심해 보였음)
2. **덮임 미보장** — 랜덤 배치라 구석·가운데가 덜 칠해진 채 남았습니다.
   완성 시점에 "전체 덮기"를 한 번 더 호출했지만 그것도 격자 배치라 틈이 생겼습니다.

→ **수정**: 얼룩 표현을 **셰이더 프로파일로 흡수**했습니다.

```
ink_spread.gdshader
  profile 0 = 스며듦   : 부드러운 경계 (zone_04)
  profile 1 = 물감 얼룩 : 덩어리 노이즈 한 겹 추가 + 딱딱한 경계 (zone_05)
paint_platform.gd
  얼룩 프로파일일 때 한 번 명중에 씨앗 3개를 살짝 흩어 심는다
```

**같은 마스크 안에서 경계 모양만 바뀌므로:**
- 실루엣을 **구조적으로 벗어날 수 없고** (알파가 원본 텍스처를 따름)
- 진행률 100% 에서 **반드시 전부 덮입니다** (마지막 한 발이 최대 반지름으로 확장)

`paint_fx.gd` 에서 얼룩 스탬프 코드(약 90줄)를 전부 걷어냈습니다.
이제 그 파일에는 "물감이 튀고 흐르는" 물리적 연출만 남습니다.

> **결과**: zone_04 / zone_05 의 차이는 이제 "기술의 차이"가 아니라 **"붓의 차이"** 입니다.
> 규칙·덮임·성능이 완전히 같고 경계 질감만 다릅니다 → 순수하게 취향으로 고르시면 됩니다.

## 2. 배경 시스템 — "바인처럼 이어지지만 변한다"

`scripts/proto/stage_backdrop.gd` 신설.

### 2-1. 바이옴 진행

```
스테이지 1        2         3         4          5
   자연 ──────→ 물가 ──────→ 판자촌 ──────→ 도심 ──────→ 고층
```

각 스테이지의 **끝 바이옴 = 다음 스테이지의 시작 바이옴**입니다.
그래서 통로를 지나 다음 스테이지로 나오면 하늘색과 실루엣이 그대로 이어집니다.

### 2-2. 어떻게 "변하게" 했나 (2가지 동시)

1. **하늘** — 네 귀퉁이 색(좌상/좌하/우상/우하)을 **월드 좌표로 보간**하는 셰이더.
   좌측 = 시작 바이옴 팔레트, 우측 = 끝 바이옴 팔레트.
   → **걸어갈수록 하늘이 실제로 변합니다.**
2. **실루엣** — 시작 바이옴 프롭은 오른쪽으로 갈수록 알파가 빠지고,
   끝 바이옴 프롭은 반대로 나타납니다. 가운데 구간에서 두 풍경이 겹칩니다.

### 2-3. 레이어 구성

| z | 레이어 | 가로 시차 | 명도 | 역할 |
|---|---|---|---|---|
| -40 | 하늘 | 0.05 | 8~40% | 바이옴 팔레트 보간 |
| -30 | 원경 | 0.20 | 58% | 가장 밝고 멀리 (공기원근) |
| -20 | 중경 | 0.42 | 36% | |
| -12 | 근경 | 0.68 | 22% | |
| **-8** | **★뒷벽** | 1.00 | 15% | **지형 뒤를 채우는 암반** |
| -6 | 안개 | 0.85 | — | 화면 아래 대기감 |
| 0 | 지형 | 1.00 | — | PaintPlatform |
| +12 | 전경 | 1.15 | 15% | 화면 하단을 스쳐 지나감 |

### 2-4. ★뒷벽이 이번 작업의 핵심

지금까지 발판이 "허공에 뜬 막대기"로 보인 **가장 큰 이유는 뒤가 비어 있어서**였습니다.
레인월드·리틀 나이트메어의 지형이 묵직해 보이는 건 방이 항상
**"덩어리에서 파낸 공간"** 이기 때문입니다.
어두운 뒷벽 한 장(노이즈로 만든 암반 질감)이면 같은 발판도 완전히 다르게 읽힙니다.

### 2-5. 라이팅

- **자연·물가** = 발광 구슬(반딧불). **판자촌·도심·고층** = 가로등.
- 물가 스테이지 바닥에 **수면 반사 셰이더** — 광원 아래가 밝게 빛나고 잔물결이 흐릅니다.
- `ZoneVisuals` 를 스테이지에도 부착 (환경광 + 플레이어 광원 + 배경 노멀맵 + 비네트).
  환경광은 스테이지용으로 0.93 (기존 존은 0.82 그대로 — 값을 씬마다 줄 수 있게 열었습니다).

## 4. 통로 — 스테이지 연결

`scripts/장애물/통로.gd` 신설, `목표문` 폐기.

### 왜 바꿨나
구 `목표문` 은 허공에 뜬 아치에 흑↔백이 맥동하는 **"게임적인 포탈"** 이었습니다.
이 게임 톤(LIMBO 계열)과 안 맞았습니다.

### 어떻게 바꿨나
- 지형에 **파인 터널 입구**. 안쪽은 어둡고, 저 끝에서 **다음 지역의 빛**이 새어나옵니다.
- **출구의 속빛 = 다음 스테이지 하늘색 / 입구의 속빛 = 이전 스테이지 하늘색**
  → 통로를 지나면 **방금 본 빛깔의 하늘이 실제로 펼쳐집니다.**
- 전환도 잉크 와이프가 아니라 **어둠 페이드**(0.55초). 터널을 지나며 어두워졌다가,
  다음 스테이지에서 밝아집니다.
- 스테이지 시작에는 **입구 통로**(장식·판정 없음)를 둬서 "저기서 걸어 나왔다"가 읽히게 했습니다.

## 5. 체크포인트 — 깃발에서 등불로

깃발은 **레이싱/플랫포머의 UI 기호**지 이 세계의 사물이 아닙니다.

→ **꺼져 있던 등불에 불이 들어오는 것**으로 바꿨습니다.
- 이 게임의 세계는 어둡고, **빛은 이미 핵심 문법**입니다(가로등·구슬·물 반사).
  체크포인트가 광원이 되면 **기능과 분위기가 같은 언어**를 씁니다.
- "여기서부터 안전하다"를 아이콘이 아니라 **화면이 밝아지는 것**으로 알립니다.
- 켜질 때 2단 트윈(확 붙었다가 안정) → 그 뒤부터 촛불처럼 미세하게 흔들립니다.
- 지나온 길을 돌아보면 켜둔 등불이 줄줄이 보입니다 = **진행 기록이 세계 안에 남습니다.**
