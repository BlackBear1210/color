## 1. STEP 2 — BRICK 512 코너 실험

같은 도형·배율·프레이밍으로 256 vs 512 를 굽고 비교했다.

| | 256 | 512 |
|---|---|---|
| 대조군 이음매 | 6.86 | 6.86 (동일) |
| 볼록 이음매 | 15.83 | 16.37 (+3%) |
| 오목 이음매 | 9.42 | 9.42 (동일) |
| **볼록 디테일 비율** | **0.56 FAIL** | **0.66 PASS** |
| 오목 디테일 비율 | 0.45 FAIL | 0.47 FAIL |

**512 채택.** 채택 조건 6개 중 2~6번은 완전 충족(새 사각 경계 없음 · OUTER/INNER 정상 ·
curve 무영향 · taper 무충돌 · grass 무영향), 1번은 부분 충족(볼록만 임계 통과).
비용은 코너 PNG 42KB → 126KB 로 무시할 수준.

⚠ 남은 것: **오목 코너 디테일 0.47 은 여전히 기준(0.60) 미달**이다.

## 2. 발견하고 고친 두 가지 (gameplay 코드)

### (A) v4/brick 머티리얼이 게임에서 칠해지지 않았다

`지형.gd _짝_텍스처()` 는 흰색 짝을 **파일명 규칙**(`black_*` → `white_*`)으로만 찾았다.
grass_v4 이후 타일셋은 `<재질>/black/edge_top.png` 구조라 이 규칙에 안 걸려
**페인트 셰이더가 아예 안 붙었다** = 총에 맞아도 색이 안 변한다.
"내 색과 다른 지형에 닿으면 즉사" 가 핵심 규칙인 게임에서 치명적이다.

→ 폴더 규칙(`/black/` → `/white/`)을 **추가**했다. 파일명 규칙을 먼저 보므로
기존 머티리얼 5개는 예전과 완전히 같은 경로로 짝을 찾는다(하위호환).

실측 검증:
```
기존 잔디 black_grass_fill.png      ✓ (규칙1)
v4 잔디  grass_edge_top.png         ✓ (규칙2)  ← 예전엔 ✗
brick    edge_top.png               ✓ (규칙2)  ← 예전엔 ✗
투명 캐리어 투명_256.png             ✗ 짝 없음 (정상)
```

### (B) 지형 하나당 경고가 하나씩 떴다

코너 전용 엣지의 기본 텍스처는 **안 보이는 투명 캐리어**라 흰색 짝이 있을 이유가 없는데
매번 경고가 났다. 쇼케이스 씬에서 **144개**가 떠서 진짜 경고를 덮었다.
→ `textures_corner_outer` 를 들고 있는 메타는 셰이더를 건너뛴다(이름이 아니라 역할로 판별).
수정 후 경고 **0개**.

## 3. 흑/백은 머티리얼이 아니라 `시작상태` 다

처음 지시는 8개 머티리얼(GRASS_BLACK/GRASS_WHITE …)이었지만
실제 구조를 읽어 보니 이 게임에서 색은 **런타임 상태**다.

- 머티리얼은 재질당 하나(검정 텍스처 기반)
- `지형.gd` 가 `white_*` 짝을 찾아 셰이더 `alt_tex` 로 물림
- 레벨 작업자는 `@export var 시작상태` 로 무색/검정/흰색/회색을 고름

'흰색 전용 머티리얼' 을 만들면 그 지형은 **검정으로 칠할 수 없게 되어** 규칙이 깨진다.
그래서 씬 프리셋(`_검정` / `_흰색`)으로 제공했다.
쇼케이스에서 흰색 블록이 정상 렌더된 것이 (A) 수정이 끝까지 통했다는 증거다.

---

## 4. 속빔(HOLLOW) — 애드온 수정 없이

`shape.gd:858` 이 `fill_textures.is_empty()` 면 채우기 메시를 통째로 건너뛴다.
→ 머티리얼에서 `fill_textures` 만 비우면 **진짜 알파 투명** 내부가 된다.
검정으로 칠하는 방식이 아니다. 쇼케이스 '검정·속빔' 블록에서 확인했다.

## 5. 안쪽 그림자 (깊이감)

지시는 "FILL 텍스처에 baked gradient" 였지만 **기술적으로 불가능**하다 —
FILL 은 내부를 반복 타일링하므로 텍스처 안에 '안쪽' 방향이 없고,
그라데이션을 구우면 그게 반복돼 줄무늬 타일 경계가 생긴다.

→ **엣지 텍스처에 구웠다.** 엣지는 외곽선을 따라가므로 v 축이 곧 '바깥→안쪽' 이다.
별도 그림자 엣지를 얹지 않은 이유: 코너와 taper 가 엣지 단면에서 합성되므로
**그림자를 자동으로 물려받고**, 필 톤도 `_안쪽톤()` 이 그림자 적용 후를 재서 자동으로 이어진다.
세기 `--그림자=0.25`.

## 9. 남은 것 (정직하게)

1. **오목 코너 디테일 0.47** (기준 0.60) — 512 로도 안 풀렸다. 원인 미확정.
2. **코너에 옅은 후광** — 확대하면 보이고 플레이 거리(0.82)에서는 안 보인다.
3. **GRASS 에는 안쪽 그림자가 없다** — grass_v4 PNG 가 LOCK 이라 다시 굽지 않았다.
   통일하려면 `grass_v5` 를 따로 만들어야 한다 (v4 는 그대로 두고).
4. **SEWER SIDE 원본**이 의도(길이 방향 벽돌 끝면)와 다르게 기둥 있는 벽면으로 나왔다.
   세로 벽에서 기둥이 가로 단으로 읽혀 쓸 만하지만 재생성 여지가 있다.
5. **실제 스테이지에는 적용하지 않았다** (지시대로).
