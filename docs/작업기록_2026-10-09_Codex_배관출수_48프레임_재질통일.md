# 배관 출수 48프레임과 입구 재질 통일

> 이 문서의 시작 연출은 사용자 피드백으로 폐기했다. 폭·높이를 키우는 방식의 문제를 고친 최종 동작은 `작업기록_2026-10-09_Codex_출수확대제거_앞끝낙하.md`에 기록했다. 아래 내용과 미리보기는 첫 시도에 대한 이력이다.

- 요청: 위쪽 입구 물을 아래 낙수 재질로 통일하고, 빈 배관에서 물이 나오기 시작하는 자연스러운 프레임 제작.
- Higgsfield는 크레딧 부족으로 생성에 실패했다. 이후 사용자가 사용하지 말고 직접 제작하도록 지시하여 외부 생성 없이 기존 낙수 RGB를 사용하는 윤곽 마스크 48프레임을 만들었다.

## 적용

- `물_힉스필드_출수구.gd`: 정적인 `pipe_joint_water` 덧그림 제거. 기존 빈 배관 이미지는 유지하고 켜짐 상태에서만 입구 물을 표시한다.
- `물_힉스필드_삼색프레임.gd`, 신규 `물_배관입구그림.gd`: 입구 자식과 낙수 본체가 정확히 같은 ShaderMaterial 리소스를 공유한다. 삼색 RGB 아틀라스, 프레임 번호, 속도, 위상을 공유한다. 런타임 자식에 owner를 지정하지 않는다.
- `water_reference_frames.gdshader`: 음수 y의 입구 영역까지 기존 물 프레임을 이어 그린다. 시작 마스크로 작은 물막이 넓어지도록 처리한다. 본체와 입구가 만나는 y=0에서는 마스크가 연결되어 가로 빈틈이 생기지 않는다.
- 시작 진행률은 기존 유체의 낙하 머리 위치에서 얻는다. 기존 밸브 판정·색·충돌 계산을 변경하지 않았다. 이전 요청의 1.4배 흐름도 유지한다.
- `tools/build_pipe_startup_masks.py`: 원본에서 멱등 생성. 에셋은 `assets/textures/obstacles/liquid/pipe_startup_20261009/inlet_masks_48.png` (1024×768, 8×6, 셀 128×128).

## 확인

- 정적 확인 통과: 48셀 크기, 첫 프레임 완전 투명, 채움 면적 단조 증가, 이후 모든 프레임의 중앙 하단 연결, 동일 재질 공유 코드, 정적 입구 물 제거, 1.4배 시계 유지, 셰이더 한글 없음, 두 번 생성한 PNG SHA256 일치, WebP 48프레임.
- 비교 시트를 직접 열어 빈 입구 → 좁은 출수 → 넓어진 낙수의 연결과 동일한 물 무늬를 확인했다.
- `git diff --check` 통과. 작업 상태에 삭제(D) 없음. 시작 전 git pull 결과 Already up to date.
- graphify AST 갱신 실행. 엔진 검사 13개 및 Godot 실행은 사용자 명시 허용이 없어 미실행. 작업 안내문 `docs/다음작업_프롬프트.md`는 현재 체크아웃에 없음.
