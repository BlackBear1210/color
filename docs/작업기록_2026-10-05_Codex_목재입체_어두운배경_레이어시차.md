# 2026-10-05 Codex — 목재 상판 재작업 · 어두운 배경 · 레이어 시차

사용자 수정 요청: 사방 테두리가 아니라 판자의 윗면과 앞 단면이 구분되는 입체감, 평평한 착지면과 부서진 밑면, 더 어두운 배경, 층별 움직임과 방별 가구 변화. 챕터1 전체에 적용.

## 변경

- `scripts/스마트월드/목재_데크지형.gd`: 상판은 법선 80~100°의 위쪽 면만 사용한다. 옆과 밑에 상판 무늬를 둘러 액자처럼 보이던 문제를 제거했다. 28.8px 상판 띠를 충돌선 안쪽에 놓는다.
- `shaders/wood_deck.gdshaderinc`: 상판의 세 가로줄을 제거하고, 약 31px 폭 판자들이 앞뒤로 뻗는 결·이음새로 변경했다. 일정한 비스듬한 투영이며 소실점은 없다. 상판 아래에 같은 이음새를 공유하는 끝단과 얇은 모서리, 접촉 그림자를 둔다. 검정 앞면은 원래 결 명도의 50%, 흰 앞면은 90%. 색 판정/칠하기/유령 처리는 공통 셰이더를 그대로 사용한다.
- 기존 다른 작업자의 `tools/쳅터1/모양.py`를 활용했다. 착지면은 평평하고 끝 8px 모따기, 옆·아랫면은 안쪽으로 불규칙하게 깎는다. 해당 알고리즘 자체는 이번 작업에서 변경하지 않았다.
- `scripts/쳅터1/방배경.gd`: 배경만 명도 0.60~0.66배로 낮춘다. PNG 원본의 회색조/투명도는 유지한다. 벽지·균열은 카메라 이동 3.5%/1.2%(x/y), 몰딩은 2.2%/0%, 바닥 가구는 5.5%/0%, 문은 3.5%/0% 시차. 샹들리에는 상단 중앙을 축으로 약 ±0.52° 흔들린다. 편집기에서는 움직이지 않는다. 카메라 변위 제한과 절대 원점 계산으로 누적 이동·빈 배경 노출을 막는다.
- 도안의 `배경.명도`, 씬의 `배경_명도`/`레이어_움직임`을 추가했다. `만들기.py`도 이 값을 기록하도록 수정했으나, Codex가 전체 씬 생성기나 Godot를 실행하지는 않았다.
- 방별 프리셋: 시작방/수납실/복도 C=판자, 복도 A=줄무늬, 서재=서재 다마스크, 침실=꽃무늬, 복도 B/계단/거실=다마스크, 굴뚝=벽돌. 복도 B는 거울·소파·괘종시계가 있는 전시 공간, 복도 C는 선반·상자·사다리가 있는 수납 공간으로 구분했다.
- 씬의 기존 `CanvasModulate(0.72,0.74,0.70)`을 중립 회색 `(0.74,0.74,0.74)`로 맞춘다. 어둠은 지형/HUD 전체를 더 낮추는 대신 배경에서 조절한다.

## 적용 도구와 보존

`tools/쳅터1/아트_v02_적용.py`는 씬 전체를 덮지 않고 지형 점 리소스·지형 노드 위치·배경·가구만 부분 변경한다. 기믹/카메라/연결 노드의 수동 편집은 보존한다. 지형이 원본 도안 또는 현재 모양.py 결과와 일치할 때만 점을 갱신한다. 원본이 다르면 보고하고 보존한다. 가구 리소스는 `art_v02_` 전용 ID를 사용한다.

최초 적용 당시 10개 씬 117개 지형을 처리했고, 수동 편집으로 건너뛴 지형은 없었다. 이후 다른 작업자가 14개 스테이지로 확장하면서 계단/거실/굴뚝 번호를 09/11/14로 이동하는 동시 변경을 확인했다. 번호가 아니라 방 이름으로 아트 설정을 대응하도록 적용 도구를 보완했다. 다른 작업자의 파일 삭제/이동을 되돌리지 않았다.

첫 적용 전 도안/씬은 `tools/쳅터1/아트_v02_검토/이전/`에 저장했다. 이전 v01 PNG와 목재 코드는 `tools/쳅터1/아트_v01_원본/이전/`에 있다. 백업 폴더에 `.gdignore`를 두어 엔진 리소스에 포함하지 않는다.

## 실행 검증 상태
