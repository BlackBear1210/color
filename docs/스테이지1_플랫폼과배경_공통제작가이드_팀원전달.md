# 스테이지 1 플랫폼·배경 제작 가이드 — 팀원 전달용

작성일: 2026-09-13 · GRAY 프로젝트

## 1. 이번 작업과 담당 범위

스테이지 1의 **일반 플랫폼과 배경**을 아래 공통 방식으로 정리하고 제작한다. 스테이지 2에서 정한 2D 표현 방식과 편집 구조를 공유하되, 소재와 공간 분위기는 스테이지 1의 기존 기획에 맞춘다.

| 담당 | 범위 |
|---|---|
| 이 문서를 전달받은 팀원 | 스테이지 1 일반 지형·플랫폼의 재질, SS2D 연결, 얇은 옆면, 배경 레이어와 시차 |
| 사용자 | 스테이지 2 및 장애물 디자인 |

가시·톱·유체·고인 물·투명 발판·붕괴 발판·압력발판·움직이는 플랫폼 등 기능성 장치는 이번 팀원 작업 범위에서 제외한다. 일반 지형과 맞닿은 부분의 미술상 문제는 기록해서 전달하고 장치 디자인·작동 규칙을 임의로 변경하지 않는다.

스테이지 1을 하수도로 바꾸는 작업이 아니다. 하수도의 벽돌·배관을 그대로 복제하지 않는다. 현재 저장소의 `scripts/스마트월드/챕터.gd`는 챕터 1을 집으로 정의하지만, 파일 숫자만 보고 담당 맵을 추정하지 말고 팀에서 실제 작업 중인 스테이지 1 씬과 원화를 먼저 확인한다.

## 2. 사용자가 확정한 공통 방향

1. 2D를 유지한다. 플랫폼의 입체감은 **얇은 옆면과 고정된 보는 각도**로 표현한다.
2. 배경과 지형의 명도 차이로 먼 플랫폼의 윤곽도 구분되게 한다.
3. 플랫폼 한 장짜리 그림을 늘이지 않는다. **반복 내부 면·상면·옆면·모서리**를 각각 제작한다.
4. 한 덩어리의 연속 플랫폼은 **하나의 SS2D**로 만들고 점을 추가해 형태를 늘린다.
5. 배경을 독립 레이어로 제작하고 카메라 이동에 대한 상대 이동량을 다르게 설정한다.
6. 검정 플랫폼 전체에 항상 켜져 있는 흰 테두리를 넣지 않는다.
7. 향후 플레이어 주변에만 매우 약한 빛이 반응하여 가까운 지형 모서리 일부가 얇게 드러나도록 한다. 멀리 있는 지형에는 이 근접 반사가 없어야 한다.

7번은 **채택한 디자인 방향**이며 구현 완료된 공용 기능이 아니다. 팀원은 이 표현을 받을 수 있는 재질을 준비하고, 공용 플레이어 조명·셰이더 변경은 사용자 담당 작업과 조율한다.

## 3. 흑백과 회색의 역할

- 검정·흰색은 플레이 규칙을 전달한다. 몸에 닿은 지형이 플레이어와 다른 색이면 사망하고, 무색·회색은 안전한 기존 규칙을 보존한다.
- 조명이나 텍스처 음영 때문에 검정 플랫폼의 넓은 면이 흰 플랫폼처럼 보이면 안 된다.
- 회색을 일반 플랫폼의 기본 안전 색으로 추가하지 않는다. 기존 회색 안전 지형도 외형만 검정으로 바꾸지 않는다. 필요하면 위치와 이유를 사용자에게 전달한다.
- 회색의 중간 명도는 배경·거리·재질 음영에 사용할 수 있다. 배경의 회색과 실제 안전 지형의 회색을 배치·대비·선명도로 구분한다.
- 검정/흰색 재질은 같은 벽돌 줄눈, 나뭇결, 균열과 윤곽을 공유한다. 색칠할 때 표면 구조나 충돌 윤곽이 바뀌어 보이지 않도록 한다.
- 흰색 재질을 검정 원본의 단순 밝기 반전만으로 최종 확정하지 않는다. 반사와 음영이 뒤집혀 입체감이 무너지는지 비교한다.

## 4. SS2D 플랫폼 제작 방식

### 필요한 자산

| 자산 | 역할 | 제작 기준 |
|---|---|---|
| 내부 채우기 | 넓은 벽·바닥 면 | 반복 가능한 재질. 가로·세로 경계가 연결되어야 함 |
| 상면 | 실제로 밟는 면의 끝 | 충돌 상면과 시각적 상면이 일치. 두꺼운 흰 선 금지 |
| 얇은 옆면 | 벽 두께와 고정 원근 | 좁게 유지. 시점이나 플레이어 위치에 따라 모양을 회전시키지 않음 |
| 바깥 모서리 | 볼록한 꺾임 | 상면과 옆면의 재질·두께가 연결되어야 함 |
| 안쪽 모서리 | 오목한 꺾임 | 텍스처 중첩·틈·진한 이중 테두리 방지 |
| 필요한 경사 연결 | 사선으로 이어지는 지형 | 벽돌·나뭇결 크기가 갑자기 늘어나거나 방향이 뒤집히지 않게 함 |

독립 PNG 또는 원본 아틀라스를 참조하는 독립 AtlasTexture 리소스 모두 가능하다. 아틀라스를 사용하면 각 영역의 위치·크기를 기록하고, 인접 영역의 픽셀이 필터링으로 새어 들어오는지 확인한다. 생성 이미지의 격자가 정확하다고 가정하지 않는다.

### 편집 구조

- 같은 플랫폼을 외형 조각별로 여러 SS2D에 나누지 않는다. **내부·상면·옆면·모서리는 한 SS2D의 재질 구성**으로 연결한다.
- 별개의 떨어진 플랫폼은 각각의 SS2D를 사용할 수 있다.
- 내부 텍스처는 반복한다. 지형 길이를 늘릴 때 벽돌이나 나뭇결 한 개가 함께 늘어나면 안 된다.
- 가장자리 재질을 방향별로 연결하고, 얇은 옆면은 같은 각도·같은 깊이 기준을 유지한다.
- 화면상 겹침이나 틈이 보이지 않도록 용접·안쪽 오프셋·모서리 연결을 조정한다. 내부 면과 가장자리 메시의 의도된 겹침까지 무조건 금지하는 뜻은 아니다.
- 장식 옆면 때문에 실제 충돌보다 넓은 발판처럼 보이지 않게 한다. 외곽에서 튀어나온 장식이 착지 지점으로 오인되지 않아야 한다.
- 점을 옮겼을 때 부속 표현도 함께 따라가도록 한다. 매번 옆면 그림을 수동으로 다시 배치하는 구조를 피한다.
- 텍스처 해상도와 월드에서 보이는 재질 크기를 구분한다. 실사용 카메라 줌에서 재질 크기와 옆면 두께를 판단한다.

## 5. 근접 빛과 재질

사용자가 원하는 것은 플레이어 주변의 매우 약한 반사이다. 모든 플랫폼을 둘러싼 상시 흰 외곽선이나 크게 번지는 후광이 아니다.

- 원본 텍스처에 강한 흰 테두리를 구워 넣지 않는다. 그 선은 플레이어가 멀어져도 사라지지 않기 때문이다.
- 모서리 반사는 짧고 약하게, 검정 본체는 검정으로 읽히게 한다.
- 배경과의 명도 분리로 기본 윤곽을 확보한다. 근접 빛을 끄더라도 먼 지형의 색과 착지 위치를 읽을 수 있어야 한다.
- 실제 반사 구현에는 노멀·반사 정보 또는 가장자리 셰이더가 필요할 수 있다. PointLight2D 하나만 추가해서 원하는 얇은 선이 자동 생성된다고 가정하지 않는다.
- 벽 뒤까지 똑같이 빛나거나 점프할 때 하이라이트가 과하게 흔들리는지 점검한다.
- 플레이어 색 변경, 페인트 판정, 기존의 굳은 빛 게임 규칙과 장식용 조명을 혼동하지 않는다.

참고 코드: `scripts/플레이어_보조광.gd`. 기존 코드가 있다는 사실은 새 스타일의 근접 반사가 완성되었다는 뜻이 아니다. 스테이지 1 전용 재질 시험부터 시작하고 공유 코드의 변경은 별도 협의한다.

## 6. 배경 레이어 제작 방식

배경은 스테이지 1의 장소에 맞춰 **공간적으로 독립된 깊이 층**으로 제작한다. 완성된 한 장의 그림을 같은 상태로 여러 번 겹치는 방식은 사용하지 않는다.

| 층 | 예시 역할 | 상대 이동 |
|---|---|---|
| 먼 배경 | 먼 벽·창 너머 공간·흐린 구조물 | 가장 작게 |
| 중간 배경 | 뒤쪽 기둥·벽체·아치 등 | 먼 배경보다 크게 |
| 가까운 배경, 필요할 때만 | 앞쪽 배경 장식과 구조물 | 지형에 가까운 이동량 |
| 실제 플레이 지형 | 발판·벽·지형에 연결된 장식 | 월드에 고정, 지형과 함께 움직임 |

- 층 수를 고정하지 않는다. 2~3개로 깊이가 잘 읽히면 충분하다.
- 먼 배경은 지형보다 낮은 대비와 덜 선명한 질감을 사용한다. 전체 화면이 하얗게 뜨지 않도록 밝기와 대비를 따로 조절한다.
- 검정과 흰색 플랫폼 모두를 배경 위에 놓고 식별성을 확인한다. 검정만 잘 보이는 배경으로 끝내지 않는다.
- 가장 뒤를 채우는 층은 빈 공간을 막고, 그 앞의 독립 층은 실제 투명 알파를 사용한다. 검정 배경이나 체크무늬를 투명으로 착각하지 않는다.
- 연결된 기둥·배관·창틀을 서로 다른 속도의 층으로 쪼개지 않는다. 이동하면 접합부가 벌어진다.
- 실제 지형에 고정된 물체는 지형과 같은 속도로 이동시킨다.
- 배경의 선반·바닥을 실제 착지 가능한 발판처럼 선명하게 그리지 않는다.
- 좌우뿐 아니라 상하 이동, 카메라 줌, 맵 끝에서도 빈 공간·레이어 끝·반복 경계가 보이지 않게 범위를 확보한다.
- 무한 반복 여부는 해당 공간에 맞춰 정한다. 반복하지 않는 방 배경에는 충분한 여유와 카메라 범위가 필요하다.

Godot에서는 Parallax2D의 `scroll_scale`로 상대 이동량을 설정할 수 있다. 스테이지 2 첫 시험의 0.25 / 0.6은 비교용 초기값이며, 스테이지 1에 그대로 복사해야 하는 공통 규격이 아니다. 수평·수직 이동량도 해당 맵과 카메라에 맞춰 조절한다.

## 7. 진행 순서와 산출물

1. **기존 상태 확인:** 스테이지 1 대상 씬·원화·재질·카메라와 편집 중인 파일을 확인한다. 기존 동선과 퍼즐은 유지한다.
2. **기준 화면:** 스테이지 1 소재로 배경과 일반 플랫폼만 있는 작은 기준 장면을 만든다. 배경 대비·재질 크기·얇은 옆면을 정한다.
3. **자산 분리:** 내부·상면·옆면·모서리와 배경 층을 독립 자산으로 준비한다. 출처·생성 프롬프트·버전을 기록한다.
4. **별도 SS2D 시험:** 직사각형, 긴 플랫폼, 경사, 볼록·오목 모서리, 수직 벽을 한곳에서 비교한다. 연결된 지형은 하나의 SS2D로 유지한다.
5. **색과 재질 확인:** 검정/흰색 짝, 페인트 전후, 충돌 윤곽을 확인한다. 가까운 반사는 공용 작업과 조율한다.
6. **배경 시차 확인:** 카메라의 좌우·상하·끝 위치에서 연결과 분리감을 비교한다.
7. **스테이지 1 일부 적용:** 검토한 재질을 작은 실제 구간에 적용한 뒤 범위를 확대한다. 장애물 디자인은 사용자에게 남긴다.

전달할 결과물: 부위별 자산과 SS2D 재질, 분리 배경 자산과 시차 설정, 편집 가능한 시험 씬, 적용한 스테이지 1 구간, 사용 안내와 변경 기록. 생성 시안·브라우저 미리보기·실제 Godot 캡처를 구분하여 표시한다.

이번 요청은 일반 플랫폼과 배경의 미술 정리이다. 새 맵 제작이나 동선 변경이 필요해지면 사용자에게 시작 위치·도착 위치·진행 방향·전체 맵 형태를 먼저 확인한다.

## 8. 완료 판단 기준

- [ ] 멀리서도 배경과 플랫폼, 검정과 흰색이 구분된다.
- [ ] 길이를 바꿔도 내부 재질의 크기가 일정하며 반복 이음새가 거슬리지 않는다.
- [ ] 상면·옆면·모서리에 빈틈, 과한 중첩, 두꺼운 흰 외곽선이 없다.
- [ ] SS2D 점 편집 후 옆면과 모서리가 함께 갱신된다.
- [ ] 경사와 오목·볼록 모서리에서 형태와 충돌 경계가 어긋나지 않는다.
- [ ] 색칠해도 재질 무늬·실루엣이 튀거나 색 판정과 외형이 어긋나지 않는다.
- [ ] 배경 레이어가 독립되어 있고 이동할 때 연결된 구조물이 분리되지 않는다.
- [ ] 화면 끝과 카메라 확대·축소에서 배경 바깥이 드러나지 않는다.
- [ ] 기존 스테이지 동선·퍼즐·장애물과 다른 담당자의 파일을 보존했다.
- [ ] 실제 확인한 항목과 실행하지 못한 항목을 구분해 기록했다.

현재 파일 참조·영역·알파 등의 정적 확인만 했다. **실제 Godot 렌더링, 모서리 연결 품질, 완전한 반복 연결, 흰색 짝, 근접 반사, 기존 페인트 시스템 통합은 완료되지 않았다.** 시험 씬은 일반 SS2D를 사용하는 외관 관찰용으로, 완성된 플레이 지형 템플릿이 아니다. 스테이지 2의 자산과 공용 코드에 직접 덮어쓰지 말고 스테이지 1 전용 경로와 버전으로 작업한다.

## 10. 저장소 작업 시 주의

- 작업 저장소의 최신 `AGENTS.md`와 `docs/다음작업_프롬프트.md`를 먼저 읽는다.
- 이 PC의 규칙상 사용자에게 명시적으로 요청받기 전에는 Godot 편집기·콘솔·headless·엔진 빌드를 실행하지 않는다. 필요할 때 시험 씬을 먼저 준비한 뒤 실행 확인을 받는다. 이 문서 전달은 엔진 실행 허가가 아니다.
- 기존 씬을 통째로 재생성하는 도구로 수동 편집 내용을 덮어쓰지 않는다. 공유 `.tres` 변경이 다른 스테이지로 전파되는지도 확인한다.
- 코드 변경에는 이유를 한글 주석으로 남기되 `.gdshader` 내부는 한글을 사용하지 않는다.
- 변경 파일과 정적/엔진 검증 여부를 작업 기록에 남긴다. 동기화 실패나 미실행 검사를 성공으로 보고하지 않는다.
