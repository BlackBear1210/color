# 작업기록 2026-09-01 — Godot 안전 실행 확인 · SS2D 배관 설계

## 1. Godot 오류 창

- 사용자 화면의 `Godot_v4.6.3-stable_win64.exe` 접근 위반 오류는, 이 프로젝트의
  Godot 4.6.3 헤드리스 스크립트 실행 경로가 signal 11로 종료될 수 있는 알려진 문제와
  같은 계열이다.
- 실행 중인 `Godot*` 프로세스가 없는 것을 확인했다. 이번 작업에서는 Godot 편집기,
  `--headless`, 빌드 도구를 실행하지 않았다.
- 프로젝트에 이미 있는 `Godot_안전실행.cmd`만 사용한다. 이 실행기는
  `tools/Godot_Safe_Editor.ps1`를 거쳐 공용 ASCII 경로의 콘솔 실행 파일,
  OpenGL 호환 렌더러, 더미 오디오, Windows 오류 대화상자 억제를 적용한다.
- 일반 `Godot_v4.6.3-stable_win64.exe`를 직접 실행하면 이 보호를 거치지 않는다.

## 2. SS2D 배관의 확정 구조

배관은 지형처럼 두꺼운 **닫힌 I자 외곽선**을 늘리는 방식으로 만들지 않는다. 그 방식은
꺾을 때 안쪽/바깥쪽 두께가 찌그러지고, 직각을 추가할 때마다 외곽선 점을 많이 관리해야 한다.

대신 아래처럼 **중심 경로 하나**를 편집하는 장식용 `SS2D_Shape_Open` 배관을 사용한다.

```text
점 0 ───────── 점 1
                 │
                 │
점 3 ───────── 점 2
│
점 4
```

- 첫 그림의 직선 배관은 경로 점 두 개다.
- 둘째 그림처럼 ㄱ자, ㄹ자, 지그재그가 필요하면 중심 경로에 점만 더 찍는다.
- SmartShape2D 재질은 가로/세로 반복 띠와 0~360도 코너 전용 메타를 함께 둔다.
  그래서 점이 90도로 꺾인 자리에 바깥 코너와 안쪽 코너가 생성된다.
- 시작점과 끝점에는 캡(마개) 스프라이트를, 긴 구간에는 필요할 때만 이음쇠 스프라이트를
  별도 배치한다. 이음쇠를 경로의 모든 점에 강제하지 않아도 된다.
- 배경 장식 배관이면 충돌을 만들지 않는다. 실제로 밟는 배관이 필요해질 때에만 충돌을
  별도 노드로 추가한다. 이렇게 해야 장식 배관을 자유롭게 겹쳐 놓을 수 있다.

## 4. 다음 구현 순서

1. 원본에서 SS2D 규격의 가로/세로 반복 띠를 뽑는다.
2. 코너·끝 taper·흰색 짝을 파생하고, `SS2D_Material_Shape` 재질을 만든다.
3. `배관_SS2D.tscn`에 `SS2D_Shape_Open`과 끝 캡 두 개를 넣는다.
4. 테스트 씬에서 직선, ㄱ자, ㄹ자, 지그재그를 먼저 확인한 뒤 실제 하수도에 배치한다.

이 작업은 사용자 안전 규칙에 따라 Godot를 실행하지 않았으므로 엔진 검사는 `미실행`이다.

## 10. 유체 SpriteFrames 적용 (2026-09-01)

- 각 색 후보를 좌우로 서로 다른 위상만큼 흔들어 흰색·회색·검정색 각각 4프레임 루프로 만들었다.
  `animated_v2/fluid_*_frames_v2.tres`는 `흐름` 애니메이션을 8fps로 반복한다.
- `유체.tscn`에 `물_애니메이션`(AnimatedSprite2D)을 추가했다. 물은 색이 바뀔 때 해당
  SpriteFrames를 교체하며, 흰·검 유체가 섞여 회색이 되는 기존 규칙도 끊기지 않는다.
- 유체는 출구가 원점이고 인스턴스마다 길이가 다르므로, 스크립트가 AnimatedSprite2D를
  실제 `크기`와 같은 폭·높이로 자동 배율한다. 켜짐/꺼짐은 부모 Area2D의 visible을 쓰므로
  애니메이션에도 별도 처리 없이 함께 반영된다.
- 연기는 기존 코드 그림 및 디자이너의 `그림` 슬롯을 유지한다. 물 애니메이션이 표시될 때만
  `_draw()`의 코드 물결을 건너뛰어 두 그림이 겹치지 않는다.

## 11. 배관·호퍼·저장고 유체 포트 (2026-09-01)

- `유체.gd`의 `색`은 `물색_` enum으로 바꿨다. 인스펙터에서 흰색·회색·검정색을 이름으로
  고를 수 있고, 값은 기존 `ColorDefs`(검정 0 / 흰색 1 / 회색 2)와 같아 기존 혼합·사망
  규칙을 바꾸지 않는다.
- 호퍼에는 이미 입구 Area2D에 겹친 여러 물을 `유체.섞기()`로 합쳐 출구에 보내는 구현이
  있었다. `출구_유체` 수동 NodePath를 유지하면서, 비워 두면 `출구_포트`에 유체 원점이
  36px 안으로 닿은 물을 자동 출구로 찾게 확장했다. 검정·흰색 물이 동시에 입구에 닿으면
  그 자동 출구 물도 회색이 된다.
- 물저장고도 `공급_유체`를 비웠을 때 상단 `출구_포트`에 닿은 유체를 자동으로 찾아,
  저장고가 칠해진 색을 공급한다. 기존 수동 NodePath는 자동 탐색보다 우선한다.
- SS2D 배관 템플릿 양 끝에 `시작_물_포트`·`끝_물_포트` Marker2D를 추가했다. 편집 화면에서
  이 마커, 호퍼/저장고 출구 마커, 유체 원점을 맞추면 배관 배치와 실제 색 흐름을 같은
  기준점으로 설계할 수 있다. 상세 순서는 `README_유체_포트_연결.md`에 적었다.
- `배관_SS2D_끝마개.gd`가 열린 SS2D 경로의 첫·마지막 점에 끝마개를 자동 배치한다.
  시작점은 첫 선분의 반대 방향, 마지막 점은 마지막 선분의 방향을 바라보므로 수평·수직·ㄱ자·ㄹ자 모두 바깥을 향한다.

## 13. 물 이미지 실루엣 판정 (2026-09-01)

- 기존 유체는 전체 `크기`와 같은 사각형 하나를 충돌 판정으로 썼다. 그래서 가는 물줄기 양옆의 투명한 공간도 파란 판정 범위에 포함됐다.
- 물 애니메이션의 알파 범위를 기준으로 판정을 물줄기(폭 33.2%)·중간 물보라(76.6%)·바닥 물보라(95.3%) 세 구간으로 나눴다. 아래로 갈수록 넓어지는 이미지와 판정이 함께 보인다.
- `물 판정 범위` 인스펙터 그룹의 세 폭 비율은 맵마다 조절할 수 있다. 연기는 기존 사각형 판정을 유지한다.
- 애니메이션의 4프레임마다 달라지는 실제 실루엣 폭도 기록해, 프레임이 바뀔 때 충돌 사각형 폭이 같은 변화량만큼 함께 갱신되게 했다. 인스펙터에서 바꾼 기본 폭은 유지된다.
- 첫 저장본에서는 `@tool` 속성 setter가 씬 자식 노드가 읽히기 전에 같은 이름의 판정 노드를 만들어, tscn에 저장한 노드와 이름 충돌이 났다. 크기·판정 비율 setter는 `is_node_ready()` 뒤에만 모양을 갱신하도록 바꿨고, 유체 템플릿에는 세 CollisionShape2D를 명시적으로 한 번씩만 저장했다.

## 14. 바닥 물보라 충격 애니메이션 (2026-09-01)

- 사용자가 승인한 기존 `animated_v2` 물줄기의 형태·질감·색감은 유지하고, 각 프레임의 아래 29~34%인 바닥 물보라만 `animated_v3`에서 바꿨다.
- 순서는 기본 낙하 → 넓어지는 접촉 → 가장 크게 튀는 충격 → 가라앉는 회복이다. 물줄기 상단은 원본 픽셀과 대조해 0px 변경임을 확인했다.
- 흰색·회색·검정색 12개 프레임과 SpriteFrames 3종을 `animated_v3/`에 저장하고 유체 씬·스크립트를 연결했다. 물보라가 위로 튀는 프레임에서는 충돌 판정의 물보라 시작 높이도 함께 위로 올라가게 했다.
- 물줄기와 새 바닥 물보라가 만나는 줄에서 알파가 즉시 바뀌어 네모난 이음선처럼 보인 문제는, 바닥 물보라 합성 시작 32px에 알파 페더를 적용해 해결했다. 상단 원본 픽셀은 그대로 보존했다.

## 15. 유체 충격 애니메이션 8프레임화 (2026-09-01)

- 사용자가 승인한 `animated_v3`의 4프레임은 짝수 프레임(0·2·4·6)으로 파일 자체를 복사해 그대로 보존했다.
- 그 사이에 약한 접촉·충격 직전·회복 시작·기본 복귀 프레임을 추가한 `animated_v4` 8프레임을 만들었다. 기존 8fps를 유지해 루프가 0.5초에서 1초로 늘어나며, 바닥 물보라의 변화가 더 자연스럽게 읽힌다.
- 유체 씬·스크립트·프레임별 판정 폭/물보라 시작 높이를 모두 8프레임 배열로 갱신했다.

## 16. 물줄기 내부 하강 상세 (2026-09-01)

- 물줄기의 밝은 물방울·하이라이트가 프레임마다 같은 자리에 남아 있어, 바닥 물보라가 움직여도 좌우 흔들림처럼 읽히는 문제가 있었다.
- 기존 `animated_v4` 본체·바닥 물보라를 수정하지 않고, 투명한 `flow_details_v1` AnimatedSprite2D 레이어를 추가했다. 반투명 물방울 네 개는 매 프레임 아래로 이동하고 크기도 미세하게 달라져 낙하 방향을 보여 준다.
- 흰색·회색·검정색 상세 SpriteFrames 3종을 유체 색 enum과 함께 교체하며, 본체와 동일한 크기·원점·8fps로 맞췄다.
