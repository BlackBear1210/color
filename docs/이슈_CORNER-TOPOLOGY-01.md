# 이슈 CORNER-TOPOLOGY-01 — 규칙적인 원본에서 코너 쿼드 경계가 사각형으로 드러남

> 상태: **열림 (수정하지 않음)** · 등록 2026-08-25 · 등록 경로: STEP 2.5-A (BRICK v2 원본 승인)
> ⚠ 이 이슈를 이유로 baker / corner=512 / miter / taper / texture_scale 을 고치지 않는다.
>   세 재질(BRICK v2 · WOOD v2 · IRON v1)의 **원본이 전부 확정된 뒤 별도 STEP** 에서 한꺼번에 다룬다.

---

## 증상

지형 코너를 확대하면 **코너 쿼드가 차지하는 정사각 영역의 경계**가 보인다.
경계선에서 무늬의 위상(phase)과 굵기가 끊긴다.

- BRICK **v1**(무너진 잔해 실루엣): 잘 안 보였다.
- BRICK **v2**(규칙적인 running bond masonry): **명확하게 보인다.**

## 이것은 새 원본의 문제가 아니다

v1 에도 있었고, 불규칙한 잔해가 가려 주고 있었을 뿐이다.
규칙적인 인공 구조물 원본으로 바꾸면서 **가려 주던 것이 사라져 드러난 것**이다.

## 원인 (구조적 · 실측으로 확인된 범위)

코너 텍스처는 AI 로 그리지 않고 **엣지 단면에서 합성**한다
(`tools/생성_타일셋_파생.gd` 의 `_코너합성_miter()`).

- 코너는 TOP 엣지를 **고정 u 오프셋 `U_TOP = 0.31`** 에서,
  SIDE 엣지를 **고정 `U_SIDE = 0.62`** 에서 잘라 온다.
- 반면 인접한 직선 엣지는 SS2D 가 **도형의 실제 길이에 따라** u 를 이어 붙인다.
- 두 u 가 일치할 이유가 없다 → 코너 쿼드 안팎에서 **벽돌 줄눈의 위상이 어긋난다.**

추가로 TOP 과 SIDE 는 u 방향으로 보이는 특징의 주기가 서로 다르다
(TOP = 벽돌 길이 ≈ 51 월드px, SIDE = 켜 높이 ≈ 25.6 월드px).
코너에서 둘을 45도로 섞으므로 코너 안쪽 무늬가 주변보다 **촘촘하게** 읽힌다.
이것 자체는 실제 masonry 코너에서도 일어나는 일이라 오류는 아니지만,
쿼드 경계와 겹치면 "사각 자국" 으로 인지된다.

## 이번에 이미 고친 것과 구분할 것 (혼동 방지)

| 항목 | 상태 |
|---|---|
| 엣지 안쪽 알파 페이드 반전 | **2026-08-25 수정 완료** |
| miter 알파 블렌드 폭(후광) | **`--코너알파폭=0.16` 으로 수정 완료** |
| 코너 u 를 월드 길이로 재도록 수정(512 가로 2배 압축) | **수정 완료** |
| **코너 쿼드 경계의 무늬 위상 불연속** | **← 이 이슈. 미해결** |

## 나중에 검토할 방향 (아직 아무것도 채택하지 않음)

1. 코너의 u 오프셋을 고정값이 아니라 **인접 엣지의 실제 u 에 맞춰** 뽑기
   → SS2D 가 코너 쿼드에 넘겨주는 u 를 읽을 수 있는지부터 확인해야 한다.
2. 원본 단계에서 **코너 전용 단면**을 따로 그려 주기(단, "코너를 AI 로 그리지 않는다" 는 기존 원칙과 충돌).
3. 코너 쿼드 경계에서만 알파를 살짝 페더링해 위상 차이를 흐리기
   → STEP 2 에서 얻은 "실루엣은 좁게 끊는다" 와 상충할 수 있다.
4. 무늬 주기가 코너 크기(월드 89.6px)의 약수가 되도록 원본의 벽돌/판자 치수를 맞추기
   → 원본 설계로 완화 가능한 부분. 가장 싸지만 완전한 해결은 아니다.

## [2026-08-25 추가] STEP 2.6 Controlled Bake 에서 다시 관찰 — 수치화

새 원본(BRICK v2 / WOOD v2)으로 구워 5배 확대 렌더에서 코너 쿼드 경계를 실측했다.
코너 쿼드의 월드 크기는 89.6px 이므로 5배 확대에서 경계는 도형 코너로부터 448px 지점이다.

| | 코너 쿼드 경계의 **톤 단차** | 평활 |기울기| 중앙값 대비 |
|---|---:|---:|
| BRICK v2 | 1.63 / 255 (0.64%) | 13.4배 |
| WOOD v2 | 3.23 / 255 (1.27%) | 34.6배 |

**핵심**: 톤 단차 자체는 1% 안팎으로 작다.
즉 이 현상은 **밝기 차이가 아니라 무늬 위상(phase)이 끊기는 것**이다.
그래서 밝기를 맞추는 방식(페더링·톤 보정)으로는 해결되지 않는다.
v1 의 불규칙한 잔해에서 안 보이던 이유도 같다 — 잔해에는 맞출 위상이 없었다.

비교용으로 같은 렌더에서 잰 **엣지↔필 경계**의 톤 단차는
BRICK 1.13/255(0.44%) · WOOD 1.22/255(0.48%) 로, 코너 경계와 같은 자릿수다.
엣지↔필은 눈에 안 띄는데 코너만 띄는 것이 "위상 문제" 라는 또 하나의 근거다.

→ 해결 방향 후보 1번(코너 u 를 인접 엣지의 실제 u 에 맞추기)이 유일하게
   위상을 직접 건드리는 안이다. 나머지는 증상 완화에 그친다.
