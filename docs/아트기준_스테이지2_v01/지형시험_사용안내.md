# 하수도 지형 · 첫 자산 및 SS2D 시험

2026-09-13. 사용자 확정: 얇은 고정 옆면, 배경과 지형의 명도 분리, 부위별 반복 자산, 배경 시차, 장애물보다 지형 우선.

## 준비한 파일

- `scenes/테스트/하수도_지형_v01/지형_레이어_시험.tscn`: 지형 외관 관찰용. 실제 스테이지 또는 사망·페인트 규칙 시험이 아니다.
- `assets/textures/smartshape/sewer_masonry_v01/brick_fill.png`: 새 반복 벽돌 원본.
- 같은 폴더의 `top.tres`, `side.tres`, `corner.tres`: 상면·옆면·바깥 모서리 각각의 독립 AtlasTexture. `trim_atlas.png`의 필요한 영역만 참조하며 원본 픽셀을 수정하지 않았다.
- `masonry_black.tres`: 약 8px 두께의 SS2D 가장자리, 안쪽 오프셋, 용접 연결. 내부 벽돌은 늘이지 않고 반복한다.
- `assets/background/stage_2/layers_v01/far_wall.png`: 불투명 먼 벽.
- `assets/background/stage_2/layers_v01/mid_arches.png`: 실제 알파가 있는 아치·붙어 있는 배관. 배관 연결을 보존하기 위해 같은 층으로 묶었다.

배경은 이전 시안의 원본 레이어를 복원한 것이 아니라, 그 방향에 맞춰 별도로 새로 생성한 두 자산이다. 먼 벽과 아치의 scroll_scale은 각각 0.25, 0.6. 지형은 일반 월드 좌표에 고정되어 있다.

## 편집 및 관찰

시험 씬에서 `연속_경사_꺾임`, `수직벽_모서리`, `낮은_직사각` 노드를 선택하고 SS2D 점을 편집한다. 연속 플랫폼을 여러 SS2D로 쪼개지 않았다. 내부와 가장자리는 한 지형의 재질 구성이다.

Godot 실행을 사용자가 허용한 뒤 이 씬만 실행하면 WASD로 관찰 카메라를 움직여 시차를 비교할 수 있다. 플레이어 대신 관찰 카메라만 있으며 충돌 노드는 준비되어 있지만 플레이 동작은 검증 대상에 포함되지 않는다.

## 확인 상태와 다음 작업

파일 참조, Atlas 영역, 배경 알파 및 지형 점 구조는 정적 확인했다. Godot 편집기·콘솔·headless는 실행하지 않았다. 따라서 실제 메시 용접, 오목 모서리·경사 연결, 반복 이음새, 화면 확대율과 배경 범위는 엔진에서 확인해야 한다. 생성 텍스처는 완벽한 반복 연결을 보장하지 않으며 첫 시험 자산이다.

원본 상면의 밝은 반사는 시험용 셰이더에서 낮췄다. 플레이어 거리 기반 반사와 흰색 지형 짝, 기존 페인트 셰이더 통합은 아직 적용하지 않았다. 검정 재질의 연결 품질을 먼저 확인한 다음 진행한다. 지금 자산을 실제 스테이지의 `지형.gd`에 무작정 교체하면 기존 흑백 텍스처 매핑과 충돌할 수 있다.

다음 순서: 검정 지형의 실제 렌더링 확인 → 이음새 보완 → 흰색 짝 및 근접 반사 → 기존 맵 한 곳 적용 → 장애물. 기존 stage_2-10, stage_2-11은 변경하지 않았다.

이미지 생성은 기본 내장 ImageGen을 사용했다. 실제 사용한 전체 프롬프트는 `지형자산_생성프롬프트.json`에 보관했다.
