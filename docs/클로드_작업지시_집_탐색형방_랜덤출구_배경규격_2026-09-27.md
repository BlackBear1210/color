# 클로드 작업 지시 — 집을 탐색하는 방·복도·복도계단

2026-09-27 · 도형 요청 정리 / Codex 저장소 대조

## 0. 작업 목표와 현재 인계 상태

**컨셉룸 하나를 스테이지 하나로 취급한다. 플레이어는 방 내부를 좌우·상하로 탐색하고, 생성 시 정해진 출구를 찾아 복도 또는 복도계단으로 이동한다.**
방들을 같은 높이로 가로 나열하는 방식은 취소한다. 배경 그림 한 장의 크기 때문에 플레이 공간을 납작하게 만들지 않는다.
제공된 두 지도에서는 ‘서로 다른 정체성을 가진 공간들이 연결되는 구조’를 참고한다. 지도 윤곽이나 타 게임 이동 능력을 그대로 복사하지 않는다.

- 집-1 `scenes/집/스테이지_1_2층방.tscn`은 Codex가 **a4e4e1a 버전으로 이미 복원**했다. 이 파일의 HEAD blob도 같다.
- 이 버전은 d946b09의 관문 작업에 발판 겹침 수정 등이 더해진 재배치 전 기준이다. 과거 맵이 새 요구를 충족한다는 뜻은 아니다.
- 복원 전 씬과 해시: `artifacts/집탐색_복원_2026-09-27/복원기록.json`. 기존 `.bak.tscn`은 덮어쓰지 않았다.
- 생성기·얇은 발판 재질·배경 시스템·집-2 복도 씬은 보존했다. **전체 reset/revert 금지.**
- 특히 현재 `--설정=방 --적용`은 다시 평평한 방을 덮어쓸 수 있다. 새 방식이 준비되기 전 기존 씬에 적용하지 않는다.
- 이번 인계에서 Godot은 실행하지 않았다. 다른 작업기록에 적힌 엔진 실행 허가는 이번 작업의 허가로 간주하지 말고, 현재 세션의 명시 허가를 확인한다.

## 1. 확인된 원인 / 재사용할 부분

### 원인

1. `tools/생성기/방층.gd`는 바닥y 하나, `층들=[바닥y]`, `통로들=[]`로 구성한다. 시작은 첫 방 왼쪽, 출구는 마지막 방 오른쪽이다. 위로 올라갈 이유가 주 동선에 없다.
2. `tools/생성기/동굴층.gd`의 이전 방식은 상하 공간이 있지만, 출구 선정은 방 중심의 직선거리 비교다. 실제 이동거리·관문 상태를 반영한 랜덤 출구는 아니다.
3. `tools/생성기/조립2.gd`가 만드는 `끝도달_검사점`은 Marker2D다. 이것만 옮겨도 다음 스테이지로 넘어가지는 않는다.
4. `scripts/스마트월드/연결통로.gd`는 역할이 출구면 오른쪽, 입구면 왼쪽으로 향한다고 가정한다. 왼쪽 출구·오른쪽 입구 및 되돌아오기에는 별도 방향/연결 정보가 필요하다.
5. `scripts/스마트월드/집_배경.gd`는 단일 바닥_y에 가구를 맞추고 주로 가로 범위에 배치한다. 상하 탐색을 지원하려면 배경도 구역별 기준 높이를 가져야 한다.

### 재사용

- `규격.gd`: 이동·점프·격자·발판 두께·칠하기 규격의 단일 출처.
- `관문.gd`: J 도약 / C 색바닥 / G 유령다리의 기하·배치 명세. 현재의 가로 띠 배치 정책은 그대로 쓰지 않는다.
- `윤곽.gd`, `형태.gd`, `조립2.gd`: SS2D 변환·형태 검사. 전부 다시 작성하지 않는다.
- `배치.gd`: 발판 겹침 방지·사격 정보·통행 보정. 마지막 통행 보정이 관문을 우회하는 발판을 추가하지 못하도록 계약을 강화한다.
- `계단층.gd`: 내려가는 복도계단에 재사용. 일반 방이나 평평한 복도에 강제로 적용하지 않는다.
- 얇은 발판 재질, 타일셋 진단, 배경 알파/후광 수정: 이번 동선 변경과 별개이므로 보존.
- `챕터.gd`, `연결통로.gd`, `장면전환.gd`: 기존 스테이지 식별/전환 흐름을 확인하고 연결한다. 폐기된 과거 체인 도구를 전제로 작업하지 않는다.

## 2. 세 가지 규모를 분리할 것

### A. 집 전체 연결 그래프

노드는 컨셉룸 또는 연결 스테이지, 간선은 실제 출입구다.

```text
침실 ─ 복도 A ─ 서재
                 │
             복도계단 B
                 │
               응접실 ─ 복도 C ─ 식당
```

이것은 예시다. 처음부터 집 전체 연결까지 무작위화하지 않는다. 첫 구현은 연결 순서를 정해 두고 방 내부·출구 위치만 시드로 바꾼다.
일반 복도는 수평 연결, 복도계단은 높이가 다른 구역 사이를 잇는 하강 중심 공간이다. 계단 출구의 다음 방 입구 높이/방향이 논리적으로 맞아야 한다.

### B. 방 하나의 내부 탐색 그래프

한 컨셉룸 안에 입구, 아래 구역, 위쪽 회랑, 책장 주변, 창가, 갈림길, 출구 후보 등의 탐색 지점을 만든다.
이들은 **별개 컨셉룸/별개 씬이 아니다.** 큰 방 안의 공간 분할이다.
먼저 ‘어디로 갈 수 있고 어떤 행동이 필요한가’를 설계하고, 그 다음 지형 좌표를 배정한다.

- 주 경로: 높이가 다른 구역을 거쳐 출구에 이른다. 단순 우측 이동만으로 완료되지 않는다.
- 갈림길: 둘 이상의 의미 있는 탐색 방향을 만든다. 보상·조망·출구 단서 등 목적 없는 긴 막다른 길을 남발하지 않는다.
- 고리: 왔던 구역으로 돌아오거나 해결 후 열리는 지름길이 있다.
- 방의 정체성: 서재라면 책장 사이/상부 회랑, 침실이라면 침대 주변/높은 창가 등 배치 의미를 가진다. 충돌 지형은 실제 SS2D이고 그림은 시각적 맥락이다.
- 배경의 책장 선반이나 계단을 실제 발판처럼 쓰려면 월드 고정 충돌 지형과 같은 위치에 그린다. 멀리 시차로 움직이는 그림에 충돌을 붙이지 않는다.

### C. 지형과 배경 조립

내부 그래프의 각 이동 간선을 유효한 점프·색 전환·사격 모듈로 바꾼다. 폴리곤 좌표를 독립적으로 뽑아 나중에 연결성을 기도하는 방식은 금지한다.
시드가 바꾸는 것은 허용된 방 유형, 구역 위치, 연결 선택, 관문 위치, 출구 후보, 장식 변형이다. 이동 능력·발판 두께·접합 규격은 고정한다.

## 3. 규모 계약 — 첫 프로토타입 제안, 확정 실측값과 구분

### 유지할 기존 수치

현재 `규격.gd` 기준: 기하 격자 16px, 생성 칸 96px, 몸 44×97px, 점프 높이160/거리320px.
안전 판정선 상승128/가로272px와 **설계 상한 상승112/틈224px를 구분**한다.
발판 두께112px, 권장 폭288~576px, 최소 착지폭192px, 최소 통로높이160px, 치명 낙하1500px.
이 값들은 개별 예산이며 상승112와 틈224를 동시에 허용한다는 뜻은 아니다. 실제 포물선·머리 여유·착지 폭 검증이 필요하다.
발판 두께는 건드리지 않는다. 작은 그림에 맞추기 위해 플레이어·격자·점프를 변경하지 않는다.

### 새 공간 크기 제안

아래는 **플레이 가능한 내부 공간**의 후보이며 외곽 두께를 별도로 더한다. 실제 재미·예산 확인 후 조정한다.

| 유형 | 초기 내부 범위 제안 | 배치 의도 |
|---|---|---|
| 작은 탐색방 | 40×24칸 = 3840×2304px | 한 화면을 넘는 좌우·상하 탐색 |
| 표준 탐색방 | 60×36칸 = 5760×3456px | 3개 이상 높이 구역·갈림길·복귀 고리 |
| 큰 컨셉룸 | 80×48칸 = 7680×4608px | 후속 확장. 첫 실험 대상 아님 |
| 수평 복도 | 폭30~60칸 / 높이8~12칸 | 통과 리듬과 소수 관문, 방보다 낮은 천장 |
| 복도계단 | 연결할 두 입구의 높이차에서 산출 | 일정 디딤 규격·중간 안전 착지·과도한 낙하 방지 |

방을 2만px까지 늘리는 것 자체가 목표가 아니다. 높이 구역 사이 700px를 이동해야 한다면 한 점프로 연결하지 말고 여러 유효한 발판/계단 구간으로 풀어야 한다.

## 4. 랜덤 출구의 정확한 뜻

출구는 플레이 중 계속 바뀌거나 죽을 때 다시 추첨되지 않는다. **새 맵 생성 시 한 번 선택하고, 동일 시드·생성기 버전이면 동일한 위치/연결을 저장한다.**

1. 방 생성 시 출구 후보 소켓을 여러 높이·방향에 예약한다. 바닥·벽·안전 착지와 자연스럽게 연결되는 곳만 후보로 둔다.
2. 유효한 플레이 경로 그래프에서 입구로부터의 이동 비용을 계산한다. 유클리드 거리나 격자 빈칸 BFS만으로 고르지 않는다.
3. 입구 바로 옆, 걸어서만 닿는 곳, 필수 행동을 우회하는 곳, 착지/스폰이 불안전한 곳을 제외한다.
4. 나머지 충분히 먼 후보군에서 시드 난수로 하나 고른다. 항상 가장 오른쪽 또는 가장 먼 한 점을 고르지 않는다. 초기 제안은 이동 비용 상위 30% 후보군이다.
5. 후보가 없는 시드는 제한 횟수만 재시도하고 명확히 실패 처리한다. 오른쪽 끝으로 몰래 대체하지 않는다.
6. 선정한 소켓으로 실제 `연결통로`/전환 노드를 만들고 목적 씬·진입점 ID·방향·스폰 안전 색을 함께 저장한다.
7. 상층 출구도 문이 될 수 있다. 바닥/천장 출구라면 별도 하강·계단 연결 모듈을 통해 잇는다. 기존 수평 통로를 무조건 90도 회전해서 해결하지 않는다.
8. 되돌아갈 수 있는 연결은 양쪽 소켓을 쌍으로 저장하고, 즉시 재전환·벽 속 스폰·반대색 접촉사를 막는다. 의도한 일방 하강은 명시한다.

무작위 출구가 방 전체 방문을 보장하는 것은 아니다. 위층의 문 실루엣, 창가의 구조 변화처럼 공간 안의 단서를 주어 ‘놓친 곳을 찾아보는 탐색’이 되게 한다. 모든 구석 방문을 의무로 만들지는 않는다.

## 5. 관문과 고리를 함께 성립시키기

기존 J/C/G는 유지한다. **관문 개수만 세어서는 통과 판정하지 않는다.**

- J: 점프가 필요한 연결. 구덩이를 다른 발판으로 덮는 통행 보정 금지.
- C: 색 전환 **또는** 지형 칠하기로 푸는 연결. C 하나로 두 행동 모두 필수라고 주장하지 않는다.
- G: 칠하기 전엔 건널 수 없는 유령 경로. 안전한 사격 지점·탄도·필요 발수·탄약 정책을 실제 규칙으로 검증한다.
- 복귀 고리는 관문 앞쪽 구역 안에 놓거나, 관문을 해결한 뒤에 열리는 지름길로 둔다. 해결 전부터 관문 반대편으로 통하는 고리가 있으면 그 관문은 필수가 아니다.
- 진행을 강제하는 관문과 선택 보상 관문을 구분한다. 모든 가지에 모든 행동을 억지로 넣지 않는다.
- 체크포인트는 관문의 ‘왼쪽’이 아니라 해당 접근 방향의 안전 지점에 둔다. 양방향 접근·위에서 내려오는 접근도 고려한다.
- 체크포인트 솎기와 광원 수 제한 때문에 필수 재시도 지점이 사라지지 않게 한다. 체크포인트 기능과 장식 광원의 예산을 구분한다.

필수 검사: 시작 상태에서 점프 행동을 막으면 출구에 도달하지 못하는가? 칠하기 행동을 막으면 G 필수 구간을 넘지 못하는가? 색 전환과 칠하기를 모두 막으면 C가 막히는가?
가능 상태에서는 출구에 도달해야 한다. 관문을 배치한 뒤 **최종 폴리곤/발판을 반영한 경로**에 대해 다시 검사한다.

## 6. 생성 파이프라인과 데이터 계약

```text
컨셉/방 크기/시드
 → 내부 탐색 그래프(주 경로·분기·고리·행동 조건)
 → 건축 구역 배치(직교 벽·상부 회랑·출구 소켓 예약)
 → 이동 간선마다 지형/관문 모듈 배치
 → 몸 크기·점프 궤적·색/칠 상태·사격 가능성 검증
 → 도달 가능한 출구 후보 중 하나 선택
 → 실제 전환 노드와 다음 스테이지 진입점 연결
 → SS2D 조립·겹침/형태/소프트락 검사
 → 같은 구역/소켓 정보로 배경 배치
 → 시드별 지도·검사 근거·출구 위치 보고
```

제안 데이터(새로 만들 계약이지 기존 구현이라고 가정하지 말 것):

```text
RoomSpec: id, concept, bounds, seed, generator_version, movement_profile
Zones: id, bounds, elevation, theme_slots
TraversalEdges: from, to, direction, action_alternatives, landing, safe_shot_anchor
Ports: id, position, orientation, landing_rect, target_stage, target_port
Gates: id, type, protected_region, required_for_progress, retry_anchor
BackgroundSlots: zone_id, layer, rect, anchor, variant, seam_family
```

기존 Dictionary 소비자를 확인하고 어댑터로 연결한다. `층들/바닥줄`을 가진다고 새 2차원 경로가 자동 검증되는 것은 아니다.
난수는 지형·출구·장식 스트림을 분리한다. 배경 변형 하나를 추가했다고 출구가 바뀌면 안 된다.
시드뿐 아니라 생성기 버전·설정·선택 출구를 저장한다. 사망/재진입 시 동일 구성과 필요한 퍼즐 상태를 복원한다.

## 7. 배경은 상하 탐색에 맞춰 조립할 것

**바탕 반복과 방 구조 반복을 구분한다.** 벽 질감의 반복은 가능하지만 창·바닥·천장까지 들어 있는 완성 방을 상하로 복사하지 않는다.

| 층 | 담을 것 | 연결 방식 |
|---|---|---|
| L1 먼 바탕 | 초점 없는 벽/어둠/옅은 대기 | 양축 반복 가능한 바탕 또는 유한한 큰 패치 |
| L2 먼 건축 | 창·벽 베이·기둥 사이·먼 출입구 | 방 구역별 비반복 랜드마크 + 호환 베이 |
| L3 중경 소품 | 책장·커튼·가구 | 구역별 높이 앵커에서 배치. 물리 발판과 연결되는 것은 월드 고정 |
| L4 전경 | 가까운 기둥·문틀·장막 | 시야를 과도하게 막지 않는 앞쪽 조각, 충분한 화면 밖 여유 |

건축 배경은 최소 ‘하단 받침/중간 벽/상단 마감/모서리’를 나눈다. 수직 확장은 **중간 벽만** 반복하고, 바닥·천장 마감은 실제 경계에 한 번만 둔다.
복도계단은 각 계단참·벽 구역에 맞춰 배경 구간을 내려 배치한다. 평평한 복도 그림 전체를 사선으로 기울이거나 아래로 무한 복사하지 않는다.

### 이미지 주문 규격

- 이미지 가로/세로 숫자를 월드 전체 크기로 취급하지 않는다. 텍스처 해상도와 월드 배치 크기를 분리해 기록한다.
- 첫 베이의 월드 폭은 제안값 8칸=768px. 세부 베이 높이·앵커는 구역별 계약에 정의하고 같은 접합 계열에서 고정한다.
- 반복 가능한 것은 방향(X/Y/XY), 좌우·상하 경계 프로필, 몰딩 높이, alpha 방식, 월드 배율을 명세한다.
- A/B/C 변형은 가장자리가 서로 호환되어야 한다. 내부 무늬만 바꾼다. 모든 A→B, B→C, C→A 및 역순 접합을 검사한다. 한 장의 A→A 반복만 통과시키지 않는다.
- 직교 벽/바닥에 맞물리는 건축은 같은 변환을 공유해야 한다. 서로 다른 시차층에 붙은 몰딩이 이동 중 벌어지게 만들지 않는다.
- 다른 시차층 사이의 경계는 실제 접합선으로 의존하지 않는다. 뒤를 충분히 그려 두고 가림/대기감으로 깊이를 만든다.
- 창과 그 창의 커튼은 함께 움직인다. 게임 규칙상 밟을 수 있는 굳은 빛·실제 출입문은 월드 좌표에 고정하고 장식 창과 역할을 구분한다.
- 원본 alpha 검사와 흰/검정/체커 바탕 합성에서 후광을 검사한다. 검정 바탕을 투명으로 착각하지 않는다.

### 이동 중 빈틈 검증

축별로 카메라 이동 범위 D, 해당 층의 이동비율 s, 최소 줌에서 월드 화면 크기 V, 여유 M을 계산한다.
단순 평행이동 시 필요한 커버리지의 1차 추정은 **V + |s|·D + 2M**이다. 이미지를 이 길이로 무조건 늘리는 공식이 아니라, 반복 타일/조각을 배치할 범위 산출용이다.
앵커 오프셋·다른 카메라 변환을 포함한 최종 값은 실제 카메라/Parallax2D 변환으로 구한다.
좌/우/상/하 끝과 네 모서리, 최소 줌, 전환 줌을 모두 검사한다. 전경도 별도 계산하며 ‘전경이라 여유 필요 없음’으로 넘기지 않는다.
단색 배경판은 최후의 바탕일 뿐, 조각 사이 직선 이음매가 사라졌다는 증거가 아니다.

## 8. 구현 순서 — 이번에는 지형 검증이 먼저

1. 현재 미커밋 변경 목록을 읽고 이번 작업 범위를 기록한다. 집-1은 이미 복원됐으므로 재복원하지 않는다. 생성 결과는 새 경로에 출력한다.
2. 작은 탐색방 1개를 대상으로, seed 1~10의 내부 그래프·출구 후보·J/C/G 위치를 표시한 미리보기와 실패 이유를 만든다. 배경은 임시 단색만 사용해도 된다.
3. 실제 이동/상태 검증을 붙인다. 점프·색·칠하기를 제거한 대조 검사로 우회 경로를 확인한다. 실패한 씨앗을 숨기거나 조건을 느슨하게 바꾸지 않는다.
4. 방 A → 수평 복도 → 방 B의 실제 출입을 완성한다. 그 다음 방 B → 복도계단 → 방 C를 추가한다. 역할·방향·스폰·재진입을 검증한다.
5. 같은 구역 정보에 배경을 조립하고 상하좌우 카메라에서 경계가 드러나는지 확인한다. 배경 때문에 탐색 그래프를 삭제하지 않는다.
6. 아래 완료 조건과 변경 전후 지도를 제출한다. 기존 씬에 적용하는 단계와 생성기 구현을 분리한다.

Godot 명시 허가가 없는 세션에서는 엔진·headless·씬 굽기·검사 도구를 실행하지 않는다. 정적 구현·검토까지 진행하고 엔진 검사는 미실행으로 보고한다. 과거 기록의 통과 수치를 새 결과로 옮겨 적지 않는다.
