## 2. 물체 약속 (같은 이름의 함수를 만들면 엔진 쪽이 알아서 부른다)

GDScript 는 부모를 하나만 둘 수 있고, 이 물체들은 Area2D · StaticBody2D · CharacterBody2D · SS2D 지형처럼 **엔진 기본형이 서로 달라
공통 부모로 묶을 수 없다.** 대신 **같은 이름·같은 모양의 함수**를 약속으로 쓴다. 부르는 쪽은 `has_method("이름")` 으로 확인한다.
→ 각 파일의 구현이 서로 다른 건 복사가 아니라 **물체마다 "내 상태" 가 달라서**다. 하나로 합치지 말 것(10-14 검토 결론).

| 약속 | 모양 | 누가 부르나 | 뜻 | 지금 구현(F5) |
|---|---|---|---|---|
| **반대색인가** | `func 반대색인가(플레이어색: int) -> bool` | `월드.gd` 사망 판정(`_반대색_대상_찾기` 가 충돌체에서 부모로 올라가며 이 함수를 가진 첫 노드를 찾는다) | 이 색 플레이어가 닿으면 죽나. 판정은 되도록 `색규칙.위험한가` 에 맡긴다 | 물저장고 · 박스 · 식물_b · 양동이 · 움직이는발판 · 웅덩이 · 유체 · 지형 · 통과플랫폼 · 호퍼 · 순찰몬스터 · 반사빛길 |
| 위치_반대색인가 | `(플레이어색: int, 월드점들: PackedVector2Array) -> bool` | 월드.gd (있으면 반대색인가보다 먼저) | 닿은 **자리**의 색으로 판정(부분 칠한 큰 지형) | 지형 |
| **현재색** | `func 현재색() -> int` | 웅덩이·유체(물이 덮을 때) · 목재잠금 등 | 지금 색. 안 칠했으면 −1 | 반대색인가 와 거의 같은 목록 + 반딧불몹 |
| **명중** | `func 명중(색: int, 월드좌표: Vector2) -> String` | 총 · 총알 · 페인트_코어 | 페인트를 맞았을 때. 돌려줌 `"painted"` 다 칠함 · `"progress"` 일부 · `"wasted"` 같은 색 덧칠 · `"blocked"` 못 칠함 | 16 파일 |
| **되돌리기** | `func 되돌리기() -> bool` | E 회수 · 웅덩이/유체가 덮을 때 | 내가 칠한 색을 지운다. 지울 게 없으면 false | 13 파일 |
| **강제_초기화** | `func 강제_초기화() -> void` | 페인트_코어(부활할 때) | 부활하면 처음 상태로(부서진 발판 복구 등) | SS2D_붕괴발판 · 움직이는발판 · 지형 · 통과플랫폼 · 하수도_붕괴발판 · 순찰몬스터 |
| 총알_막나 | `(총알색: int) -> bool` | 총알 | 켜진 반대색 물만 막는다(꺼진 물은 아무것도 아니다 — 맵제작_공통규칙 §6) | 웅덩이 · 유체 · 순찰몬스터 |
| 물에_안지워짐 | `() -> bool` | 웅덩이 · 유체 | 물이 덮어도 색이 안 지워지는 것(격자) | 움직이는발판 · 통과플랫폼 |
| 칠_가능_미리보기 | `(색: int) -> bool` | 총(조준 X 표시) | 지금 쏘면 칠해지나 | 지형 · 순찰몬스터 · 반딧불몹 |

**새 물체를 만들 때**
- 플레이어를 죽일 수 있으면 `반대색인가` + `현재색`. 판정은 `색규칙.위험한가`.
- 칠해지면 `명중` + `되돌리기`(+ 부활 때 원래대로 돌아가야 하면 `강제_초기화`).
- **절대 안 죽이는 물체도** 충돌체가 있고 그 부모가 색 물체면 `반대색인가 → false` 를 둔다(박스·호퍼처럼) —
  안 그러면 `_반대색_대상_찾기` 가 부모로 올라가 엉뚱한 물체의 색으로 판정한다.
- 상속(`extends "부모.gd"`)으로 부모 변수를 쓰면 부모가 바뀔 때 조용히 깨진다(10-10 `통과플랫폼._상태색` 이 없어져 `stage_2_10_반환격자.gd` 파싱 오류).
  부모가 가진 **함수**(약속)를 쓰고, 부모의 `_` 로 시작하는 변수는 쓰지 말 것.

## 3. 그 밖의 규칙 (CLAUDE.md 와 같은 것 · 여기 모아 둠)

- `월드.gd` 의 밑줄 이름(`_사망_판정` · `_리스폰` · `_카메라` …)은 **시험·촬영 도구 약 45 개와 상속 스크립트가 직접 부른다** —
  이름을 바꾸거나 다른 파일로 옮기지 말 것(목록은 월드.gd 머리말). 화면 조립(HUD·메뉴)만 `월드_화면조립.gd` 로 나뉘어 있다.
- `지형.gd` 도 같다 — 자식 5(+손자 1)가 `_셰이더_설치`·`_셰이더_만들기`·`_짝_찾기`·`_충돌레이어_갱신` 을 덮어쓰고,
  시험 도구가 `_시드`·`_목표`·`_셰이더들` 등을 직접 만진다(목록은 지형.gd 머리말). 구역들이 같은 상태를 같이 만져서 나누지 않았다.

- 매 프레임 함수(`_process`·`_physics_process`)에서 같은 값을 다시 넣지 않는다(position · 셰이더 값 — 9-30 프레임 드랍 원인).
- **화면 밖에서 `queue_redraw()` 하지 않는다**(10-15 프레임 방어). Godot 은 안 보이는 CanvasItem 도 `_draw` 를 다시 돌려 그림 명령을
  새로 만든다 — 2-3 호퍼 입구 15 개가 그래서 p99 16 ms(60 FPS 한계)에 붙어 있었다. 본보기: `호퍼_입구수면.gd` `_화면에_보이나()` —
  시간은 계속 흐르게 두고 그리기만 건너뛰며, 화면에 들어오는 프레임에 바로 다시 그린다.
- 프레임은 `python -X utf8 tools/전후비교/전후비교.py 비교 --단계=프레임` 으로 본다(30 스테이지 · 16.7 ms 초과 수 · 스테이지마다 18 ms 초과 2 개부터 실패).
  전환 직후는 `tools/측정_전환_첫방문.gd` (창 모드 · 출발 씬 → 도착 씬 · 밝아진 뒤 3 초).
  ⚠ 이 PC(창 모드 · OpenGL)에서는 VSync 를 켜면 오히려 놓치는 프레임이 4~5 배 늘었다 — 프로젝트 VSync 끔 유지.
- **화면을 그래픽 칩에서 읽는 일(`get_texture().get_image()`)은 플레이 중에 하지 않는다** — 한 번에 12~17 ms 멈춘다.
  스테이지 전환의 까만 동안에 몰아서 한다: `화면준비.암전_중()`(장면전환·전경전환이 부른다 · 첫 방문 그림 준비도 여기서).
- `@tool` 스크립트의 에디터 다시 그리기는 `에디터_다시그리기.서명` 으로 바뀌었을 때만.
- 셰이더(.gdshader) 안에 한글 금지 · `TIME` 금지.
- 읽어 온 씬의 노드에 owner 를 다시 박지 않는다(세그폴트).
