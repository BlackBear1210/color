# 2-2 흑백 벽돌 맞물림

대상: `res://scenes/world_2_클로드/stage_2-2.tscn`.
다른 `world_2`의 동명 씬은 수정하지 않았다. 시작 위치와 장치 배치는 유지했다.

## 적용 위치

- 가로: `지형/좌상_덩어리` ↔ `지형/탑_왼벽`. 원래 경계 x=0..768, y=1856.
- 세로: `지형/좌하_채움` ↔ `지형/탑_바닥`. 원래 경계 x=768, y=3584..4352. 끝 접점은 보존하고 가운데 y 약 3670..4110에 맞물림을 넣었다.
- 플레이어 시작점은 (2560,3584)로 그대로다. 위 접합부는 시작 화면 바로 옆이 아니다. 편집기에서 해당 노드를 선택하고 F로 확인한다.

## 구현

벽돌별 노드를 추가하지 않았다. 4개 기존 SS2D의 공유 경계 점을 상보적으로 바꾸고, 같은 점으로 CollisionPolygon2D 저장값도 맞췄다. 가로/세로 모두 양방향으로 불규칙하게 침범한다. 접합부 양끝과 두 지형의 합집합 외곽은 유지된다.

흑백 fill.png의 줄눈 위치를 직접 읽어 측정한 표에 따라 경계선을 만든다. 가로는 1~2개 벽돌 줄 높이, 세로는 약 반 장~두 장 너비로 바뀐다. 원본 그림의 벽돌 너비가 일정하지 않아 고정 px 격자를 쓰지 않는다. 가로 경계가 높이를 바꿀 때도 각 줄의 세로 줄눈을 따라 작은 단차로 연결한다.

2-2의 벽체 참조를 기존 TEMPLATE_WALL_SOLID 대신 하수도_기본지형_검정/흰색으로 바꿨다. 공통 재질과 stage_2-1은 이번 작업에서 수정하지 않았다. 새 맞물림_black/white.tres는 기존 땅 재질의 별도 복사본이며, fill_texture_absolute_position=true, scale=.18, offset=(0,1792.1)을 공유한다. 흑백 텍스처는 같은 그림의 색상 짝이라 이 설정으로 줄눈이 이어진다.

지형을 늘릴 때는 Scale을 바꾸지 않고 SS2D 점을 편집한다. 맞물린 쪽의 점만 단독으로 옮기면 틈/겹침이 생긴다. 양쪽 공통 경계를 함께 편집해야 한다. 이 도구는 범용 자동 편집기 기능이 아니며 두 위치 전용이다.

## 색칠 보존

- 기존 하수도_자연발판 → 하수도_벽돌지형 → 지형 상속과 흑백 페인트 셰이더를 유지했다.
- 명중/회수/위치별 색 판정 함수는 수정하지 않았다. 그림을 덧붙이지 않고 실제 각 색의 영역을 바꿨으므로 물감도 해당 SS2D 영역 안에서 그려진다.
- `위치별_판정=true`, 기본 흑백 시작상태, 기존 칠하기 방식 유지.
- `L3_유령발판`은 새 검정 프리팹의 시작상태=1을 상속하지 않도록 명시적으로 0을 저장했다. 기존 무색 통과 상태 보존 목적이다.
- 공유선의 내부 윗면/옆면은 기존 이웃 다각형 가림 로직으로 제외한다. 실제 선분은 42/40/44/46개로 64개 제한 안이며, 이웃 커버도 256개 안이다.

## 검증 결과와 한계

실행한 것: `tools/test_stage22_masonry_joint.py`.
실제 저장된 씬에서 공유선 양쪽 1,092개 지점의 중복/빈틈 없음, 원래 합집합 포함, 양쪽 동일 공유선, 자기 교차, 모든 지형의 저장 충돌 일치, 색칠 플래그, 유령 초기상태, 재질 UV, 리소스 참조, 마감 배열 한도를 검사했고 통과했다.

Godot 편집기/게임/headless는 실행하지 않았다. AGENTS.md의 사용자 안전 예외를 따랐다. 따라서 화면 품질, 셰이더 컴파일, 총알 물리 충돌, 연결 페인트 확산, 실제 플레이어 사망은 아직 실행 검증 완료라고 말할 수 없다.

실행 허가 후:

1. `tools/test_stage22_joint_paint.gd`: 저장 씬에서 실제 4개 지형을 꺼내 경계마다 코어 명중 → 위치 색 판정 → 수동 회수 → 탄약/원래색 복구 검사. 실제 투사체 비행/플레이어 몸 충돌 검사는 이 파일에 포함하지 않는다.
2. 기존 `tools/test_하수도_벽돌_색칠사망.gd` 회귀 검사.
3. 실제 2-2에서 두 접합부의 내부 마감 띠가 없는지, 흑백 줄눈이 같은지 확대 확인. 총알이 벽에 닿아 번지는 색과 몸 접촉 사망을 양쪽 플레이어 색으로 확인. 경계 인근의 연결 페인트와 회수도 확인.
4. 맵 저장/재로드 후 점/충돌/UV 유지, 디버거 새 오류 없음 확인.

## 도구 관리

`tools/apply_stage22_masonry_joint.py`는 기본 dry-run이며 `--apply`에만 저장한다. 이미 적용된 씬에는 재기록하지 않으며 전체 맵 빌더를 실행하지 않는다. 도구를 새 맵용으로 재사용할 때는 좌표/줄눈 표/원래 윤곽을 먼저 검토해야 한다. 적용 이후에는 `tools/test_stage22_masonry_joint.py`로 저장 결과를 검사한다.
