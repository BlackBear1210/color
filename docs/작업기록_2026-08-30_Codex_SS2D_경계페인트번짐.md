# 작업기록 2026-08-30 · Codex — 2층방 SS2D 경계 페인트 번짐

> 목표: `스테이지_1_2층방.tscn`에서만 서로 맞닿은 BRICK·WOOD SS2D의 페인트가
> 끊기지 않게 하고, 큰 벽돌의 뾰족한 번짐 경계를 매끈하게 만든다.

---

## 문제와 원인

일반 스마트지형은 페인트 시드를 각 SS2D의 로컬 좌표 배열에 따로 보관한다. 벽돌 안에서
시작한 완료 번짐은 벽돌 셰이더 안에서만 커지므로, 나중에 나무 외곽에 도착해도 나무에는
같은 시드가 없어서 경계에서 잘렸다.

빨간 원으로 지적된 검은 못 모양은 `blob_wobble = 0.14`가 얼룩 반지름에 비례해
경계를 흔들기 때문에 생겼다. 폭 5,000px가 넘는 바닥에서는 흔들림도 수백 px가 되어
작은 물결이 아니라 길고 뾰족한 홈으로 보였다.

---

## 최종 적용 — 2층방 전용

`스테이지_1_2층방.tscn`에만 `2층방_연결페인트` 노드를 추가했다. 이 노드가 없으면
새 동작은 전혀 실행되지 않는다. 공용 `총알.gd`·`지형.gd`는 원본과 동일하므로 다른
스테이지의 페인트 화면과 규칙은 바뀌지 않는다.

전용 관리자는 다음처럼 동작한다.

1. 시작할 때 2층방 `지형` 아래의 칠하기 가능한 SS2D 외곽을 비교한다.
2. 두 외곽 사이가 10px 이내이면 같은 접촉면 묶음으로 연결한다.
3. 같은 묶음의 실제 페인트 시드 위치·현재 반지름·색·흐름을 월드 좌표로 변환해
   매 프레임 공유한다.
4. 각 SS2D는 자기 나무·벽돌 텍스처를 계속 사용하고 페인트 마스크만 공유한다.
5. 공중에 떨어진 SS2D는 다른 묶음이므로 페인트가 허공을 건너뛰지 않는다.

직접 맞은 SS2D만 필요 명중 횟수와 탄약 규칙을 처리한다. 연결면은 같은 전선을
표현하지만 한 발이 여러 지형의 탄약·완료 횟수를 복제하지 않는다.

---

## 한 발 면적 통일과 필요 명중 횟수

2층방의 부분칠은 출발한 SS2D의 전체 크기나 스케일과 무관하게 월드 기준 반지름
`160px`을 쓴다. 평균 면적은 `PI × 160² ≈ 80,425px²`이고, 각 탄의 결정적 오차는
**면적 기준 80~120%**다. 원의 면적은 반지름의 제곱에 비례하므로 반지름에 ±20%를
직접 더하지 않고 `160 × sqrt(면적계수)`로 계산했다. 따라서 면적 오차가 요청 범위를
넘지 않는다.

필요 명중 횟수는 가장 작은 허용 탄흔(기준 면적의 80%)만 연속으로 나와도 부족하지
않도록 다음처럼 보수적으로 계산한다.

```text
필요 횟수 = ceil(SS2D 실면적 / (PI × 160² × 0.8))
```

현재 2층방 실측 결과:

| SS2D | 실면적(px²) | 필요 횟수 |
|---|---:|---:|
| 바닥_STAGE1_BRICK_01 | 4,370,877 | 68발 |
| SS_WOOD_BED_DESK_01 | 403,200 | 7발 |
| SS_WOOD_GHOST_01 | 114,000 | 2발 |
| SS_WOOD_SHELF_B_01 | 116,863 | 2발 |
| 나머지 작은 WOOD 4개 | 49,600~80,600 | 1~2발 |

따라서 탄창을 나중에 6~10발로 정해도 큰 나무는 칠할 수 있지만, 거대한 바닥은 의도대로
한 탄창으로 전부 칠할 수 없다. 탄창 수 자체는 아직 코드에 고정하지 않았다. 플레이 테스트
후 `기준_월드반지름` 하나를 바꾸면 모든 지형의 필요 횟수도 같은 공식으로 다시 계산된다.

## 2층방 전용 물결 보정

전용 관리자가 처리하는 2층방의 칠하기 가능한 SS2D에는 런타임에만 다음 값을 적용한다.

```text
blob_wobble       0.0   (반지름 비례 큰 돌출 제거)
noise_amount      1.5px (작은 잔물결만 유지)
edge_soft         3.0px (부드러운 경계)
drip_width        0.18  (아래로 흐르는 가닥)
```

따라서 기존의 가늘고 긴 검은 돌출부가 사라지고, 벽돌과 나무를 같은 매끈한 곡선이
통과한다. 이 값도 전용 노드가 없는 다른 스테이지에는 적용되지 않는다.

## Git 상태 메모

원격 `dev_4`의 새 커밋도 사용자가 수정한 `스테이지_1_2층방.tscn`을 변경하고 있어서
`git pull`은 덮어쓰기 방지로 중단된 상태다. 해당 씬을 stash·병합하지 않았고 기존
사용자 변경 위에 전용 노드 부분만 작게 추가했다. 현재 로컬은 원격보다 1커밋 뒤다.
