## 2. 진짜 원인 — `SS_WOOD_FURNITURE_01` 의 점 두 개가 뒤바뀌어 있었다

`스테이지_1_2층방.tscn` 은 **커밋 안 된 작업트리 수정본**이었고,
그 안에서 가구 덩어리(25 점)의 **0 번 점과 20 번 점 값이 서로 바뀌어** 있었다.

```
           커밋본(정상)        작업트리(깨짐)
 0 번   (-1515,  35)   →     ( 1215, -75)
20 번   ( 1365,  35)   →     (-1515,  35)
```

계단 모양으로 왼→오른쪽으로 흘러야 할 다각형이
중간에 왼쪽 끝으로 튀었다 돌아오면서 **자기 자신을 관통**한다.
SS2D 는 이걸 삼각분할하지 못한다.

```
ERROR: 'SS_WOOD_FURNITURE_01': Couldn't Triangulate shape
   [0] _build_fill_mesh (addons/rmsmartshape/shapes/shape.gd:873)
```

→ **채움(fill) 메시가 아예 안 구워지고 테두리 메시 1 장만 남는다.**
방 폭의 절반을 차지하는 3030×590 짜리 가구가 **속 빈 윤곽선**으로만 보인다.
"지형이 안 보인다" 의 정체가 이것이다.

### 숫자로 확인 (`tools/진단_지형메시.gd`)

```
              고치기 전            고친 뒤
메시 수         1                    2      (fill + edge)
콜리전 점      25 (자기관통)         24
메시 실크기   3050×590 (좌측 20px 삐져나감)   3030×590
```

### 고친 방법

`.tscn` 의 `Resource_neqkp` · `Resource_grrsy` 두 `position` 을 커밋본 값으로 되돌렸다.
지형 자체·재질·템플릿은 손대지 않았다.

### 고친 뒤 검증

- `진단_지형메시` — 지형 14 개 전부 메시 2 장 · 오류 0

## 3. 왜 뒤바뀌었나 (추정)

SS2D 는 `@tool` 이라 씬을 여는 것만으로 점 배열을 다시 쓴다.
에디터에서 가구 점 하나를 아주 살짝 끌었을 때
`_point_order` 는 그대로인데 두 점의 값만 서로 자리를 바꾸면 이 모양이 된다.
**같은 사고를 다시 겪으면 `진단_지형메시` 의 "메시 수" 열을 먼저 볼 것.**
`2` 가 아니라 `1` 이면 그 지형은 삼각분할에 실패한 것이다.

## 8. ★★공중 발판을 못 쓴다 (레벨검사가 실측으로 잡아냈다)

처음에는 v3 처럼 좌우 지그재그하는 공중 발판을 놓았다. **9 개가 "도달 불가" 로 잡혔다.**

```
같은 세로줄에서 두 칸(220) 위에 두께 160 발판을 놓으면
  위 발판 실효 아랫면 = 윗면 + 160 − 24 = 윗면 + 136
  아래 발판 실효 윗면 = 윗면 + 220 + 24 = 윗면 + 244  →  틈 60
지나다니려면 키 96 + 콜리전 48 = 144 가 필요하다.  60 ≪ 144
→ 아래 발판이 밟을 수 없는 면이 된다.
```

Z1 은 폭 920 이라 발판 자리가 좌·우 두 줄뿐이고, 두 줄로 지그재그하면 같은 줄이
반드시 두 칸 간격으로 겹친다. **좁은 방에서는 지그재그가 성립하지 않는다.**

더 근본적으로, 바닥(y 0) 아래로 지나가려면 발판 윗면이 −(144+24+160) = **−328** 보다
높아야 하는데, 거기까지 오르려면 110 짜리 계단 세 칸이 필요하고 그 세 칸이 또 겹친다.

→ **전부 바닥에 뿌리내린 계단 덩어리로 짓는다.** 겹칠 일이 없고, 어디서 떨어져도
바닥이며 계단 옆면(110)으로 다시 오른다. 원화의 가구가 원래 바닥에 놓인 것들이라 그림과도 맞는다.

⚠ 유령 발판(칠해야 생기는 발판)은 층고 1062 안에서 놓을 높이가 안 나온다 → **STAGE 2 로 미뤘다.**
