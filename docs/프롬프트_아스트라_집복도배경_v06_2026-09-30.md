# §0. 한 문단 요약

복도를 걸을 때 **"긴 복도 안을 걸어간다"** 는 원근감을 만들고 싶다.
그래서 복도 배경을 **벽지 · 징두리(아래 판벽) · 몰딩 · 천장 · 바닥 · 벽 소품 · 중경 기둥 · 전경 들보**
여덟 종류의 레이어로 나눠 받는다. 게임은 이것을 **서로 다른 속도로** 흘려서 깊이를 만든다.
이번 주문에서 가장 중요한 것은 **천장과 바닥을 "펼친 평면도"로 그리는 것**이다(§2).
원근을 그림에 그려 넣으면 안 된다 — 원근은 게임이 움직임으로 만든다.

당신은 그림만 그린다. 씬(.tscn)·스크립트 수정, Godot 실행, 커밋/푸시는 **하지 않는다.** 내가(Claude) 한다.

# §1. 이 복도가 게임에서 어떻게 생겼나 (실측)

대상 스테이지: `scenes/집/스테이지_2_복도.tscn`

| 값 | 월드 px | 뜻 |
|---|---:|---|
| 스테이지 크기 | 19,200 × 1,728 | 가로로 길쭉한 직사각형 하나. **바닥이 평평하다** |
| 복도 길이(걷는 구간) | 672 ~ 18,432 | 약 17,760 px = 화면 9 장 반 |
| 바닥 윗면 | y = −96 | 지형(검정/흰 SS2D)이 이 선부터 아래를 덮는다 |
| 천장(지형) | y = −1,152 | 바닥에서 **1,056 px** 위 = 사람 키의 11 배 |
| 플레이어 | 44 × **96** | 화면 높이(1,080)의 8.9 % |
| 화면 | 1,920 × 1,080 | 카메라는 발밑보다 60 px 위를 본다 |

플레이어가 바닥에 서 있을 때 화면에는 **바닥 위 약 600 px · 바닥 아래 약 480 px** 가 보인다.
화면 아래 약 40 % 는 지형(바닥)이 덮는다. **배경이 보이는 곳은 화면 위 60 %** 다.

방(집-1)과 복도의 대비가 이 챕터의 리듬이다.
**방 = 높고 넓고 창빛이 든다 · 복도 = 낮고 길고 어둡다.** 복도를 방처럼 화려하게 그리면 이 대비가 사라진다.

# §2. ★★원근감을 만드는 방식 — 이걸 이해하지 못하면 전부 다시 그려야 한다

## 2-1. 복도를 옆에서 보면

플레이어는 복도를 **옆에서** 본다(횡스크롤). 복도 단면은 이렇게 보인다:

```
 화면 위 ┌──────────────────────────────────────────────┐
         │ ▓▓▓ 전경 들보 (가장 가깝다 · 가장 빠르다) ▓▓▓  │  N1
         │  ═══ 천장 (가까운 쪽 → 먼 쪽으로 좁아진다) ═══ │  R1  ← 여러 띠로 잘려 속도가 다르다
         │ ─────────── 몰딩(코니스) ───────────────────── │  W4 ┐
         │   ░░ 벽지 ░░  [액자]  ░░ 벽지 ░░  [촛대]      │  W1 │ 먼 벽 = 한 평면
         │ ─────────── 징두리 윗단(체어레일) ─────────── │     │ (모두 같은 속도 0.30)
         │ ║ 판벽 ║ 판벽 ║ 판벽 ║  [궤짝] ║ 판벽 ║        │  W3 ┘
         │  ─── 바닥 (먼 쪽 → 가까운 쪽으로 넓어진다) ─── │  F1  ← 여러 띠로 잘려 속도가 다르다
 지형 윗면 ├══════════════ 게임 지형(바닥) ════════════════┤  (속도 1.0 · 플레이어가 밟는 곳)
         │██████████████████████████████████████████████│
 화면 아래 └──────────────────────────────────────────────┘
```

## 2-2. 게임이 하는 일 — "띠 시차"

- **먼 벽(벽지·판벽·몰딩·벽 소품)** 은 한 평면이라 **모두 같은 속도(0.30)** 로 흐른다.
  (벽에 걸린 액자가 벽지 위를 미끄러지면 안 된다 → 벽 소품도 벽과 같은 속도.)
- **천장과 바닥**은 게임이 **가로 띠 여러 개로 잘라서**, 벽에 붙은 띠는 느리게(0.30),
  플레이어 쪽 띠는 빠르게(0.8~0.9) 흘린다. 그러면 천장 들보와 바닥 널판 이음매가
  **걸을 때마다 비스듬히 기울어졌다 펴졌다** 한다 — 이것이 진짜 원근처럼 보이는 이유다
  (옛날 레이싱 게임의 도로, 레이맨 레전드의 복도가 같은 방식이다).
- 그래서 **천장·바닥 그림에는 원근(소실점, 기울어진 선)을 그려 넣으면 안 된다.**
  기울기는 움직임이 만든다. 그림에 기울기가 있으면 움직임과 싸워서 **선이 꺾여 보인다.**

## 2-3. 그러므로 천장과 바닥은 "펼친 평면도"로 그린다

```
  천장 R1 — 바로 밑에서 천장을 올려다본 평면도 (원근 없음)
  ┌────┬────────┬────┬────────┬────┬────────┬────┬────────┐  ← 캔버스 위 = 플레이어 쪽(가깝다)
  │들보│ 회반죽 │들보│ 회반죽 │들보│ 회반죽 │들보│ 회반죽 │     들보는 **세로 띠**(벽과 직각)
  │    │  금·얼룩│    │        │    │ 물자국 │    │        │
  └────┴────────┴────┴────────┴────┴────────┴────┴────────┘  ← 캔버스 아래 = 벽 쪽(멀다)

  바닥 F1 — 바로 위에서 내려다본 평면도 (원근 없음)
  ┌─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┐  ← 캔버스 위 = 벽 쪽(멀다)
  │ │ │ │▒▒▒▒▒ 긴 러너 카펫 ▒▒▒▒▒│ │     널판 이음매는 **세로선**(벽과 직각)
  │ │ │ │▒▒▒▒▒ (가로로 끝없이) ▒▒│ │     러너 카펫은 **가로 띠**(복도 방향)
  └─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┘  ← 캔버스 아래 = 플레이어 쪽(가깝다) · 거의 검정
```

- 들보·널판 이음매는 **완전한 수직선**. 굵기와 간격이 일정해야 한다(§4 의 개수 규칙).
- 게임이 세로로 눌러(원근 단축) 쓰므로 **세부를 크게, 여유 있게** 그린다. 작은 무늬는 눌리면 뭉개진다.

# §3. 절대 규칙 — v05 주문서 §3 그대로 + 복도 추가분

아래 블록을 **모든 프롬프트 맨 끝에 그대로 복사해 넣는다.** 요약하지 말 것.

```text
CRITICAL RULES, these are game-mechanic requirements, not stylistic preferences:
- NO lit flames, NO burning candles, NO glowing light source of any kind. Every lamp,
  candle, sconce and chandelier in this world is EXTINGUISHED and cold. In this game the
  player can physically STAND ON hardened light, so any painted glow reads as a solid
  platform and the player will die trying to land on it.
- NO soft bright halo, bloom or rim glow around any object. Where an object ends, alpha
  must fall to zero within about 2 pixels. Do not feather objects outward into pale mist.
- NO white outlines and NO bright horizontal top edge on any ledge, stair tread, shelf,
  sill, rail, skirting or cornice. Those read as standable platforms and the player will
  jump at them.
- BRIGHTNESS BANDS: keep every pixel either below 40 percent or above 60 percent
  brightness. The 45-55 percent band is RESERVED for gray safe terrain in this game and
  must not appear anywhere in the background.
- Strictly neutral grayscale, no color tint anywhere.
- NO characters, NO gameplay platforms, spikes, saw blades, water, chains, HUD or text.
- NO perspective drawn into the image: no vanishing point, no converging lines, no
  diagonal floorboards or beams. The game creates perspective by scrolling strips of this
  image at different speeds; painted perspective fights that motion and looks broken.
```

**복도에서 특히 조심할 것 (왜 이 규칙인가)**

| 규칙 | 이유 |
|---|---|
| 체어레일·걸레받이·몰딩의 **윗면을 밝게 칠하지 않는다** | 복도는 가로로 긴 선이 많다. 밝은 가로선 = 밟을 수 있는 선반으로 읽힌다. v05 복도에서 걸레받이 경계선이 "바닥 위 낮은 턱"으로 읽혀서 지웠다 |
| 바닥 F1 의 **플레이어 쪽(아래) 25 % 는 거의 검정** | 그 아래에 진짜 지형 바닥이 온다. 그림 바닥이 밝으면 **바닥이 두 겹**으로 보인다 |
| 벽지 무늬 대비를 **낮게** | v05 에서 벗겨진 벽지 띠가 밝고 빽빽하면 "매달린 널판 줄"로 보였다 |
| 촛대·샹들리에는 전부 **꺼져 있다** | 굳은 빛을 밟는 게임이다. 배경에 빛이 있으면 발판으로 오해한다 |

# §4. 크기 계약 — 모든 조각이 **같은 픽셀 밀도**다

벽 레이어들은 게임에서 **한 평면으로 조립**된다. 그래서 캔버스 픽셀 크기가 서로 맞물려야 한다.
기준은 **벽 소품 캔버스(1536 × 1024)** 다. 모든 벽 조각은 이 캔버스와 **같은 1 px = 같은 크기**다.

```
  벽 소품 캔버스 1536 × 1024 안의 세로 배치 (y = 위에서부터 px)

    y    0 ─┬─ 천장 자리 — 벽 소품은 여기에 아무것도 그리지 않는다 (알파 0)
    y  160 ─┼─ 몰딩(W4) 아랫면
            │     벽지(W1) 480 px
    y  240 ─┤  ← 몰딩 윗단 = 벽지 시작 (W4 는 y 160~240 · 80 px)
            │
    y  720 ─┼─ 체어레일 = 징두리(W3) 윗단
            │     판벽(W3) 240 px
    y  960 ─┴─ ★벽 밑동 = 바닥선 (캔버스 높이의 93.75 %)
    y 1024     그 아래 64 px 는 비운다 (알파 0) — 바닥 F1 이 여기 온다
```

| 기준 | 캔버스 px | 비고 |
|---|---:|---|
| **서 있는 사람 키(벽 앞)** | **72** | 복도 높이가 사람 키 11 배라서 벽 800 px ÷ 11 |
| 문 높이 | 180 ~ 290 | 사람 키 2.5 ~ 4 배 (저택이라 일부러 크다) |
| 판벽 패널 한 칸 폭 | 128 | 1024 폭에 **정확히 8 칸** (반복 이음매가 칸 경계에 온다) |
| 벽지 무늬 한 단위(가로) | 128 또는 256 | 1024 를 나누어떨어지게 |
| 천장 들보 간격 | 256 | 1024 폭에 **정확히 4 개** |
| 바닥 널판 폭 | 64 | 1024 폭에 **정확히 16 장** |

**작업 요령**: 그리기 전에 72 px 사람 실루엣을 y 960 위에 세워 두고 그린다. 제출할 때 지운다.

**★생성 크기와 제출 크기가 다르다.** 이미지 생성은 1536 × 1024 / 1024 × 1024 / 1024 × 1536 로만 된다.
길쭉한 조각(W3 · W4 · N1)은 **크게 생성한 뒤 잘라서** 제출한다. 무엇을 어떻게 잘랐는지
`asset_notes.md` 에 적는다. **축소해서 비율을 맞추지 말 것**(픽셀 밀도가 깨진다) — 자르기만 한다.
