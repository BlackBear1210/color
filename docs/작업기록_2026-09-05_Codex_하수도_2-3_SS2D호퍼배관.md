# 하수도 2-3 — SS2D 관과 호퍼

작업일: 2026-09-05

## 만든 것

- `scenes/world_2_클로드/stage_2-3.tscn`을 만들었다. 루트는 `월드.gd`이고, 시작점은 x=470·끝도달 검사점은 x=7480이다.
- 1~5 관문을 한 화면 흐름으로 배치했다: 관이 물든다 → 한 색 호퍼 → 검정+흰색 호퍼의 회색 출구 → 호퍼 두 장으로 건너는 구덩이 → 3갈래 관.
- 보이는 관은 전부 `TEMPLATE_PIPE_OPEN_GRAY` SS2D다. `배관.tscn`은 참조·인스턴스하지 않았다.
- SS2D 지형끼리는 면적을 겹치지 않게 배치했다. 인접 바닥·벽·천장은 경계선만 맞닿는다.
- 회색 CEMENT 지형은 없다. 회색은 호퍼(색 규칙 밖 장치)와 H3 혼합 물 출구에만 사용했다.

## 실제 통행 경로 설계

- 시작 검정 → 관문 1의 140px 배수구 점프 → 관문 2·3의 물줄기 아래 통로 → 관문 4.
- 관문 4는 H5(검정 물) → H6 왼쪽(흰 물 회피) → H6 위에서 흰색 전환 → 오른쪽 착지 전 검정 복귀 순서다.
- 간격은 바닥→H5 40px/상승 92px, H5→H6 120px, H6→착지 120px으로 점프 안전치(수평 160px·상승 160px) 안이다.
- 일반 통로 위의 물은 플레이어 몸 윗선보다 높게 끝나게 배치해, 관문 4 외에는 길을 막지 않는다.

## 검사

- 정적 확인: 외부 리소스 경로 존재, SS2D 배관만 사용, 회색 지형 상태 없음, 이전 승강발판 참조 없음, 괄호 수 일치, `git diff --check` 통과.
- 사용자가 요청한 실제 실행을 위해 Godot 4.6.3 콘솔 빌더를 한 번 실행했다.
- 결과: Godot가 프로젝트/스크립트 로딩 전에 **signal 11 접근 위반**으로 종료됐다. `stage_2-3.tscn` 빌더 출력과 실제 플레이 검사는 실행할 수 없었다.
- 같은 충돌을 반복하지 않기 위해 직접 열 수 있는 `stage_2-3.tscn`을 텍스트로 추가했다. 엔진 충돌이 해결되기 전에는 실제 플레이어 통과를 확인했다고 주장하지 않는다.

## 호퍼 출구 물줄기 조절 (추가)

- `호퍼.gd`에 인스펙터용 `출구 물줄기 모양/출구 물줄기 폭`, `출구 물줄기 길이`를 추가했다.
- 폭은 보이는 물기둥의 두께(px), 길이는 아래로 내려가는 길이(px)다. 길이 `-1`은 해당 유체가 원래 가진 길이를 유지한다.
- `H1_한색`의 출구는 투명 가장자리 때문에 얇고 짧게 보이던 `64×100`에서 `96×220`으로 늘렸다. 호퍼 노드를 선택해 두 값을 바꾸면 게임 실행 전에도 연결된 출구 유체의 그림이 함께 갱신된다.
