# 타일맵 페인트 시스템 (v4) — 색칠 · 회수

> **작성일**: 2026-07-30
> **한 줄 요약**: **TileMapLayer 로 맵을 찍기만 하면** 런타임에 플랫폼을 자동으로 찾아내
> zone_04(v3)와 똑같은 규칙으로 색칠·회수가 되는 시스템. 플랫폼을 노드로 하나하나 배치하거나
> 타일 조각을 새 씬으로 복붙할 필요가 없다.
> **핵심 아이디어**: 디자이너 PNG 안에 흑/백 버전이 나란히 들어 있으므로, **아틀라스 좌표만 보면
> 그 타일이 흑인지 백인지 알 수 있고 ±24칸 옮기면 같은 무늬의 반대색 타일이 된다.**

## 1. 왜 만들었나 (v3 와의 차이)

| | v3 (zone_04/05) | **v4 (이 문서)** |
|---|---|---|
| 색칠 단위 | `PaintPlatform` 노드 1개 | **연결된 같은 색 타일 덩어리** 1개 |
| 지형 제작 | 플랫폼 노드를 하나하나 배치 | **TileMapLayer 로 맵을 찍기만** |
| 그림 | 384px 덩어리 아트 1장 + 9슬라이스 | 디자이너 타일셋 그대로 |
| 콜리전 | 스크립트가 사각형 생성 | TileSet 의 physics layer 그대로 |

v3 는 발판 하나가 노드 하나여서, 새 스테이지를 만들 때마다 발판을 배치해야 했다.
v4 는 그 반대다 — **맵을 타일로 찍으면 시스템이 알아서 "플랫폼"을 찾아낸다.**

> ⚠ v3 는 폐기되지 않았다. zone_04/05·스테이지 1~5 는 그대로 `PaintPlatform` 을 쓴다.
> v4 는 `stage_lab.gd` 의 `타일맵_페인트` 를 켠 스테이지에서만 동작한다 (기본 꺼짐 → 회귀 없음).

## 3. 색을 어떻게 인지하는가 ★

디자이너 PNG 5장은 한 장 안에 흑 버전과 백 버전이 들어 있다.
타일 크기가 **16px**, 한 버전이 **384px** 이므로 경계는 정확히 **24칸**이다.

| 파일 | 해상도 | 배치 | 흑 ↔ 백 변환 |
|---|---|---|---|
| `brick.png` | 768×768 | 흑 **좌** / 백 **우** | `x ± 24` |
| `grass.png` | 768×896 | 흑 **좌** / 백 **우** | `x ± 24` |
| `rock.png` | 768×384 | 흑 **좌** / 백 **우** | `x ± 24` |
| `soil.png` | 768×384 | 흑 **좌** / 백 **우** | `x ± 24` |
| `wood.png` | 768×768 | 흑 **상** / 백 **하** | **`y ± 24`** |

> **`wood.png` 만 축이 다르다.** 좌우는 액자형/평면 구분이고, 위아래가 흑/백이다.
> 실측 검증(2026-07-30): 각 PNG의 384px 셀별 평균 밝기를 측정해 확인했다 —
> brick/grass/rock/soil 은 좌측 셀이 lum 2~14, 우측이 240~255. wood 는 **상단 행**이 6~17,
> **하단 행**이 243~248.

### 구현 (하드코딩 회피)
소스 id 를 하드코딩하지 않고 **텍스처 파일명**으로 규칙을 찾는다 → TileSet 의 소스 순서가 바뀌어도 안 깨진다.

```gdscript
const 반칸: int = 24                      # 384 / 16
const 축_by_파일 := { "brick.png": 0, "grass.png": 0, "rock.png": 0, "soil.png": 0, "wood.png": 1 }

TilePaintMap.셀_색(layer, cell)            # → ColorDefs.BLACK / WHITE / -1(모르는 타일)
TilePaintMap.반대색_좌표(tile_set, src, atlas)  # → 같은 무늬의 반대색 아틀라스 좌표
```

`반대색_좌표()` 는 짝 타일이 **실제로 타일셋에 존재하는지**(`has_tile`) 확인하고, 없으면 원래
좌표를 그대로 돌려준다. (`grass.png` 의 "두꺼움" 셀처럼 백 버전이 없는 경우 대비)

## 4. 플랫폼 자동 검출

`_ready()` 에서 씬 안의 모든 TileMapLayer 를 훑어 **4방향 플러드 필**로
"연결된 **같은 색** 타일 덩어리" = 플랫폼 1개로 묶는다.

- 색이 다르면 인접해도 **다른 플랫폼**이다 → 검정 바닥에 붙은 흰 발판이 따로 잡힌다.
- 규칙을 모르는 타일(`셀_색 == -1`)은 아예 대상에서 제외된다.
- `stage_1-1` 실측: 타일 6626칸 → **플랫폼 74개**.

### 필요횟수 (내구도)
```
필요횟수 = clamp( ceil(플랫폼 긴 변 칸수 / 타일_필요횟수_나눗값), 1, 최대_필요횟수 )
```
- `타일_필요횟수_나눗값` 기본 **4**. v3 는 32px 를 1칸으로 세고 `ceil(긴변/2)` 였는데
  이 타일셋은 16px 이므로 2배가 되어 나눗값도 2배(4)로 맞췄다.
- `최대_필요횟수` 기본 **12** — 거대한 바닥이 사실상 못 칠하게 되는 것을 막는 상한.

### 고정 지형
`타일_고정_타일수` 를 넘는 덩어리는 "칠할 수 없는 고정 지형"으로 본다(→ `blocked`).
**기본값 0 = 제한 없음.**

> ⚠ 예전 기본값 400 은 함정이었다. 타일맵으로 그린 스테이지는 바닥이 하나로 크게 연결되기
> 쉬운데, `stage_1-1` 은 스폰 앞 바닥이 **560칸 한 덩어리**여서 전부 고정으로 빠졌다
> (전체 타일의 40.7%). 쏴도 `blocked` 만 나와 "색칠이 아예 안 되는" 것처럼 보였다.

## 5. 색칠 로직 ★

`on_hit(layer, cell, color)` — `PaintSystem`(v2) 과 **같은 시그니처**라 총알 코드를 고치지 않고 끼워진다.

### 5.1 명중 좌표 보정 (필수)
총알이 준 셀이 빈 칸이면 **반경 2칸(32px)** 안에서 등록된 타일을 가까운 순으로 찾는다.

> ⚠ 이게 없으면 대부분의 명중이 `miss` 로 새서 "색칠이 안 되는" 것처럼 보인다.
> · `ProtoBullet` 은 **반지름 6px 원형 Area2D** 다. `body_entered` 는 원의 *테두리*가 타일에
>   닿는 순간 터지므로 그 시점의 총알 **중심은 타일 밖(최대 6px)** 에 있다. 타일은 16px 다.
> · 게다가 총알은 프레임당 **7.5~22px** 씩 튀어 이동한다(초속 450~1350). 한 프레임 이동거리가
>   타일 한 칸보다 클 수 있어 `proto_bullet` 의 "10px 앞을 한 번 더 본다" 보정으로는 부족하다.
> → `proto_bullet.gd` 는 손대지 않는다 (zone_01/02 의 v2 경로에 영향 없도록).

### 5.2 판정 순서
| 조건 | 결과 | 동작 |
|---|---|---|
| 플랫폼을 못 찾음 | `miss` | — |
| `고정` 또는 `회색` | `blocked` | 아무 일 없음 |
| 이미 칠해짐 + **같은 색** | `wasted` | 덧칠 = 낭비 |
| 이미 칠해짐 + **반대색** | `mixed_gray` | **영구 회색**. 회수 큐에서 제외 |
| 아직 원래색인데 **같은 색** | `wasted` | 칠할 이유 없음 |
| 그 외 | `progress` / `painted` | 명중 누적 |

- **진행 중 다른 색이 오면** 회색이 아니라 **새 색으로 리셋**(맞은횟수 0부터). v3 규칙 3 그대로.
- `맞은횟수 >= 필요횟수` 가 되면 `painted` → 회수 큐(FIFO)에 등록.

> ★**검정 구역에서는 흰 지형만 칠할 수 있다.** `ColorZone` 이 플레이어 색을 강제하므로,
> 검정 구역 안의 검정 지형은 "같은 색"이라 `wasted` 가 된다. 버그가 아니라 규칙의 결과다.
> 레벨을 짤 때 **구역 색과 반대색인 지형을 퍼즐 대상으로** 배치해야 한다.

### 5.3 잉크 번짐 표현 ★ — 원본 레이어는 절대 건드리지 않는다

**원본 셀을 `set_cell` 로 바꾸지 않는다.** 그러면 색칠 단위가 타일 한 칸이라 칸 경계가 그대로
드러나 **각지게** 보인다 (실제로 그 문제를 겪고 구조를 바꿨다).

대신 이렇게 한다:

```
TileMapLayer (원본, 콜리전 보유)          ← 절대 수정 안 함
└─ _페인트오버레이_N (TileMapLayer)        ← 플랫폼 전체에 반대색 타일을 찍어둠
      material = ink_spread_mask.gdshader  ← 알파만 깎는다
      collision_enabled = false, z_index = 1
```

- 마스크 **1** → 오버레이(칠해진 무늬)가 드러난다
- 마스크 **0** → 알파 0 → **아래 원본 무늬가 그대로 비친다**

경계는 `fbm` 3옥타브 노이즈로 일그러져 **칸 경계와 무관하게** 물감이 스민 모양이 된다.
단색을 덮는 게 아니라 **원본 흑/백 타일의 결·명암이 그대로 살아 있다.**

번짐 공식은 v3(`paint_platform.gd`)를 그대로 가져왔다:
- 초반 = **면적 비례 원**(원 넓이 = 진행률 × 플랫폼 넓이) → 조금씩 스미는 느낌
- 마지막 한 발 = `pow(진행, 5.0)` 로 가속해 **확 덮이는 쾌감**
- 명중 직후 **0.8초간 젖은 광택**(`wet_amount` 1 → 0)
- 씨앗은 플랫폼당 최대 **16개**(셰이더 `MAX_SEEDS` 와 동일)

애니메이션은 GPU `TIME` 이 아니라 **CPU(`_process`)** 에서 굴린다 — "지금 몇 % 번졌나"를
정확히 알아야 저장·회수·자동테스트가 가능하기 때문(v3 와 같은 이유). 번질 것이 없으면
`set_process(false)` 로 꺼둔다.

#### ⚠ 셰이더 좌표계 — 반드시 월드 좌표로
`TileMapLayer` 는 타일을 하나의 CanvasItem 에 그리지 않고 **렌더링 쿼드런트별 CanvasItem** 으로
쪼개 그린다. 그래서 `VERTEX` 는 레이어 원점이 아니라 **그 쿼드런트 원점 기준**의 작은 값이다.

레이어 로컬 좌표(`origin_px`)를 넘겼더니 뺄셈이 성립하지 않아 거리가 터지고
**마스크가 전 영역 0 → 오버레이가 완전히 투명**해졌다. (스크린샷 2장 비교로 원인 확정:
셰이더 없이 얹으면 정상 렌더링, 붙이면 사라짐)

```glsl
void vertex() {
    vec2 world_pos = (MODEL_MATRIX * vec4(VERTEX, 0.0, 1.0)).xy;   // ★필수
    local_uv = (world_pos - origin_world) / max(size_world, vec2(0.0001));
}
```
GDScript 쪽도 `origin_world = layer.to_global(...)`, `size_world = 크기 * 타일 * global_scale` 로
**월드 좌표**를 넘긴다. 쿼드런트가 몇 개로 쪼개지든 각자의 `MODEL_MATRIX` 가 자기 오프셋을
품고 있어 **하나의 이어진 번짐 원**이 된다.

### 5.4 회색 (영구)
칠해진 플랫폼에 반대색이 맞으면 되돌릴 수 없는 회색이 된다.
회색 전용 타일이 타일셋에 없으므로, **오버레이를 꽉 덮고 셰이더의 `locked` 로 대비를 죽인다**
(레벨디자인 가이드 §5 의 45~55% 대역).

> 예전엔 런타임에 `create_alternative_tile` + `modulate` 로 회색 타일을 만들었다.
> 그 방식은 **TileSet 리소스를 건드려 저장될 위험**이 있었고 각진 느낌도 그대로였다 → 폐기.

## 6. 회수 로직 (E) ★

`되돌리기()` / `recover()` — 이름을 v2 `PaintSystem` 과 맞춰 `proto_gun.gd` 가 그대로 부른다.

- 색과 무관하게 **가장 먼저 칠한 플랫폼부터** 전역 FIFO 로 원래 모습으로 되돌린다.
- **회색이 된 플랫폼은 큐에서 빠져 영원히 돌아오지 않는다.**
- 회수는 자원 회수가 아니라 **"칠한 길을 되돌리는 지형 조작 도구"** 다.

### 원본을 안 건드린 덕에 회수가 완벽하다
되돌리기 = **오버레이 레이어를 `queue_free()` 하고 씨앗을 비우는 것**뿐이다.
원본 레이어를 한 번도 수정하지 않았으므로 아틀라스 좌표가 100% 원상복구된다.

```gdscript
p.오버레이.queue_free()
p.오버레이 = null
_시드_비우기(p)
p.맞은 = 0 ; p.진행색 = -1 ; p.칠해짐 = false
```

## 7. 총 · 총알과의 연결

`stage_lab.gd` 가 조립한다. `on_hit` / `되돌리기` 이름이 v2 와 같아 **덕 타이핑으로 그대로 끼워진다.**

```gdscript
gun.setup(타일페인트, null, player)                       # 총알의 TileMapLayer 명중 → TilePaintMap
gun.페인트매니저 = 타일페인트                              # E 회수도 이쪽으로
```

`proto_bullet.gd` / `proto_gun.gd` 는 타입 힌트만 `PaintSystem` → `Node` 로 완화했다(로직 무수정).
`proto_bullet.gd` 의 타일맵 분기에는 `_paint_system != null` 체크를 추가했다 —
플랫폼 전용 스테이지에서는 `paint_system` 이 `null` 인데 원본 지형 타일맵이 남아 있으면
`Nonexistent function 'on_hit' in base 'Nil'` 로 터졌기 때문.

## 8. 사용법 (디자이너 워크플로)

1. 씬 루트에 `scripts/proto/stage_lab.gd` 를 붙인다.
2. 루트 Inspector 에서 **`타일맵_페인트` 를 켠다.**
3. `TileMapLayer` 로 지형을 찍는다 (TileSet = `scenes/플랫폼/shared_tileset.tres`).
4. 끝. 플랫폼 검출·필요횟수·콜리전·색칠·회수가 전부 자동.

### Inspector 튜닝 (루트 노드)
| 속성 | 기본 | 설명 |
|---|---|---|
| `타일맵_페인트` | `false` | 이 시스템을 켠다 |
| `타일_필요횟수_나눗값` | `4` | 클수록 적게 쏴서 완성. **테스트할 때 20 정도로 올리면 1~2발** |
| `타일_고정_타일수` | `0` | 이 칸수 초과 덩어리 = 칠 불가. 0 = 제한 없음 |
| `타일_명중_표시` | `false` | 명중 결과를 화면 중앙에 표시(디버그). ⚠켜면 쏠 때마다 **화면이 번쩍이는 것처럼 보인다** |

### 번짐 모양 튜닝
`shaders/ink_spread_mask.gdshader` 의 유니폼 기본값:
`noise_amount`(0.13 · 경계 일그러짐) / `noise_scale`(3.2 · 세밀도) / `edge_soft`(0.035 · 부드러움)

## 9. ⚠ `.tscn` 을 손으로 편집할 때 (한글 속성 함정)

Godot 는 `.tscn` 에 **비ASCII(한글) 속성 이름을 따옴표로 감싸서** 저장한다.

```
"타일맵_페인트" = true      ← 맞음
타일맵_페인트 = true        ← Godot 가 에러 없이 조용히 무시 → 기본값 false 로 남음
```

이걸 몰라 `TilePaintMap` 이 **아예 생성되지 않은 채** 색칠 로직·색 인지 규칙·총알 연결을 전부
의심하며 오래 헤맸다. 로그에 아무것도 안 남으므로 **넣은 뒤 실제로 반영됐는지 확인해야 한다.**

## 11. 제약 / 남은 일

- ★**반대색 지형을 밟았을 때의 사망 판정이 아직 연결되지 않았다.**
  `stage_lab._발밑_플랫폼()` 은 여전히 `PaintPlatform` 노드만 레이캐스트로 찾는다.
  타일맵 지형에는 안 걸리므로, **지금은 색칠해도 게임 규칙상 의미가 없는 상태다.**
- `PaintFX`(스플래시·물감 흐름)와 `StageHUD`(붓 커서·남은 횟수 표시)는 `PaintPlatform` 노드만
  구독한다 → v4 스테이지에서는 동작하지 않는다.
- 플랫폼당 씨앗 상한 16개. 넘으면 가장 오래된 씨앗이 밀려난다.
- 셰이더가 **회전을 가정하지 않는다** (`size_world` 를 축정렬로 계산). 타일맵을 회전시키면 마스크가 어긋난다.
- 회색 상태는 오버레이의 `locked` 로만 표현된다 → 회색 전용 아트가 생기면 교체를 검토할 것.
- `scripts/proto/tile_paint_platform.gd` + 구 `ink_spread_mask` 사용법(3레이어 방식)은 이 시스템으로
  대체되어 **아무도 참조하지 않는다.** 삭제 보류 중(2026-07-30 도형 "일단 둬").
