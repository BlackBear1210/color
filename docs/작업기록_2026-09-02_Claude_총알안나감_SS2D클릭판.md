## 1. 무엇이 잘못돼 있었나

`addons/rmsmartshape/shapes/shape.gd` 의 `_setup_click_rect()` 는
에디터에서 도형을 마우스로 집을 수 있게 **투명한 ColorRect** 를 자식으로 붙인다.
그리고 집히게 하려고 마지막에 이렇게 한다:

```gdscript
_click_rect.owner = self  # Needed to make it clickable
```

★ `owner` 가 박힌 노드는 **씬을 저장할 때 .tscn 에 같이 저장된다.**
그래서 지형 Template **20 개 전부**에 이 판이 구워져 있다:

```
[node name="@ColorRect@18821" type="ColorRect" parent="."]
modulate = Color(1, 1, 1, 0)          ← 투명이라 눈에 안 보인다
offset_left = -656.0 … offset_bottom = 1712.0   ← 7648 × 2960
metadata/__ss2d_click_rect__ = true
```

`_setup_click_rect()` 자체는 `if Engine.is_editor_hint():` 안에서만 불리지만,
**이미 씬에 저장된 판은 런타임에도 그냥 로드된다.** 여기가 함정이다.

이 판은 `mouse_filter` 가 Control 기본값인 **STOP** 이다.
Godot 의 입력 순서는

```
_input  →  GUI (Control)  →  _shortcut_input  →  _unhandled_input
```

이라서, 좌클릭이 **GUI 단계에서 이 판에 먹히고** `총.gd` 의
`_unhandled_input` 까지 내려오지 않는다. 그래서 `발사()` 가 아예 안 불린다.

### 왜 stage_2-1 에서만 터졌나
그 스테이지에만 새로 찍은 SS2D 지형이 들어왔기 때문이다.
지형을 새로 놓는 스테이지는 **전부 같은 증상**이 난다.

### 어떻게 확인했나 (헤드리스)
1. `총.발사()` 를 직접 부르면 총알이 잘 생긴다 → 발사 코드는 무죄.
2. 좌클릭 `InputEvent` 를 뷰포트에 밀어 넣으면 `_input` 까지는 오는데
   `_unhandled_input` 에 안 온다 → **GUI 가 먹는다.**
3. 트리의 Control 을 전부 찍어 보니 범인이 나왔다:
   `지형/TEMPLATE_CEMENT_SOLID/@ColorRect@18821  filter=0(STOP)  rect=7648×2960`

## 2. 어떻게 고쳤나

`scripts/스마트월드/지형.gd` 의 `_ready()` 에서, **런타임일 때만**
`__ss2d_click_rect__` 메타가 붙은 자식을 치운다.

```gdscript
	if Engine.is_editor_hint():
		return
	_에디터_클릭판_치우기()      # ← 추가
```

```gdscript
func _에디터_클릭판_치우기() -> void:
	# 내부(INTERNAL) 자식으로 붙는 경우도 있어 `get_children(true)` 로 훑는다.
	for 자식 in get_children(true):
		if 자식.has_meta(CLICK_RECT_TAG):
			자식.queue_free()
```

### 왜 씬 파일에서 지우지 않았나
씬에서 지워도 **에디터에서 그 지형을 다시 저장하면 또 구워진다.**
근본 원인이 플러그인 쪽이라 씬을 고치는 건 그때뿐인 임시방편이고,
`Template` 20 개를 손으로 고치면 규약 4 번(디자이너 편집분 날림) 위험도 있다.
반면 이 함수는 매 실행마다 돌고 몇 번을 돌려도 결과가 같다 — **멱등**(규약 5).
에디터에서는 이 판이 있어야 지형을 집을 수 있으므로 `is_editor_hint()` 뒤에서만 부른다.

지형은 전부 `지형.gd` 를 쓰므로(`__ss2d_click_rect__` 가 든 씬 20 개 전수 확인)
이 한 곳만 고치면 **모든 스테이지가 같이 낫는다.**

## 4. 다음 사람이 알아야 할 것 (지뢰 추가)

**SS2D 지형을 새로 찍은 뒤 "마우스 클릭이 안 먹는다"** 면 이걸 의심할 것.
증상은 총알만이 아니다 — `_unhandled_input` / `_gui_input` 을 쓰는 것은 **전부** 막힌다.

확인법 (헤드리스에서 Control 전수 조사):

```gdscript
func _walk(n: Node) -> void:
	if n is Control:
		print(n.get_path(), " filter=", n.mouse_filter, " rect=", n.get_global_rect())
	for c in n.get_children(): _walk(c)
```

`filter=0`(STOP) 이면서 화면보다 큰 Control 이 나오면 그놈이 범인이다.
