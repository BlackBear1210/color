# 2-11 · 잠긴 폭포의 계단

## 확정 요구와 결과

사용자 지정: 왼쪽 맨 위 시작, 오른쪽 맨 아래 도착, 우하향 하강. 물·압력발판으로 움직이는 플랫폼·지형 변색 장애물·레버로 끄는 대량의 폭포·투명 발판·밟으면 부서지는 발판. 2-10보다 크게 제작할 수 있으며 장애물 빈도를 높인다.

- 새 씬: `scenes/world_2_클로드/stage_2-11.tscn`
- 배치표: `scenes/world_2_클로드/stage_2-11_배치표.json`
- [전체 설계도](설계도_하수도_2-11.png): 좌표 기반 도면이며 실제 게임 화면이 아니다.
- 작성기: `tools/작성_하수도_2-11.mjs`
- 시작 (384,1024), 목적지 (17216,8448). 실제 출구는 우하단 연결통로 하나이며 다음 씬은 로비다.
- 카메라 안쪽 범위 17664×8704. 2-10 설계 범위 6400×11648 대비 **면적 약 2.06배**다. 플레이 시간이 두 배라는 의미는 아니다.
- 사방 2048px 외곽 마감. 기본 줌 0.85. 메인 캠페인의 챕터표·기존 씬 연결은 변경하지 않았다.

## 구역과 공략

| 구역 | 시작 기준 x,y | 핵심 동작 |
|---|---|---|
| 1 | 256,1024 | 낮은 단상의 레버로 흰색·검정 폭포를 잠그고 수문을 연다. 아래 징검다리 또는 칠한 상부 투명 지름길을 선택한다. |
| 2 | 3584,2560 | 압력발판을 밟아 천장 보관 위치의 다리를 640px 내린다. 생긴 길을 건너며 분사기가 바꾸는 발판 색을 읽는다. |
| 3 | 6912,4096 | 투명 발판을 칠해 빠르게 건너거나, 검정 물길로 내려가 오른쪽 격자 계단으로 우회한다. 두 번째 투명 발판에 분사기가 있다. |
| 4 | 10240,5632 | 레버로 두 폭포와 수문을 제어하고, 압력발판으로 별도의 이동 다리를 내려야 통과한다. |
| 5 | 13568,7168 | 두 폭포를 잠근 뒤 균열 있는 붕괴 발판 3개를 건넌다. 두 번째 발판은 분사기가 칠한다. 하강 계단을 거쳐 오른쪽 아래 출구로 간다. |

각 방을 통과한 뒤 경사진 짧은 계단으로 내려간다. 경사 부분은 192px 진행에 96px 하강(약 26.57도), 수직 단차는 주로 224px다. 방 사이 전환은 128px 틈과 256px 하강이다. 다음 방 입구와 각 경사 계단에는 완충수를 두었다.

첫 구역 상부 지름길을 굳히면 아래 징검다리 위 공간이 좁아진다. 그때는 굳힌 상부 길로 건너거나 안전한 시작 쪽에서 물감을 회수하고 아래 길을 쓴다. 세 번째 구역의 물길 우회는 위의 투명 발판을 칠하지 않아도 오른쪽에 재합류하는 별도 선택지다.

## 수량과 편집 단위

- 폭포 6줄, 원형 차단 레버 3개, 연동 수문 3개.
- 압력발판 2개, 움직이는 다리 2개.
- 투명 SS2D 발판 3개, 붕괴 SS2D 발판 3개, 페인트 분사기 3개.
- 위의 주요 퍼즐 요소 합계 25개. 물받이·완충수 29개와 복귀용 격자 계단 18개는 별도다.
- 각 구역의 바닥·구덩이·착륙대·경사·하강 계단은 **하나의 연속 SS2D 윤곽**이다. 전체 SS2D는 25개다.
- 투명 발판·붕괴 발판·독립 이동 수문은 별도 SS2D다. 실제로 떨어진 플랫폼이거나 독립 상태 변화가 필요하기 때문이다.
- 복귀 계단은 기존 `통과플랫폼.tscn`을 이용한 얇은 격자다. 일반 복귀 폭 128px, 오른쪽 우회 폭 96px, 두께 24px, 높이 차 96px. 아래에서 머리가 걸리지 않도록 충돌 자식에 단방향 충돌을 설정했다.

## 물과 낙하

구덩이 깊이는 384px, 물받이 수심은 192px다. 물은 충돌 발판이 아니므로 그 아래 실제 SS2D 바닥까지 둔다. 실패하면 물길에서 왼쪽 격자 계단으로 돌아가 재시도한다.

**2·3·5구역 구덩이는 검정 물**이다. 해당 물받이에 떨어지기 전에는 플레이어도 검정이어야 한다. 이동 다리가 올라가 있거나 붕괴 발판이 사라졌을 때 분사기의 흰 탄이 검정 물에 막히도록 한 배치다. 바닥이 흰색으로 칠해져 재시도 경로가 바뀌는 것을 방지하려는 목적이다. 나머지 물받이와 계단 완충수는 회색이다. 폭포 물과 바닥 물의 영역은 서로 겹치지 않게 두었다.

치명 낙하 판정은 끄지 않았다. 실제 색 전환·낙하 타이밍과 임의 점프 착지 안전성은 엔진 주행으로 아직 확인하지 않았다.

## 장치 구현

### 압력발판 다리

기존 스마트월드 `움직이는발판.tscn`(AnimatableBody2D)을 썼다. `이동거리=0`으로 자동 왕복을 끄고 압력버튼만 위치를 제어한다. 버튼의 대상은 타입을 명시한 `Array[NodePath]`, 이동량은 `Array[Vector2]`다.

다리 폭 768px·두께 48px. 활성화되면 구덩이 양끝에 128px씩 틈을 남기고 바닥 높이에 맞춰진다. 버튼은 **한 번 누르면 유지** 모드다. 플레이어가 버튼에서 내려온 뒤에도 길이 유지되도록 했다. 보관 위치는 천장 안이며 내려오는 동안 천장과 겹치는 것은 의도된 이동 경로다.

### 폭포와 수문

새 `scripts/스마트월드/폭포_수문묶음.gd`는 기존 원형 레버의 `켜짐` 계약을 구현한다. 레버 하나가 같은 방의 폭포 두 개를 끄고 수문을 위로 640px 이동시킨다. 색만 바꿔 물을 지나더라도 닫힌 수문이 남아 레버 조작의 목적이 유지된다. 에디터에서는 장치를 움직이지 않는다.

### 투명 발판

WALL SS2D에 `시작상태=무색`, `무색일때_통과=true`, 필요 발수 1을 설정했다. 상부 지름길 폭 864px가 기본 전체 칠 한도 576px를 넘으므로, 투명 부품에만 `전체_색칠_최대긴변=1024`를 명시했다. 큰 바닥 전체에 이 예외를 확장하지 않았다.

### 붕괴 발판

기존 `scripts/장애물/무너지는발판.gd`는 예전 PaintPlatform 시스템용이다. 최신 사용자 요청을 구현하기 위해 해당 부품을 그대로 넣는 대신, 새 `scripts/스마트월드/SS2D_붕괴발판.gd`가 현재 `지형.gd`를 상속하도록 했다. 예전 제작 문서의 보류 부품을 검증된 것으로 표시하지 않았다.

- 실제 플레이어의 바닥 충돌이 자신을 가리키는지 확인해 밟힘을 감지한다.
- 표면 균열 표시, 밟은 뒤 0.9초간 알파 점멸, 이후 충돌 해제와 희미한 잔상.
- 3초 뒤 복구하되 플레이어가 복구 영역 안에 있으면 비킬 때까지 기다린다.
- 무너진 동안 덮어칠·회수로 충돌이 다시 켜지지 않게 한다.
- 좌표를 흔들지 않아 StaticBody2D가 플레이어를 밀어내지 않게 했다.
- SS2D 점 편집, 기존 텍스처와 페인트코어 계약을 유지한다. 에디터에서는 타이머를 실행하지 않는다.

### 부활 위치

새 `scripts/스마트월드/하강수로_월드.gd`는 기존 월드를 상속하며 안전지점 저장만 제한한다. 각 방의 지정된 고정 바닥 구간에서 검정 상태일 때만 기존 바닥 레이·낙하 위험·저장 유예 검사를 수행한다. 투명·붕괴·이동 발판이 사라진 위치를 자동 부활 지점으로 저장하지 않기 위한 새 맵 전용 설정이다.

## 확인 결과와 한계

완료한 정적 확인:

- 작성 도구의 JavaScript 문법 확인 및 기본 읽기 전용 `--check` 비교.
- 25개 SS2D의 시계 방향·16px 격자·90px 이상 변 길이 확인.
- 오목 윤곽 삼각분할 후 내부 겹침 0개. 공유 경계 접촉은 겹침으로 세지 않았다.
- 직접 리소스 파일·내부 참조·중복 노드 경로·상대 NodePath 연결 확인.
- 페인트코어 그룹 직렬화 확인. 월드와 분사기의 코어 검색 계약에 필요하다.
- 다리가 배치된 상태에서 분사기 아래 첫 지형은 각각 이동 다리·투명 발판2·붕괴 발판2다. 폭포가 흐르는 상태에서는 유체가 발사체를 먼저 막을 수 있다.
- 점프 수식상 96px 높은 착지면까지 수평 거리 약 273.9px. 첫 지름길의 틈 224px와 같은 높이 징검다리 최대 틈 256px를 좌표로 확인했다. 실제 입력·충돌 검사는 아니다.
- 새 GDScript 3개의 문자열·괄호 기본 균형과 상속 경로를 텍스트로 확인했다. **GDScript 엔진 파싱을 통과했다는 뜻은 아니다.**
- `git diff --check` 오류 없음. Git 삭제 변경 및 누락 추적 파일 목록은 비어 있었다.

**미실행:** Godot 편집기·콘솔·headless·레벨검사·주행검사·저장소 엔진 회귀검사. 사용자 안전 예외에 따라 엔진을 실행하지 않았다. 아래 항목은 향후 엔진 실행을 명시적으로 요청받았을 때 확인할 사항이다.

1. 새 GDScript 로드와 실제 붕괴 감지, 충돌 해제, 몸 안에서 복구하지 않는 동작.
2. 버튼에서 내려온 뒤 다리가 유지되는지, 이동 중 충돌과 라이더 동작.
3. 레버 양방향 조작 시 두 폭포와 수문이 일관되게 전환되는지.
4. 투명 발판을 각각 칠하고 회수할 때 상부·하부 경로가 유효한지.
5. 검정 물받이의 반대색 탄 차단, 색을 맞춘 실제 낙하, 재시도 및 부활.
6. 실제 카메라 모서리 화면, 화면비 변화, 분사기 타이밍과 전체 난이도.

## 작업 보존과 환경

2-10·2-9·2-8 씬과 기존 공용 스크립트를 재작성하지 않았다. 새 작성기는 기본 실행 시 읽기 전용이며 `--write`를 명시할 때 2-11 씬과 배치표만 쓴다. **사용자가 2-11을 편집한 뒤에는 작성기를 다시 쓰지 말 것.**

작업 시작 보존 해시:

- 2-10: `26B699C42C29F9C48F7A972E8E59ABB2A192974FB35425B72CBB40023ADB2892`
- 2-9: `83D35215A0D936F4421287E523C8744D40D406D23E3D69762D21FF1D3CE732B5`

최종 확인에서도 두 씬의 해시가 작업 시작 값과 일치했다. 최종 배치표로 설계도 이미지를 다시 만들고 육안으로 전체 위치·표시를 확인했다.

`git pull --ff-only`는 `.git/FETCH_HEAD` 접근 권한 문제로 실패했다. 동기화 완료로 보고하지 않는다. 커밋·푸시하지 않았다.

지식 그래프 파일이 없어 원본 코드를 읽었다. 변경 후 `graphify update .`는 `uv trampoline failed to canonicalize script path`로 실패했다. 그래프 갱신은 미완료다.
