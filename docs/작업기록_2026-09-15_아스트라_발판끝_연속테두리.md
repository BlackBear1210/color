# 발판 끝부분과 길이 변경 시 테두리 처리

## 원인과 변경

side.png의 왼쪽에는 대각선 끝마감이 포함되어 있어 길게 반복하면 끝마감이 중간에도 나타났다. top/side/corner는 높이가 각각 53/49/56px여서 같은 0.16 배율에서 두께도 달랐다. 네 방향을 서로 다른 edge meta로 나누면 전체 외곽을 한 번에 용접할 수 없었다.

흑백 masonry 재질을 각각 하나의 전방향 edge meta로 통합했다. 끝마감이 없는 top.png를 사용하고 corner 텍스처 배열을 제거했으며 use_corner_texture=false, use_taper_texture=false로 설정했다. 마지막 꼭짓점 생성 경로가 모서리 배열을 확인하므로 배열도 제거했다. uniform_width=true, weld=true로 SS2D의 미터 조인을 사용한다. 아트 재생성이나 애드온 공통 코드 변경은 하지 않았다.

## 늘리기·줄이기

fit_mode=1(CROP)을 유지한다. 반복 주기는 284×0.16=45.44px, 수직 두께는 53×0.16=8.48px로 일정하다. 길이가 160/340/680/1360px로 바뀌어도 텍스처를 한 장으로 늘리지 않고 반복 횟수만 달라진다. 채움의 fill_texture_scale과 위치 기반 UV 설정도 유지한다.

맵 제작자는 **SS2D 점을 이동**해 길이와 높이를 바꾼다. 루트나 부모 Scale은 (1,1)을 유지한다. 노드 자체를 비균일 확대하면 테두리도 늘어나므로 이 사용법까지 자동 보정한다고 보장하지 않는다. 여섯 공중 발판의 editor_description에 안내를 넣었다. 두께 24px 미만 또는 아주 예리한 모서리는 테두리끼리 겹치거나 미터 한계가 적용될 수 있으므로 피한다.

## 검증 범위

정적 확인: 흑백 재질 모두 하나의 전방향 meta, corner 배열 없음, CROP, uniform_width, weld, 같은 반복 주기와 두께. 참조 PNG와 흑백 짝 존재. 씬의 점과 충돌 폴리곤은 변경하지 않았다. git diff --check 확인.

Godot 실행·확대 화면·132개 색칠사망 검사는 이번에 미실행이다. 따라서 끝부분의 실제 화면이 완전히 자연스러워졌다고 검증 완료를 선언하지 않는다. 기존 top 이미지 자체의 반복 이음이나 재질 느낌을 새 심리스 아트로 개선하는 작업은 별도다.
