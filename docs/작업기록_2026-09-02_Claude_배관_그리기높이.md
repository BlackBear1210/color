# 작업기록 2026-09-02 · Claude — 배관을 물 위로 (인스펙터 `깊이`)

> **한 줄 요약**: 배관 두 종류 모두 인스펙터에 **`깊이`(z_index)** 를 두고, 기본값을
> **3** 으로 맞췄다. 유체는 0·1·2 세 겹을 쓰므로 3 이면 항상 물 위다.

- 지시: 성진님 — "배관이 유체보다 위에 있게 하고 싶어. 2D 워크스페이스에서 배관이
  유체(물) 밑에 있는 게 싫어. 높이를 설정할 수 있게 인스펙터에도 넣어놔."
- 고친 파일
  - `scripts/스마트월드/배관_SS2D_끝마개.gd` — `깊이` **신설** (SS2D 배관)
  - `scripts/스마트월드/배관.gd` — `깊이` 기본값 **2 → 3**
  - `docs/SS2D_배관_유체_맵제작_가이드_2026-09-01.md`
- 새 파일: `tools/test_배관_유체_높이.gd` (통과 9 · 실패 0)
- ⚠ 씬 파일은 안 건드렸다. 값이 스크립트 기본값에서 나오므로 손댈 필요가 없었다.

---

## 1. 무엇이 문제였나

배관이 **두 종류**인데 둘 다 물에 깔렸고, 원인이 서로 달랐다.

| 배관 | 쓰는 곳 | 문제 |
|---|---|---|
| SS2D 배관 (`TEMPLATE_PIPE_OPEN_GRAY`) | stage_2-1 | 높이 설정이 **아예 없었다** (z 0 고정) |
| 옛 배관 (`배관.tscn` · `배관.gd`) | stage_2-2 · 2-3 | `깊이` 기본 **2** = 물결 상세와 **같은 높이** |

유체는 세 겹으로 그려진다(`유체.tscn`):

```
유체 (Area2D)              z  0  → 실효 0
 ├ 물_애니메이션            z +1  → 실효 1
 └ 물결_상세_애니메이션      z +2  → 실효 2
```

자식 z 는 부모에 **더해지는 상대값**이다(`z_as_relative` 기본 켜짐).

★ 옛 배관의 2 가 특히 나빴다. 물결 상세와 **높이가 같으니** 누가 위로 갈지가
**트리 순서**로 갈린다 → 어떤 배관은 물에 깔리고 어떤 것은 안 깔리는,
**재현이 안 되는** 상태였다. "가끔 그래요" 로 보고되기 딱 좋은 종류다.

---

## 2. 어떻게 고쳤나

두 스크립트 모두 인스펙터에 `깊이`(int) 를 두고 기본값 **3**.

```gdscript
@export var 깊이: int = 3:
	set(v):
		깊이 = v
		z_index = v
```

배관에 값을 주면 이렇게 퍼진다:

| 부분 | 실효 높이 |
|---|---|
| 배관 본체(`경로`) | `깊이` |
| 끝마개 Sprite 2 개 | `깊이 + 1` (자기 z 가 1 이다) |

**값 고르는 법**

| 하고 싶은 것 | `깊이` |
|---|---|
| 물 위로 (기본) | **3** |
| 지형 뒤로 숨기기(배경처럼) | 음수 (예: -6) |
| 더 앞으로 | 4~28 (플레이어 이펙트가 29~30) |

`@tool` 이라 **에디터 2D 화면에서 값을 바꾸면 그 자리에서 순서가 바뀐다.**

---

## 3. ★ 함정 — GDScript 는 **멤버 초기화식에서 세터를 안 부른다**

처음에 SS2D 배관에 세터만 달고 `_ready()` 에는 아무것도 안 넣었다.
"씬을 읽을 때 세터가 불리니 충분하다"고 봤는데 **틀렸다.**

검사가 바로 잡아냈다:

```
── SS2D 배관
    배관_SS2D : 실효 0        ← 3 이어야 하는데 0
      경로 : 실효 0
  ✖ 가장 낮은 부분(0)도 물의 가장 높은 겹(2)보다 위다
```

`@export var 깊이: int = 3` 의 **`= 3` 은 세터를 거치지 않고** 백킹 변수에 바로 들어간다.
세터는 **씬이 그 값을 저장해 뒀을 때만** 불린다. 그러니 값을 덮어쓰지 않은
인스턴스는 `z_index` 가 0 인 채로 남는다.

→ `_ready()` 에서 한 번 반영한다:

```gdscript
func _ready() -> void:
	z_index = 깊이     # ★초기화식은 세터를 안 부른다 → 여기서 한 번 반영한다
```

⚠ 단, `_ready()` 에 **상수를 박으면 안 된다.** `@tool` 이라 에디터에서도 돌기 때문에
디자이너가 인스펙터에서 올린 값을 씬 열 때마다 되돌려 버린다.
`배관.gd` 가 예전에 `z_index = -6` 으로 정확히 그 사고를 냈고, 그 주석이 아직 남아 있다.
**변수를** 반영하는 것은 안전하다 — 값의 출처가 인스펙터 한 곳이기 때문이다.

---

## 4. 옛 배관 인스턴스는 어떻게 되나

stage_2-2 의 배관들은 씬에 `z_index = 2` 가 덮어쓰기로 저장돼 있다.
그런데 `배관.gd::_ready()` 가 `z_index = 깊이` 로 **덮는다** → 기본 3 이 적용된다.
그게 의도다. 높이의 출처를 인스펙터의 `깊이` **한 곳**으로 모으려는 것이고,
그 뜻을 코드에 주석으로 적어 뒀다.

특정 배관만 물 뒤로 보내고 싶으면 그 인스턴스의 `깊이` 에 음수를 주면 된다.

## 6. 다음 사람이 알아야 할 것 (지뢰 추가)

**`@export var x = 3: set = f` 의 `= 3` 은 세터를 안 부른다.**

- 증상: 인스펙터 기본값은 3 인데 세터가 하는 일(여기서는 `z_index` 반영)이 **안 일어난다.**
  값을 한 번이라도 덮어쓴 인스턴스만 제대로 돌아서 **일부만 되는** 것처럼 보인다.
- 확인: 기본값 그대로인 인스턴스에서 세터가 만지는 쪽(`z_index` 등)을 찍어 본다
- 해결: `_ready()` 에서 **그 변수를** 한 번 반영한다. **상수를 박지 말 것**
  (`@tool` 이면 에디터에서 인스펙터 값을 되돌려 버린다)
