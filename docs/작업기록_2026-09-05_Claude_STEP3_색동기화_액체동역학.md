## 1. 먼저 실측한 것 (§1) — 코드를 고치기 전에

### Player 색 렌더링의 실제 구조

```
자유색  (Shift 로만 바뀌는 유일한 상태값)
  │
  ├─ 색경계.분할_셰이더값()  →  color_table (조각마다 0=검정 / 1=흰색)
  │                              ↓
  │                        색분할.gdshader
  │                          "내 sheet_color 와 다른 조각은 discard"
  │                              ↓
  ├─ CharacterSprite (AnimatedSprite2D)  sheet_color = 애니 접두어로 결정
  └─ └ 색겹침       (AnimatedSprite2D)  항상 부모의 **반대색** 시트를 같은 프레임으로 재생
```

즉 흑·백 시트 **두 장이 늘 겹쳐 있고**, 셰이더가 조각마다 하나만 남긴다.
"Player 를 흰색으로 만든다"는 것은 `color_table` 이 1 이 되는 것이고, 그건
`자유색` 에서 이미 나온다.

### 그래서 실제 화면을 재 봤다 (헤드리스가 아니라 렌더링을 켜고)

| 자유색 | color_table | CharacterSprite | 색겹침 | 화면의 밝은 픽셀 | HUD 초상 | 게이지 잉크 |
|---|---|---|---|---|---|---|
| BLACK | (0,0,0,0) | black_idle | white_idle | 601 | black_walk | (0.07,0.07,0.07) |
| WHITE | (1,1,1,1) | white_idle | black_idle | **2133** | white_walk | (0.95,0.95,0.93) |

→ **결론: Player 전체 색 동기화는 이미 동작하고 있었다.** 스크린샷에서도 월드의 캐릭터가
흰색으로 바뀌는 것을 눈으로 확인했다. 그래서 **색분할 시스템을 교체하지 않았다.**
(도형님 §0 의 금지사항: modulate 금지 · 색분할 교체 금지 — 둘 다 할 필요가 없었다)

### 다만 하나가 어긋나 있었다 — `player_anim.gd`

```gdscript
# 고치기 전
_color = "black" if _player.player_color == ColorDefs.BLACK else "white"
```

이 한 줄이 **어느 시트를 부모로 재생할지**를 `player_color`(대표색)로 골랐다.
대표색은 몸이 색 경계에 걸치면 **물리 프레임마다 뒤집히는 파생값**이라, 그때마다
접두어가 바뀌어 `_switch()` 가 `play()` 를 다시 부르고 **걷기 애니메이션이 첫 프레임으로
계속 리셋**된다.

보이는 색은 셰이더가 정하므로 접두어를 `자유색` 으로 바꿔도 **그림은 똑같다.**
떨림만 사라진다. → `선택색()` 으로 교체했다(§2 의 "셋 다 자유색 하나만 본다" 와도 일치).

## 2. 색 3중 동기화 (§2 · §11)

```
player.자유색  ← Shift
   │
   ├── 실제 Player 그림 : 색분할.gdshader 의 color_table (원래부터 이랬다)
   ├── HUD 초상        : black_walk ↔ white_walk  (STEP 2)
   └── 게이지 잉크      : liquid_color            (STEP 2)
```

세 곳 모두 `player.선택색()` 이라는 **하나의 창구**만 본다. `player_color` 를 읽는 곳은
이제 총알 색(`얼굴색()`)뿐이고, 그건 "위치의 함수"가 맞는 자리다.

검사(`tools/test_HUD_액체동역학.gd`)가 스테이지마다 자유색을 뒤집어
**Player 시트 · 초상 시트 · 잉크색 셋이 동시에** 맞는지 확인한다.

## 3. 액체 동역학 (§5~§8)

STEP 2 가 뚫어 둔 uniform 을 `페인트_HUD.gd` 의 `_액체_동역학()` 이 굴린다.

### ⚠ 절대 규칙 — 채움 높이는 안 건드린다
`fill_level` 은 **언제나** `페인트HUD어댑터.탄약()` 의 `남은/최대` 그대로다.
동역학이 만지는 것은 **수면의 기울기·잔물결·충격**뿐이다(§7).

### 최종 값 (전부 `Player > ActionFX` 가 아니라 **HUD 씬 루트 인스펙터**에서 조절)

| 인스펙터 | 값 | 뜻 |
|---|---|---|
| `잔물결_크기` | 0.006 | 정지 상태 잔물결. "눈치채면 움직이는" 정도 |
| `잔물결_주기` | 1.4 | 파장 |
| `잔물결_속도` | 0.45 | 느리게 — 물이 아니라 잉크 |
| `이동_기울기` | 0.085 | 좌우 이동 시 최대 기울기 |
| `기울기_방향` | **+1 = 관성** | 오른쪽으로 가면 잉크가 왼쪽에 쏠린다 |
| `기울기_추종` | 3.2 | 낮을수록 무겁고 늦게 따라온다 |
| `충격_감쇠` | 5.0 | 발사 충격이 ~0.9초에 가라앉는다 |

잔물결은 흔들릴수록(기울기·충격) 최대 2.2 배까지 커진다 —
"무거운 잉크가 출렁이다 가라앉는다"로 읽히게 하려는 것이다.

### ⚠ 기울기 부호 — 지시서와 시안이 서로 반대라 시안을 따랐다
- 지시서 §7 예시: "velocity.x > 0 → 수면이 아주 조금 **오른쪽으로** 기울어짐"
- 도형님 시안 이미지: "오른쪽 이동 시 액체가 **왼쪽으로** 기울어짐"
- 같은 §7 본문: "액체가 아주 조금 **늦게 따라오는** 느낌"

"늦게 따라온다" = 관성이고, 시안도 관성이라 **관성**으로 넣었다.
`기울기_방향` 을 −1 로 바꾸면 인스펙터에서 즉시 반대로 뒤집힌다.
셰이더 부호 관계도 코드 주석에 적어 뒀다(UV.y 가 아래로 커져서 헷갈리기 쉽다).

### 발사 충격 (§8)
**총·총알·Paint Impact 를 한 줄도 안 건드렸다.**
HUD 가 어댑터의 `남은` 값이 바뀌는 것을 스스로 알아채서 튄다.
- 줄면 충격 1.0, 환급으로 늘면 0.45 (조용히 차오르면 무슨 일이 났는지 모른다)
- 화면 흔들림·큰 UI 효과는 넣지 않았다

## 4. 게이지 대비 (§10)

흰 잉크가 가득 차면 **순백색 원 하나**로 뭉개지던 문제를 알파를 낮추지 않고 고쳤다
(§10 이 알파 낮추기를 금지했다).

`HUD_액체.gdshader` 에 두 가지를 더했다.
1. `edge_shade` — 그릇 벽 쪽으로 갈수록 잉크가 어두워진다 → 평면이 아니라 **둥근 액체 덩어리**로 읽힌다
2. 수면선 바로 아래의 얇은 그늘 띠 → 액체에 **두께**가 생긴다

수면선(`foam_color`)은 여전히 잉크의 반대 톤이라 흑·백 어느 쪽에서도 보인다.

## 7. ★확인이 필요한 설계 경계 — 강제색 구역 안의 Player

스크린샷 검수 중에 하나 발견했다. `world_1/1-1/stage_1-1.1` 에서
**자유색 = WHITE 인데 월드의 캐릭터가 검게 보이는 자리**가 있다.

실측해 보니 원인은 명확하다.

```
플레이어 위치 (8373, -4140) 의 강제색 = 0 (BLACK)   ← ColorZone 이 색을 강제하는 구역
셰이더 color_table = (0,0,0,0)  → 검정 시트만 남는다
부모 시트 애니 = white_fall     → 자유색은 WHITE 그대로다
HUD 초상·게이지 = 흰색          → 선택 상태를 보여준다
```

즉 **버그가 아니라 `색경계` 시스템의 규칙**이다(2026-08-23 설계).
경계 구역 안에서는 몸의 색이 구역에 의해 강제되고, 색이 안 맞으면 죽는다 — 그게 퍼즐이다.
지시서 §4 도 "대표색이 경계 지형의 색에 영향을 받아도 **선택색 자체가 변경되면 안 된다**"
라고 했고, 그 조건은 지켜진다(자유색·HUD 모두 안 바뀌고, 깜빡임도 0.000).

**다만 이 순간 HUD 와 월드 캐릭터의 색이 다르게 보인다.** 두 가지 해석이 가능하다.

| 안 | 뜻 | 지금 |
|---|---|---|
| A | HUD 는 **내가 고른 색**을 보여준다 (지금 동작) | ★현재 |
| B | HUD 는 **지금 몸이 실제로 띠고 있는 색**을 보여준다 | 미구현 |

A 는 "다음에 쏠 색 / Shift 상태"를 알려주고, B 는 "지금 내가 어느 색이라 어디서 죽는지"를
알려준다. 어느 쪽이 맞는지는 **기획 결정**이라 임의로 고르지 않고 그대로 두었다.
B 로 가려면 HUD 의 `_잉크색()` 한 함수만 `색_at(몸 중심)` 으로 바꾸면 된다.

## 8. 다음 사람이 알아야 할 것

1. **액체를 조절하려면** `scenes/ui/페인트_HUD.tscn` 루트의 "액체 동역학" 그룹 7 값만 만진다.
   셰이더나 스크립트를 안 고쳐도 된다.
2. **기울기가 반대로 느껴지면** `기울기_방향` 을 −1 로 바꾼다. 그게 전부다.
3. **`fill_level` 에 손대지 말 것.** 그건 실제 탄약이고, 여기에 연출을 섞으면
   "게이지가 실제 탄약과 다르다"는 최악의 버그가 된다.
4. **흰색으로 검은 지형 위에 서면 죽는다**(색 규칙). 리스폰이 `코어.리셋()` 을 불러
   탄약이 가득 찬다 — 검사에서 색·탄약을 조작할 때는 **색을 먼저, 탄약을 나중에**.
