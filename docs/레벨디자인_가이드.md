## 1. 구역(룸) 설계 4원칙

1. **1구역 = 1아이디어.** 새 요소(첫 회수, 첫 회색, 첫 전환 잠금...)는 반드시 낙사 없는 안전한 구역에서 처음 등장. (Celeste GDC 원칙)
2. **기승전결 배치.** 지역(지하/경계/하늘)마다: 기(안전 소개) → 승(약간 복잡) → 전(비틀기: 다른 요소와 결합) → 결(종합 시험). (닌텐도 하야시다 공식)
3. **긴장-휴식 교차.** 발사·점프가 밀집된 구역 뒤에는 걷기만 하는 감상 구역(배경 보여주기 + 체크포인트). 색의 흔적 연출 3곳이 곧 휴식 지대. (리듬 그룹 이론, Smith et al. 2011)
4. **완성 기준 = 제3자 테스트 통과.** 매주 일요일 전원 플레이테스트에서 관찰: 어디서 멈칫? 어떤 색 규칙을 오해? 의도 밖 해법? (Portal/Valve 기준)

## 2. 물감 이코노미 설계 공식 (★이 게임 레벨디자인의 핵심)

> ⚠ **v1.2 (2026-07-14) 규칙 변경**: 게이지 폐지 → 발사 무제한. 이코노미의 축이
> "잔량 관리"에서 **"발판별 필요 횟수(내구도 1~3발) + FIFO 회수 순서 + 회색 리스크"**로 이동했다.
> 아래 표의 S(최소 발수)는 이제 "정답 루트에 필요한 총 명중 수(발판 내구도 합)"로 읽고,
> P(지급 물감)는 폐기. 여유분 대신 **내구도 배치**(중요 발판일수록 비싸게)로 난이도를 조절한다.
> 추가 배치 규칙(결정⑫): **흑 발판 군집과 백 발판 군집은 붙여 배치 금지** — 함께 쓸 경우
> 최소 4타일 이상 띄우고, 그 사이는 칠하기 또는 색 전환으로만 건너게 한다.

구역을 설계할 때 반드시 이 표를 채운다:

| 항목 | 기호 | 규칙 |
|---|---|---|
| 해법에 필요한 최소 발수 | S | 설계자가 정한 정답 루트의 발사 횟수 |
| 지급/보유 물감 | P | **P = S + 여유분** (아래 난이도표) |
| 필요한 회수 횟수 | R | FIFO 순서가 꼬이지 않는지 손으로 시뮬레이션 |
| 회색 함정 수 | G | 반대색을 유도하는 배치가 몇 곳인가 |

**난이도별 여유분:**

| 지역 | 여유분 | 회색 함정 | FIFO 깊이(회수 계획 단계 수) |
|---|---|---|---|
| 지하 1~4 (튜토리얼) | S+3 이상 | 0 | 0~1 (회수 없이 클리어 가능) |
| 지하 5~12 | S+2 | 0~1 | 1~2 |
| 경계 13~18 | S+1~2 | 1~2 | 2~3 |
| 하늘 19~28 | S+1 | 2~3 | 3~4 |
| 최종 29~30 | S+1 | 최대 | 배운 것 전부 |

**소프트락 금지 3규칙 (전 구역 절대 준수):**
1. 회색을 아무리 만들어도 **회수 가능한 발판만으로 체크포인트까지 복귀**할 수 있어야 한다. (회색이 유일 경로를 막을 수 있는 배치 금지)
2. 물감 0 + 회수할 것 없음 상태가 **물리적으로 불가능**해야 한다. (칠할 것이 있어야만 진입 가능한 구조로)
3. 그래도 갇히면: 체크포인트 재시작 버튼(일시정지 메뉴)이 최후 탈출구 — P-B에 요청 완료 항목인지 확인.

## 5. 가독성 규칙 (색이 곧 규칙이므로)

| 요소 | 명도 | 비고 |
|---|---|---|
| 흑 발판 | 0~10% | 외곽 플랫 실루엣 (그라데이션 금지 — 콜리전 경계가 점프 기준선) |
| 백 발판 | 90~100% | 〃 |
| 회색(죽은 지형) | 45~55% | **이 명도대는 회색 발판 전용.** 배경 침범 금지 |
| 무색(칠 가능) 발판 | 점선 외곽 or 70% 중간톤 + 패턴 | "칠할 수 있음"이 한눈에 보여야 함. ART와 W2 확정 |
| 배경 | 15~40% / 60~85% (지역별) | 45~55% 대역 회피, 원경일수록 밝고 흐림 |
| 전환 존(V3) | 명도 아닌 **형태**로 표시 (테두리 문양) | 색을 쓸 수 없으므로 |

- 배경은 컬러 원화 + 전역 채도0 셰이더로 자동 흑백화되므로, ART에게는 "명도만 위 표에 맞춰달라"고 전달하면 됨.

## 8. 수직 레벨 · 낙하 사망 시대의 수치 규칙 (2026-08-06 추가)

> 스마트월드에 **낙하 거리 기반 즉사**(`scripts/스마트월드/낙하_감시.gd`)가 들어가면서
> 레벨 디자인 문법이 하나 늘었다. 이 절의 숫자는 전부 **플레이어 실제 물리에서 역산**한 값이고,
> `tools/레벨검사.gd` 가 씬을 띄워 실측으로 다시 확인해 준다.

### 8-1. 기준 수치

| 항목 | 값 | 출처 |
|---|---|---|
| 점프 높이 | **160px** | 점프_높이_칸 10 × 타일 16px |
| 점프 거리 | **320px** | 점프_거리_칸 20 × 타일 16px |
| 도약대 상승 | **418px** | 도약속도 −1500 · v²/(2·gravity·상승_배수) |
| 치명 낙하 거리 | **520px** | 점프 높이 × 3.25 (`월드.gd.치명_낙하거리`) |
| 플레이어 콜리전 | 폭 50px · 높이 47px | Player.tscn (scale 반영 실측) |

### 8-2. 배치할 때 지킬 값

| 규칙 | 값 | 안 지키면 |
|---|---|---|
| 올라가는 단차 | **≤ 110px** | 못 올라가서 갇힌다 (판정선 128px · 여유 18px) |
| 가로 간격 | ≤ 260px | 못 건넌다 (점프 거리 320px × 0.85) |
| 의도치 않은 낙차 | ≤ 520px | 그냥 죽는다 |
| 발판 위 머리 공간 | **≥ 52px** | 겹쳐서 **설 수가 없다** ← 겹침 사고 1위 |
| 통로 안 높이 | ≥ 100px | 통로에 못 들어간다 |

> ⚠ **"명목 간격"과 "실측 간격"은 다르다.**
> 선반은 두께가 서로 다르고 윗면이 살짝 기울어 있어서, 노드를 125px 간격으로 놓으면
> 실측 단차가 **131px** 로 나온다(실제 사고 사례). 명목값은 판정선보다 **15px 이상** 여유를 둘 것.

### 8-3. "구멍 = 죽음" 을 지형 언어로 만들기

낙하 사망을 넣었으면 **플레이어가 그 규칙을 지형만 보고 배울 수 있어야** 한다.

- 죽이려는 구멍은 **반드시 520px 보다 깊게** 판다. 어중간하면 "왜 죽었지?" 가 된다.
- 죽이지 않으려는 낙차는 **400px 이하**로 잡는다(경고 비네트도 안 뜬다).
- 구멍 가장자리에는 **광원을 둔다.** 안 보이는 함정은 불합리하다.
- 깊은 곳으로 내려가는 정식 루트는 **선반을 110px 간격으로 좌우 엇갈려** 깐다.
  → "조심히 내려가면 살고, 뛰어내리면 죽는다" 가 그림만으로 읽힌다.
- 내려간 곳에는 **반드시 올라올 길**을 둔다(선반 사다리 또는 도약대).
  없으면 죽지도 못하고 갇히는 진짜 소프트락이 된다.

### 8-4. 도약대를 놓을 때

- 상승 418px 은 치명 거리(520px)보다 **작다** — 받아줄 발판이 없어도 죽지는 않는다.
- 하지만 `도약속도` 를 키워 상승이 520px 을 넘기면 **도약대 자체가 자살 장치**가 된다.
- 도약대 위 상승 높이 지점에 **받아줄 발판이 있는지 반드시 레벨검사기로 확인**할 것.

### 8-5. 레벨을 고쳤으면 이걸 돌린다

```bash
Godot --headless --path . -s res://tools/레벨검사.gd -- <씬경로> --지도
```

| 보고 항목 | 뜻 | 대응 |
|---|---|---|
| `[도달불가]` | 시작 지점에서 갈 수 없는 발판 | 배치 실수 또는 죽은 콘텐츠 |
| `[소프트락]` | 들어가면 출구까지 못 가는 곳 | 올라올 길을 만든다 |
| `[치명낙하]` | 걸어 나가면 죽는 가장자리 | **오류 아님** — 의도한 구멍이면 그대로 |
| `ⓘ …로 갈 뻔했다` | 몇 px 만 조정하면 닿는 후보 | 그 숫자만큼 발판을 옮긴다 |

`--상세` 를 붙이면 선반 하나하나와 그 이웃을 전부 찍는다. "내가 생각한 y" 와 "실측 y" 가
다를 때 원인을 찾는 용도.
