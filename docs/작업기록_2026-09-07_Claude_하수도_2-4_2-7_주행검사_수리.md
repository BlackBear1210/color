## 1. 코드 버그 세 개 (맵이 아니라 스크립트 쪽)

이 셋은 **하수도 밖에서도 터진다.** 먼저 적는다.

### ① `player.gd` — 박스·양동이를 **정면으로는 한 번도 못 밀었다**

```gdscript
move_and_slide()
_양동이_밀기_시도()          # 여기서 velocity.x 를 본다
```

`move_and_slide()` 는 벽 법선 방향 성분을 지운다. 상자를 **정면으로** 밀면 그 순간
`velocity.x` 가 0 이 되고, 밀기 시도가 첫 줄 `if absf(velocity.x) < 1.0: return` 에서
그냥 돌아간다. 즉 **미는 힘이 전달된 적이 없다.**

→ 미는 방향을 `move_and_slide()` **전에** 붙잡아 넘긴다.

```gdscript
var 밀_방향 := signf(velocity.x)
move_and_slide()
_양동이_밀기_시도(밀_방향)
```

실측: 2-7 관문 2 에서 플레이어가 박스에 붙은 채(`벽=true 충돌수=1`) `vx=0` 으로
4초를 밀고 있어도 박스가 1px 도 안 움직였다.

### ② `압력버튼.gd` — 메타 이름이 **ASCII 여야 한다**

`set_meta("_압력버튼_원래위치", …)` → 밑줄로 시작해서 거부.
어제 밑줄만 뗐더니 이번엔 **한글이라서** 거부됐다(`Object::set_meta` 는 ASCII 식별자만 받는다).
씬을 열 때마다 `Invalid metadata identifier` 가 뜨고 원래 위치가 한 번도 안 적혔다.

→ `set_meta("pressure_button_origin", …)`.

> ⚠ [2026-09-07 도형님] **이름은 이대로 둔다.** 나중에 한글로 바꿔 보고 싶어서 직접 손보기로 했다.
> 참고 — `Object::set_meta` 는 ASCII 식별자만 받으므로 **한글 메타 이름은 엔진이 거부한다.**
> 한글 이름을 쓰고 싶으면 메타 대신 스크립트 변수(예: `var _원래위치: Dictionary`)에 담으면 된다.

### ③ `.tscn` 의 `PackedStringArray` 에는 **대괄호를 쓰지 않는다**

```
"누름_가능_그룹" = PackedStringArray(["player"])   ✖ 씬 전체가 파싱 실패
"누름_가능_그룹" = PackedStringArray("player")     ✔
```

`stage_2-7.tscn` 에 6곳 있었고, 그래서 **씬이 통째로 안 열렸다**(`Parse Error ... :131`).
`scenes/world_2_클로드/하수도_오브젝트_사용법.md` 가 대괄호 쓴 예를 적고 있었다 — 문서도 고쳤다.

## 4. ★양동이가 물을 못 받는다 — 다음에도 똑같이 터진다

`양동이.tscn` 의 `물감지` Area2D 는 원점 기준 **y −102 ~ −26** 이다.
양동이가 바닥(1,100)에 서면 실제 범위는 **1,008 ~ 1,084**.

그런데 2-6·2-7 의 양동이용 물줄기는 전부 **y 1,010 에서 끝났다.** 겹침이 **2px** 뿐이고,
물 판정은 [2026-09-02 변경] 이후 **프레임마다 흔들리는 그림 실루엣**이라
그 2px 은 사실상 한 번도 안 닿는다 → `물참` 이 영원히 false → 버튼이 안 눌린다.

→ 양동이를 채우는 물줄기는 **아랫끝을 1,060 이하로** 내린다(겹침 50px).

| 규칙 | 값 |
|---|---|
| 양동이 물감지 범위 (바닥 1,100 기준) | y 1,008 ~ 1,084 |
| 채우는 물줄기의 아랫끝 | **1,060 이하** |
| 길을 막는 물줄기의 아랫끝 | **1,100**(바닥까지). 1,000 에서 끊으면 여유가 4px 뿐이다 |

## 4-2. ★[2026-09-07 추가] 2-6 은 양동이가 물줄기까지 **갈 수가 없다**

`player.gd` 밀기 버그(§1-①)를 고친 뒤 2-6 에서 양동이를 실제로 밀어 봤다.

```
밀기 양동이_검정_1 → 1310    (940 → 1189 까지 밀림)  ✖ x=1189 에서 멈춤
```

밀기 자체는 고쳐졌다(전에는 1px 도 안 움직였다). 멈춘 이유는 **물받이 호퍼**다.

| | 범위 |
|---|---|
| 양동이 몸통 (바닥 1,100 에 섰을 때) | y **1,000 ~ 1,094** |
| `양동이용_호퍼_*` 의 밟는면 (y 1,080 · 높이 56) | y **1,024 ~ 1,036** |
| 양동이용 물줄기 | x 1,262 ~ 1,358 |

호퍼의 밟는면이 **양동이 몸통 한가운데 높이**에 있어, 양동이가 x 1,235 에서 막힌다.
물줄기는 1,262 부터라 **영원히 안 닿는다.** 2-6 의 호퍼 6개가 전부 y 1,080 이다
(2-7 은 호퍼 없이 물이 바로 양동이에 떨어져서 정상 작동한다).

→ 고치려면 호퍼를 **y 1,044 이하**로 올린다(밟는면 아랫변이 양동이 윗면 1,000 위로 나가야 한다).
  예: y 1,030 이면 밟는면이 974~986 이 되어 양동이(1,000~)와 플레이어 머리(1,004)를 둘 다 비켜간다.

# [2026-09-07 추가] 2-2 관문 4 곁방 — 지나갈 수 있게 고침

> 도형님 지적: "가는 길에 막히지 않냐. 실제 플레이어가 되어서 검수하라고 했잖아."
> 맞다. 본선만 태우고 **곁방은 회색을 걷어낸 뒤 다시 안 봤다.** 공략에 곁방 왕복을 넣어
> 실제로 태우니 **네 겹으로 막혀 있었다.**

## 막혀 있던 것 네 가지

| # | 증상 | 원인 |
|---|---|---|
| 1 | 흰색이 될 자리가 없다 | 회색을 없애며 입구 턱을 검정으로 내렸다. 다리는 흰 물이 스쳐 **흰색으로 칠해야** 남는데, 총알 색 = 플레이어 색이라 흰색이 될 방법이 없었다 |
| 2 | ★**다리가 아무리 쏴도 안 굳는다** | `지형.gd` 의 `_긴변` 이 **로컬 좌표**로 재져 있다(§아래) |
| 3 | 들어가면 못 나온다 | 통로가 140 높이라 그 안에서 44px 밖에 못 뛴다. 갱도로 돌아가려면 123px 을 올라야 하는데 천장에 머리가 박힌다 |
| 4 | 관문 1 유령 발판이 유령이 아니었다 | 씬에 `무색일때_통과 = true` 가 빠져 있었다(빌더에는 있다). 안 칠해도 밟혔다 |

## ★코드 버그 ④ — `_긴변` 을 로컬 좌표로 재고 있었다

```gdscript
_긴변 = maxf(최대.x - 최소.x, 최대.y - 최소.y)   # 점 배열은 **로컬** 좌표다
…
func 전체_색칠_가능() -> bool:
    return 전체_색칠_최대긴변 <= 0.0 or _긴변 <= 전체_색칠_최대긴변   # 한도 576
```

`_긴변` 은 **게임 규칙 두 개**(`필요횟수()` · `전체_색칠_가능()`)가 쓰는 값인데 축척을 안 곱한다.
Template 을 축척해서 꽂은 지형은 로컬 긴변이 **Template 원본 크기**다 — 시멘트는 1,731px.

```
SS_CEM_BR_4A  실제 180×120   ·  _긴변 = 1731  ·  전체_색칠_가능 = false
→ 2발을 다 맞혀도 "progress" 만 나오고 영원히 무색 = 통과되는 유령
```

**축척으로 찍은 모든 작은 발판이 같은 병에 걸린다.** 점 배열을 월드 좌표로 직접 찍은 지형
(2-1 빌더가 만든 것들)은 축척이 1 이라 원래부터 맞았고, 그래서 여태 안 드러났다.

→ 월드 크기를 따로 재서 그 둘이 쓰게 했다. 기존 씬의 동작은 안 바뀐다(축척 1 이면 값이 같다).

```gdscript
var 배율 := global_scale if is_inside_tree() else scale
_세계긴변 = maxf((최대.x - 최소.x) * absf(배율.x), (최대.y - 최소.y) * absf(배율.y))
```
