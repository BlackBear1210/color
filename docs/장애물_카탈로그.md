# 장애물 카탈로그 — 드래그해서 바로 쓰는 부품들

> 작성: 도형 + Claude / 2026-07-24
> 위치: 씬 `scenes/장애물/` · 코드 `scripts/장애물/`
> 관련: [레벨디자인_가이드.md](레벨디자인_가이드.md) §3 퍼즐 어휘 카탈로그

## 쓰는 법 (공통)

1. Godot 파일시스템에서 `scenes/장애물/○○.tscn` 을 찾는다
2. 스테이지 씬의 `장애물` 노드 위로 **끌어다 놓는다**
3. 인스펙터에서 한글 항목 몇 개만 바꾼다 → **끝**

**씬 1개 = 노드 1개 + 스크립트 1개**다. 그림(콜리전 · 스프라이트)은 스크립트가 스스로 만든다.
따로 이미지를 붙이거나 콜리전을 그릴 필요가 없다.

> **왜 이렇게 만들었나**
> 이 게임은 지형이 순흑 아니면 순백이라, 장애물 이미지를 한 장 붙이면 어느 한쪽 지형 위에서는
> 반드시 안 보인다(16차 조준 궤적에서 이미 겪은 문제). 그래서 모든 장애물을
> **"어두운 외곽선 + 밝은 코어" 2겹**으로 그린다 — 흰 지형에선 외곽선이, 검은 지형에선 코어가
> 보여 **항상 실루엣이 산다.** 위험물에는 **붉은 경고점**을 하나 찍는다
> (흑백 게임에서 유일하게 허용하는 색 = 위험 신호. 색맹 대비로 형태도 뾰족하게).
> 공통 그리기 코드: `scripts/장애물/장애물_공통.gd`

## 1. 🗡 가시 (`가시.tscn`)

가장 기본적인 즉사 함정. **색과 무관하게** 닿으면 죽는다.

| 인스펙터 항목 | 뜻 | 기본값 |
|---|---|---|
| `칸수` | 가로로 몇 칸(1칸=32px) | 3 |
| `방향` | 가시가 향하는 쪽 (위/아래/왼쪽/오른쪽) | 위 |
| `가시높이` | 가시 하나의 높이(px) | 22 |

**배치 요령**
- 원점 = 가시가 박힌 면의 중앙. 발판 윗면에 딱 붙이면 된다.
- **6칸 이하**로 잡는다(플레이어 최대 도약 10칸이지만, 여유를 남겨야 실수해도 넘을 수 있다).
- 가시는 "칠하기 실패의 벌"이 아니라 **"경로를 좁히는 도구"** 로 쓴다.
  칠하기를 강제하려면 가시가 아니라 반대색 발판을 쓰는 게 이 게임의 문법이다.

## 2. ⚙ 회전톱 (`회전톱.tscn`)

정해진 경로를 왕복하며 회전하는 톱날. 즉사.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `반지름` | 톱날 크기(px) | 26 |
| `이동거리` | 왕복 거리(px). **0이면 제자리 회전** | 0 |
| `이동방향` | 가로 / 세로 | 가로 |
| `왕복시간` | A→B→A 한 바퀴에 걸리는 시간(초) | 3.0 |
| `회전속도` | 보이는 속도감만 담당(판정과 무관) | 6.0 |

**배치 요령**
- **왕복시간 2.0초 이상.** 그보다 빠르면 패턴을 읽기 전에 죽어 "불공정하다"는 느낌을 준다.
- 판정 반지름은 그림의 **72%** 다 — "스칠 듯 말 듯 피했다"를 만들기 위한 의도적 여유
  (상업 플랫포머의 표준 기법).
- 톱은 **타이밍**을, 색칠은 **판단**을 요구한다. **둘을 동시에 요구하면 난이도가 곱셈으로 뛴다** →
  스테이지 4 이후에만 겹친다.

## 3. ↔ 움직이는 발판 (`움직이는발판.tscn`)

**PaintPlatform 을 상속** → 움직이면서 **색칠도 되는** 발판.
"달리는 발판을 조준해서 맞히기"라는 이 게임만의 상황이 만들어진다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `재질` / `크기_칸` / `시작상태` / `무색일때_통과` | 일반 발판과 동일 | — |
| `이동거리` | 왕복 거리(px) | 160 |
| `이동방향` | 가로 / 세로 | 가로 |
| `왕복시간` | 왕복 1회(초) | 4.0 |
| `시작지연` | 여러 발판을 엇갈리게 움직일 때의 위상 지연(초) | 0 |

**배치 요령**
- **왕복시간 3초 이상** 권장. 움직이는 발판 위에서 조준까지 시키면 2초 이하는 가혹하다.
- **세로 이동 발판을 낙사 구간 위에 두지 않는다** (내려갈 때 강제 낙사 = 불공정).

> 구현 메모: `AnimatableBody2D.sync_to_physics = true` 를 켜서 **위에 선 플레이어가 같이 실려 간다.**
> (안 켜면 발판만 빠져나가고 플레이어는 미끄러진다)

## 4. 💥 무너지는 발판 (`무너지는발판.tscn`)

밟으면 잠깐 흔들리다 무너지고, 일정 시간 뒤 되살아난다. **PaintPlatform 상속** → 색칠도 된다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `버티는시간` | 밟고 나서 무너지기까지(초) | 0.6 |
| `되살아나는시간` | 무너진 뒤 복구까지(초) | 2.4 |

**이 부품이 특별한 이유**
이 챕터에서 **"칠할 시간"에 압박을 거는 유일한 부품**이다.
무색 발판 위에 서서 여유롭게 조준하는 게 기본 리듬인데, 이 발판 위에서는
**버티는 시간 안에 조준하고 쏴야 한다** → 같은 퍼즐이 순간적으로 액션이 된다.

기본값 0.6 / 2.4 초는 "한 번 조준해서 한 발 쏠 수 있는" 길이로 맞춰 놓았다 (실플레이 검증 필요).

## 5. 🚪 색문 (`색문.tscn`)

**지정한 색일 때만 통과**할 수 있는 문. 다른 색이면 벽이다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `통과색` | 검정 / 흰색 | 검정 |
| `크기_칸` | 문 크기(가로, 세로) | (1, 4) |

**배치 요령**
- 즉사가 아니라 **"막힘"** 이라 실패 비용이 낮다 → **배우는 구간(스테이지 2~3)** 에 적합.
- 문 앞에 **회색(중립) 발판**을 두면 "칠해서 확인 → 색을 바꾸고 → 통과" 리듬이 만들어진다.
- 문 위에 통과색 원 아이콘이 뜬다 — 한눈에 "무슨 색이어야 하나"가 읽힌다.

## 6. ⬇ 떨어지는 블록 (`떨어지는블록.tscn`)

천장에 매달려 있다가, 플레이어가 아래를 지나가면 떨렸다가 낙하한다. 즉사.
바닥에 닿으면 부서지고 잠시 뒤 원위치에 다시 매달린다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `크기_칸` | 블록 크기 | (2, 2) |
| `감지높이` | 아래 몇 px 안에 오면 발동하는가 | 320 |
| `경고시간` | 떨리는 예고 시간(초) | 0.45 |
| `재생성시간` | 부서진 뒤 복구까지(초) | 3.0 |
| `낙하중력` | 떨어지는 가속(px/s²) | 1500 |

**배치 요령**
- **경고시간 0.45초 = "보고 나서 반응할 수 있는" 최소치.** 이보다 짧으면 암기 게임이 된다.
- 통로 하나에 **3개 이상 연속으로 두지 않는다**(암기 강요).
- **낙하 지점 바로 아래에 무색 발판을 두면** "쏘고 나서 피하기" 순서가 강제된다 — 좋은 배치.

## 7. 🚩 체크포인트 (`체크포인트.tscn`)

지나가면 부활 지점이 여기로 바뀐다. **그 순간의 플레이어 색도 함께 기억한다.**

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `감지폭` / `감지높이` | 감지 영역 크기(px) | 48 / 96 |

**색을 같이 기억하는 이유** (7/14 에 실제로 겪은 사고)
반대색인 채로 부활하면 **부활하자마자 발밑 발판에 죽는 무한 사망 루프**가 된다.
그래서 체크포인트는 위치만이 아니라 "여기서는 이 색이면 안전하다"까지 저장한다.

안전한 발판 위에 드래그해 놓으면 된다. `stage_lab.gd` 가 `checkpoint` 그룹을 자동으로 찾아 연결한다.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `폭` / `높이` | 문 크기(px) | 64 / 112 |

문 안쪽은 흑↔백 그라데이션이 천천히 도는 "출구" 연출이다(이 게임의 주제 그대로).

## 10. 🧱 칠하는 발판 (`scenes/페인트/칠하는발판.tscn`)

장애물은 아니지만 같은 방식으로 쓰는 지형 부품.

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `재질` | 벽돌 / 벽돌액자 / 나무 / 나무액자 / 바위 / 흙 / 풀 / 풀두꺼움 | 벽돌 |
| `크기_칸` | 가로·세로 칸 수(1칸=32px) | (8, 1) |
| `시작상태` | 무색 / 검정 / 흰색 / 회색 | 무색 |
| `필요횟수_수동` | 0이면 크기에서 자동 계산 | 0 |
| `칠하기_허용` | 끄면 총알을 맞아도 안 변하는 구조물 | 켜짐 |
| `무색일때_통과` | **켜면 칠해야만 밟을 수 있는 유령 지형** | 켜짐 |

**필요 횟수 자동 계산**: `ceil(긴 변 칸 수 / 2)` → **8칸 = 4번**(7/24 회의 결정과 일치)

**재질 고르는 요령 (실측 기준)**
- **32px 짜리 얇은 발판** → `벽돌` / `나무` (무늬가 또렷하게 읽힌다)
- **64px 이상 두꺼운 블록 · 바닥 · 벽** → `바위` / `흙` / `풀` / `벽돌액자` (유기적 가장자리가 살아난다)
- 얇은 발판에 `바위`·`흙`을 쓰면 뜯긴 가장자리가 화면을 다 먹어 얼룩처럼 보인다 (실제로 겪음)

## 새 장애물을 추가할 때

1. `scripts/장애물/○○.gd` 작성 — 맨 위에 **한글 설명 + 쓰는 법 + 레벨 디자인 규칙**을 반드시 쓴다
2. 위험물이면 `add_to_group("hazard")` (그러면 `stage_lab.gd` 가 알아서 사망 판정을 붙인다)
3. `scenes/장애물/○○.tscn` 을 만든다 (노드 1개 + 스크립트만)
4. 이 문서에 항목을 추가한다
5. `docs/레벨디자인_가이드.md` §3 부품표에 코드(V9, V10 …)를 부여한다
6. `tools/build_stages.gd` 의 `_장애물_만들기()` 에 `match` 갈래를 추가하면 생성기에서도 쓸 수 있다
