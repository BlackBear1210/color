# 출수 확대 제거와 앞끝 낙하

사용자 지적: 첫 시도는 물이 흘러나오는 동작이 아니라 작은 물 덩어리가 커지는 모습이었다. 원인은 시작 진행률에 따라 전체 물 폭을 12%에서 100%로 키우고 입구 윗경계를 위로 올린 처리였다.

## 수정

- 시작 진행률과 폭 확대를 제거했다. 입구 윤곽·폭·RGB 샘플 배율은 고정한다.
- 물의 앞끝은 입구 안쪽에서 출발해 아래로 이동한다. 앞끝 뒤의 물이 연속적으로 이어지고, 기존 RGB 아틀라스 무늬도 아래로 흐른다. 아틀라스가 이미 무늬를 이동시키므로 UV 스크롤을 추가로 겹치지 않았다. 승인된 1.4배 시계를 유지했다.
- 입구 마스크는 시간에 따라 커지는 48셀 대신 고정된 `inlet_profile.png` 한 장이다. 입구와 본체는 같은 ShaderMaterial과 프레임을 공유한다.
- `유체_흰물v2.gd`의 새 `출수_앞끝()` 값을 그림과 충돌에서 함께 사용한다. 앞끝이 배관 안에 있는 동안 외부 낙수와 위험 판정이 생기지 않는다. 배관이 없는 유체의 선행거리는 기본 0이라 기존 동작을 유지한다.
- 낙수 선두를 작은 물결 윤곽으로 처리했다. 윤곽 후퇴량 최대 3px와 2px 페더는 기존 6px 판정 여유 안에 있다.
- 배관 출수를 켠 직후 끌 때 앞끝을 보존한다. 이전에는 OFF에서 앞끝을 -1(전부 보임)로 바꿔 아직 도착하지 않은 아래 물까지 나타날 수 있었다. 꺼짐 판정은 기존처럼 즉시 해제된다.
- 전 단계 소스는 `tmp/pipe_flow_direction_20261009/`에 보관했다. 기존 다른 작업과 씬 배치를 재생성하지 않았다.

## 산출물과 확인

- 생성 도구: `tools/build_pipe_startup_masks.py`.
- 런타임 고정 윤곽: `assets/textures/obstacles/liquid/pipe_startup_20261009/inlet_profile.png` (128×128).
- 검토용 투명 출수 48프레임: 같은 폴더의 `outflow_48.png` (1024×2304, 8×6, 셀 128×384).
- 새 미리보기: `docs/visual_review/pipe_startup_20261009/출수_앞끝이동_48프레임.webp` 및 `출수_앞끝이동_비교.png`.
- 프리뷰는 60fps의 기존 낙하 적분식(초기 250, 중력 2600, 시간 1.4배)으로 조립했다. 프레임 0의 빈 상태만 관찰을 위해 250ms 유지한다. 실제 게임 캡처가 아니며 게임 물보라·배경·조명은 생략했다.
- 생성 시 확인: 첫 프레임 투명, 앞끝 위치 단조 하강, 앞끝이 입구 밖에 도달하기 전 하단 물 없음.
- 결과 확인: 48프레임, 올바른 셀 크기, 입구 도달 이후 42프레임의 경계 폭 동일, 시작 확대 유니폼 제거, 그림/판정의 같은 앞끝 사용, 셰이더 한글 없음. 비교 시트를 직접 열어 앞끝 이동과 고정된 입구/폭을 확인했다.
- Godot을 실행하지 않는 별도 문법 검사기로 GDScript 4개 파싱 통과. `git diff --check` 통과, 삭제 상태 없음. graphify AST 갱신 완료.

상태: **수정 완료·시각 검증 대기**. 사용자 명시 실행 허용이 없어 Godot 및 엔진 검사 13개는 미실행이다. 실제 엔진 캡처 경로는 없다. 허용 후 스테이지 2-1 동일 카메라·해상도에서 입구가 고정된 채 선두가 내려오는지, 경계 이음새, OFF/ON/출수 직후 OFF/재활성화, 삼색 전환과 판정 도착 시점을 확인해야 한다. 검토용 프리뷰를 엔진 검증 이미지로 대체하지 않는다.
