지면 높이는 **레이캐스트로 실측**한다. 지형을 다듬어도 통로가 뜨거나 파묻히지 않는다.

## 3. 장애물 씬(.tscn) 부품화

> "장애물들이 현재 gd로만 구현되어 있는데, 나중에 이미지 넣고 관리하기 쉽게 하기 위해서
>  씬으로 만들어 놓는게 좋을 듯. 이미지는 디자이너가 그리고 있으니까 바로 넣을 수 있게."

`tools/build_장애물씬.gd` 로 **14종**을 만들었다 → `scenes/스마트월드_장애물/`

```
○○ (Area2D / StaticBody2D / Node2D · 장애물 스크립트)
└─ 그림 (Sprite2D · 아트슬롯.gd)   ← ★여기 Texture 만 꽂으면 끝
```

| 슬롯 상태 | 동작 |
|---|---|
| **비어 있음** | 지금까지처럼 `_draw()` 가 코드로 그린다 → **회귀 없음** |
| **텍스처 있음** | `_draw()` 가 스스로 멈추고 그림만 보인다 |

`기준_크기` 가 적혀 있어 **디자이너가 몇 px 로 그리든 게임 안 크기는 항상 같다.**
→ "이거 몇 px로 그려야 해요?" 라는 질문 자체가 없어진다.

각 장애물 스크립트의 `_draw()` 맨 위에 **한 줄**만 넣었다:
```gdscript
if 아트슬롯.그림_있나(self):
    return
```

| 만들어진 씬 | 만들어진 씬 |
|---|---|
| 도약대 · 무너지는바위 · 색레이저 · 연결통로 | 식물A · 식물B · 물저장고 · 유체 |
| 배관 · 제어레버 · 호퍼 · 송풍기 | 통과플랫폼 · 발광체 |

**레벨 디자이너**: 파일시스템에서 `.tscn` 을 스테이지의 `오브젝트` 노드로 끌어다 놓고
인스펙터의 한글 항목만 조절하면 된다.

### 4-2. 바인(Vane)식 구역 카메라

> "stage_1-1에서 1-2로 넘어갈 때 카메라 넣어주셈. 바인식 연출로.
>  **카메라가 움직임과 플레이어의 움직임이 같이 가야해.**"

#### 리서치한 것

- **Vane (2019)** — 위치에 따라 카메라가 자동 줌 인/아웃되며 컷 없이 이어진다.
  다만 리뷰에서 **"카메라가 플레이를 방해한다"** 는 혹평을 받았다. 원인은 연출이
  **플레이어 입력과 무관하게 제멋대로 움직였기** 때문이다.
- **Hollow Knight** — 구역마다 카메라 오프셋이 다르고 이동은 부드럽게 보간된다.
  "구역별로 보여줄 것을 디자이너가 정한다"는 발상만 가져왔다.
- **Itay Keren, GDC 2015 "Scroll Back"** — 이 프로젝트 카메라의 원래 설계 근거.

#### ★핵심 — 전환은 시간이 아니라 플레이어 위치로 굴러간다

기존 `ProtoCamera.set_limit_rect(rect, true)` 는 **1.1초 시간 트윈**이었다. 그러면
- 경계에서 멈춰도 카메라는 혼자 1.1초를 마저 흘러가고
- 되돌아가면 카메라는 앞으로 가는 중이라 **화면과 조작이 반대로 논다**

→ Vane 이 욕먹은 지점이 정확히 이것이다.

새로 만든 `scripts/proto/카메라_연출.gd` 는 진행도 t 를 **플레이어 x 에서 직접** 계산한다.
```
t = (플레이어x − 밴드시작) / 전환폭
```
| 플레이어 | 화면 |
|---|---|
| 앞으로 걷는다 | 앞으로 열린다 |
| **멈춘다** | **멈춘다** |
| **되돌아간다** | **정확히 되돌아간다** |
| 뛴다 / 걷는다 | 벌어지는 속도 = 내가 움직이는 속도 |

`smoothstep` 으로 섞어 이음매가 안 보이고, 전환 한가운데(t=0.5)에서만
`sin(πt)` 만큼 살짝 줌아웃한다(**전환 숨**) — Vane 에서 가져온 좋은 부분.

#### 구역 설정 (자동 계산)

| 구역 | x 범위 | 줌 | 시선 | 성격 |
|---|---|---|---|---|
| 1-1 | 128 ~ 12,576 | 0.72 | −20 | 좁고 아기자기 — 조금 당겨서 아늑하게 |
| 1-2 | 12,576 ~ 22,864 | 0.62 | −40 | 크고 높다 — 넓게 빼서 스케일을 보여준다 |
| 전환폭 | 1,400px | | | 이 거리를 걷는 동안 화면이 바뀐다 |

경계는 타일맵을 실제로 훑어 계산한다(원래 stage_1-1 이 786칸=12,576px 이었다).

**검증**: `tools/test_카메라연출.gd` — 10항목 전부 통과.
그중 결정적인 3가지: **가역성**(되돌아가면 같은 값, 오차 0.000000) ·
**정지성**(30프레임 서 있어도 흔들림 0.000000) · **밴드 밖 진행도 0**.

## 5. ★장애물 치수 재검증 — 스테이지가 통째로 막혀 있었다

> "장애물을 다시 확인해보는 과정이 꼭 필요해.
>  거리나 플레이어의 크기에 안맞거나 점프거리까지 신경써서 만들어봐."

### 5-1. 먼저 발견한 것 — 플레이어가 두 배로 커졌다

신우님이 `Player.tscn` 콜리전을 바꿨다.

| | 전 | 후 |
|---|---|---|
| 콜리전 | 63.4 × 128 @ (0.28, −64) | 55.3 × 263.8 @ (0, −131.9) |
| **실제 크기(스케일 반영)** | **폭 50px · 키 47px** | **폭 44px · 키 97px** |

레벨 검사기는 "머리 공간 52px" 를 **상수로 박아** 두고 있었다.
그대로 뒀다면 **머리가 천장에 박히는 자리를 "설 수 있다"고 보고**했을 것이다.
→ 이제 `Player.tscn` 에서 **직접 재서** 쓴다. 캐릭터를 또 바꿔도 검사기가 따라온다.

### 5-2. 스마트월드1 이 통째로 막혀 있었다

`tools/레벨검사.gd` 결과: **밟는 지형 26개 중 도달 6개.**

원인: 첫 구덩이 발판이 지면에서 **152px** 위. 점프 높이 160px 이라 여유 8px —
사실상 못 넘고, 못 넘으면 **그 뒤 전부가 막힌다.** 씬을 열면 발판이 멀쩡히 그려져 있어
눈으로는 절대 안 보인다.

### 5-3. `tools/치수_보정.gd` 신설 — 재서 고친다

전략 순서가 중요하다. **발판을 내리는 건 최후의 수단**이다
(첫 시도에서 발판을 216px 내리려 했다 — 그건 보정이 아니라 레벨 디자인을 바꾸는 것).

|---|---|---|
| ① | **도약대를 놓는다** | 점프(128px)로는 안 되지만 도약대(418px)로는 닿으면, 아래 지형에 도약대 신설 |

## 6. ⚠⚠ 엔진이 죽던 크래시 — 반드시 읽을 것

통로를 지나는 순간 **Godot 이 signal 11(세그폴트)로 죽었다.** 실제 플레이에서도 죽는다.

### 어떻게 찾았나

증상이 "씬을 교체할 때" 나서 통로·장면전환 쪽을 한참 뒤졌다.
`tools/repro_통로크래시.gd`(임시)로 **씬을 하나씩 바꿔 넣어 이분**해서 찾았다.

| 조합 | 결과 |
|---|---|
| 신우 원본 → 2 | ✔ |
| **우리 1 → 2** | **✖ 크래시** |
| 통로만 얹은 1 → 2 | ✔ |
| → 범인은 **치수_보정이 저장한 결과물** | |

### 진짜 원인

후처리 도구가 저장 전에 `_주인_지정(루트, 루트)` 로 **트리 전체에 owner 를 박았다.**

코드로 처음부터 만드는 씬(`build_*.gd`)에서는 그게 맞다 — 그래야 저장된다.
그런데 **이미 있는 씬을 읽어서 손보는 도구**에서는 완전히 틀렸다:

- PackedScene 에서 불러온 노드는 **이미 owner 가 올바르다.** 건드릴 필요가 없다.
- 스마트월드 오브젝트(호퍼·유체·통과플랫폼·송풍기…)는 `_ready()` 에서
  판정·모양 노드를 **런타임에** 만든다. 얘들은 owner 가 없어야 정상이다.
- 거기에 owner 를 박으면 **씬 파일에 한 벌 더 저장**되고, 다음에 불러올 때
  `_ready()` 가 또 만들어 **노드가 두 벌**이 된다.
- 그 상태로 씬을 교체하면 이미 해제된 짝을 참조해 **세그폴트**.

> 🔴 **규칙**: 후처리 도구에서는 **우리가 새로 만든 노드에만** owner 를 준다.
> 인스턴스는 **루트에만**, 안쪽 자식에는 **절대** 주지 않는다.
> (2026-08-02 의 Gun2/Placeholder2 사고와 **같은 계열**이다. 같은 실수를 또 했다)

### 덤 — 무한 재귀도 하나 있었다

`아트슬롯.gd` 에 이런 코드를 썼다가 스택 오버플로를 냈다:
```gdscript
func _set(속성, 값) -> bool:
    if 속성 == &"texture":
        texture = 값          # ← ★_set 이 또 불린다 = 무한 재귀
```
GDScript 의 `_set()` 은 **네이티브 프로퍼티보다 먼저** 불린다.
→ 지금은 Sprite2D 가 원래 주는 `texture_changed` 신호를 쓴다. **프로퍼티 훅을 가로채지 말 것.**
