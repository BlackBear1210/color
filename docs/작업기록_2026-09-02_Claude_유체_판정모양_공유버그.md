## 2. 무엇이 잘못돼 있었나

`유체.tscn` 안의 판정 사각형 3 개는 서브리소스다.

```
[sub_resource type="RectangleShape2D" id="RectangleShape2D_liquid_stream"]
size = Vector2(18.592, 225)
```

★ 씬에 박힌 서브리소스는 `resource_local_to_scene` 이 꺼져 있으면
**그 씬의 모든 인스턴스가 한 개를 공유한다** (Godot 기본 동작).

그런데 `유체.gd` 의 `_직사각_판정()` → `_판정_사각_설정()` 은 그 사각형을
**제자리에서** 고친다.

```gdscript
var 모양 := 판정.shape as RectangleShape2D
모양.size = Vector2(크기.x * 폭_비율, 크기.y * 높이_비율)   # ← 14개가 같은 객체에 쓴다
```

그래서 **맨 마지막에 `_모양_갱신()` 을 부른 놈이 이긴다.**
게다가 `_물_애니_판정_따르기()` 가 애니 프레임이 바뀔 때마다 다시 부르니,
매 프레임 14 개가 서로 덮어쓰고 있었다.

### 고치기 전 실측 (stage_2-1)

```
이름          크기(인스펙터)   물줄기_판정.size    shape 객체ID
유체_2 검정   (56, 800)       (18.592, 675.0)    -9223371990331554355
유체_1 흰색   (300, 800)      (18.592, 675.0)    -9223371990331554355   ← 폭 300인데 판정 18.6
유체5         (56, 1400)      (18.592, 675.0)    -9223371990331554355
...  (14개 전부 같은 객체 · 같은 size)
```

`675` = 900 × 0.75 = **마지막 노드 `유체6`(56×900)의 값**이다.
`position` 만 멀쩡했던 이유는 그건 리소스가 아니라 **노드 속성**이라서다.

### 실제 증상
- 물기둥 **그림은 각자 크기대로** 그려지는데(스프라이트 scale 은 노드 속성) **판정만 한 값**이다.
- `유체_1 흰색` 은 폭 300 으로 보이는데 판정은 18.6px — 한가운데로 걸어가야 겨우 닿는다.
- 짧은 물은 판정이 아래로 튀어나오고, 긴 물은 중간에서 끊긴다.
- 노드 순서에 따라 이기는 값이 바뀌어서 **재현이 안 되는 버그**로 보인다.

## 3. 어떻게 고쳤나 — 두 겹

### ① `유체.tscn` — 사각형 3 개를 인스턴스마다 고유하게

```
[sub_resource type="RectangleShape2D" id="RectangleShape2D_liquid_stream"]
resource_local_to_scene = true      ← 추가
size = Vector2(18.592, 225)
```

엔진이 인스턴스마다 복사본을 만들어 준다. **에디터에서도** 판정이 제대로 보이고,
복사를 엔진이 하므로 **부모 씬에 덮어쓰기가 저장되지 않는다** — stage 씬 파일이 안 불어난다.

### ② `유체.gd` — 그래도 공유된 사각형이 들어오면 복제 (안전망)

플래그 없는 새 유체 씬을 만들었을 때를 대비한다.

```gdscript
	elif not (Engine.is_editor_hint() or 모양.resource_local_to_scene
			or 판정.has_meta(내_모양_표식)):
		# 남과 나눠 쓰는 사각형이다 → 내 것으로 복제한다. 한 번만 하면 된다.
		모양 = 모양.duplicate() as RectangleShape2D
		판정.shape = 모양
		판정.set_meta(내_모양_표식, true)
```

⚠ **런타임에서만** 복제한다. 에디터에서 `판정.shape` 에 새 리소스를 넣으면
그게 인스턴스 덮어쓰기로 **씬 파일에 저장**되어(유체 1 개당 3 개 × 씬마다 십수 개) 파일이 지저분해진다.

### 고친 뒤 실측

```
유체_2 검정   (56, 800)    (18.592, 600.0)    ID …812110   OK
유체_1 흰색   (300, 800)   (99.6,   600.0)    ID …039940   OK   ← 폭이 제 크기로 돌아왔다
유체5         (56, 1400)   (18.592, 1050.0)   ID …783994   OK
...
서로 다른 shape 객체 개수 : 14  (유체 개수만큼 = 정상)
폭이 어긋난 유체          : 0 개
```

## 4. ⚠ 아직 남아 있는 것 — 물이 거의 다 **회색**이다

이번 수정과 **별개 문제**다. 판정 크기는 고쳤지만, 색이 회색이면 애초에 아무도 안 죽는다.

`유체.tscn` 원본에 `"색" = 2`(회색)가 저장돼 있고, 인스턴스에서 색을 지정한 것은 **딱 하나**다.

| 씬 | 유체 개수 | 색 지정됨 | 회색(기본값 그대로) |
|---|---|---|---|
| stage_2-1 | 14 | 1 (`유체_2 검정`) | **13** |
| stage_2-2 | 13 | 0 | **13** |
| stage_2-3 | 1 | 0 | **1** |

회색 유체는 `색규칙.gd` 상 **의도적으로 누구에게나 안전**하고, `총알_막나()` 도 false,
페인트 지우기도 건너뛴다 → **아무 기능 없는 순수 장식**이다.
`유체_1 흰색` 이라는 이름을 달고 실제로는 회색인 것도 이 때문이다.

**성진님 결정 대기 중**: `유체.tscn` 기본값을 흰색으로 바꿀지 / 스테이지에서 하나씩 지정할지.

색 판정 자체는 정상 작동을 확인했다:

```
유체_2 검정(검정) + 흰색 플레이어  →  죽는다   ✅
유체_2 검정(검정) + 검정 플레이어  →  안 죽는다 ✅
회색 물          + 아무 색        →  안 죽는다 (규칙대로)
회색 물을 흰색으로 바꾸면 + 검정 플레이어 → 죽는다 ✅
```

## 6. 다음 사람이 알아야 할 것 (지뢰 추가)

**씬 안의 Shape2D · Material · 그 밖의 리소스를 스크립트가 제자리에서 고치면,
그 씬의 인스턴스 전부가 같이 바뀐다.**

- 증상: 인스펙터 값은 제각각인데 **화면과 판정이 따로 논다** · 노드 순서에 따라 결과가 달라진다
- 확인: `노드.shape.get_instance_id()` 를 인스턴스별로 찍어 본다. **ID 가 같으면 공유 중이다**
- 해결: 씬 서브리소스에 `resource_local_to_scene = true`, 또는 스크립트에서 `duplicate()`
- ⚠ 이 저장소에서 같은 구조를 쓰는 곳(`통과플랫폼` · `투명블럭` 등)도 한 번 훑어볼 것
