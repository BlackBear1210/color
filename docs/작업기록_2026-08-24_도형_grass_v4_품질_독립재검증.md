## 2. texture_scale — 0.35 재확인

7개 배율 각각을 **실제 게임 프레이밍**으로 따로 렌더해서 봤다
(줌 0.82 · 뷰포트 1920×1080 → 화면이 담는 월드 2341×1317).

| scale | 띠 | 주기 | 플레이어키 대비 | 화면당 반복 | 판정 |
|---|---|---|---|---|---|
| 0.15 / 0.20 | 38 / 51 | 154 / 205 | 15% / 19% | 15.2 / 11.4 | ❌ 잔디가 노이즈로 뭉개진다 |
| 0.25 | 64 | 256 | 24% | 9.1 | △ 잎사귀가 겨우 읽힌다 |
| 0.30 | 77 | 307 | 29% | 7.6 | ○ **차점** — 술이 잎이 아니라 보풀로 읽힌다 |
| **0.35** | **90** | **358** | **34%** | **6.5** | ✅ 잎·하이라이트가 가장 잘 읽히고 반복이 아직 안 보인다 |
| 0.40 / 0.45 | 102 / 115 | 410 / 461 | 39% / 44% | 5.7 / 5.1 | △ 잔디 뭉치를 **셀 수 있게** 된다 |

보조 근거 (전부 실측):

- **코너 한 변 = 투명 캐리어 높이 256 × scale = 띠 두께**. 배율을 바꿔도 항상 같다
  → 코너/엣지 크기 관계는 배율 선택과 **무관**하다. 배율은 순수하게 밀도 문제다.
- 잔디 술 높이 = TOP 텍스처에서 행평균 알파가 0.5 에 닿는 지점 = **69px / 256px (27.0%)**.
  0.35 에서 월드 **24px**. (문서의 "37% / 33px" 은 다른 정의로 잰 값이다.)
- 0.35 의 띠 90px 은 grass_v3 와 **정확히 같다** → 기존 레벨 지오메트리가 그대로 옮겨온다.

## 3. 대비 — 감마 1.60 재확인

원본(`tools/grass_v4_pipeline/src/`)에 감마만 걸어 STEP 4 의 사다리를 수치로 재현했다.
감마는 단조증가라 픽셀 밝기 **순서**가 안 바뀌므로 분위수 자리도 그대로다.

| 단계 | 감마 | BLACK 평균 | WHITE 평균 | 대비폭 | 필 내부 p05~p95 |
|---|---|---|---|---|---|
| 현재(원본) | 1.00 | 65.00 | 190.00 | 125.0 | 18 단계 |
| A | 1.35 | 40.80 | 214.20 | 173.4 | 14 단계 |
| **B (채택)** | **1.60** | **29.39** | **225.61** | **196.2** | **12 단계** |
| C | 1.90 | 19.95 | 235.05 | 215.1 | **9 단계** ← 필이 평평해진다 |

커밋된 PNG 의 **실측** 집계 (알파>127 가중, 4엣지+코너2+필):

```
BLACK 평균 31.25   min 0   p05 20   p50 27   p95 56   max 255   (<=40 인 픽셀 90.1%)
WHITE 평균 223.75  min 0   p05 199  p50 228  p95 235  max 255   (>=200 인 픽셀 95.0%)
대비폭 192.5 / 255 (75.5%)
```

- 사다리의 B(29.4) 와 실측(31.25) 이 다른 이유: 파이프라인이 감마 외에
  알파 바닥 제거 · 안쪽 페이드 · 필 톤 맞추기를 더 하기 때문. 방향과 크기는 일치한다.
- **흑백 반전 오차 0.0/255** — 9개 텍스처 쌍 전부에서 `|(255−BLACK) − WHITE| = 0`,
  알파 차이도 0. 구조 대응이 수식으로 보장된다는 주장이 실측으로 확인됐다.
- 요구사항 대조: WHITE 는 95% 픽셀이 200 이상 · p50 228 이라 "회색" 이 아니고,
  필 내부 12단계가 남아 "평평한 덩어리" 도 아니다. BLACK 은 90% 픽셀이 40 이하.

## 4. ★ 새로 찾은 결함 — 코너의 세로 톤 이음매

기존 검증은 **코너 쿼드 개수**와 **텍스처 단면**만 봤다. 둘 다 통과다:

- 사각 OUTER 4 / INNER 0, L자 OUTER 5 / INNER 1 (재측정 일치)
- `apply_final.py build_corners` 를 GDScript 로 **그대로 다시 계산**해 커밋된 PNG 와 비교:
  **전체 평균 0.48 / 최대 1.00 / 255**, 알파도 최대 1.00
  → 커밋된 코너 PNG 는 파이프라인 출력 그 자체이고,
    경계열은 진짜 TOP 단면(u = 0.31 + 반텍셀)이다. 문서의 "약 1/255" 은 사실이다.

**그런데 합성된 화면은 통과가 아니다.**

### 어떻게 찾았나 (헛짚은 것 포함)

1. 확대 렌더에서 코너 자리에 사각 경계가 보였다.
2. 실루엣(바깥 윤곽)의 축정렬 직선 구간을 쟀다 → **코너가 대조군보다 짧다**
   (코너 3.0~6.3 월드px vs 그냥 직선 엣지 28~39). 실루엣은 결백하다.
3. "임계를 넘는 픽셀이 연속되는 길이" 로 안쪽을 쟀다 → 이것도 **대조군이 더 컸다**.
   잔디 잎사귀 한 획이 50px 씩 이어지기 때문. **이 지표는 쓰면 안 된다.**
4. 제대로 된 지표: **열 전체의 평균 가로 기울기**의 MAD z점수.
   쿼드 경계는 그 열의 거의 모든 픽셀이 동시에 튀는 자리고,
   붓질은 한 열 전체를 동시에 밝히지 못한다.

| 대상 | 세로 이음매 z | 단차 |
|---|---|---|
| 대조군 · 그냥 직선 엣지 | **3.3** | 5.6/255 |
| 대조군 · 큰 곡선 | **5.8** | 7.5/255 |
| 볼록 코너 (좌상 / 우상) | **9.6 / 8.8** | 16.0 / 15.6 /255 |
| L자 안쪽 | **13.2** | 8.2/255 |
| 오목 코너 | **16.5** | 8.6/255 |

가로 방향은 의미가 없다 — 가로 띠는 원래 가로 구조라 대조군이 z 39.7 로 제일 크다.
**세로**가 판별력을 가진다: 가로 띠에는 세로 구조가 있을 이유가 없다.

BLACK 평균이 31/255 이라 단차 16/255 은 **상대 50%** 다. 그래서 어두운 테마에서
사각 블록 경계로 읽힌다.

### 원인 (추측 아님 — 갈라서 확인했다)

`tools/진단_grass_v4_코너합성.gd` 로 같은 도형을 셋으로 구웠다.

| 구성 | 코너 쿼드 | 실루엣 직선 |
|---|---|---|
| A. 4방향 엣지만 | 0 / 0 | 수평 22.4 · 수직 26.8 월드px ← **코너 없이도 ㄱ자 단차가 있다** |
| B. 코너전용만 | 4 / 5+1 | (엣지 띠가 없어 의미 없음) |
| C. 현재 구성 (A+B) | 4 / 5+1 | 수평 11.6 · 수직 4.4 월드px |

즉 **코너 텍스처는 단차를 절반 이하로 줄여 준다.** 코너가 원인이 아니다.
남은 원인은 하이브리드 구조 자체다:

> SS2D 는 **한 엣지 안에서만** 코너 자리를 비워 준다 (코너 쿼드가 마지막 쿼드를 대체).
> 4방향 엣지와 코너전용 엣지는 **서로 다른 머티리얼**이라,
> 4방향 띠는 꺾이는 자리까지 그대로 그려지고 코너 정사각형이 그 **위에 겹쳐** 그려진다.
> 두 실루엣이 안 맞는 만큼이 세로 톤 단차로 남는다.

### 고칠 방향 (애드온 수정 없음 · AI 재생성 없음)

애드온에 **taper 기능이 이미 있는데 꺼져 있다**:

```
edge_material.gd:23  textures_taper_left / textures_taper_right
edge_material.gd:35  use_taper_texture: bool = true   ← v4 의 4방향은 전부 false
shape.gd:1618        is_first/last_tess_point 에서 _taper_quad() 를 끼워 넣는다
shape.gd:1525        edge_material_meta.taper_sharp_corners
```

taper 텍스처는 띠 끝을 각지게 끊지 않고 마무리하는 **정규 수단**이고,
코너를 엣지에서 극좌표로 합성했던 것과 같은 방식으로
기존 엣지 텍스처에서 **파생**할 수 있다 (새 그림을 그리지 않는다).
