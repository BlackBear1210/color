# 하수도 2-1~2-7 스프링·열쇠 새 디자인 적용

- 요청: 새로 들어온 점프대와 열쇠(조각 포함) 디자인을 2-1부터 2-7까지 적용.
- 시작 전 git pull: Already up to date. 이전 세션에서 없었던 `신규기믹_v02/게임용` 자산과 스프링 도약대 코드가 들어온 것 확인.

## 적용

| 스테이지 | 적용 대상 |
|---|---|
| 2-1 | 기존 점프대·열쇠 없음 |
| 2-2 | 방방_점프대_1~3: 하수도 재질(주철 판·코일·받침) 명시 |
| 2-3 | 기존 점프대·열쇠 없음 |
| 2-4 | 기존 점프대·열쇠 없음 |
| 2-5 | 검은열쇠: 새 원형 열쇠의 두 조각을 겹친 완성 그림 |
| 2-6 | 검정열쇠: 같은 완성 그림 |
| 2-7 | 점프대_1~3 하수도 재질, 검은열쇠조각 왼쪽 그림, 흰열쇠조각 오른쪽 그림 |

- 새 점프대 코드는 이미 판·코일·받침과 탄성 움직임을 지원한다. 해당 6개 인스턴스의 `재질 = 2`만 명시했다. 빈 아트슬롯이 새 그림을 가리지 않는 것 확인.
- `scripts/스마트월드/열쇠.gd`에 `새_디자인` 선택을 추가. 새 시스템으로 교체하면 색별 획득 조건·문·진행 저장까지 바뀌므로 기존 열쇠의 그림만 교체한다. 이유는 한글 주석으로 기록.
- `왼쪽.png`, `오른쪽.png`는 동일한 80×143 캔버스. 0.5배로 같은 원점에 그려 완성 열쇠의 이음매를 맞춘다. 조각도 같은 기준점과 크기 사용. 원본 PNG를 수정하거나 새로 생성하지 않음.
- 그림은 캐시하여 매 프레임 파일을 읽지 않는다. 임포트 전 PNG 직접 읽기 지원. 신규 owner 설정 없음.
- 기존 위치, 도약속도, 감지·충돌, 문들, 문 이동량, 두 조각을 함께 요구하는 연결, 획득 동작은 변경하지 않았다. 새 점프대 코드가 이 작업 전에 가진 판정·탄성 설정도 변경하지 않았다.
- 대상이 없는 스테이지에 새 기믹을 추가하지 않았다.

## 확인

- 작업 직전 7개 씬을 `tmp/key_spring_design_20261010/`에 보존하고 비교: 새 그림 선택 속성을 제외하면 바이트 내용 동일. 6개 점프대 + 2개 완성 열쇠 + 2개 조각, 총 10개 연결 확인.
- 새 열쇠 양쪽 그림과 하수도 상판을 직접 열어 확인. 하수도 부품 3개 및 열쇠 양쪽의 파일 존재·크기·알파 영역 확인.
- 기존 로컬 gdtoolkit으로 열쇠 스크립트 구문 분석 통과. 이 검사는 Godot API 인자 타입이나 실제 화면을 검증하지 않는다.
- git diff --check 통과. 엔진을 실행하는 빌더·촬영 도구는 실행하지 않음.
- 삭제된 추적 파일(D) 없음. graphify update . 실행: 새 그래프 14644개가 기존 34472개보다 작아 graph.json 덮어쓰기를 거부하는 보호 경고 발생. 강제로 덮어쓰지 않았으며 전체 갱신 완료로 보고하지 않는다.
- `docs/다음작업_프롬프트.md`는 현재 체크아웃에 없음. Godot 실행·엔진 검사 13개는 명시적 허용이 없어 미실행.
