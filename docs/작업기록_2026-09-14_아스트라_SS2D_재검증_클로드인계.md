# SS2D 재검증과 클로드 인계

사용자 요청: 직접 테스트를 수행한 다음 world_2_클로드 폴더에 기존 아스트라 프롬프트보다 상세한 클로드용 프롬프트 작성.

## 실제 작업

- 기존 120개 검사에 실제 페인트총알 생성→비행→물리 충돌→코어 명중→색 전환→E 회수에 해당하는 코어 회수 복구 검사를 추가했다. 키보드 E 입력 자체를 자동 입력한 검사는 아니다.
- 검정/흰색 × 얇은/두꺼운/경사 발판에서 **132/132 PASS**, 실행 로그 ERROR/FAIL 없음.
- 실제 OpenGL 그래픽 검사 **GRAPHICS_RESULT failures=0**, 실행 로그 ERROR 없음. 기본 줌1.0, 칠한 화면, 카메라 끝 캡처를 확인했다.
- 반사 켬/끔 비교: 407픽셀 변경, bbox(645,471,877,473), 최대 RGB 채널 차20/255. 가까운 발판 상면의 2픽셀 영역에 한정됐다.
- 이번 변경은 전용 테스트와 인계 자료다. 게임 공용 로직과 기존 맵을 수정하지 않았다. 이전 공용 회귀 실패는 다시 실행하거나 해결했다고 주장하지 않는다.

## 전달물

- `scenes/world_2_클로드/프롬프트_클로드_하수도_SS2D_지형배경_적용과검증.md`
- 같은 폴더 `검증자료_하수도_SS2D_2026-09-14/`: 테스트/그래픽 로그, 실제 렌더링 PNG3장, 검사·스크립트·셰이더 SHA256.
- 기존 아스트라 프롬프트의 맨 위에 새 상세 지침 링크를 추가했다. 기존 팀원 지침 본문은 유지했다.

프롬프트에는 작업 범위, 사전 질문, 자산 경로, 색 enum 차이, 한 연속 SS2D 원칙, 저장/재로드, 공통 빌더의 옛 템플릿 주의, 물리 배치, 시차/외곽 마감, 테스트 계층, 버그 재현 양식, 통과/실패/미실행 판정, 기존 문서 충돌, 실제 검증 범위와 한계를 명시했다.

## 한계

테스트는 기능 통합·고정 위치 물리 질의·투사체 비행·렌더링이다. 실제 대상 맵의 입력 기반 완주, 모든 카메라 전환, 일방통행, 32개 초과 선분 반사, 대형 맵 성능은 미검증이며 인계 작업에서 따로 확인하도록 적었다.

클로드에게 메시지를 전송하거나 새 작업을 만들지는 않았다. 사용자가 파일을 전달하면 된다. 커밋/푸시는 하지 않았다.
