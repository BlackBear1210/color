# 작업기록 2026-08-29 · SS2D 색 시스템 흑백 대칭화 + 흰색 키트

> 요청(도형/성진):
> *"기준을 ss2d로 잡고 진행하자. (키트 씬 6개) 디자인은 똑같이 진행하되, 흰색버전으로 만들자."*

드러나 함께 고쳤다.

## 2. 고친 것 — 색 시스템을 **흑백 대칭**으로

### `shaders/지형_페인트.gdshader` — 유니폼 두 개
| 유니폼 | 하는 일 |
|---|---|
| `base_is_white` | 이 조각이 **흰 아트를 기본으로 들었다**. 검정/흰색 매핑을 통째로 뒤집는다 |
| `alt_invert` | 짝 파일이 없을 때 `1.0 - base.r` 로 즉석에서 만든다 (안전망) |

`alt_invert` 의 식은 근사가 아니라 `tools/생성_타일셋_파생.gd _반전()` 과 **같은 식**이다.
진짜 짝 파일이 나중에 들어오면 `_짝_찾기()` 가 파일을 먼저 집으므로 저절로 교체된다.

### `scripts/스마트월드/지형.gd`
- `_짝_텍스처()` → **`_짝_찾기()` (양방향)**. 흑→백뿐 아니라 백→흑도 찾고,
  이 조각이 흰 아트인지(`흰색이_기본`)를 같이 돌려준다.
- 파일명 규칙이 넓어졌다. 예전엔 `begins_with("black_")` 만 봐서
  `brick_black_seamless_341x307.png`(벽돌 계단의 채움)이 규칙 밖으로 빠졌다.
  이제 `_` 로 끊어 **정확히 `black`/`white` 인 토막**을 본다.
- **짝이 없어도 셰이더를 붙인다.** 예전엔 null 을 돌려 조각이 원래 색으로 남았다.
- 투명 캐리어(`투명_256.png`)는 계속 건너뛴다 — 화면에 안 나오므로 붙일 이유가 없다.
- `되돌리기()` · `강제_초기화()` → **`_원래대로()`**. "원래" 는 무색이 아니라 `시작상태` 다.
  ⚠ 기존 씬은 전부 `시작상태 = 무색` 이라 동작이 하나도 안 바뀐다.

### 씬 승격
`벽돌 계단.tscn` · `벽돌 테스.tscn` 의 스크립트를 `지형.gd` 로 바꿨다(각 1줄).
점 배열이 이미 닫혀 있어서(계단은 13점, 마지막 = 첫 점) 그대로 `SS2D_Shape_Closed` 가 된다.

### 흰색 키트 6종 + 흰색 재질 2개 — `tools/생성_흰색키트.gd` (신규 · 멱등)

|---|---|
| `벽돌 계단.tscn` | `벽돌 계단_흰색.tscn` |
| `벽돌 테스.tscn` | `벽돌 테스_흰색.tscn` |
| `TEMPLATE_GRASS_SOLID` / `_STAIRS` | `..._WHITE` |
| `TEMPLATE_WOOD_SOLID` / `_STAIRS` | `..._WHITE` |

새로 생긴 재질: `지형_벽돌v2_opaque_white_사방.tres`, `지형_나무v2_white_detail_얇은_사방.tres`
(잔디는 `지형_잔디_v4_white_detail.tres` 가 이미 있어서 그대로 썼다.)

**왜 "검정 재질 + 시작상태만 흰색" 으로 안 했나** — 그러면 **에디터에서 검게 보인다.**
페인트 셰이더는 런타임 전용이라(`_ready()` 가 `Engine.is_editor_hint()` 로 막는다)
작업자는 흰 지형을 놓고도 검은 덩어리를 보며 맵을 찍게 된다. 키트의 존재 이유가 사라진다.
→ 흰색 씬은 **흰 아트를 기본으로** 든다. 에디터·런타임 둘 다 희게 보이고,
   `_짝_찾기()` 가 양방향이라 **검정으로 칠하는 것도 그대로 된다.**

## 4. ★지뢰밭 — 새로 밟은 것 두 개

### `.tscn` 의 한글 속성 이름은 **반드시 따옴표**로 쓴다
```
시작상태 = 2      ← 조용히 무시된다 (씬엔 적혀 있는데 노드는 기본값)
"시작상태" = 2    ← 이렇게 써야 한다
```
따옴표가 없으면 Godot 의 텍스트 파서가 이름을 **바이트 단위(Latin-1)로** 읽는다.
`시작상태`(12바이트 UTF-8)에 UTF-8 이 한 번 더 씌워져 **다른 이름**이 되고 무시된다.
Godot 자신도 한글 속성은 따옴표로 저장한다 (`집_2층방.tscn` 의 `"칠하기_허용" = false`).

### `.tscn` 에서 `id="` 를 찾으면 `uid="` 가 먼저 걸린다
속성을 찾을 때는 **앞의 공백까지** 붙여 `' id="'` 로 찾아야 한다.
이것 때문에 지형 스크립트의 id 자리에 uid 문자열을 집어서 `시작상태` 가 한 줄도 안 들어갔다.

# 이어서 · SS2D 전용 색 연출 (같은 날)

> 요청: *"ss2d 전용 색 시스템 만들자"* → 범위는 **연출을 타일맵 수준으로**,
> 추가로 *"테두리부터 물든다 + 물감이 아래로 흘러내림, 둘을 합칠 수 없나?"*

합쳐집니다. **테두리가 먼저 물들고 → 안쪽이 따라오고 → 그 사이 물감이 아래로 흘러내리는**
한 동작이 됐습니다. 규칙(`페인트_코어`)은 한 줄도 안 건드렸습니다.

## 1. 왜 SS2D 가 타일맵보다 밋밋했나

타일맵은 씨앗이 **0 에서 자라고**, 마지막 한 방에 전체로 확 튄다(`_목표반지름_갱신`).
SS2D 는 맞은 자리에 46px 얼룩이 **즉시** 찍히고 끝이었다. 규칙은 같은데 손맛만 달랐다.

## 2. 옮긴 것 · 더한 것

| | 어떻게 |
|---|---|
| **번짐** | `tile_paint_map.gd` 의 공식을 px 좌표로 이식. 목표 = `lerp(면적반지름, 전체반경, 진행^5)`, 지수 감쇠 상수 `0.0008` 은 **같은 값**을 쓴다(두 시스템 손맛이 갈리면 안 된다) |
| **테두리 선행** | 테두리 재질에만 셰이더 `r_scale` 을 크게 넣어 가장자리부터 잠기게 하는 장치. ⚠ **기본값은 1.0(끔)으로 내렸다** — 이유는 아래 마지막 절 |
| **흘러내림** | 셰이더에서 얼룩 아래로 늘어지는 줄기. 길이는 `seed_d`(지형.gd 가 시간에 따라 키운다), 굵기는 아래로 갈수록 가늘어진다 |
| **덮어쓰기** | 옛 얼룩을 **지우지 않고** 새 얼룩을 뒤에 붙인다. 안 그러면 새 색이 자라는 동안 바탕(안 칠한 색)이 드러나 덮어쓰기가 아니라 지우기처럼 보인다 |

### 연출이 있으면 안 되는 자리 (중요)
`시작상태` 로 태어난 지형 · 회수 복귀 · 강제 초기화는 **즉시** 적용된다.
스테이지를 열 때마다 흰 지형이 퍼지는 애니를 보여줄 이유가 없고,
태어날 때부터 흰 지형에서 물감이 흘러내리면 "방금 칠했다"는 거짓말이 된다.
→ `_시드_추가(..., 즉시)` 와 시드별 `_흘림상한` 으로 갈랐다.

## 3. 작업자가 만질 수 있는 값 (인스펙터 · 연출 그룹)

| 값 | 기본 | 뜻 |
|---|---|---|
| `흘러내림_길이` | 74px | 0 이면 흘러내리지 않는다 |
| `흘러내림_속도` | 110px/s | |
| `테두리_선행` | **1.0** | 한 덩어리로 칠해진다. 올리면 테두리가 먼저 물든다 (아래 마지막 절 참고) |

## 4. 지뢰밭 (또 밟은 것)

- **흘러내림 줄기를 칸(hash) 단위로 흔들면 네모난 계단으로 보인다.** 실제로 그렇게 찍혔다.
  이어지는 노이즈(`vnoise`)로 흔들어야 물감처럼 흐른다.
- **캡처 도구의 배경은 `z_index = -10` 이어야 한다.** SS2D 채우기는 `z_index -1` 로 그려져서,
  배경을 0 에 두면 채움이 배경 뒤로 숨어 **속이 빈 액자**처럼 찍힌다.
- 검사에서 `_지형.get_parent().queue_free()` 를 하면 안 된다 — 지형이 씬 루트면
  그 부모는 **SceneTree 의 root** 라, 트리가 통째로 무너져 검사가 멈춘다.

# 이어서 · 프로토 스테이지에 SS2D 지형을 놓았을 때 (같은 날)

> 제보(성진): *"stage_2-3 에 벽돌 테스를 넣고 색 시스템을 확인하려는데 총알이 그냥 통과한다."*

원인이 **두 겹**이었다. 둘 다 "한쪽 계열에서만 되는 것" 이었다.

## 1. 총알이 통과한 진짜 이유 — 물리 몸이 아예 없었다

`벽돌 테스.tscn` 의 SS2D 노드에는 **`StaticBody2D` 도 `CollisionPolygon2D` 도 없었다.**
`collision_polygon_node_path` 도 비어 있어서 SS2D 가 콜리전을 구울 곳 자체가 없었다.
→ 총알만 통과한 게 아니라 **플레이어도 통과**하는 상태였다. 그림만 있는 씬이었다.

```
[node name="SS2D_Shape_Closed" ...]
collision_update_mode = 2
collision_size = 24.0
collision_polygon_node_path = NodePath("StaticBody2D/CollisionPolygon2D")

[node name="StaticBody2D" type="StaticBody2D" parent="SS2D_Shape_Closed"]
[node name="CollisionPolygon2D" type="CollisionPolygon2D" parent="SS2D_Shape_Closed/StaticBody2D"]
```
런타임에 7 점 폴리곤이 구워지는 것을 확인했다. (흰색판도 도구로 다시 파생했다)

## 2. 그 다음에 나올 뻔한 것 — 칠해지는데 **안 죽는다**

`stage_lab.gd _발밑_플랫폼()` 이 콜리전을 **`PaintPlatform` 으로 캐스팅**하고 있었다.
SS2D 지형은 그 타입이 아니라 항상 null → 총으로 칠할 수는 있는데 **밟아도 안 죽는다.**
색이 곧 규칙인 게임에서 화면과 판정이 어긋나는, 가장 나쁜 상태다.

→ **타입이 아니라 계약으로 찾는다.** `반대색인가()` 를 가진 조상을 거슬러 올라가며 찾는다.
   (`월드.gd _반대색_대상_찾기()` 와 같은 방식 — 두 계열이 같은 말을 쓰게 했다)
   `PaintPlatform` 도 그 메서드를 갖고 있어 기존 스테이지는 그대로 돈다.

## 3. 덤 — 탄약이 잠긴 채 남던 것

SS2D 지형은 부분 칠이 4초+1초 뒤 스스로 무색으로 돌아간다. 그런데 그 사실을
`페인트코어` 에게만 알렸다. 프로토 계열에는 페인트코어가 없어(`TilePaintMap` 이 그 자리다)
**지형은 비었는데 탄약은 잠긴 채**로 남았다.
→ `지형.gd` 가 규칙 엔진을 **계약(`부분_자동회수`)으로** 찾게 하고,
   `TilePaintMap` 에 같은 이름의 메서드를 붙였다.

## 4. ★따로 보고 — stage_2-3 의 타일맵은 원래부터 못 칠한다

진단하다가 나온 것이다. `stage_2-3` 의 `TileMapLayer` 는 `assets/png/metal.png` 를 쓰는데,
`tile_paint_map.gd 축_by_파일` 에는 brick/grass/rock/soil/wood **5 종만** 등록돼 있다.
→ `분할축 = -1` → `좌표_색 = -1` → **플랫폼 0 개**. 실측으로 확인했다:

```
타일맵_페인트 켜짐? true
타일 플랫폼 수: 0
paint_platform 그룹 수: 0
```

즉 이 스테이지는 **지금까지 아무것도 칠할 수 없었고 색으로 죽지도 않았다.**
metal 타일셋에 흑/백 두 판이 없으면 타일맵 방식으로는 살릴 수 없다.
→ SS2D 지형으로 가는 편이 맞다(이번에 그 길이 열렸다).

콜리전이 구워졌나 → 총알 마스크(1|8)에 걸리나 → 총알이 부모를 거슬러 지형을 찾나 →

# 이어서 · 흰색 판이 "페인트 한 겹"으로 보이던 것 (같은 날)

> 제보(성진): *"예전에는 흑·백 두 가지 타일을 쓰면서 반대되는 색의 **디자인**이 나오게 했는데,
> 지금은 그냥 페인트가 덮히는 것처럼 된다."*

맞는 지적이었고, **벽돌만** 흰색 판이 잘못 만들어져 있었다.

## 1. 재 보고 알아낸 것 — 반전이 항상 옳은 게 아니다

흰색 판은 지금까지 전부 `1 - r`(휘도 반전)으로 만들었다. 이건 **밝은 디테일**을 가진
그림에만 맞다. 반전하면 밝은 선이 어두운 선이 되어 흰 바탕 위에서 잘 읽히기 때문이다.

문제는 **어두운 디테일(파인 곳)** 을 가진 그림이다. 벽돌이 그렇다.

| 그림 | 중앙(바탕) | 밝은 디테일 : 어두운 디테일 | 반전이 맞나 |
|---|---|---|---|
| 벽돌 채움 | 0.149 | 866 : **2273** | ✖ 줄눈이 바탕보다 어둡다 |
| 벽돌v2 채움 | 0.149 | 8461 : **23757** | ✖ |
| 나무 채움 | 0.118 | **28426** : 25429 | ✔ |
| 잔디 윗면 | 0.098 | **7181** : 1510 | ✔ |
| 잔디 채움 | 0.110 | **14374** : 5381 | ✔ |

검정 벽돌은 벽돌면(0.149)보다 **줄눈이 더 어둡다**(0.0). 반전하면 줄눈이 1.0 이 되어
**줄눈이 빛나고** 벽돌면은 회색이 된다 → 흰 바탕에 흰 선이라 무늬가 안 읽히고,
흰 물감을 한 겹 부은 것처럼 보인다. 그게 제보의 정체다.

여기에 사람 눈의 비대칭이 겹친다. 검정 쪽 0.0 대 0.149 는 잘 보이지만
흰 쪽 0.851 대 1.0 은 거의 안 보인다(같은 0.15 차이인데도).

## 2. 고친 방법 — `파임유지`

`tools/생성_흰색짝.gd` 에 두 번째 방식을 넣었다.

```
흰색 = (1 - 중앙값) + (r - 중앙값) x 대비        # 기본 대비 1.6
```
바탕 톤은 뒤집히고 **줄눈은 바탕보다 어두운 회색 선으로 남는다.**
디자이너가 예전 타일맵 흑/백 두 판을 그렸을 때 쓴 것과 같은 문법이다
(`assets/tileset/brick.png` 의 백 판도 흰 벽돌 + 회색 줄눈이다).

벽돌 계열 33 장을 이 방식으로 다시 구웠다.
```
godot --headless --path . -s res://tools/생성_흰색짝.gd -- \
    --방식=파임유지 --대비=1.6 --덮어쓰기 \
    --폴더=res://assets/textures/smartshape/brick_v2 \
    --폴더=res://assets/textures/smartshape/brick_v2_opaque \
    --파일=res://assets/tileset/brick_black_seamless_341x307.png
godot --headless --path . --import
```

**나무·잔디는 일부러 그대로 뒀다.** 그쪽에 파임유지를 쓰면 흰 풀잎과 나무 결이
날아가 오히려 흐릿해진다(세 재질을 나란히 렌더해 눈으로 확인).
어느 쪽인지 모르는 재질은 `--진단` 으로 먼저 재 본다.

## 3. 눈으로 확인

`tools/_shots/벽돌_04.png`(전) → `벽돌새_04.png`(후).
전에는 흰 부분이 회색 벽돌 + 빛나는 흰 줄눈이라 무늬가 안 읽혔고,
후에는 **흰 벽돌 + 회색 줄눈**으로 벽돌 무늬가 그대로 읽힌다.
부분 칠 얼룩(`벽돌새_02.png`)도 안에서 벽돌 모양이 보인다.

## 4. 지뢰밭

**`생성_타일셋_파생.gd` 는 아직 반전만 쓴다.** 마스터에서 벽돌을 다시 구우면
흰 판이 옛 규칙으로 되돌아간다 → 그 도구에 경고를 박아 두었고, 다시 구운 뒤에는
반드시 `생성_흰색짝.gd --방식=파임유지` 를 이어서 돌려야 한다.

# 이어서 · "테두리와 안쪽을 따로 칠한 것처럼 보인다" (같은 날)

> 제보(성진 · 스크린샷): *"색칠되는 게 모서리와 안쪽이 따로 구분되어 있는 것 같다.
> 그래서 저렇게 어색한 모양이 나온 것 같다. 한 덩어리로 판단해서 칠해지게 해봐."*

정확한 진단이었다. 범인은 **내가 바로 앞에 넣은 `테두리_선행 = 1.35`** 다.

## 무엇이 보였나
SS2D 는 테두리 메시와 채움 메시가 **서로 다른 재질**이다. 테두리 쪽 얼룩만 1.35 배로
그리면, 얼룩이 커질수록 **테두리 띠는 이미 다 칠해졌는데 안쪽은 아직 덜 칠해진** 상태가 된다.
그 경계가 그대로 눈에 보인다:

- 위쪽 띠가 통째로 하얘지고 **띠 두께를 따라 경계가 직선으로 잘린다**
- 모서리에서는 안 칠해진 **검은 쐐기**가 하얀 영역 안으로 파고든다 (제보 스크린샷의 빨간 동그라미)

"물감이 번진다" 가 아니라 "테두리와 안쪽을 따로 칠했다" 로 읽힌다.

## 고침
`테두리_선행` 기본값을 **1.35 → 1.0**. 테두리와 채움이 **같은 반지름**을 쓰므로
얼룩이 경계를 넘어 이어진다. 값은 남겨 뒀다 — 그 효과를 일부러 쓰고 싶으면 1.05~1.1 정도만.

`tools/_shots/벽돌한덩어리_{03,04}.png` — 얼룩이 한 덩어리로 번지고, 여러 발 맞은 뒤에도
위아래로 이어지는 물결 경계 하나만 남는다(직선 잘림·검은 쐐기 없음).

# 이어서 · 물줄기가 톱니처럼 줄줄이 났던 것 (같은 날)

> 제보(성진 · 스크린샷): *"페인트 모양이 죄다 왜저래. 빨간 원으로 표시한 게 하나, 혹은
> 두 개(두 개면 서로 길이가 다르게) 하던가. 색칠될 때 살짝 랜덤한 모양이 되게 만들어."*

## 1. 왜 톱니가 났나

첫 구현은 **줄기 길이만** x 를 따라 흔들었다(`lane = dv.x / (r*0.5)` 마다 길이를 노이즈로).
그러면 얼룩 폭 **전체**에서 일정한 간격으로 줄기가 생긴다 — 얼룩이 커질수록 개수도 늘어
톱니처럼 줄줄이 달린다. 실제 물감은 몇 군데에서만, 서로 다른 길이로 흐른다.

## 2. 고침 — 가닥을 세어서 그린다

얼룩 하나당 **한 가닥, 많아야 두 가닥**. 가닥마다 씨앗 번호로 뽑는다:
- 시작 x (얼룩 폭 안 어딘가) · 길이(`run` 의 35~100%) · 굵기
- 두 번째 가닥은 **절반 확률**로만 생긴다 → 어떤 얼룩은 한 가닥, 어떤 얼룩은 두 가닥
- 흐르면서 좌우로 살짝 휜다(자로 그은 듯 곧으면 물감으로 안 보인다)
- 끝은 뾰족하지 않게(0.45 만 가늘어진다) → 물방울처럼 둥근 끝

## 3. "살짝 랜덤한 모양" — 얼룩 자체를 일그러뜨린다

경계 노이즈(`noise_amount = 5px`)는 **px 단위**라 얼룩이 커지면 상대적으로 안 보인다.
그래서 큰 얼룩일수록 **완벽한 원**이 됐다. 반지름에 비례하는 물결을 하나 더 얹었다:

```
r = seed_r[i] * (1.0 + nlow * blob_wobble)      // blob_wobble = 0.14
```

크기와 상관없이 덩어리 모양이 제각각이 된다.

### ⚠ 같이 고쳐야 했던 것 — 전체 색칠 반경
반지름이 자리마다 14% 씩 줄어들 수 있으므로, **전체 색칠 반경에 그만큼 여유**를 안 주면
오목한 쪽 구석이 안 칠해진 채 남는다 = "다 칠했는데 검은 자국".
`지형.gd 얼룩_일그러짐` 상수를 셰이더 `blob_wobble` 로 그대로 밀어 넣고,
전체 색칠·덮어쓰기·회색화 반경에 `x (1 + 0.14 + 0.02)` 를 곱했다.
**이 두 값은 항상 같아야 한다.**
