# 몬스터 몸색을 플레이어 페인트로 바꾸기

- 날짜: 2026-10-10
- 사용자 확인: 몬스터를 죽이는 기능이 아니라 페인트로 몬스터 색을 바꾸는 기능을 요청했다.

## 원인

- 순찰몬스터는 명중() 구현이 없었고 총알_막나()가 false를 반환했다.
- 총알은 총알_막나() 메서드가 있으면 false인 경우 그냥 통과하므로 몬스터 몸색이 바뀔 경로가 없었다.

## 변경

- 순찰몬스터.gd에 페인트코어 명중/현재색/회수/초기화 계약을 추가했다. 검정·흰색 페인트 한 발로 몸색을 즉시 바꾸며, 같은 색은 wasted로 환급한다.
- 기존 색 setter를 사용하므로 몸 스프라이트와 접촉 위험 판정이 동시에 바뀐다. 사격몬스터는 부모의 현재 몸색을 사용하므로 다음 발부터 바뀐 색 페인트를 쏜다. 이미 날아가는 탄은 발사 당시 색을 유지한다.
- 원래 몸색은 런타임 ready에서 저장한다. 페인트코어 E 회수/리스폰 초기화로 원래 몸색을 복원한다. 플레이어가 쓴 발수 정산은 기존 페인트코어가 담당한다.
- 총알.gd에서 몬스터 명중을 이동 구간 레이캐스트로 처리한다. 몬스터와 단단한 지형을 동시에 만날 경우 가까운 충돌만 선택해 벽 뒤 몬스터를 칠하지 않는다.
- 몬스터가 공유하는 유체 레이어의 일반 물 영역은 몬스터 탐색에서 제외한다. 기존 유체 차단 경로는 유지한다.
- 장치 탄은 몬스터를 통과하며 몸색을 바꾸지 않는다. 따라서 총구가 몸 안에 있어도 자기 자신에게 막히지 않는다.
- 기존 발소리와 페인트 효과음 변경을 유지했다. 모든 변경 이유에 한글 주석을 붙였다.

## 확인

- git pull: 원격 최신 상태.
- 수정 전 순찰몬스터/총알 GDScript 문법 확인 통과.
- 수정 후 순찰몬스터/사격몬스터/총알/페인트코어 로컬 GDScript 문법 확인 통과.
- 수정 파일 git diff --check 통과, 삭제 상태 파일 없음.
- Godot 편집기·콘솔·headless 및 엔진 검사 13개: 사용자 실행 허용이 없어 미실행. 지정된 docs/다음작업_프롬프트.md는 현재 체크아웃에 없다.
- 실제 엔진 캡처: 없음. 시각 및 물리 동작 검증 대기.
- 실행 허용 후 확인할 동작: 흑→백/백→흑 한 발 명중, 같은 색 명중 환급, E 회수, 리스폰 복원, 바뀐 사격색, 빠른 총알의 몬스터 명중, 벽 뒤 몬스터 차단, 장치 탄 자기 몸 통과.

## 실제 엔진 동작 검증 (사용자 허용 후)

- 사용자가 음성으로 “동작 확인해봐”라고 요청해 Godot 실행을 명시적으로 허용했다.
- Godot 4.6.3 그래픽 모드로 실제 stage_2-8 씬을 로드했다. headless는 사용하지 않았다. 충돌 오류 대화상자 억제를 적용하고 자동 종료 제한을 두었으며 기존 Godot 프로세스에는 손대지 않았다.
- `tools/test_몬스터_몸색_실행.gd`에서 실제 몬스터와 실제 총알/페인트코어를 사용한 28개 확인이 전부 통과했다.
- 검정→흰/흰→검 실제 투사체 명중, 흰색 스프라이트 변경, 바뀐 접촉 위험 판정, 다음 발사 흰색/검정색, 같은 색 명중 환급, E 회수와 탄약 복구, 장치 탄 몸 통과, 실제 월드 `_리스폰()` 후 원래 몸색/탄약 복구를 확인했다.
- 기본 1배 게임 카메라에서 같은 구도 전후 PNG를 저장하고 직접 열어 검정 몸이 흰 몸으로 바뀌는 것을 확인했다. 실행 창에서 측정된 화면은 1920×1055였다(프로젝트 요청 1920×1080, 실제 데스크톱 창 높이 반영). 배경/발판 구도는 전후 동일하며 흰 몬스터와 E 회수 마커가 정상 표시된다.
- 실제 캡처: `docs/visual_review/몬스터_몸색_20261010/before_black.png`, `after_white.png`, `after_black.png`.
- 검사 결과: 같은 폴더 `result.json`, 엔진 기록 `engine.log`.
- 검증 범위: 자동 검사에서 이동을 잠시 정지하고 실제 투사체를 발사했다. 전체 스테이지 수동 플레이와 총 클릭 입력은 이번 검사 범위가 아니다.
- 환경 로그에 루트 인증서 읽기/셰이더 캐시 저장 오류가 기록됐으나 모든 동작 확인과 캡처가 완료됐고 스크립트 오류나 엔진 충돌은 없었다.
