# 행동 손맛 정적 진단

- 날짜: 2026-10-12
- 요청: 발사·점프·착지·상호작용이 심심하거나 어색한 이유와 개선 방법 설명.
- 범위: 현재 파일 읽기와 분석. 게임 코드·씬 수정 없음.
- Godot 실행 및 엔진 검사: 미실행. 사용자 명시적 실행 허용 없음.
- 실제 동작 영상·소리 비교: 미실행. 아래 체감 해석은 코드에 근거한 가설이며 실제 플레이 확인 필요.

## 현재 사용하는 경로

`scenes/player/Player.tscn`의 본체는 `scripts/paint_head_anim.gd`를 사용하며 `player_anim.gd`를 상속한다. 이전 별도 `player_shoot_anim.gd`보다 현재 본체 경로를 기준으로 분석했다. 스마트월드 발사는 `scripts/스마트월드/총.gd`, 점프·착지 이벤트는 `scripts/player.gd`, 파티클은 `scripts/player_action_fx.gd`에 연결된다.

## 확인한 원인

1. **착지 파티클이 숨겨진 부모에 생성된다.** Player.tscn의 ActionFX는 visible=false. 착지 함수는 기존 먼지 경로만 사용하며 `_새_파티클`은 기본적으로 self에 붙인다. 점프의 새 잉크 시트는 current_scene에 붙어 이 문제를 피하지만 착지 먼지는 같은 처리가 없다. 명중의 주 이펙트도 current_scene에 붙지만 잔점은 숨겨질 수 있다.
2. **착지 스쿼시가 충돌 후 속도를 읽고 같은 렌더 프레임에 회복된다.** player_anim.gd는 착지 때 `_player.velocity.y`를 읽는다. 일반적인 평지 충돌 후에는 0에 가까워 최소 세기 0.25×0.16=0.04가 된다. 이어서 회복값 10×delta를 더해 60fps에서는 약 0.167만큼 회복하므로 이 작은 변형이 적용되기 전에 사라진다. player.gd에는 이미 move_and_slide 이전의 착지_직전속도가 있다.
3. **발사가 전신 모션을 약 0.267초 덮는다.** paint_head_anim.gd는 12/45초 동안 shoot를 walk/jump/fall/land보다 우선한다. 스마트월드 기본 발사간격 0.22초보다 길어 빠르게 반복 발사하면 회복 끝 전에 재시작할 수 있다. 이동 중에는 발이 지면을 따라가는 걷기 대신 전신 사격이 나와 미끄러짐으로 읽힐 수 있다.
4. **방향과 총구 표현이 단순하다.** 본체 발사 자세는 마우스 x로 좌우만 바뀌고, 실제 탄은 마우스 방향 전체를 따른다. 총구 좌표는 특정 원본 프레임의 고정 좌표를 사용한다. 상하 조준·모션별 총구 정합은 실제 시트와 플레이 영상에서 확인할 필요가 있다.
5. **상호작용이 플레이어 자세와 연결되지 않는다.** 월드는 대상의 조작 함수를 직접 부른다. 벽레버는 자체 움직임은 있으나 캐릭터 손 뻗기·접촉 모션 호출은 없다. 잠긴 레버는 닿아있나에서 false를 반환해 일반 E 경로에서 조작 함수의 덜컥 피드백까지 도달하지 않는다.
6. **퍼즐 카메라 연출과 사망 상태가 혼동될 수 있다.** 레버퍼즐은 성공 연출 중 플레이어 물리 처리를 끈다. player_anim.gd는 물리 처리 비활성을 사망 모션 조건으로 사용한다. 해당 퍼즐 경로에서 성공 중 death 자세가 선택될 수 있으므로 별도 상태 구분 필요.
7. **수평 이동은 입력 즉시 고정 속도다.** player.gd의 velocity.x=dir*move_speed에는 가속·감속 구간이 없다. 이는 정밀 조작 선택일 수 있지만 그림에도 출발·정지·방향 전환 반응이 없으면 몸의 무게가 약하게 읽힐 수 있다. 물리 가속 도입은 기존 점프 거리와 퍼즐 통과성 검증이 필요한 별도 변경이다.

## 제안 우선순위

1. 숨겨진 착지 효과와 소실되는 스쿼시부터 복구. 충돌 전 속도로 세기를 정하고 발을 기준으로 약 0.10~0.16초 회복하는 시각 반응을 시험한다.
2. 발사 중 걷기·공중 상태 유지. 상체 반동이나 상태별 사격 자세를 사용하고, 발사 순간의 총구 물감 튐·몸 반동·소리를 같은 이벤트에 맞춘다.
3. 점프는 입력 반응을 늦추지 않으면서 이륙·정점·낙하·착지 실루엣을 구분하고 실제 속도에 시트를 맞춘다.
4. 상호작용 대상 표시, 접촉 자세, 대상 움직임·소리, 성공·거절 피드백 연결. 연출 정지와 사망은 별도 상태로 처리한다.
5. 재질별 소리·작은 잔여 움직임 추가. 화면 흔들림은 높은 낙하나 큰 장치 작동에 제한적으로 시험한다.

제안 시간·세기는 확정 사양이 아니라 비교 실험의 시작값이다. 배경·캐릭터·칠해진 지형의 흑백 규칙이 혼동되지 않게 작은 범위에서 시험한다. 기존 점프 높이·거리·색 접촉 판정을 바꾸기 전에 시각 연결 문제부터 해결하는 편이 타당하다.

## 조회 및 확인

- graphify query 실행. 그래프에 임시 의존성 파일이 다수 포함되어 광범위 쿼리의 관련성이 낮아 현재 소스로 추가 확인했다.
- 설치된 graphify는 reflect 명령을 지원하지 않는다.
- 안내된 docs/다음작업_프롬프트.md는 현재 체크아웃에서 찾을 수 없었다.
- 기존 수정·미추적 파일은 보존했다. 분석 작업이므로 pull·씬 생성·엔진 검사·빌드 실행은 하지 않았다.
- 엔진 캡처 경로: 없음. 실행 미허용으로 시각 검증 대기.
