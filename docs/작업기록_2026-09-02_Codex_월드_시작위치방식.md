# 작업기록 — 월드 시작 위치 방식 (2026-09-02 · Codex)

## 요청

`월드.gd`를 사용하는 SS2D 스테이지에서 다음 두 시작 방식을 Inspector로 번갈아 쓰고 싶다.

- 고정 좌표 `시작_위치`
- 2D 워크스페이스에 저장한 `Player` 배치 좌표

## 변경

`scripts/스마트월드/월드.gd`에 `시작 위치 방식` Inspector enum을 추가했다.

| 선택값 | 현재 씬 직접 실행(F6) 시 위치 |
| --- | --- |
| 고정 좌표 | 루트 노드의 `시작_위치` |
| 에디터 Player 위치 | 씬에 저장한 `Player.position` |

- 통로를 통해 진입하면 기존처럼 입구 통로 위치가 두 방식보다 우선한다.
- 자동 체크포인트를 끈 리스폰도 선택한 직접 실행 시작 위치로 돌아가도록 맞췄다.
- 기본값은 `고정 좌표`라 기존 스마트월드 씬의 동작은 바뀌지 않는다.

## 사용법

1. SS2D 스마트월드 씬의 최상위 노드를 선택한다.
2. Inspector의 `시작 위치 방식`에서 원하는 값을 고른다.
3. `에디터 Player 위치`를 선택했을 때는 2D 워크스페이스에서 Player를 원하는 바닥 위에 배치한 뒤 씬을 저장한다.

## stage_2-1 적용

- `scenes/world_2/stage_2-1.tscn`에 `페인트코어` 노드를 추가했다. `월드.gd`와 페인트총이 같은 코어를 찾아 SS2D 지형 색칠 상태를 공유한다.
- 이 씬은 `시작_위치_방식 = 에디터 Player 위치`로 저장돼 있다. 따라서 현재 2D 워크스페이스에 저장한 Player 배치에서 F6 실행이 시작된다.

## stage_2-1 점프 기준

현재 Player 설정은 타일 크기 16px, 높이 8칸, 거리 15칸, 이동 속도 300px/s다.

- 최대 상승: 128px = 8칸
- 수평 설정값: 240px = 15칸
- 실제 같은 높이 착지 거리: 약 210px = 13.1칸. `낙하_가속_증가율 = 9`가 하강 시간을 줄이므로 설정값보다 짧다.
- 코요테 포함 같은 높이 착지 거리: 약 229px = 14.3칸. 절벽을 벗어난 0.12초 동안 약 7.6px 내려간 상태와 누적 낙하 가속까지 반영한 값이다.

## 점프 범위 편집기 표시

`점프범위_표시.gd`를 `stage_2-1`에 붙였다. 2D 워크스페이스에서만 보이며 게임 실행 화면에는 나타나지 않는다.

- 노랑 실선: 일반 점프 궤적과 CollisionPolygon2D 착지 몸통
- 청록 점선: 코요테 시간 0.12초를 포함한 실제 궤적과 착지 몸통
- 세로선: 일반 점프 최대 높이
- 숫자: px와 현재 Player의 타일 크기 기준 칸 수

## stage_2-1 색상 사망 판정 복구

`월드.gd`의 사망 판정 코드는 그대로 있었지만, 새로 배치한 SS2D 시멘트 인스턴스에는
`위치별 판정`이 꺼져 있었다. 이 경우 기본 아트색(검정/흰색)을 기준으로 하는 접촉 판정이
실행되지 않는다.

- stage_2-1의 검정 시멘트, 계단, 흰 시멘트에 `위치별 판정 = true`를 저장했다.
- `TEMPLATE_CEMENT_SOLID_WHITE`에는 `시작상태 = 흰색`을 저장했다. 이제 흰 아트가 화면만
  흰색이고 규칙상 검정으로 취급되던 불일치가 없다.
- 따라서 검정 플레이어는 흰 시멘트, 흰 플레이어는 검정 시멘트에 몸의 해당 부위가 닿으면
  즉사하며, 회색은 안전하다.

## 검증

- Godot 실행·헤드리스 검사는 사용자 안전 규약에 따라 실행하지 않았다.
- 정적 확인: 시작 위치 결정, 통로 진입 fallback, 자동 체크포인트 비활성 리스폰이 모두 같은 선택 함수를 사용한다.
- 추가 정적 확인: stage_2-1의 세 시멘트 인스턴스에 `위치별 판정`이 있고, 흰 시멘트 템플릿에
  `시작상태 = 2(흰색)`가 기록된 것을 확인했다. `git diff --check`도 통과했다.
