# 작업기록 2026-08-25 · 동현 — 안쪽 코너에서 벽돌이 90° 서는 문제 규명과 수정

> 도형 부재로 대신 처리. baker 를 고치고 BRICK v2 를 다시 구웠다 (WOOD v2 는 예외).
> 상세 분석은 `docs/이슈_CORNER-SIDE-ROTATION-01.md` 에 있다. 이 문서는 경위만 적는다.

---

## 발단

`scenes/집/스마트 매쉬 assets/BRICK_벽돌/` 의 TEMPLATE 3종(SOLID · HOLLOW · STAIRS)에서
직각 코너마다 "다른 재질을 덧댄 사각 자국"이 보였다. 확대 화면이 아니라 편집 화면이었다.

## 규명

`_코너합성_miter()` 를 Python 으로 옮겨 실제 산출물과 대조했다.
`corner_outer` 0.29/255, `corner_inner` 0.36/255 (최대 1.0 = 반올림) 로 일치해
이 재현 위에서 실험할 수 있었다. **Godot 은 규명 단계에서 쓰지 않았다.**

무늬 방향 지수(세로기울기÷가로기울기)를 재질 5종에 걸어 원인을 좁혔다.

원인: `_코너합성_miter()` 의 `바깥 == false` 분기에서 **`px` 와 `py` 가 뒤바뀌어 있다.**
TOP·SIDE 두 단면이 모두 90° 돌아간 채로 합성된다.

v1 에서는 이 결함이 **바깥 코너**에 있었고(SIDE 원본을 회전 없이 그렸으므로),
v2 에서 `원본_소스_제작규칙.md` §2 대로 SIDE 를 회전시키자 **안쪽 코너로 옮겨왔다.**
없던 문제가 생긴 것이 아니라 자리를 옮긴 것이다.

## 헛짚은 것 두 개 (다시 파지 말 것)

1. **벽돌 주기를 코너 크기의 약수로** (`CORNER-TOPOLOGY-01` 검토방향 4번)
   주기 142→128텍셀, `U_TOP` 0.31→0.375. 산술은 맞아떨어지는데 렌더에 차이가 없었다.
2. **코너의 반투명 후광**
   `corner_inner` 반투명 비율이 32.9% 로 높지만, 알파 전환폭을 좁혀도 톤 변화가 그대로였다.

※ 이때 만든 위상 측정 지표는 **믿을 수 없다.** 연속인 대조군에서도 28px 어긋남으로 나왔다.
  러닝본드는 켜마다 반 장씩 밀려 상호상관이 여러 지점에서 똑같이 높다.

## 조치

**1. baker 를 고쳤다** — `tools/생성_타일셋_파생.gd` 의 `_코너합성_miter()` `else` 분기 UV 4줄.

**2. BRICK v2 를 다시 구웠다.** 감마가 문서에 없어 역산했다 — **2.62**.
이 값으로 구우면 출하본 32장 중 30장이 오차 **0.000/255** 로 완전히 같고,
실제로 바뀐 파일은 `corner_inner.png` 흑·백 2장뿐이다. 방향지수 0.47 → 1.47.

**3. WOOD v2 는 다시 굽지 않았다.** 어떤 감마로도 출하본이 재현되지 않았다
(최소 0.476/255 @ 2.85). 그대로 구우면 나머지 31장까지 미세하게 달라지므로
`corner_inner.png` 2장만 갈아 끼웠다. 그 2장이 고쳐진 baker 산출물과 같은지는 확인했다.

Godot **4.6.3** 으로 확인했다. `실험_코너_렌더.gd` 의 ㄱ자, 그리고 `WORKER_GUIDE.tscn` 의
BRICK 구역을 실제로 찍었다. 계단 각 단의 안쪽 구석에 있던 사각 얼룩이 사라졌다.

## 남은 것

- **WOOD v2** 는 텍스처만 교체된 상태다. 다시 구울 일이 생기면 감마부터 찾아야 한다.
  원본 `tools/wood_v2_pipeline/src` 가 구운 뒤 손질됐을 가능성이 있다.
- **IRON v1** 은 baker 가 고쳐졌으므로 평소대로 구우면 된다.
- `CORNER-TOPOLOGY-01`(코너 무늬 **위상** 불연속)은 **그대로 남아 있다.** 별개 문제다.

## 겸사겸사 알아낸 것

콘솔에 반복되던 아래 오류의 출처를 확인했다. 이번 작업과 무관한 기존 문제다.

ERROR: Parameter "data.tree" is null.
   at: get_tree (scene/main/node.h:549)
