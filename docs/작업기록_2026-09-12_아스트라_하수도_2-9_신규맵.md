# stage_2-9 · 돌아오는 물길

사용자 요청: `res://scenes/world_2_클로드/stage_2-9.tscn` 신규 생성.

첨부 프롬프트는 레벨 디자인 참고 자료로 읽었다. 그 안의 별도 승인 절차, Godot 실행 명령, 챕터표 변경 지시를 사용자 직접 요청으로 취급하지 않았다. AGENTS.md의 엔진 실행 금지 예외에 따라 Godot 편집기·콘솔·헤드리스·기존 빌더를 실행하지 않았다.

## 생성 파일

- `scenes/world_2_클로드/stage_2-9.tscn`: 독립 스테이지. 월드.gd, 페인트코어, Player 및 기존 장애물 재사용.
- `tools/작성_하수도_2-9.mjs`: Godot 없이 좌표표를 TSCN 텍스트로 직렬화하는 보조 도구. 기본 실행과 `--check`는 읽기 전용. `--write`는 이 새 씬 하나만 덮어쓰므로 향후 에디터 수정 후 재실행에 주의.

기존 스테이지·게임 코드·챕터 순서·로비 목록은 변경하지 않았다. 출구의 다음 씬은 후속 스테이지가 지정되지 않아 기존 로비로 설정했다. 현재 씬은 에디터에서 직접 열어 실행할 수 있는 구성이다. 실제 실행 검증은 하지 않았다.

## 동선

```text
3층  서쪽 승강기 → 검정 → 흰 정비 회랑 → 회전톱 → 검정 출구 → 로비
       ↑
2층  서쪽 참 ← 완만한 경사 ← 중앙 승강기 교차점 ← 흰 회랑 ← 동쪽 승강기
                              ↑                              ↑
별도  F1 흰 선반 → 유지 버튼   F3 흰 준비 선반 → 열리는 문     |
        ↑          ↓          ↑                              |
1층  시작 → 낮은 수로 ← 복귀 → 갈림길 → F2 하부 우회 → 흰 수로 → 톱
```

- 주층 3개(바닥 기준 y=3072/2304/1536), 별도 F1 선반을 포함한 4단 구조. 실사용 가로 구간 약 12,500px.
- F1: 시작 바닥 오른쪽의 128px 틈에서 흰 상부 길과 검정 하부 길 선택. 흰 선반 끝의 검정 버튼방에서 F3 문을 연다. 끝벽 앞 오른쪽으로 내려가면 352px 낙하 후 하부 동선에 합류한다.
- F2: 오른쪽 끝까지 진행하고 동쪽 승강기로 2층에 오른 뒤 왼쪽 끝까지 돌아간다. 서쪽 승강기로 3층에 올라 다시 오른쪽 출구로 간다. 기본 왕복 동선의 설계 길이는 약 37,000px이며 실제 주행으로 측정하지 않았다.
- F3: 중앙의 흰 준비 선반을 점프로 통과하고 F1 버튼으로 열린 문 안의 중앙 승강기를 탄다. 2층의 중간 교차점으로 합류하여 동쪽 왕복을 생략한다. 문이 닫혀 있으면 준비 선반 옆의 틈으로 하부 길에 복귀할 수 있다.
- 회전톱 2개는 검정 바닥에 배치. 승강기 3개, 회색 집수조 3개, 유지 버튼 1개, 이동 문 1개를 포함해 장치·위험물 10개. 체크포인트 7개와 출구 1개는 별도.
- 색이 바뀌는 보행 경계는 128px 틈으로 분리했다. 층간 승강기 샤프트에는 회색 집수조를 두었다. 나머지 색 전환 틈의 점프 실패는 낙사 위험이 있다.
- 플레이어는 기존 기본 검정 시작, 점프 높이 10칸/거리 20칸을 명시했다.

## 정적 확인

`node tools/작성_하수도_2-9.mjs --check`

- 지형 53개, 검정 면적 64.71%, 흰색 35.29%.
- WALL 검정/흰색 Template만 사용. 모든 지형 전체칠 허용, 회색 지형 없음.
- 좌표 16px 격자, 시계 방향 폴리곤, 최소 변 길이 90px 이상.
- 볼록 폴리곤 분리축 검사: 지형 내부 겹침 0. 공유 경계의 접촉은 허용. 열린 문 위치의 동적 겹침은 이 검사 범위 밖이다.
- 직접 외부 리소스 경로 존재, 내부/외부 리소스 ID 참조, 출구 1개, 페인트코어 그룹, 버튼 대상 존재 확인.
- 템플릿의 기존 CollisionPolygon2D에 새 좌표만 덮어썼다. 자식을 복제하거나 owner를 재지정하지 않았다. 충돌 오프셋은 0으로 하여 맞댄 지형 경계가 벌어지지 않도록 했다.
- 작성 후 읽기 전용 비교에서 결과 일치(멱등). `git diff --check` 통과, 삭제된 추적 파일 없음.

## 검증의 한계

Godot 기본 검사 전체, 레벨검사, 하수도 주행검사, 렌더링 및 실플레이는 모두 **미실행**이다. 정적 확인은 Godot 파싱 성공이나 사망 없는 클리어를 증명하지 않는다.

참고 프롬프트의 최소 발수/FIFO 퍼즐, 장애물 사이 최대 1,500px, 한 화면마다 모양 3종 등의 전체 디자인 체크리스트는 충족했다고 보고하지 않는다. 실제 이동·색 전환·승강기 대기·버튼 후 복귀는 엔진 실행이 명시적으로 요청된 후 확인할 항목이다. 이 작업은 요청한 새 씬 생성 범위이며 캠페인 등록까지 수행한 것은 아니다.
