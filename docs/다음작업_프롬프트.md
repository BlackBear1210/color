### 작업 A ★최우선 — 스테이지 1·2 의 "못 넘는 턱" 손보기

**왜**: 변환된 스테이지 1·2 의 도달률이 낮습니다(86중 11, 44중 19).
지형은 원본과 픽셀 단위로 같으니 **변환 오류가 아닙니다** — 원본 레벨 디자인에
원래 있던 아슬아슬한 구간이 이제 드러난 것입니다.
막히는 첫 지점은 x≈3,200 의 **128px 단차**인데, 이 스테이지 점프 높이가 정확히 128px이라
"이론상 가능하지만 실제로는 턱을 못 넘는" 자리입니다.

```text
스마트월드_1 과 스마트월드_2 의 통행성을 고쳐 줘.

먼저 확인:
  레벨검사.gd 를 두 씬에 돌려서 [불가] 로 뜨는 선반들의 x 좌표를 뽑아 줘.
  --상세 를 붙이면 선반 목록이 전부 나온다.

원인:
  이 스테이지의 플레이어는 점프 높이가 128px 이다(씬에서 8칸으로 튜닝돼 있다).
  그런데 지형에 딱 128px 짜리 단차가 있어서, 이론상 닿지만 실제로는 턱을 못 넘는다.
  레벨검사기는 점프 높이의 80%(102px)까지만 "올라갈 수 있다"고 본다.

두 가지 중 하나를 골라 적용해 줘. 나는 ①을 선호한다:
  ① 문제 지점의 지형만 20~30px 낮춘다
     → 레벨 디자인의 리듬은 유지되고, 그 자리만 부드러워진다
  ② 그 스테이지 플레이어의 점프_높이_칸을 8 → 9 로 올린다
     → 한 줄로 끝나지만 **스테이지 전체의 감각이 바뀐다.** 다른 구간이 너무 쉬워질 수 있다

②를 고르면 `tools/스마트월드_체인.gd` 의 `_플레이어_튜닝_잇기` 가 원본 씬에서
값을 읽어오므로, 원본(`scenes/world_1/stage_1-1, 1-2.tscn`)의 Player 를 고쳐야 한다.

목표: 스마트월드_1·2 모두 "밟는 지형 중 도달" 비율 80% 이상, 갇히는 곳 0.
끝나면 §1 검사 12개를 전부 돌려서 회귀가 없는지 확인해 줘.
```

**완료 판정**: 두 스테이지 모두 도달률 80% 이상 · 갇힘 0 · 검사 12개 전부 통과.

### 작업 B — 챕터 3 (도시) 스테이지 만들기

**왜**: 스토리가 자연 → 물 → **도시**인데 챕터 3 스테이지가 아직 없습니다.
팔레트·BGM 톤·장식 종류는 이미 표에 준비돼 있어서, 지형만 만들면 됩니다.
특히 챕터 3 은 **수직 상승**이 핵심이라 지금까지의 수평 스테이지와 성격이 다릅니다.

```text
챕터 3(올라가는 도시) 의 첫 스테이지를 만들어 줘. 스마트월드_5 가 된다.

준비돼 있는 것 (건드리지 말고 그대로 쓰면 된다):
  · `챕터.gd` 의 챕터표 3번 — 하늘색·BGM 기음 65.41Hz·설명이 이미 있다
  · `장식배치.gd` 의 챕터_지면[3] / 챕터_천장[3] — 파이프·잔해·전선이 나오게 돼 있다
  · `지형공통.gd` 의 재질 "거친암반" · `벽_점들()` · `선반_점들()`

해야 할 일:
  1. `챕터.gd` 스테이지표에 한 줄 추가:
       { "번호": 5, "챕터": 3, "이름": "5 · 판자촌 굴뚝",
         "원본": "res://scenes/스마트월드/_원본/원본_판자촌.tscn",
         "입구x": ..., "출구x": ..., "낙사y": ... }
  2. `tools/build_원본_판자촌.gd` 를 새로 만들어 원본 씬을 짓는다.
     ★기존 build_스마트월드_1-1.gd 를 참고하되 **복사하지 말고** 공통 부품
       (`지형공통.gd` · `지형규칙.gd`)을 써라. 복사하면 같은 버그를 두 벌 고쳐야 한다.
  3. `tools/스마트월드_체인.gd` 를 돌리면 스마트월드_5 가 생기고 4→5 가 자동으로 이어진다.

★이 챕터의 핵심은 **수직 상승**이다 (도형님 기획):
  "수평 이동이 중심이던 전 스테이지와 달리, 엘리베이터·외벽 파이프·무너지는 계단 등을
   타고 오직 '위'로만 올라가는 극적인 시점 변화. 창밖으로 점차 멀어지는 판자촌 풍경이
   미니어처처럼 보이며 고독감과 압박감을 극대화."
  → 좌우 벽(`벽_점들`) 사이에 선반(`선반_점들`)을 지그재그로 깔아 굴뚝을 만들고,
    도약대로 구간을 나눈다. 스마트월드_4 의 "굴뚝선반_9~16" 이 좋은 참고다.

레벨 디자인 안전 수치 (지형규칙.gd 상수 그대로):
  안전 오름 단차 128px · 안전 건널 간격 128px · 최소 통로 높이 128px · 최소 발판 폭 64px

끝나면 레벨검사로 도달률 80% 이상·갇힘 0 을 확인하고, §1 검사 12개를 돌려 줘.
```

**완료 판정**: 로비에서 시작 → 통로만 따라가면 5편까지 도달 · `test_챕터전환` 통과.

### 작업 C — 디자이너 그림 꽂기 (신우님 신규 에셋 9종)

아직 게임에 안 붙어 있습니다. 슬롯은 이미 다 파여 있어서 **Texture 만 끌어다 놓으면** 됩니다.

```text
신우님이 올린 신규 에셋을 게임에 붙여 줘.

에셋:
  assets/plantA/black.png · white.png
  assets/plantB/black/1~3.png · white/1~3.png

  각 장애물 씬(`scenes/스마트월드_장애물/*.tscn`)에는 `그림`(Sprite2D · 아트슬롯.gd)
  슬롯이 있다. 거기에 Texture 를 꽂으면 `_draw()` 코드 그리기가 스스로 멈춘다.
    식물A.tscn      ← assets/plantA
    식물B.tscn      ← assets/plantB
    물저장고.tscn   ← assets/water tank

  1. `아트슬롯.gd` 의 `기준_크기` 가 맞는지 — 디자이너가 몇 px 로 그렸든

  2. 흑/백 짝이 제대로 바뀌는지. 플레이어 색이나 지형 색이 바뀔 때 그림도 바뀌어야 한다.
  3. 스마트월드_2 에 식물 A/B 가 12개 이식돼 있다. 거기서 눈으로 확인하면 된다.
  4. 물저장고는 스마트월드_3 에 있다.

★주의: 씬을 저장할 때 `그림` 노드 말고 다른 노드의 owner 를 건드리지 마라(§5-1).
끝나면 스크린샷을 `tools/_shots/` 에 남기고 §1 검사를 돌려 줘.
```

### 작업 D — 사운드 4종 (12차부터 계속 밀린 공백)

**왜**: 색칠에 성공했는지, 회색이 됐는지(= 되돌릴 수 없는 실수), 죽었는지가
**전부 눈으로만** 전달됩니다. 퍼즐 게임에서 이건 큰 공백입니다.

```text
사운드 4종을 붙여 줘. 재생 지점은 이미 코드에 다 있다 — 훅만 걸면 된다.

  1. 색칠 성공  → `페인트_코어.gd` 의 `상태_변경` 시그널, 결과 "painted"
  2. 회색화     → 같은 시그널, 결과 "mixed_gray"
     ★이건 **되돌릴 수 없는 실수**다. 소리가 확실히 달라야 한다(둔탁하게 '툭')
  3. 착지       → `player.gd` 의 is_on_floor() 가 false → true 로 바뀌는 순간
  4. 사망       → `월드.gd` 의 `_리스폰()`
```

## 5. ⚠ 지뢰밭 — 전부 실제로 한 번씩 터진 것들

### 5-1. 후처리 도구에서 owner 를 트리 전체에 박지 말 것 (엔진이 죽는다)

읽어온 씬의 노드는 **이미 owner 가 올바르다.** 거기에 owner 를 다시 박으면
런타임 생성 노드가 씬 파일에 한 벌 더 저장되고, 다음 로드 때 두 벌이 되어
씬 교체 시 **signal 11(세그폴트)** 이 난다.
→ **우리가 새로 만든 노드에만** owner 를 준다. 인스턴스는 루트에만.

### 5-2. 도구는 멱등해야 한다 ("기존 값 + 여유" 금지)

체인 빌더가 카메라 리밋을 "기존 값 + 700px" 로 넓혔더니 돌릴 때마다 커졌다.
`레벨검사.gd` 가 그 리밋을 훑을 범위로 쓰기 때문에, 범위가 넓어지자
한 x 에서 세는 층이 위쪽 지형에 먼저 소모돼 진짜 바닥을 못 찾았다.
→ **스마트월드_4 의 도달 지형이 43개 → 18개**로 떨어졌다. 지형은 1px 도 안 바뀌었다.
→ 항상 **내용물에서 다시 계산**할 것.

### 5-3. 레벨 디자인은 캐릭터 튜닝과 한 세트다

씬마다 플레이어 점프 설정이 다르다.

| 씬 | move_speed | 점프 높이 | 점프 거리 |
|---|---|---|---|
| `stage_1-1, 1-2` | 300 | 8칸 = 128px | 15칸 = 240px |
| `원본_늪으로` / `원본_폐수로` | 390 | 10칸 = 160px | 20칸 = 320px |
| `Player.tscn` 기본 | 390 | 10칸 = 160px | 10칸 = 160px |

지형을 옮길 때 플레이어 설정도 같이 옮겨야 한다. 기본값으로 만들었더니
점프 거리가 240 → 160px 로 줄어 **160px 구덩이를 못 건너고 스테이지 전체가 막혔다.**

### 5-4. 단순화 허용오차는 가장 얇은 구조물 두께의 절반보다 작아야 한다

타일맵 변환기의 RDP 허용오차를 타일 한 칸(16px)으로 줬더니
**두께 16px 짜리 발판이 삼각형으로 찌그러졌다.** 얇은 막대 윤곽에서 모서리가
현에서 벗어난 거리는 두께의 절반(8px)이라, 16 ≥ 8 이면 그 모서리가 지워진다.
→ 지금은 6px. 더 얇은 구조물을 다룰 일이 생기면 더 줄일 것.

### 5-5. 셰이더 코드에는 한글을 쓸 수 없다

GDScript 는 한글 변수명을 허용하지만 GDShader 토크나이저는 거부한다.
`SHADER ERROR: Tokenizer: Unknown character` 가 뜨고 **셰이더가 조용히 안 나온다**
(게임은 안 죽어서 더 찾기 어렵다).
→ 셰이더 안은 전부 ASCII, 설명만 한글 주석.

### 5-6. `_set()` 으로 네이티브 프로퍼티를 가로채지 말 것

GDScript 의 `_set()` 은 네이티브 프로퍼티보다 **먼저** 불린다.
`_set()` 안에서 그 프로퍼티에 대입하면 무한 재귀 → 스택 오버플로.

### 5-7. `is_on_floor()` 만 믿지 말 것

CharacterBody2D 의 이 값은 **마지막 `move_and_slide()` 결과가 그대로 남아 있다.**
코드로 순간이동시키면 다음 물리 프레임까지 "아직 땅에 서 있다"고 답한다.
그 프레임에 체크포인트가 찍히면 **허공이 안전지점으로 저장**된다.

### 5-8. 테스트가 실패하면 코드부터 의심하지 말 것

2026-08-08 에 실패 원인 3건이 **테스트 자체의 함정**이었다.
· 월드의 `_physics_process` 가 켜져 있어 리스폰이 좌표를 지웠다
· 플레이어가 중력으로 떨어져 나가 검사 대상에서 멀어졌다
· 진자의 주기를 무시한 시간 기준으로 "감쇠가 안 된다"고 오판했다

### 5-9. 브랜치를 통째로 교체하지 말 것

2026-08-07 에 `dev_4` 를 로컬 폴더로 통째 복사해 덮어써서 **남의 작업 55개가 조용히 삭제**됐다.
· 작업 전 `git pull` → 충돌은 파일 단위로 해결
· 커밋 전 `git status` 로 **삭제(D)로 잡힌 파일**이 있는지 확인.
  내가 안 지운 파일이 D 로 잡혀 있으면 그게 사고 신호다.
