## 1. 스테이지 이름 정리

> 도형님 지시: "스마트월드1-1 씬과 스마트월드1 씬이 따로 있는데 이렇게 헷갈리게 만들지 말고
> 새로 추가되거나 만드는 스테이지를 짧게 이름 지어서 스마트월드 뒤에 숫자만 붙이자."

### 전 / 후

| 전 (5개가 섞여 있었다) | 후 |
|---|---|
| `스마트월드_테스트.tscn` | → `_원본/원본_숲에서물가로.tscn` |
| `스마트월드_1-1.tscn` | → `_원본/원본_숲_코드생성.tscn` |
| `스마트월드_1-2.tscn` | → `_원본/원본_폐수로.tscn` (뒤에 보정본으로 교체) |
| `스마트월드_1.tscn` | → `_원본/원본_늪으로.tscn` (**재료로 강등**) |
| `스마트월드_2.tscn` | → `_원본/원본_폐수로.tscn` (**재료로 강등**) |

**지금 `scenes/스마트월드/` 에 있는 것**

```
스마트월드_1.tscn   ← 챕터1 · 숲의 초입        (타일맵 셀 0~785 변환)
스마트월드_2.tscn   ← 챕터1 · 뒤틀린 나무들    (타일맵 셀 786~1429 변환)
스마트월드_3.tscn   ← 챕터1 · 늪으로           (원본_늪으로)
스마트월드_4.tscn   ← 챕터2 · 폐수로           (원본_폐수로)
_원본/              ← 재료 4개. 플레이에 직접 쓰이지 않는다
```

`tools/스마트월드_연결.gd` 는 **삭제**했다 — 1↔2 만 잇도록 코드에 박혀 있어서
3편을 만들려면 도구를 고쳐야 했다. `tools/스마트월드_체인.gd` 가 대체한다.

## 2. 챕터 흐름 · 스테이지 전환 연출

### 2-1. 순서는 표 하나에 (`scripts/스마트월드/챕터.gd` — 신규)

예전에는 "다음 스테이지가 어디냐" 가 **씬 파일 안 통로 노드의 문자열**에 흩어져 있었다.
순서를 바꾸려면 씬을 열어 고쳐야 했고, 한 곳만 고치면 길이 조용히 끊겼다.

```gdscript
const 스테이지표: Array = [
    { "번호": 1, "챕터": 1, "이름": "1 · 숲의 초입",     "원본": "타일맵:0:785",    ... },
    { "번호": 2, "챕터": 1, "이름": "2 · 뒤틀린 나무들", "원본": "타일맵:786:1429", ... },
    { "번호": 3, "챕터": 1, "이름": "3 · 늪으로",        "원본": "res://.../원본_늪으로.tscn", ... },
    { "번호": 4, "챕터": 2, "이름": "4 · 폐수로",        "원본": "res://.../원본_폐수로.tscn", ... },
]
```

**순서를 바꾸고 싶으면 이 배열의 줄 순서만 바꾼다.** 통로 목적지·로비 버튼·전환 연출이
전부 이 표를 읽으므로 저절로 따라온다.

### 2-2. 챕터 정의 (스토리 기획 그대로)

| 챕터 | 이름 | 하늘 | BGM 기음 | 성격 |
|---|---|---|---|---|
| 1 | 잠식된 숲 | 채도 죽인 녹회색 (0.36,0.36,0.34) | 55.0Hz (A1) | 뒤틀린 나무·거대 식물 |
| 2 | 지워지는 물 | 푸른끼·더 어둡게 (0.24,0.30,0.33) | 43.65Hz (F1) | 잉크가 색을 지운다 · 떨림 2배 |
| 3 | 올라가는 도시 | 차가운 무채색 (0.22,0.22,0.25) | 65.41Hz (C2) | 판자촌 → 고층. **수직 상승** |

챕터 3 은 표에 정의만 해 두었다(스테이지는 아직 없다). 스테이지를 추가하면 바로 쓰인다.

### 2-3. "스테이지 전환" 과 "챕터 전환" 을 다르게 했다

> 도형님 기획: "화면이 암전된 후 다음 스테이지가 짜잔 하고 밝아지면, BGM 의 톤이 바뀌며
> 새로운 물리 환경이나 위험한 함정이 눈앞에 나타납니다. … 설레는 압박감과 도전 욕구가
> 동시에 찾아오는 전환 느낌이 특징입니다."

같은 챕터 안에서 매번 거창하게 연출하면 그 감각이 닳는다. **챕터가 바뀔 때만** 다르게 한다.

| 구간 | 스테이지 전환 | 챕터 전환 | 왜 |
|---|---|---|---|
| 페이드 색 | 검정 | **흰색** | 물감 게임이다. 흰색은 "이 구역이 통째로 지워졌다"로 읽힌다 |
| 암전 | 0.85초 | 1.30초 | 천천히 지워져야 "구간이 끝났다"가 된다 |
| **정적(무음)** | 0.22초 | **0.80초** | ★이 침묵이 압박감의 정체다 |
| 점등 | 1.35초 | 2.10초 | 새 지역을 눈으로 훑을 시간 |
| BGM | 유지 | **톤 전환** | 눈만 바뀌고 귀가 그대로면 "배경이 바뀌었다"로만 읽힌다 |
| 등장 줌 | ×1.14 → 제자리 | ×1.22 → 제자리 (2.4초) | 조여드는 동안 시선이 화면 전체를 훑는다 |

### 2-4. 카메라 (요청: "고정되거나 주인공을 따라 움직이다가 자연스럽게 페이드 아웃")

전환 중에도 카메라는 **플레이어를 계속 따라간다.** 멈추면 플레이어만 걸어가
화면 밖으로 나가버린다(실제로 그랬다). 대신 두 가지를 건다.

* 들어갈 때 : 아주 살짝 **줌 인**(×0.94) → 통로로 빨려 들어가는 감각
* 나올 때 : 살짝 **줌 아웃 된 채로 시작해 제자리로** → "짜잔" 하고 펼쳐진다

### 2-5. BGM — 음원이 0개라서 **직접 합성**했다 (`scripts/스마트월드/음향.gd` — 신규)

작업기록 12차부터 계속 밀려 있던 "사운드 4종" 공백 때문에, 음원을 기다리면
전환 연출이 통째로 미완성으로 남는다.
→ `AudioStreamGenerator` 로 **낮은 드론(지속음)** 을 합성한다.

* 챕터마다 기음·밝기·떨림이 달라 톤이 확실히 바뀐다
* 파일이 0바이트다 — 저장소도 안 무겁고 라이선스 문제도 없다
* **선율을 넣지 않았다.** 림보·리틀나이트메어·레인월드는 선율이 거의 없다.
  선율이 붙는 순간 "게임 음악"이 되어 긴장이 풀린다.
* 진짜 음원이 나오면 `챕터음향.음원_꽂기(2, preload("...ogg"))` 한 줄로 갈아끼운다.

씬을 갈아끼워도 소리가 안 끊기도록 `get_tree().root` 에 붙인다.

## 3. 스마트 지형 물리 제어 규칙 (`scripts/스마트월드/지형규칙.gd` — 신규)

> 도형님 지시: "지형 포인트들이 너무 밀집되어 뭉치거나, 경사가 지나치게 가팔라
> 캐릭터가 물리적으로 위로 올라가지 못하는 문제가 있어."

### 3-1. 먼저 **이 프로젝트 캐릭터를 실측**했다

숫자를 짐작으로 정하면 캐릭터가 바뀌는 순간 전부 어긋난다(2026-08-07 에 키가
47px → 97px 로 바뀌면서 실제로 겪었다). `Player.tscn` 을 열어 직접 쟀다.

| 항목 | 실측값 |
|---|---|
| 콜리전 폭 / 키 | **44px / 97px** |
| 이동속도 | 390 px/s |
| 중력 / 점프 초속 | 5147.9 / −1283.5 |
| **점프 높이** | **160px** |
| **점프 수평거리(같은 높이 착지)** | **160px** |
| 체공시간 | 0.410초 (상승 0.249 + 하강 0.161) |
| floor_max_angle | 45° |

★도형님이 제시한 "최대 단차 48px = 점프 높이의 30%" 는 **실측값과 정확히 맞았다**
(160 × 0.30 = 48). 그대로 채택했다.

### 3-2. 규칙 4가지 — 근거를 숫자로 붙였다

| # | 규칙 | 값 | 근거 |
|---|---|---|---|
| 1 | 최소 수평 간격 | **64px** | 플레이어 폭 44 + 여유 20. 지형 타일도 32px 라 정확히 2칸 |
| 2 | 최대 단차 | **48px** | 점프 높이 160 × 30% |
| 2 | 최대 경사각 | **40°** | floor_max_angle 45° 아래. 착지에 미끄러지는 애매한 구간이 안 생긴다 |
| 3 | 평탄 구간 | 연속 **3~5점** | 계속 오르내리면 착지·조준·기다림의 리듬이 사라진다 |
| 4 | 자기교차 방지 | x 오름차순 + 닫기 공식 | 꼬이면 콜리전이 조용히 깨진다 |

★규칙 1 과 2 를 함께 지키면 **경사각 규칙은 저절로 지켜진다** —
atan(48/64) = 36.9° < 45°. 자동 검사가 이걸 확인한다.

### 3-3. 구조 — 예술과 물리를 분리했다

```
모양을 만드는 쪽(사인 곡선 / 손으로 찍기 / 타일맵 추출)
        ↓
   지형규칙.정리()      ← 규칙 1·2·4 를 여기서 한 번에 건다
        ↓
   지형규칙.닫기()      ← 시계 방향 닫힌 다각형
```

`지형규칙.지면_윗면()` 은 **상태 머신**으로 평지(3~5점) ↔ 경사(1~3점)를 번갈아 만든다.
레인월드/리틀나이트메어의 방이 읽히는 이유가 정확히 이것이다 —
넓은 평면이 있고 그 사이를 짧은 경사가 잇는다.

`tools/지형공통.gd` 의 `평바닥_점들` · `굽은바닥_점들` 이 이제 이 규칙을 통과한다.
⚠ `굽은바닥_점들` 의 기본 간격이 **40px** 이었다 — 규칙 1 을 그 자체로 어기고 있었고,
사인 진폭이 크면 40px 사이에 100px 넘는 단차(경사 68°)가 생겼다. 64px 로 올렸다.

### 3-4. 레벨 디자인 안전 수치 (검사기·배치기가 같이 쓴다)

| 항목 | 값 |
|---|---|
| 안전 오름 단차 | 128px (점프 높이의 80%) |
| 안전 건널 간격 | 128px (점프 거리의 80%) |
| 최소 통로 높이 | 128px (키 97 + 여유) |
| 최소 발판 폭 | 64px (폭 44 + 여유) |

**검증**: `tools/test_지형규칙.gd` — 씨앗 200개 전수 생성 검사 포함 **28 / 28 통과**.
무작위 생성기를 쓰는 이상 "한 번 돌려보니 되더라"는 증거가 못 되기 때문이다.

## 4. stage_1-1 / 1-2 지형을 스마트월드 방식으로 재구현

> 도형님 지시: "맵 레벨 디자인이 끝났기에 씬과 똑같은 지형을 스마트월드의 방식으로
> 다시 재구현해줘."

### 4-1. 손으로 다시 그리지 않았다 — **읽어서 옮겼다**

손으로 옮기면 레벨 디자인이 미묘하게 달라지고, 지금까지의 플레이 테스트가 전부 무효가 된다.
`tools/타일맵_변환.gd` (신규) 가 타일맵을 읽어 SS2D 지형으로 바꾼다.

```
① 윤곽 추출 : 채워진 칸의 "이웃 없는 변"만 모아 닫힌 고리로 잇는다
              (변을 직접 이어서 자기교차가 구조적으로 불가능하다)
② 단순화   : 일직선 점 제거 + RDP
③ 진단     : 규칙 위반과 "플레이어가 들어갈 만한 구멍" 을 보고
```

| | 스마트월드_1 | 스마트월드_2 |
|---|---|---|
| 타일맵 셀 | 0 ~ 785 | 786 ~ 1429 |
| 월드 범위 | x 128 ~ 12,576 | x 12,576 ~ 22,864 |
| 지형 조각 | 66 개 (점 341) | 11 개 (점 106) |
| 자기교차 | 0 | 0 |
| 플레이어 크기 구멍 | 0 | 0 |
| 규칙 위반 | 5 건 (원본 그대로) | 0 건 |

경계 786 은 손으로 정한 값이 아니라 그 씬의 **카메라 구역 경계**(x=12,576)다 —
원래 레벨 디자인이 거기서 1-1 / 1-2 로 나뉘어 있었다.

### 4-2. ★대조 검증 — 지형이 원본과 **완전히 같다**

원본 씬과 변환된 씬을 동시에 띄우고 x 를 16px 씩 훑으며 표면 높이를 레이캐스트로 비교했다.

```
지형 대조: 표본 731개 · 평균 차이 0.00px · 최대 차이 0px
```

### 4-3. 좌표를 0 으로 옮기지 않았다

스마트월드_2 의 지형은 x 12,576 에서 시작한다. 0 으로 당기면 보기엔 깔끔하지만
**원본과 대조할 때 좌표가 안 맞아 "똑같은 지형인지" 확인할 수 없게 된다.**

## 5. 스마트월드 우클릭 포물선 조준선

> 도형님 제보: "스마트월드에는 실행하면 우클릭을 눌렀을때 포물선으로 경로가 나오지않아서 불편해."

`stage_1-1, 1-2`(v3)는 `proto_gun.gd` 가 궤적을 그려주는데, 스마트월드는 총이
다른 파일(`총.gd`)이라 그 기능이 없었다. 거기에 넣었다.

* **총알.gd 와 완전히 같은 물리**로 미리 굴린다 — 중력·충돌 레이어·수명 상수를
  총알에서 직접 가져다 쓴다(`총알_스크립트.중력`). 한쪽만 바꾸면 조준선이 거짓말을 한다.
* **송풍기 바람도 계산에 넣는다.** 바람 구간에서 조준선만 곧게 가면 없느니만 못하다.
* 흑백 게임이라 단색 점은 어느 한쪽 배경에서 반드시 묻힌다
  → **어두운 링 + 밝은 코어** 2겹(2026-07-22 에 정한 문법 그대로).
* 점선이 표적 쪽으로 흐르고, **지형에 실제로 닿았을 때만** 빨간 탄착 마커를 그린다.

**검증**: 실제 총알을 60프레임 쏴서 궤적을 기록하고 조준선 공식과 비교 →
**최대 오차 0.000px**.

## 6. 사망 판정 전수 점검 (★실제 버그 2건 + 도구 버그 2건)

> 도형님 제보: "플레이어와 지형이 다른 색이면 죽는 사망 판정이 있는데 지금은 오류 때문인지
> 작동이 잘 안돼. 또한 가까이 가면 죽거나 통과를 하거나 사망 판정에 오류가 있어."

### 6-1. 버그 ① — 사망 판정이 **발밑 20px 레이 3발**이 전부였다

```gdscript
for dx in [-16.0, 0.0, 16.0]:          # ← 플레이어 반폭은 22px 이다
    시작 = 기준 + Vector2(dx, -6.0)
    끝   = 기준 + Vector2(dx, 14.0)
```

근사라서 **두 방향으로 어긋났다.**

| 증상 | 원인 |
|---|---|
| **"통과한다"** | 반대색 **벽·천장에 몸이 닿아도** 안 죽었다. 규칙은 "밟으면"이 아니라 "색이 다르면" 이다 |
| **"가까이 가면 죽는다"** | 공중에 떠 있어도 발밑 14px 안에 반대색이 걸리면 죽었다 |
| (숨어 있던 3번째) | 레이 간격 ±16px < 반폭 22px → **발끝 6px 은 아예 안 봤다.** 발판 끝에 아슬아슬하게 걸치면 반대색인데도 안 죽는 자리가 있었다 |

**고친 방법 — 근사를 없앴다.**
플레이어의 **콜리전 모양 그대로**를 3px 만 부풀려 겹침 질의(`intersect_shape`)를 한다.

* 닿으면 죽는다 — 발밑이든 벽이든 천장이든 방향을 안 가린다 → 증상 1 해결
* 안 닿으면 안 죽는다 — 허공에서 스쳐도 안전 → 증상 2 해결
* 모양 그대로라 사각지대가 없다 → 증상 3 해결

여유 3px 인 이유: Godot 물리는 물체를 약 0.08px 틈을 두고 재운다.
0 이면 바닥에 멀쩡히 서 있는데도 "안 겹쳤다"가 나온다.

크기는 **씬에서 실측**한다(상수로 안 박는다). `몸통_접촉_사망` 을 끄면 예전 동작.

### 6-2. 버그 ② — 유체 색이 런타임에 바뀌지 않았다

`유체.gd` 는 매 물리 프레임 `_원래색` 을 기준으로 섞임을 다시 계산한다.
그래서 바깥에서 `색` 을 바꾸면 **다음 프레임에 원래 색으로 되돌아갔다.**
레버로 물 색을 바꾸거나 도구/테스트가 색을 지정할 때 조용히 무시됐다.
→ 바깥에서 지정하면 `_원래색` 도 같이 갱신한다(`_섞는중` 플래그로 자기 갱신만 제외).

### 6-3. ⚠⚠ 도구 버그 — **"기존 값에 더하기" 를 하면 안 된다**

체인 빌더가 카메라 리밋을 "기존 값 + 700px" 로 넓혔다. 도구는 멱등해야 하는데
더하기만 하면 **돌릴 때마다 700px 씩 커진다.** 그게 왜 치명적이냐면:

`tools/레벨검사.gd` 가 **그 리밋을 훑을 범위로 쓴다.** 범위가 위로 넓어지면
한 x 에서 세는 층(최대 12층)이 위쪽 지형에 먼저 소모돼 **진짜 바닥을 못 찾는다.**
→ 스마트월드_4 의 도달 가능 지형이 **43개 → 18개**로 떨어졌다.
지형은 1px 도 안 바뀌었는데 검사 결과만 무너져서 원인을 찾기 매우 어려웠다.

지금은 **콜리전의 실제 경계에서 매번 새로 계산**한다.

### 6-4. ⚠ 도구 버그 — 플레이어 점프 튜닝을 안 이어받았다

원본 스테이지의 플레이어는 씬에서 점프를 따로 튜닝해 놓았다.

| | move_speed | 점프 높이 | 점프 거리 |
|---|---|---|---|
| `stage_1-1, 1-2` | 300 | 8칸 = 128px | **15칸 = 240px** |
| `Player.tscn` 기본 | 390 | 10칸 = 160px | **10칸 = 160px** |

레벨 디자인은 **그 튜닝을 전제로 그려져 있다.** 기본값으로 만들었더니
점프 거리가 240 → 160px 로 줄어, x1840~1900 의 **160px 구덩이를 못 건너고**
그 뒤 스테이지 전체가 막혔다(레벨검사: 87개 중 도달 5개).
→ 원본 씬의 플레이어 설정을 그대로 이어받게 했다.

### 6-5. ⚠ 도구 버그 — RDP 허용오차가 얇은 발판을 뭉갰다

변환기의 RDP 허용오차를 **타일 한 칸(16px)** 으로 줬더니 **두께 16px 짜리 발판이
삼각형으로 찌그러졌다.** 얇은 막대의 윤곽에서 모서리가 현에서 벗어난 거리는
**두께의 절반(8px)** 인데, 허용오차 16 ≥ 8 이라 그 모서리가 지워진 것이다.
→ **허용오차는 가장 얇은 구조물 두께의 절반보다 작아야 한다.** 6px 로 내렸다.

### 6-6. 검증 — `tools/test_사망판정.gd` (신규)

실제 스테이지는 지형이 30개가 넘어 "왜 죽었는지"를 특정할 수 없다.
지형 하나·플레이어 하나만 놓고 좌표를 손으로 정해 검사한다.

| 항목 | 결과 |
|---|---|
| 무색 / 같은 색 / 회색 지형 위 = 생존 | ✔ |
| **검정 지형 + 흰 플레이어 = 사망** | ✔ |
| **지형 밖(안 밟음) = 생존** ← "가까이 가면 죽는다" | ✔ |
| **흰 벽에 몸이 닿은 검정 플레이어 = 사망** ← "통과한다" | ✔ |
| **흰 천장에 머리가 닿은 검정 플레이어 = 사망** | ✔ |
| 잎발판 / 통과플랫폼도 판정된다 | ✔ |
| 유체 — 반대색 사망 / 같은 색·회색·꺼짐 = 생존 | ✔ |
| 색 레이저 — 빔 안 다른 색 = 사망 / 빔 밖 = 생존 | ✔ |
| **합계** | **22 / 22** |

> ⚠ 이 테스트를 만들며 겪은 함정: 월드의 `_physics_process` 를 켜 둔 채로 검사하면
> 스스로 사망을 감지해 **리스폰(시작 위치로 순간이동)** 해 버려서, 세워둔 좌표가
> 다음 프레임에 사라진다. `set_physics_process(false)` 로 꺼야 한다.

## 7. 레인월드식 장식 오브젝트 + 벨레 덩굴 물리

> 도형님 제보: "오브젝트가 부족해서 게임 느낌이 안 나. 우리 게임은 레인월드 같은
> 오브젝트들이 너무 필요해. 도트 같지만 디테일이 살아있는 것들."

### 7-1. 왜 외부 에셋을 안 썼나

1. 상업 이용 가능한 에셋을 들이면 **라이선스 관리 대상**이 늘어난다.
2. 이 게임은 **흑백**이고 지형이 색칠에 따라 변한다. 남의 에셋은 그 팔레트에 안 맞는다
   (실제로 기존 배경 프롭 `tree_pine.svg` 등이 붕 떠 보이는 원인이었다).
3. **디자이너 그림이 나오면 바로 갈아끼운다** — 다른 장애물과 똑같이 자식 `그림`
   (`아트슬롯.gd`)에 Texture 를 꽂으면 코드 그리기가 스스로 멈춘다.

### 7-2. 장식 6종 (`scripts/스마트월드/장식.gd` — 신규)

이끼 · 버섯 · 녹슨파이프 · 잔해 · 갈대 · 얼룩.
전부 씨앗 기반이라 같은 종류라도 실루엣이 매번 다르고, 씬을 다시 구워도 같은 모양이 나온다.

**Z 레이어 규약** (요청: "배경/중경/전경으로 Z-Index 를 분리")

| 층 | z_index | 처리 |
|---|---|---|
| 먼배경 | −40 | 알파 0.30 — 먼 것은 **대비를 낮춰야** 멀어 보인다 |
| 배경 | −12 | 알파 0.62 |
| 중경 | 0 | 그대로 |
| **전경** | **+40** | 어둡게(0.55). ★플레이어를 살짝 가린다 — 이게 깊이감의 핵심 |

### 7-3. 벨레 적분 덩굴 (`scripts/스마트월드/덩굴.gd` — 신규)

종류 3가지: **덩굴 / 전선 / 사슬** (물리는 같고 그림과 기본값만 다르다).

**왜 벨레인가 (스프링이 아니라)** — 벨레는 속도를 따로 들지 않는다.
이전 위치와 현재 위치의 차이가 곧 속도다.

* 위치를 그냥 옮기면 그게 자연스러운 충격이 된다 → 플레이어가 미는 처리가 한 줄
* 길이 제약을 반복해 밀어 넣어도 **발산하지 않는다** (스프링은 강성을 올리면 한 프레임에 터진다)
* 마디 12개 × 반복 4회면 충분하다. 아주 싸다

**플레이어 상호작용** — 두 가지를 같이 준다.

1. **밀어내기**: 몸이 파고든 만큼 바깥으로 (덩굴이 몸을 통과하지 않는다)
2. **끌기**: 플레이어 속도를 실어준다 (달리며 스치면 뒤로 휩쓸린다)

플레이어 원점은 발바닥이므로 **몸 중앙(키의 절반 위)** 을 기준으로 삼는다 —
안 그러면 발끝만 스쳤는데 덩굴 위쪽까지 휘는 이상한 그림이 나온다.

송풍기 바람도 탄다(총알의 25% 세기 — 그대로 받으면 수평으로 뻗어버린다).

**성능** — 스테이지가 22,000px 이나 된다. 플레이어에서 `활성_거리`(2400px) 밖이면
물리도 그리기도 통째로 쉰다.

### 7-4. 자동 배치 (`scripts/스마트월드/장식배치.gd` — 신규)

> "지형 노드의 표면 좌표를 감지해 자연스럽게 밀착되어 스폰 / 경사면에서는 법선에 맞춰 회전 /
> 천장 하단면을 감지해 늘어지는 사슬·전선의 부착점을 찾을 것."

지형이 SS2D 곡선이라 수식으로 지면 높이를 알 수 없다. 좌표를 손으로 적으면 지형 점 하나만
끌어도 장식이 전부 뜨거나 파묻힌다 → **씬을 띄우고 레이캐스트로 잰다.**

⚠ **한 x 에서 면을 하나만 찾으면 안 된다.** 레인월드식 지형은 한 x 에 면이 3~4개 있다
(천장 지붕 → 천장 아랫면 → 발판 윗면 → 진짜 바닥). 위에서 한 번만 쏘면 **천장의 지붕**이
잡히고, 그걸 지면으로 여기면 늘어지는 덩굴이 **한 개도** 안 걸린다(실제로 그랬다).
→ 물체를 뚫고 내려가며 층을 전부 모은다.

**배치 규칙** (레인월드를 그대로 베끼지 않고 우리 게임에 맞춘 부분)

* **밟는 면 위에는 큰 것을 놓지 않는다.** 지형인지 장식인지 헷갈리는 순간 색칠 퍼즐이 망가진다
  → 지면 장식 키를 38px(발목 아래)로 제한.
* **전경은 드물게, 크게.** 자주 나오면 시야를 가려 짜증만 난다(스테이지당 1~4개).
* **챕터마다 종류가 다르다.** 1 = 이끼/버섯/갈대, 2 = 이끼/얼룩/잔해, 3 = 파이프/잔해/전선.

## 11. 이번에 배운 것 (같은 실수를 또 하지 않기 위해)

1. **도구는 멱등해야 한다.** "기존 값 + 여유" 는 두 번 돌리면 두 배가 된다. §6-3 은
   지형을 1px 도 안 바꿨는데 레벨이 무너진 사례다. 항상 **내용물에서 다시 계산**할 것.
2. **레벨 디자인은 캐릭터 튜닝과 한 세트다.** 씬마다 점프 설정이 다르므로,
   지형을 옮길 때 플레이어 설정도 같이 옮겨야 한다(§6-4).
3. **단순화 허용오차는 가장 얇은 구조물의 절반보다 작아야 한다**(§6-5).
4. **판정에 근사를 쓰면 반드시 양쪽으로 어긋난다.** 모양 그대로 겹침을 보는 게
   결국 더 간단하고 더 정확했다(§6-1).
5. **테스트가 실패했을 때 코드부터 의심하지 말 것.** 이번에 실패 원인 3건이
   테스트 자체의 함정이었다 — 리스폰이 좌표를 지움 / 플레이어가 중력으로 떨어져 나감 /
   진자의 주기를 무시한 시간 기준.
