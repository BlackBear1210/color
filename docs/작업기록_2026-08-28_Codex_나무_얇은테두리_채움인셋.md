# 작업기록 2026-08-28 · Codex — 나무 얇은 테두리 채움 인셋

## 증상

`TEMPLATE_WOOD_SOLID`과 `TEMPLATE_WOOD_STAIRS`에서 내부 목재 채움이 얇은 테두리의 직각 모서리 바깥으로 비쳐 보였다.

## 원인

`SS2D_Material_Shape.fill_mesh_offset`의 기본값은 `0.0`이다. 따라서 FILL 메시가 도형 외곽선까지 생성된다. 얇은 사방 엣지는 안쪽으로 38px만 덮으므로, 미터 조인의 모서리 가장자리에서 FILL이 노출될 수 있다.

## 수정

`assets/textures/smartshape/wood_v2/tres/지형_나무v2_black_detail_얇은_사방.tres`에 아래 값을 추가했다.

```text
fill_mesh_offset = -0.0375
```

SS2D는 이 값에 FILL 텍스처 폭 1024px를 곱한다. 따라서 채움 경계를 약 38.4px 안쪽으로 줄여, `edge_top` AtlasTexture의 월드 두께 `109 × 0.35 ≒ 38.15px`와 맞췄다.

HOLLOW 재질은 FILL을 쓰지 않으므로 변경하지 않았다. 원본 WOOD PNG는 SOURCE LOCK 규칙에 따라 수정·재베이크하지 않았다.

## AtlasTexture 교체

처음에는 원본 `edge_top.png`의 `Rect2(0, 68, 1024, 109)` 부분을 `AtlasTexture`로 참조했다. 그러나 SS2D 렌더러는 CanvasItem에 텍스처 RID를 직접 넣기 때문에 AtlasTexture의 UV 잘라내기 정보를 적용하지 않는다. 화면에는 원본 256px 엣지가 그대로 그려져, 내부 그림이 모서리에서 다시 튀어나왔다.

따라서 원본을 수정하지 않고 아래 파생 PNG를 만들었다.

- `assets/textures/smartshape/wood_v2/black/edge_top_thin.png`
- `assets/textures/smartshape/wood_v2/white/edge_top_thin.png`

두 파일은 각각 원본의 불투명 구간 `y=68..176`을 픽셀 그대로 잘라낸 1024×109 PNG다. 얇은 SOLID·HOLLOW·STAIRS 재질은 이제 AtlasTexture가 아닌 이 실제 PNG를 참조한다. 흰색 짝도 함께 만들어 색칠 시스템의 black/white 경로 규칙을 보존했다.

## 검증

Godot은 실행하지 않았다. 재질의 FILL 인셋 값과 엣지 AtlasTexture의 월드 두께를 정적으로 대조했으며 `git diff --check`를 통과했다.
