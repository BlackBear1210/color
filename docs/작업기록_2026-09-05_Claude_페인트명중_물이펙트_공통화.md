## 2. 어디에 붙였나 — 공통 출구는 이미 있었다

프로젝트에는 실제로 쓰이는 발사체가 **세 계열**이다.

| 발사체 | 총 | 쓰는 스테이지 |
|---|---|---|
| `scripts/스마트월드/총알.gd` (`페인트총알`) | `총.gd` (`페인트총`, `월드.gd` 가 만든다) | 집 스테이지_1·2, world_2/stage_2-1 |
| `scripts/proto/proto_bullet.gd` (`ProtoBullet`) | `proto_gun.gd` (`ProtoGun`, `stage_lab.gd` 가 만든다) | world_1/stage_1-1,1-2, world_2/stage_2-2·2-3 |
| `scripts/bullet.gd` | `gun.gd` | 옛 타일맵 씬 |

★ 그런데 이 셋은 **이미 같은 곳**을 부르고 있었다 —
`Player > ActionFX` 의 `명중()` (`scripts/player_action_fx.gd`).

```
페인트총알  ┐
ProtoBullet ├─→ Player/ActionFX.명중(지점, 속도, 색, 법선, 발사체)
bullet      ┘                    │
                                 ▼
                    scenes/effects/PaintImpactEffect.tscn
                                 │
                     water_05 / 06 / 07 / 08 중 랜덤
                                 │
                          재생 → 자동 queue_free
```

그래서 **이펙트를 끼운 자리는 딱 한 곳**이다. 스테이지가 10개 20개로 늘어도
발사체가 저 셋 중 하나면 아무것도 안 해도 이펙트가 나온다.

## 3. 원본 시트 실측 — 인수인계 숫자가 틀렸다

인수인계 문서에는 `water_05 = 176×176 × 16프레임` 이라고 적혀 있었다.
**실제 파일은 전혀 달랐다.** 눈으로 세지 않고 `tools/생성_물감명중_프레임.gd` 가 픽셀로 잰다.

| 시트 | 파일 크기 | 격자 | 프레임 | 명중 기준점(칸 안) |
|---|---|---|---|---|
| water_05 | 5572 × 124 | 28칸 × 199px | 1~20번 칸 = **20장** | (58.7, 75.2) |
| water_06 | 5264 × 131 | 28칸 × 188px | 0~12번 칸 = **13장** | (104.0, 46.6) |
| water_07 | 5068 × 107 | 28칸 × 181px | 0~14번 칸 = **15장** | (82.2, 55.9) |
| water_08 | 5348 × 121 | 28칸 × 191px | 0~24번 칸 = **25장** | (106.3, 54.0) |

★ **가장 중요한 발견: 이 시트들은 배경이 투명이 아니라 불투명한 검정이다.**
알파가 전 픽셀 1.0 이라 그냥 붙이면 화면에 **검은 네모**가 찍힌다.
→ `shaders/물감_명중.gdshader` 가 **밝기를 알파로 바꿔** 물만 뽑아낸다.
**원본 PNG 는 한 픽셀도 안 고쳤다.**

★ 회전 기준(`바깥방향`)은 자동으로 못 잰다.
처음엔 "첫 프레임 → 끝 프레임 무게중심 이동"으로 뽑으려 했는데, 끝 프레임은 물방울이
**중력으로 떨어진 뒤**라 네 시트 모두 아래쪽(+y)이 나왔다. 잰 것은 "자라는 방향"이 아니라
"떨어진 방향"이었다. 원화 넷 다 바닥에 맞은 그림이라 바깥쪽은 전부 위(−y)다
→ 도구의 `바깥방향표` 에 손으로 적었다(새 시트를 넣는데 방향이 다르면 한 줄만 더한다).

### 왜 두 겹(`받침` + `본체`)인가
흑백 게임이라 **검정 페인트를 어두운 배경에 그리면 아무것도 안 보인다.**
`본체` = 페인트 색, `받침` = 반대색을 1.10 배로 살짝 크게 깔았다.
(`물감_스플래시.gd` 가 테두리를 깔던 것과 같은 수법)

## 7. 다음 사람이 알아야 할 것

1. **프레임을 다시 굽고 싶으면** `tools/생성_물감명중_프레임.gd` 만 돌린다.
   `.tres` 와 `.json` 을 손으로 고치지 말 것 — 다음 실행 때 덮어써진다.
2. **새 물 이펙트(water_09 …)를 넣으려면** `assets/vfx/water_impact/` 에 PNG 를 넣고
   도구의 `시트들` 목록과 `바깥방향표` 에 한 줄씩 더한 뒤 도구를 돌린다.
   런타임 코드는 **애니메이션 이름을 리소스에서 읽으므로 안 고쳐도 된다.**
3. **검사 도구의 함정 두 가지** (겪은 것 그대로 적어 둔다)
   - 총구는 마우스를 옮기면 같이 돈다 → **두 번 겨눠야** 한다.
   - `월드.gd` 는 페인트 코어를 `get_tree().get_first_node_in_group()` 으로 **트리 전체에서**
     찾는다. 앞 씬을 `queue_free` 하자마자 다음 씬을 올리면 새 월드가 **죽어가는 앞 씬의
     코어**를 집어 가서 총이 아예 안 나간다. 검사는 씬 사이에 4프레임을 쉰다.
     (실제 게임은 `change_scene` 이 앞 씬을 먼저 지우므로 이 일이 없다)
