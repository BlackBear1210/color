### 2-2. 기존 유체를 차오르게 하기

하수도 스테이지의 물은 전부 `유체` 다. 그것들도 인스펙터에서 **차오름** 그룹만
켜면 그대로 차오른다. 손잡이 이름·기본값은 웅덩이와 똑같다.

⚠ 유체는 **원점이 물의 윗끝**이라, 차오를 때 스크립트가 **위치까지 같이 올린다.**
그래야 바닥이 제자리에 남고 수면만 올라온다. 손으로 `크기.y` 만 키우면
차오르는 게 아니라 **아래로 흘러내린다.**

유체의 `낙하_받아줌` 은 **기본 꺼짐**이다 — 유체는 원래 떨어지는 물줄기이고,
폭포가 낙하를 받아주면 이상하다. 바닥에 눕혀 웅덩이처럼 쓰는 유체에만 켠다.
**새로 놓는 웅덩이는 `웅덩이.tscn` 을 쓸 것.**

### 2-3. 레버로 물을 차오르게 하기

`제어레버` 의 `대상_유체` 에 웅덩이나 유체를 물리면 끝이다.
레버를 켜면 `차오르기_시작()`, 끄면 `차오르기_멈춤()` 이 자동으로 불린다.
(이때는 `차오름_자동시작` 을 **끄고**, 레버의 `시작_켜짐` 도 꺼 두는 것이 보통이다.)

코드에서 직접 부를 수도 있다 — 웅덩이·유체 둘 다 같은 이름이다:

```gdscript
물.차오르기_시작()      # 오르기 시작
물.차오르기_멈춤()      # 지금 높이에서 멈춤 (다시 시작하면 이어서)
물.차오르기_초기화()    # 처음 높이로. ★리스폰 때 월드가 자동으로 부른다
물.수면_월드y()         # 지금 수면의 월드 y (작을수록 높다)
물.수심()               # 지금 깊이
```

## 3. 설계 판단 — 왜 이렇게 만들었나

### 3-1. 낙사 안전망을 **공짜로 주지 않았다**

웅덩이도 `색규칙.gd` 안에 있다. 검은 웅덩이는 흰색 플레이어를 죽인다.
즉 "낙하를 받아주는 물"과 "닿으면 죽는 물"이 **같은 물**이고,
살아남으려면 **떨어지기 전에 색을 맞춰야** 한다.

★이게 이 부품의 핵심이다. 그냥 안전망이면 레벨이 쉬워지기만 하는데,
색을 물으면 **높은 곳에서 뛰어내리기 전에 화면을 읽는 이유**가 생긴다.
[맵분석](맵분석_2026-09-07_Claude_하수도_2-1_2-7.md) §4-3 에서 지적한
"위험해 보이는데 아무 일도 안 일어난다" 의 정반대를 만드는 부품이다.

누구에게나 안전한 물이 필요하면 색을 **회색**으로 두면 된다.

### 3-2. 왜 `유체.gd` 에 옵션만 더하지 않고 새 파일을 팠나

`유체` 는 **떨어지는 물줄기**다. 원점이 물의 **윗끝**이고 아래로 뻗으며,
그림도 세로로 흐르는 폭포 실루엣 8 프레임이다(`유체_판정모양.gd`).
웅덩이는 정반대다 — 원점이 **아랫변**이고 위로 자란다.
같은 스크립트에 두 원점 규칙을 넣으면 맵 찍는 사람이 매번 헷갈린다.

그래도 하수도 스테이지의 기존 물이 전부 `유체` 라서, `유체.gd` 에도
**같은 이름의 손잡이**를 따로 달았다. 레버·버튼은 둘 중 무엇이 물려 있는지
모른 채 `차오르기_시작()` 한 줄만 부르면 된다.

### 3-3. 판정을 매 프레임 다시 굽지 않는다

물 판정은 프레임마다 54 점짜리 실루엣을 다시 만드는 비싼 일이다(`_판정_폴리곤들`).
차오름은 높이를 **2px 계단**으로 잘라서 갱신한다 — 60px/s 로 차올라도 초당 30 번뿐이고,
눈으로는 매끈하다.

## 4. 터진 지뢰 3개 (전부 검사가 잡았다)

### 4-1. ★`hit_from_inside` 를 안 켜면 **물에 들어가는 순간 죽는다**

처음에는 이렇게 짰다:
1. 이미 물속이면 `Area2D.get_overlapping_bodies()` 로 잡는다
2. 아직 공중이면 발밑 레이로 잡는다

**둘 다 실패하는 프레임이 정확히 하나 있다.** 몸이 수면을 넘은 바로 그 프레임이다.

- 레이는 `hit_from_inside` 가 기본 false 라 **자기가 출발한 도형을 통째로 건너뛴다**
  → 이미 물 안이니 물이 안 잡힌다
- Area2D 의 겹침 목록은 **물리 스텝이 끝난 뒤에** 갱신되는데 플레이어 좌표는 이미
  갱신되어 있다 → "아직 안 들어왔다"고 답한다

그 한 프레임에 정확히 죽었다. (통합 검사가 `y 82` 로 잡아냈다 — 물에 닿자마자 리스폰)

→ **`질의.hit_from_inside = true` 한 줄로 해결.** 나를 품은 도형이 거리 0 으로 잡혀
**항상 물이 이긴다.** 겹침 검사는 통째로 지웠다.

### 4-2. ★`위험도()` 로 물으면 플래그가 굳어 **아무 데서도 안 죽는다**

낙하감시의 `_받아줌` 이 켜지면 `위험도()` 가 0 을 돌려준다(경고 비네트를 끄려고).
그런데 월드가 `위험도() > 0` 일 때만 물을 검사하게 짜면 —
받아준 순간 위험도가 0 → 검사 중단 → 플래그가 **true 로 굳는다** → 그 뒤로
아무 데서 떨어져도 안 죽는다.

→ `원_위험도()` 를 따로 뒀다. 물이 받아주든 말든 순수하게 낙하 거리만 본다.
**월드는 반드시 `원_위험도()` 로 물어야 한다.**

### 4-3. 인스턴스를 만든 **뒤에** 크기·위치를 넣으면 물이 순간이동했다

차오름 기준값(처음 높이 · 바닥 y)을 `_ready` 에서만 잡았더니,
배치 도구·코드처럼 나중에 값을 넣는 경우 엉뚱한 바닥으로 튀었다.
→ `차오르기_시작()` 이 **아직 한 번도 안 차올랐을 때만** 기준을 다시 잡는다.
한 번 차오른 뒤에는 안 건드린다 — 그래야 `차오르기_초기화()` 가 제자리로 돌아온다.

## 5. ⚠ 반드시 지켜야 할 것

- **리스폰 때 `차오르기_초기화()` 를 부르는 것을 지우지 마라.**
  `월드.gd::_리스폰()` 이 `차오르는물` 그룹을 훑는다. 이걸 빼면 물이 가득 찬 방으로
  되살아나 **무한히 죽는다** — 플레이어가 스스로 빠져나올 방법이 없다.
- **`hit_from_inside = true` 를 지우지 마라.** §4-1.
- **`원_위험도()` 를 `위험도()` 로 바꾸지 마라.** §4-2.
- 차오르는 물을 놓을 때는 **탈출로가 물보다 빨리 닿는 곳에 있는지** 직접 태워 볼 것.
  (`치명_낙하거리` 처럼 숫자 하나로 방 전체의 긴장이 바뀐다)
