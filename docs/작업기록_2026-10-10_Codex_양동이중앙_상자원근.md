# 양동이 접지 중앙 및 상자 원근 적용

- 요청: 양동이를 지형 윗면 중앙에 배치하고, 상자를 게임 지형의 원근에 맞춰 적용한다.
- 기준: 제공된 하수도 화면. 여기서 중앙은 발판의 가로 중앙이 아니라 윗면의 앞뒤 깊이 중앙이다.
- 시작 시 `git pull` 결과: Already up to date. 기존 작업 변경은 유지했다.

## 적용

- `scripts/스마트월드/이동물체_접지그림.gd`: 현재 지지면의 `발_그림_깊이()`를 읽어 그림 위치를 계산한다. 접지 중에만 실제 바닥과 그림 원점 차이를 보정하고, 공중에서는 마지막 지형의 깊이를 유지한다. 보정값은 누적하지 않는다.
- `양동이.gd`: 물리 몸통의 바닥(-6px)을 기준으로 유리, 내용물, 앞 쇠살을 함께 지형 상판 중앙으로 옮긴다. 채운 양동이 위에 선 플레이어에게도 그림 깊이를 전달한다.
- `박스.gd`: 앞면을 (+9,+11), 뒷면을 (-9,-11)로 배치해 바닥과 상판 중심이 물리 위치와 일치하도록 했다. 지형과 같은 (-18,-22) 방향으로 윗면과 왼쪽 옆면을 연결했다. 기존 주철 이미지의 금속 테두리를 윗면/옆면에 사용하고 명암을 분리했다. 목재 상자에도 같은 투영과 실제 96px 높이를 적용했다.
- 공통 스크립트를 사용하는 게임 소품에 적용된다. 씬의 가로 배치 좌표, 충돌 크기, 밀기 및 물 감지 영역은 변경하지 않았다.

## 확인 및 제한

- 변경한 GDScript 3개: gdtoolkit 구문 분석 통과.
- `git diff --check` 통과.
- 투영 정적 확인: 상자 앞뒤 바닥의 중점은 (0, 지형 깊이), 상판 중점은 (0, -96 + 지형 깊이). 하수도 깊이 7px에서 앞바닥 y=18, 뒷바닥 y=-4로 지형 상판과 일치한다.
- 필수 검사 목록을 안내하는 `docs/다음작업_프롬프트.md`가 저장소에 없어 13개 검사 명령을 확인할 수 없었다.
- 사용자 안전 규칙에 따라 Godot 및 빌드 도구 미실행. 실제 엔진 전후 캡처 경로 없음. 양동이 접지, 상자 원근과 명암, 밀기/낙하/리스폰 및 상자 위 플레이어 접지의 시각 검증 대기.
- `graphify update .` 실행: AST 1,027개 파일 분석 완료. 기존 그래프 34,911개 노드 대비 새 그래프 14,733개로 축소되어 보호 장치가 `graph.json` 덮어쓰기를 거부했다. 강제 덮어쓰기는 하지 않았다. 마지막 성공 문구와 별개로 그래프 본체 갱신은 완료로 간주하지 않는다.
- 삭제로 표시된 추적 파일 없음.
