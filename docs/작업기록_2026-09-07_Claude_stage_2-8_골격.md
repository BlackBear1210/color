## 2. 단면 — 층 간격 560px

```
y  140  ─── 맨 위 천장 아랫면          ┐
                                      │ L3 헤드룸 440
y  580  ─── L3 바닥 윗면               ┘
y  580~640  L3 바닥 (60)      ┐ 슬래브 2장 = 120
y  640~700  L2 천장 (60)      ┘
y  700  ─── L2 천장 아랫면             ┐
                                      │ L2 헤드룸 440
y 1140  ─── L2 바닥 윗면               ┘
y 1140~1200 L2 바닥 (60)      ┐
y 1200~1260 L1 천장 (60)      ┘
y 1260  ─── L1 천장 아랫면             ┐
                                      │ L1 헤드룸 440
y 1640  ─── 수면 (수심 60)             │
y 1700  ─── L1 바닥 윗면               ┘
```
(위 값은 기복 0 기준. 구간마다 ±120씩 통째로 오르내린다)

### 헤드룸을 440으로 잡은 이유
층이 성립하는 **최소**는 280px이다(점프 160 + 키 96 = 머리 256). 최소치로 짜면 층이
**복도**가 된다. 440이면 층 안에 160px 점프를 두 단 쌓을 수 있어서 **각 층이 방처럼** 된다.

### 슬래브가 두 장인 이유
규약 4 때문에 천장도 색 규칙에 참여한다. 한 장을 위아래 층이 나눠 쓰면
`시작상태`가 노드당 하나뿐이라 **위층과 아래층의 색이 묶인다.**
두 장이면 층마다 색을 따로 준다 — 검사에서 `L3 바닥 흰색 / 바로 아래 L2 천장 검정`을 못 박았다.
⚠ **회색 지형은 안 썼다**(하수도 규약). 검사에서 0개를 확인한다.

## 3. ★560px이 만든 문제와 해법

```
치명 낙하거리 520  <  층 간격 560   → 한 층 떨어지는 것만으로 죽는다
```

400px였을 때와 **규칙이 완전히 다르다.** 해법은 중간 선반이 아니라
**낙하구를 아예 L1까지 관통시키는 것**이다.

`월드.gd`의 `_낙하를_받아주나()`는 물이 받아주면 **낙하 거리와 무관하게** 살려준다.
L1 전체가 물길이므로 L3에서 1,120px을 떨어져도 안 죽는다.

> ⚠ **함정 하나** — `유체.gd`의 `낙하_받아줌` 기본값은 **꺼짐**이다.
> 빌더가 켜 주지 않으면 맵 전체가 즉사 함정이 된다. 한 줄이다.
> 그래서 검사에서 **실제로 떨어뜨려** 확인한다(`test_하수도_2-8_골격` §5).

### 따라서 내려가는 방법은 두 가지뿐이다
- **뚫린 틈으로 맨 아래까지** 떨어진다 (안 죽는다)
- **갈래점 승강기로 의도적으로** 한 층 내려간다

어중간하게 한 층 떨어져 죽는 자리는 이 맵에 **하나도 없다.**

## 3-2. ★[수정 1] 끼는 사다리 — 무엇이 잘못됐나

처음에는 240px 샤프트 안에 96px 발판을 좌우로 번갈아 놓았다. 세 군데가 동시에 잘못됐다.

| 어디 | 폭 | 왜 문제인가 |
|---|---|---|
| 발판 ↔ 벽 | **12px** | 플레이어(44)보다 좁은 세로 슬롯 |
| 발판 ↔ 발판 | **24px** | 같은 이유. 여기 빠지면 못 나온다 |
| 위 칸 아랫면 ↔ 아래 칸 윗면 | **88px** | 플레이어 키가 **96px**이라 두 칸이 가로로 겹치는 자리에서 **머리가 위 칸에 박힌다** |

★**교훈 셋**
1. 끼는 슬롯은 폭이 **플레이어보다 좁을 때** 생긴다. 0px(막힘)과 60px+(통과)는 안전하고,
   **10~44px이 사고를 낸다.** 어중간한 폭이 제일 나쁘다.
2. 사람이 설 수 있는 자리 위에는 **96px + 여유**가 반드시 있어야 한다.
3. **좌우로 번갈아 놓는 사다리는 위 칸이 아래 칸의 처마가 된다.** 처마가 곧 함정이다.

## 3-3. ★[수정 2] 계단을 다시 살렸다 — 스위치백

도형님 지시: "끼는 플랫폼 다 없앨 필요 없는데 왜 다 없애. 몇 개 살려놔. 끼는 거 없이."

**갈래점 4곳 중 2곳(A · C)을 계단으로 되돌렸다.** 나머지 2곳(B · D)은 승강기 그대로.

```
            ┌── 2층 계단: 왼쪽으로 오른다 ──┐
  L3 ●─────┤                              │
            └──────────────┐   ┌─ 층참 ─┐  │
                           └───┤  L2   ├──┘   ← 오른쪽 구간의 L2 바닥으로 이어진다
            ┌── 1층 계단: 오른쪽으로 오른다 ┘
  L1 ●─────┘
```

**끼지 않는 조건은 딱 하나 — 단조롭게 오를 것.** 한 방향으로만 오르는 계단에는 처마가 없다.
각 칸을 얇은 판이 아니라 **윗면부터 바닥까지 꽉 찬 덩어리**로 만들어 칸 사이 틈도 없앴다.

| 값 | | 왜 |
|---|---|---|
| 한 칸 오름 | **112px** | ⚠ 처음엔 140으로 잡았다가 `레벨검사`가 "못 오른다"고 잡았다 — 검사기는 **점프 높이 × 0.85 = 136**을 안전선으로 쓴다. 사람이 겨우 되는 높이는 레벨에 쓰면 안 된다 |
| 한 칸 깊이 | **140px** | 플레이어 폭 44보다 넉넉하다 |
| 2층 계단 밑 머리 공간 | **224px** | 키 96 + 여유 128 (전에 낀 사다리는 88이었다) |
| 중간 선반 | y = L2 − 224 | ⚠ 없으면 L3 → 층참이 **560px**라 치명 낙하(520)를 넘는다. 336 + 224로 쪼갠다 |

### ⚠ 여기서 한 번 더 틀렸다 — 층참을 2층 계단이 덮었다

1층 계단의 첫 칸을 `sx0`에서 시작했더니 꼭대기 칸(= L2 층참)이 샤프트 왼쪽으로 밀렸고,
그 자리를 2층 계단 덩어리가 통째로 덮어 **층참이 사라졌다.**
레벨검사가 `1F_4 → 1F_5 사이 160px`(점프 한계 136 초과)로 정확히 집어냈다.
→ 1층 계단을 **한 칸 오른쪽으로 밀어** 시작하니 층참이 살아났다. 도달 6 → **43**.

## 3-4. ★[수정 3] 에디터에서 움직이는 발판이 원점에 모이던 버그

도형님 제보: "움직이는 발판은 왜 이상한데 0,0에 다 모여있어?"

씬 파일의 좌표는 멀쩡했다. **에디터에서만** 밀린 것이다.

```gdscript
func _ready():
    if Engine.is_editor_hint():
        return              # ← 여기서 빠져나가는 바람에 `_시작위치` 가 (0,0) 인 채로 남았다
    _시작위치 = position
```

그런데 `_physics_process` 는 **메서드가 있으면 에디터에서도 돈다**(기본 활성).
그래서 `position = (0,0) + 오프셋` 이 되어 발판들이 전부 원점 근처로 모였다.
**그 상태로 씬을 저장하면 밀린 좌표가 파일에 박힌다** — 조용히 맵이 망가지는 종류의 버그다.

고친 방법 두 겹:
1. `_시작위치` 를 **에디터 분기보다 먼저** 잡는다.
2. 에디터에서는 `set_physics_process(false)` + `_physics_process` 첫 줄에서 `is_editor_hint()` 로 한 번 더 막는다.

## 5. 움직이는 발판 (신규 부품)

| 인스펙터 | 뜻 | 기본값 |
|---|---|---|
| `크기` | 발판 크기(px) | 180 × 28 |
| `이동거리` | 왕복 거리(px). 0이면 안 움직인다 | 300 |
| `이동방향` | 좌우 / 상하 | 좌우 |
| `왕복시간` | A→B→A 한 바퀴(초) | 3.4 |
| `시작지연` | 위상 지연(초). 여러 장을 엇갈리게 | 0 |
| `원점이_가운데` | 끄면 **놓은 자리가 곧 출발 자리** | 끔 |
| `필요횟수` | 칠하는 데 드는 발수 | 2 |

**왜 새로 만들었나** — 기존 것 두 개가 다 못 쓴다.
1. `scripts/장애물/움직이는발판.gd`는 v3의 `PaintPlatform` 상속이라 스마트월드 `페인트코어`와 안 물린다.
2. SS2D 지형의 충돌은 `StaticBody2D`라 **위에 선 플레이어를 안 태우고 혼자 빠져나간다.**

→ `AnimatableBody2D` + `sync_to_physics` + `_physics_process` 안에서 이동.
검사에서 **플레이어가 실제로 실려 가는지**(발판 273px · 플레이어 275px) 확인한다.

**왕복은 사인파다.** 삼각파(등속 + 즉시 반전)는 끝점에서 플레이어를 튕겨 낸다.
사인파는 끝에서 저절로 느려져 **끝점이 곧 타이밍 창**이 된다.

색 계약은 통과플랫폼과 **완전히 같다** — 안 칠하면 검정이라 흰 플레이어가 올라타면 죽고,
분사기가 칠할 수 있으며, 분사기가 칠한 것은 E로 못 지운다.
