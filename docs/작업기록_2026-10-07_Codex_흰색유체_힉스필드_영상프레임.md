# 흰색 유체 전체를 힉스필드 생성 영상으로 교체

- 요청: 바닥 물막이 낙수 본체보다 지나치게 넓으므로 본체 폭 안으로 줄이고, 흰색 물의 본체와 튀는 움직임을 힉스필드로 만든다.
- 상태: **파일 수정 완료·실제 엔진 시각 검증 대기**. Godot 실행 요청이 없으므로 편집기, 콘솔, headless 검사 및 씬 빌더는 실행하지 않았다.

## 생성 결과와 선택 이유

Higgsfield MCP에서 GPT Image 2.5로 흰색 낙수 전체의 시작 이미지를 생성했다. 기존 승인 시안의 흑백 회화 질감과 가는 물방울을 참고하되 벽, 바닥, 벽등을 제외한 유체 자산으로 요청했다.

게임 애니메이션 가이드의 Seedance 1.5를 두 번 시도했으나 큰 왕관 모양과 넓은 바닥 반사가 생겨 적용하지 않았다. 이 문제를 사용자에게 알리고 일반 Higgsfield 생성 흐름의 Seedance 2.5로 변경했다. 마지막 결과는 물줄기가 유지되고 작은 방울이 분리되어 움직이며 앞선 시도의 큰 왕관과 긴 바닥 반사가 없어 채택했다. 배경 제거 모델도 시험했으나 작은 방울이 사라지고 분홍 가장자리가 남아 최종 자산에는 사용하지 않았다.

- 이미지 생성 작업: `33c9c12b-15cb-4b85-a46b-49854effdfb8`.
- **채택 영상 작업: `d1cdeff6-da65-4c4a-a743-6c24e171acf4`**, Seedance 2.5, 720×1280, 24fps, 약 4초, 무음.
- 채택 원본: `docs/visual_review/white_fluid_higgsfield_20261007/흰색유체_힉스필드_최종영상.mp4`.
- 원본 SHA256: `ff3264bde968bb51a0c08d9293d5fdfbc8bf7d75acc4a28cb3733cb7c7f8a130`.
- `흰색유체_힉스필드_생성영상.mp4`는 탈락한 Seedance 1.5 결과의 감사 자료다. 최종 영상과 혼동하지 않는다.

## 실제 프레임과 적용

`tools/흰색유체_힉스필드_영상프레임.py`는 원본 영상의 97프레임을 추출한 뒤 0, 2, …, 96번째를 고른다. 반복 끝의 참고 프레임을 제외한 48프레임을 12fps·4초 반복 시트로 조립했다. 고정 카메라의 위치를 유지하며 프레임마다 재배치하지 않는다. 배경 색만 제거하고 흰색/회색 RGB로 정리했다. 수면 줄무늬나 물방울 운동을 코드로 새로 만들어 넣지 않았다.

- 시트: `assets/textures/obstacles/liquid/white_fluid_higgsfield_v1/white_fluid_f48_256x512_g8x6_fps12_loop.png`.
- 256×512 셀, 8×6 배열, 전체 2048×3072 RGBA.
- 출처/반복 정보: 같은 폴더 `metadata.json`.
- `scripts/스마트월드/흰물_디자인.gd`: 텍스처를 캐시하고, 미임포트 PNG의 직접 읽기도 지원한다. 자연물 하수도 재질 중 `stage_2-1.tscn`~`stage_2-4.tscn`에 새 유체 재생을 연결한다.
- `shaders/water_stream_natural.gdshader`: 흰색일 때 본체와 착수부 모두 채택 영상의 실제 프레임을 재생한다. 프레임 사이 색/알파를 보간한다. 기존 낙수 도착/종료 위치로 착수부 표시를 제한한다.
- 바닥 접촉 물막은 물줄기 본체 폭 안에서만 나타난다. 공중으로 튄 물방울에는 바닥 폭 마스크를 씌우지 않는다. 해당 네 스테이지의 기존 검정/회색 물에도 바닥 폭 제한을 적용한다.
- 그림의 기준 본체 폭은 26px로 사용한다. 원본 기준 폭 27.733px보다 작게 잡아 가시 본체가 기존 충돌 영역의 가장자리 안으로 줄어들지 않도록 했다. 원본 추출 메타데이터는 변조하지 않았다.
- 씬 배치, 충돌, 물색 판정 및 씬 재생성 도구는 수정하지 않았다. 기존 다른 작업의 변경 파일은 유지했다.

## 확인 결과와 한계

- 실제 원본 영상 해시, 추출 순서, 48개의 서로 다른 프레임, RGBA/흑백 색, 투명 시트 테두리 확인: 통과.
- 반복 경계의 평균 차이 6.337, 이웃 프레임 차이 중앙값 5.713. 경계도 일반 이웃 프레임 차이와 비슷하다. 첫·마지막 그림이 완전히 동일하다고 단정하지 않는다.
- 셰이더의 전체 유체 분기, 네 스테이지 범위, 도착/종료 조건, PNG 읽기, 셰이더 한글 없음 및 괄호 균형: 정적 확인 통과.
- 폭 8~500px에서 시트 본체의 충돌 가장자리 알파가 보이는지 표본 계산: 통과. 바닥의 본체 폭 밖 마스크가 0인지 확인: 통과.
- 애니메이션 미리보기의 48프레임과 반복 설정: 통과. 원본 영상의 대표 프레임, 정리된 자산과 확대 착수부를 직접 열어 확인했다.
- `tools/test_sewer_color_modules.py`: 37,288개 색 저장 영역 검사 통과.
- `git diff --check`: 통과. 기존 다른 파일의 CRLF 안내는 남아 있다.
- `git pull --ff-only`: `FETCH_HEAD` 접근 거부로 미완료. 강제 갱신은 하지 않았다.
- `graphify query`/`graphify update .`: 실행은 시도했으나 유효한 결과를 얻지 못해 그래프 갱신을 확인하지 못했다.
- 지정된 `docs/다음작업_프롬프트.md`가 현재 체크아웃에 없어 13개 검사 명령을 읽을 수 없었다. 엔진 검사 13개가 통과했다고 보고하지 않는다.
- **Godot 구문 컴파일, 실제 실행, 스테이지 2-3 동일 카메라/해상도의 수정 전후 PNG, 입수·재진입·리스폰·소멸 확인: 미실행**. 사용자 명시적 실행 허용 규칙을 따른다.
- 실제 엔진 캡처 경로: **없음**. 아래 자료는 생성 영상에서 만든 자산 미리보기이며 게임 캡처를 대체하지 않는다.
