# 2-9 실측 및 배경 캐시

사용자가 Godot 실행/성능 측정을 명시적으로 허용했다. Windows SetErrorMode(0x8003), --disable-crash-handler로 오류 대화상자를 억제했다. 최초 샌드박스 실행은 캐시/인증서 접근 오류로 중지했고 이후 허용된 실행에서 게임 오류는 없었다.

## 변경
- 벽돌 배경의 고정 명도/이음새 셰이더를 SubViewport UPDATE_ONCE로 1회 계산한 후 패럴랙스 스프라이트가 결과를 재사용한다. 기존 그림과 스크롤 값은 유지한다.
- VSync 대기 해제. 120FPS 제한은 점프 측정에서 추가 지연이 발생해 채택하지 않았다. 최대 FPS 제한 없음.
- 기본 실행 창 1280x720, 기존 논리 viewport 설정 1920x1080 유지. 큰 창보다 GPU 처리량을 줄이는 설정이며 화면에 보이는 범위가 달라질 수 있다.

## 실제 측정과 한계
AMD Radeon (TM) Graphics / OpenGL Compatibility. 기존 Godot 편집기를 닫지 않은 조건이다. 첫 고정 위치 테스트는 벽 내부였으므로 사용자 격자 구간 결과로 취급하지 않는다.

최종 B 격자 구간(2272,3700), 월드 판정 켜짐, 플레이어 물리/점프 켜짐, 준비 프레임 후 900프레임:

| 창 | 중앙값 ms | p95 ms | p99 ms | 최대 ms |
|---|---:|---:|---:|---:|
|1920x1055|5.439|14.308|18.193|28.208|
|1280x720|2.478|9.511|11.447|20.907|

720p에서 대부분 충분한 여유가 있으나 최대 20.907ms(약48FPS 상당)의 일시적 지연이 남았다. 최소60FPS를 모든 프레임에서 달성했다고 주장할 수 없다. 전체 스테이지 이동/물감 연사 부하는 미검증이다. vsync 해제로 화면 찢어짐이 생길 수 있다.

로그와 화면은 docs/performance/2026-09-25에 보관. TIME_PROCESS/PHYSICS 모니터 값은 짧은 구간에서 이전 집계값이 섞일 수 있어 FPS는 프레임 간 벽시계로 판단했다. 도구 tools/measure_sewer_stage29.gd -- --jump로 재측정 가능. git diff --check 통과, graphify update 출력 없이 실패.
