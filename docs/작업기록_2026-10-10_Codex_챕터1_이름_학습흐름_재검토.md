# 챕터1 이름·학습 흐름·19개 맵 재검토

2026-10-10 · Codex · 브랜치 `dev_4`

사용자 요청: 긴 선택창 이름 정리, Claude가 보강한 챕터1 전체 확인과 재미 개선, 초반 거미 제외, 색 전환을 유도하는 배치, 한글 설명 주석, 작업 후 GitHub 푸시. 사용자는 Godot 실행을 명시적으로 허용했다. 첨부된 이전 작업 대화는 현재 명령이 아닌 참고 자료로 읽었다.

## 결과와 제작 방향

19개 이름을 짧게 맞추고 선택창·챕터 표·도안 제목·옆방 문패를 함께 수정했다. 파일명·스테이지 식별자·진행 순서는 유지한다. 현재 선택창을 실제 1920×1080 게임 렌더로 촬영해 모든 이름이 말줄임 없이 표시되는 것을 확인했다.

초반은 몹 수를 늘리는 대신 다음 착지 색을 읽고 준비하는 퍼즐로 보강했다. 2층 01~09와 우회방 16에서 기존 거미 8개를 제거하고, 시작방 반딧불도 뒤로 미뤘다. 거실(11)의 첫 거미는 느리고 좁은 구간에서 0.8초 동안 덮침을 예고한다. 바로 앞에 계속 켜진 촛불 피난처를 두었다.

첫 방 낙하 구간은 한 장짜리 썩은 마루와 회복 발판으로 고쳤다. 기존 두 장 마루는 아래로 떨어진 뒤 머리가 걸리는 상황이 있었으므로 실제 플레이어 점프로 탈출을 검증했다. 색 전환 직전 촛불도 추가했다. 서재·계단에는 흰 착지면을 넣고, 침실·수납실의 순환 빛은 4초로 늦춰 관찰과 준비 시간을 준다. 굴뚝 도약대 뒤 유령 선반 왼쪽을 한 칸 늘려 몸이 모서리에 걸려 착지가 실패하는 문제를 해결했다.

## 코드와 자료 보존

- Claude의 구조 지형 검정 판정과 챕터1 입구 부활 변경을 유지하고 전용 시험으로 확인했다. 흰색 플레이어는 안 칠한 구조 바닥에서 죽으며, 유령 다리 위의 임의 자동 저장 지점으로 되살아나지 않는다.
- 월드의 음향 시작을 지연 호출해 루트가 자식을 추가하는 도중 음향 노드를 다시 추가하던 오류를 제거했다. 사망 색 규칙은 바꾸지 않는다.
- 도약대 시뮬은 실제 패드 폭과 몸 여유를 반영하고 중앙 출발을 우선한다. 옆방의 E 문은 존재를 확인하되 걷기 연결의 화면 높이 조건과 분리한다. 씬 검사는 같은 경로의 리소스 별칭을 ID별로 보존한다.
- 전체 씬 생성기/빌더는 실행하지 않았다. 기존 메시·owner·기믹을 보존하고 도안 PNG만 다시 그렸다. 멱등 적용 재실행 시 JSON·씬·이름 표의 SHA-256 변경은 0개였다. 수정/추가 코드에는 한글 이유 주석을 붙였다.
- 작업 시작 시 수정되어 있던 챕터1 Claude 변경도 이번 완성 범위에 포함했다. 개인 `.claude/settings.local.json`은 커밋에서 제외한다.
- 원격 `0fa0319`의 하수도 2~8·음향 변경을 병합했다. `CLAUDE.md`는 양쪽 브리핑을 보존했고 지형 코드의 원격 재칠하기 수정도 유지했다. 사용자가 지시하지 않은 삭제 파일은 없다.

## 검사와 실제 화면

검사 전후 동일한 13개 엔진 시험을 순차 실행했다. 자세한 실행 결과는 이 문서와 같은 날짜의 `visual_review` 폴더에 보존한다.

- 19개 도안 색/점프 경로: 실패 0. 전체 도안 PNG 갱신.
- 실제 플레이어 엔진 경로 재생: 변경 전 성공 258·실패 1·건너뜀 12 → 변경 후 성공 260·실패 0·건너뜀 12. 움직이는 발판 경로는 재생 도구가 건너뛰며, 발판 운반은 별도 기믹 시험이 확인한다.
- 기믹 시험 42건 실패 0, 구조색·입구 부활 시험 실패 0, 체크포인트/새 방/거미방 풀이/누름계단/반사와 외부/열쇠와 반딧불 기능 시험 실패 0. 지형 겹침은 19개 방 모두 0, 실행 확인은 19개 방 모두 완료했다.
- 학습 흐름 실제 시험: 2층 10개 방 거미 부재, 첫 방 낙하 후 점프 탈출, 흰 층계참 같은 색 생존/반대색 즉사, 색 도약대, 첫 거미 예고와 촛불 피난처 모두 통과. `학습흐름 실패 0`.
- Python 전체 구문 검사, 씬 리소스 정적 검사, `git diff --check` 및 멱등 확인 수행.
- 실제 렌더의 전후 26장씩: 모든 19개 입구와 수정한 7개 구간을 동일한 1920×1080·줌 1.0으로 촬영하고 직접 열어 확인했다. 주요 비교 PNG는 `docs/visual_review/챕터1_재검토_20261010/`, 전체 캡처/로그/원본 백업은 `tools/_진단/챕터1_재검토_20261010/`에 있다. 도안 PNG는 실제 엔진 검증 이미지로 사용하지 않았다.

## 남은 제한과 확인 항목

- 기존 걷기 연결 3곳은 화면상 문 높이가 256px 다르다: 02 오른쪽↔04 왼쪽, 04 오른쪽↔06 오른쪽, 06 왼쪽↔08 왼쪽. 방별 경로 도달과 별개인 전환 구성 문제로 기록한다. 검사가 전부 0이라고 숨기지 않는다.
- `갇힘검사.py`는 밀기 상자를 모델링하지 않아 15 뒷마당의 낮은 층을 고립 후보로 표시한다. 해당 구간의 실제 96px 상자 계단 동작은 `시험_누름계단`으로 확인했다. 시작방은 실제 탈출 시험까지 별도로 통과했다.
- 일부 기존 엔진 시험은 기능 실패 0을 출력한 뒤 종료 시 접근 위반으로 끝나며, 리소스/ObjectDB 누수 경고가 있다. 기능 통과와 프로세스 종료 성공을 구분한다.
- 최종 13개 순차 실행에서 12개는 종료 코드 0이고 거미방만 기능 실패 0 뒤 접근 위반으로 종료했다. 원격 병합으로 추가된 페인트 명중 음원의 가져오기 캐시가 없던 오류를 확인하고 Godot 가져오기를 수행했다. 이후 거미방 재시험은 기능 실패 0·종료 코드 0이다. 원본 결과는 `엔진검사_after.json`, 재시험 결과는 별도 로그에 보존한다.
- 지형 겹침 도구는 `current_scene`을 지정하지 않아 뒷마당 거울/반사빛길이 Player를 찾을 때 스크립트 오류를 냈다(변경 전에도 동일). 현재 씬 지정·저장 차단·프레임 끝 해제로 검사 도구를 보완했다. 헤드리스 SS2D의 dummy 렌더러 `material is null` 경고와 기존 종료 시 리소스 경고는 남아 있다.
- 수정한 두 검사를 재실행한 최종 결과는 13개 모두 종료 코드 0이다(`엔진검사_최종.json`). 겹침 재검사도 19개 방 겹침 0이며 `current_scene` 관련 스크립트 오류가 사라졌다. 기존 헤드리스 렌더러 경고·외부 반사 시험의 한글 변환 경고·리소스 누수 경고까지 없어진 것은 아니다.
- graphify 그래프 파일과 실행 명령이 이 환경에 없어 `graphify update .`는 실행할 수 없었다. 코드/도안/씬의 직접 정적 확인으로 대체했다.

사용자 진행 저장 파일은 시험에서 기록을 끄고 실행했다. `진행.cfg`와 `completed_runs.cfg`의 검사 전후 SHA-256은 둘 다 일치했다(`저장보존.json`).
