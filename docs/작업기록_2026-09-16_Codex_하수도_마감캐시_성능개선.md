# 하수도 마감 계산 구조 변경

## 원인과 변경

기존 자연 지형 셰이더는 큰 지형의 픽셀마다 자기 윤곽/주변 가림 다각형을 반복 탐색했다. 맞물림으로 점이 늘면서 비용이 증가했고, 지형별 0.5초 이웃 전수 검사도 있었다.

하수도_마감메시.gd를 추가했다. 로드/편집 변경 때 노출된 변을 구하고, 이웃과 만나는 구간을 나눈 후 Geometry2D 차집합으로 가려진 띠를 제거한다. 남은 24px 상면/18px 측면 띠만 MeshInstance2D로 만든다. 상면은 발밑 선 뒤 4px, 앞 4px 깊이를 유지하고 볼록한 뒤 모서리를 좁힌다. 충돌과 SS2D 점은 변경하지 않는다.

본체 셰이더 cached_draw_mode=1은 윤곽/가림 루프를 건너뛴다. 마감 메시 cached_draw_mode=2는 자기 변 1개, 가림 변 0개만 사용한다. 상면 거리 계산은 한 번으로 줄였다. 넓은 본체의 고정 bbox 명암도 제거하고 실제 마감 띠가 담당한다. 구형 경로 mode=0은 비교 도구용으로 남아 있다.

마감 메시의 원점은 부모 지형과 같고 본체의 SS2D UV 변환을 사용한다. 본체 재질을 복제하여 흑백 짝, 노멀/유기적 번짐 설정을 보존한다. 런타임에는 기존 _셰이더들에 등록하여 물감/회수/연결페인트 정보를 동일하게 받는다. 재생성 전에는 기존 재질을 목록에서 제거하고 메시를 해제한다.

하수도_자연발판은 0.5초 폴링을 제거했다. points_modified, 배치/표시/자식 목록 변경 등 이벤트로 요청하고 서명이 달라질 때만 재생성한다. 파생 메시에는 owner를 설정하지 않아 디스크 씬에 중복 저장하지 않는다. 원본 SS2D만 편집한다. 현재는 디스크에 완성 메시를 굽는 방식이 아니라 로드 시 메모리 캐시다.

근접 반사는 기존 물감 _process를 그대로 호출한 뒤 별도로 최대 30Hz 갱신한다. AABB 바깥의 먼 지형은 선분 배열/물리 레이를 만들지 않는다. 가까운 지형에서도 실제 빛 범위/방향에 맞는 변만 최대32개 전달한다. 셰이더도 빛 반경 밖 픽셀에서는 반사 선분 루프를 건너뛴다.

## 적용 범위

공통 하수도 자연 지형 스크립트와 셰이더를 쓰는 2-1/2-2 및 해당 프리팹/시험 씬에 적용된다. 공중 선반의 전용 아트 셰이더는 유지한다. 메인 로비/스테이지 배치/맞물림 점/충돌/사망 규칙 파일은 수정하지 않았다.

## 실제 검증 범위

- tools/test_cached_trim_static.py: 실제 두 씬의 노출/가림 14,038 표본을 Python 기준 계산으로 확인. 정적 캐시/페인트 등록/UV 연결 검사 통과.
- tools/test_stage21_masonry_joint.py: 기존 맞물림 경계 980표본, 면적/충돌/리소스 검사 통과.
- git diff --check 확인.
- Godot는 사용자 안전 예외로 **실행하지 않았다**. GDScript/셰이더 엔진 컴파일, Geometry2D 실제 메시 생성, 최종 스크린샷, FPS/CPU/GPU 개선은 아직 검증 전이다. 정적 표본 검사는 엔진 테스트를 대체하지 않는다.

## 실행 허가 후 필수 확인

1. tools/test_sewer_cached_trim.gd: 실제 2-1 지형을 로드하여 마감 생성, 동기화된 물감/회수, 충돌 보존, 정지 시 재생성 0, 이동 이웃 재생성, 재질 누적 없는지 검사.
2. 기존 하수도 색칠사망 검사와 실제 플레이어/총알 실행. 연결페인트가 경계를 넘을 때 본체/마감이 같은 색인지 확인.
3. tools/measure_sewer_cached_trim.gd를 창 모드로 실행. --legacy-trim 유무로 같은 위치/해상도/VSync에서 비교. 이 대조군은 GPU 구형 마감만 복원하며 CPU 구형 폴링은 복원하지 않는다. 완전한 이전 버전과 동일한 기준이라고 주장하면 안 된다. median/p95 프레임, process/physics 시간, draw call을 출력한다.
4. 상면 모따기, 얇은 측면 줄눈/마감 연결을 확대 비교. 메시로 옮긴 방식은 원래 픽셀 알파 마스크와 픽셀 단위로 완전히 동일하다고 보장하지 않는다. 가림 클리핑으로 마감이 누락/돌출하지 않는지 확인한다.
5. 이동/숨김/삭제/재로드 후 캐시가 갱신되는지 확인. 생성된 메시 수 증가가 draw call 병목이 되면 마감을 배치 병합하는 후속 최적화를 검토한다.

현재 단계에서 프레임 개선률, 무오류 실행, 배포 성능을 확정해서 보고하면 안 된다.
