## STEP 4 — 실제 인게임 조명·재질 최종 검수

### 4-1. 코드를 고치기 전에 먼저 찍었다 (지시서 §1)

스테이지_1_2층방을 여섯 자리(플랫폼 위 / 벽 근처 / 광원 근처 / 광원에서 멂 / 시작 / 바닥)에서
BLACK 상태로 찍고 문제부터 적었다.

| 관찰 | 판정 |
|---|---|
| A. Player 가 배경에 묻히나 | **밝은 구역·중간 구역은 잘 보인다.** 어두운 구역에서는 흰 외곽선에만 의존한다 |
| B. 플랫폼 밝기 | 창문 쪽은 적정. **어두운 구역의 옷장/서랍 발판이 검은 덩어리로 사라진다** ← 최대 문제 |
| C. 벽 노멀맵 | 자연스럽다. 벽돌 하나하나가 살아 있고 번들거리지 않는다 |
| D. 빛의 방향 | **느껴진다.** 오른쪽(창문)이 밝고 왼쪽으로 죽는다 |
| E. 그림자 | 기둥 그림자가 보이지만 **그늘 안쪽 정보가 좀 많이 사라진다** |
| F. 회색 얼룩 | 없다 |
| G. 주변부 | 형태는 남지만 어두운 구역은 아슬아슬하다 |
| H. HUD | 크기 적정. 화면을 안 가린다 |

→ 결론: **B(어두운 구역 발판 소실)** 가 진짜 문제이고, 이건 환경 밝기를 올려서
풀 문제가 아니라 **국소 보조광**으로 풀어야 한다(= STEP 5).

### 4-2. Lighting Standard 미세조정 — 실제로 바꾼 것은 **하나**

| 항목 | 후보 | 결과 | 근거 (실화면) |
|---|---|---|---|
| CanvasModulate | 0.58 / 0.62 / 0.66 | **0.62 유지** | 0.66 은 어두운 구석이 아주 조금 나아질 뿐. 그 구역은 보조광이 국소적으로 푸는 것이 맞고, 환경 밝기를 올리면 어두운 분위기 예산을 통째로 쓴다 |
| PointLight2D height | 96 / 128 / 160 | **128 유지 (LOCK)** | 96 은 벽돌 면이 납작하다. 160 은 벽돌 윗모서리가 젖은 것처럼 번들거리기 시작한다 |
| energy | ×0.75(≈1.2) / ×0.875(≈1.4) / ×1.0(1.6) | **1.6 유지** | "중앙이 너무 밝다" 증상이 없다. 1.2 는 어두운 쪽 발판이 더 죽는다 |
| range | ×0.786(≈550) / ×1.0(700) / ×1.214(≈850) | **700 유지** | 850 은 화면이 평평해져 **빛의 방향이 사라진다**. 550 은 방향은 세지만 왼쪽이 더 죽는다 |
| **shadow alpha** | 0.50 / 0.60 / 0.72 | **0.72 → 0.60 (변경)** | 0.50 은 그림자가 값 단차로만 남아 깊이가 안 생기고, 0.72 는 그늘 안쪽 지형 정보가 거의 사라진다. 0.60 = 방향은 확실히 읽히면서 그늘 속 발판이 보인다 |

→ `scripts/스마트월드/조명표준.gd` 에 `그림자_알파 = 0.60` 상수로 넣었다.
  (`발광체.gd` 가 그 상수를 읽는다 — 값이 두 곳에 흩어지지 않는다)

### 4-3. Material Standard 확정 — **LOCK**

⚠ 노멀 세기와 광원 height 를 섞어서 움직이지 않았다.
**먼저 조명 표준을 고정하고**, 그 상태에서 재질 세기만 흔들었다.

| Material | Normal Strength | Height | 상태 | 근거 (실화면) |
|---|---:|---:|---|---|
| BRICK | 수제 노멀맵 (texturemap.app) | 128 | **LOCK** | 2026-09-05 실런타임 검증을 통과한 기준선. 소벨로 다시 뽑지 않는다 |
| WOOD | **1.6** | 128 | **LOCK** | 0.8·1.2 는 나뭇결이 안 산다. 2.0 은 넓은 발판에서 **타일 반복 이음**이 눈에 띈다 |
| GRASS | **0.9** | 128 | **LOCK** | 1.2 는 고주파 노이즈가 증폭돼 사포처럼 자글거린다. 0.6 은 표면 질감이 사라진다 |
| IRON | **1.4** | 128 | **LOCK** | 1.8 은 리벳·이음매가 번들거려 "반짝이는 금속판"으로 읽힌다. 1.0 은 거의 평평하다 |

WOOD 는 **본 스테이지의 창문 구역**(빛이 실제로 닿는 자리)에서 비교했다.
어두운 구역에서 비교했더니 네 값이 전부 똑같이 보여서 판단이 안 됐다 — 재질 비교는
**빛이 닿는 자리에서** 해야 한다.
GRASS · IRON 은 본 스테이지에 없어서 조명 실험실에서 같은 표준값으로 비교했다.

세기 비교는 도구에 CLI 를 붙여서 했다(표를 매번 고치면 어떤 값으로 찍은 그림인지 헷갈린다):
```
godot --headless --path . -s res://tools/생성_지형_노멀맵.gd -- --세기=나무:1.2 --만=나무
```

## STEP 5 — Player Follow Light + 2층 방 조명 연출

### 5-1. 조명을 세 종류로 갈랐다 (역할을 섞지 않는다)

```
            [창문]                     A. Environment Key Light
               ↓                          공간의 밝기와 **방향**을 만든다
        ┌──────────────┐                  고정 좌표. 플레이어를 절대 안 따라간다
        │   밝은 영역   │
        │      ↓       │               B. Player Follow Fill Light
        │  [Player] ◉  │ ← 아주 약함      플레이어 주변 지형의 **최소 가시성**만
        │      ↓       │                  그림자 없음
        │   플랫폼      │
        │      ↓       │               C. LightOccluder2D Shadow
        │    그림자     │                  환경광에만. 공간의 **깊이**를 만든다
        └──────────────┘
```

### 5-2. Player Follow Light 구현 — 자식 노드, 추적 코드 없음

```
Player (CharacterBody2D)
 ├ CharacterSprite
 ├ GunRig / ActionFX / Camera2D / CollisionPolygon2D
 └ 플레이어_보조광 (Node2D · scripts/플레이어_보조광.gd)
     └ PointLight2D
```

- **매 프레임 추적 코드를 안 만들었다.** 부모-자식 트랜스폼 전파로 공짜로 따라간다.
- `player.gd` · `gun.gd` · `bullet.gd` **무수정**. `Player.tscn` 에 자식 노드 한 개만 추가.

#### ★함정 — Player 는 스케일이 비균등하다

`Player.tscn` 루트 `scale = (0.7950, 0.3677)`. 그냥 자식으로 달면 빛이 **세로로 눌린 타원**이 된다.
(`proto/zone_visuals.gd` 가 자식 대신 매 프레임 추적을 쓴 이유가 바로 이것이다)

→ `플레이어_보조광` 이 부모의 전역 스케일 **역수**를 자기 scale 로 잡아 상쇄한다.
   진단 도구 확인: `빛 global_scale (1.0, 1.0)` = 정확한 원. 자식 구조도 유지된다.

### 5-3. 값 결정 — 숫자가 아니라 화면으로

Energy 0.25 / 0.35 / 0.45 × Range 250 / 300 / 350 을 실제로 찍고,
**플레이어 주변 220 px 창의 평균 밝기**도 같이 쟀다(눈으로 애매한 차이라서).

| Energy | 주변 밝기 (off 대비) | 화면 판정 |
|---|---|---|
| off | 0.0752 | 옷장 발판이 검은 덩어리 |
| 0.25 | 0.0858 (+14 %) | 발판 윤곽만 겨우 |
| **0.35** | **0.0899 (+20 %)** | **나뭇결·발판 테두리가 읽힌다. 빛이 따라오는 티가 안 난다** ← 채택 |
| 0.45 | 0.0937 (+25 %) | 발판만 스포트라이트처럼 밝아지기 시작 |

Range 는 250/300/350 셋 다 후광이 안 생겼고 차이가 작다 → **300**(가운데) 채택.

★확인: 0.70 까지 올려 봐도 눈에 띄는 원형 후광은 안 생겼지만,
**"발판만 밝아지는 스포트라이트"** 로 읽히기 시작하는 지점이 0.45 였다.
지시서의 실패 기준("빛이 따라오는 게 눈에 띄면 너무 강함")에 걸리기 전에서 멈췄다.

#### 최종값

| 항목 | 값 |
|---|---|
| Energy | **0.35** |
| Range | **300 px** |
| Height | **128** (환경광과 같은 표준) |
| Shadow | **OFF** |
| Blend | **ADD** |
| 색 | `Color(0.92, 0.92, 0.95)` — 중립. BLACK/WHITE 상태와 **연결하지 않는다** |

`조명표준.보조광_세기 / 보조광_반경 / 보조광_색` 에 상수로 있고,
스테이지별 미세조정은 노드 인스펙터에서 한다.

### 5-4. 왜 보조광에 그림자를 안 켜나

플레이어가 점프할 때마다 광원이 움직이면 **그림자 + 노멀맵 하이라이트**가 한꺼번에
따라 움직여서 화면이 부산스러워진다.
→ 그림자는 **고정된 환경광**(스테이지_1 의 `창문_주광` 하나)만 만든다.

### 5-5. 조명 Debug 토글 (개발용)

- 촬영 도구: `조명모드=1~5`
  1 환경만 / 2 보조만 / 3 환경+보조 / 4 환경+그림자 / 5 전체
- 실험실 씬 F6: `Z / X` 보조광 밝기, `C` 보조광 ON/OFF, `← →` 환경광 위치,
  `↑ ↓` height, `Q / W` energy, `1~4` CanvasModulate, `N` 노멀맵
- ⚠ **게임플레이 Input Map 은 한 글자도 안 건드렸다.** 실험실 씬 안에서만 도는 키다.

모드 4·5 에서만 기둥 그림자 띠가 나타나는 것을 스크린샷으로 확인했다 = 토글이 실제로 동작한다.

### 5-6. Lighting Lab 개편 — 세 구역

`scenes/테스트/Lighting_Standard_Lab.tscn` 을 **지우지 않고** 세 구역으로 다시 구웠다.

```
구역 A  환경광만                  BRICK · WOOD · GRASS · METAL + Player
구역 B  환경광 + 보조광            (같은 배치)
구역 C  환경광 + 보조광 + 그림자     (같은 배치 + 그림자 기둥)
```

#### ★구역끼리 빛이 새지 않게 — light_mask

2D 라이트는 화면 전체에 작용해서, 구역을 멀리 두기만 하면 반경 700 짜리 빛이 옆 구역을 물들인다.
→ 구역마다 광원 레이어를 하나씩 줬다(A=1 · B=2 · C=4).
   지형/플레이어의 `light_mask` 와 광원의 `range_item_cull_mask` 를 맞춘다.

#### ★두 번 겪은 함정 — Player.tscn 안의 Camera2D

구역마다 Player 를 넣었더니 그중 하나가 `current` 가 되어 **실험실 카메라가 무시**됐다
(세 구역 사진이 전부 똑같이 나왔다). 씬에 구운 `enabled=false` 가 인스턴스 오버라이드로
안 남는 경우가 있어서 컨트롤러가 **런타임에 확실히** 끈다.
