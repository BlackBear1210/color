```cpp
if (snames[nprops[j].name] == CoreStringName(script)) {
```

### 1-4. 순서를 따라가면 (지형 1 개)

1. 템플릿 인스턴스 생성: 지형.gd 붙음. `_init()` → 빈 점배열 P0 연결. 템플릿 값 set → `_points = P_t`(P0 해제·P_t 연결), `shape_material = M_t`(연결).
2. stage_2-1 오버라이드 `script` 처리:
   - ① old_state = { `_points: P_t`, `shape_material: M_t`, … }
   - ② `set_script(하수도_자연발판.gd)` → 새 GDScript 인스턴스, **`_init()` 이 다시 돌아** `_points = P1`(새 빈 배열, 연결). `shape_material` 은 기본값 `SS2D_Material_Shape.new()`(초기화자는 setter 를 안 거치므로 미연결).
     **P_t·M_t 에 붙어 있던 연결은 그대로 남는다** — 시그널 연결은 (오브젝트 ID, 메서드명) 기준이고 스크립트 교체는 이를 지우지 않는다. 로그의 콜러블 표기가 `Node2D(하수도_자연발판.gd)::_points_modified` 인 것은 "지금 붙은 스크립트" 를 보여줄 뿐, 연결 자체는 지형.gd 시절 것이다.
   - ③ `set("_points", P_t)` → setter: `_points(P1) != P_t` 라 P1 만 해제 → `P_t.connect(...)` → **이미 있음 → ERROR ×2**.
     `set("shape_material", M_t)` → 현재 재질(기본값)은 미연결이라 해제 없음 → `M_t.connect(...)` → **이미 있음 → ERROR ×1**.
3. 이어서 stage_2-1 의 `shape_material = natural_material8`, `_points = ledge_points0` → P_t·M_t 에서 정상 해제, 새 리소스 연결. (connect 가 실패했으니 연결은 1 개뿐이라 깨끗이 정리된다.)

→ 결과적으로 **연결 개수는 망가지지 않고 오류만 찍혔다.** 게임 동작 이상은 이 오류에서 나오지 않는다. 다만 진짜 오류를 108 건 밑에 묻는다.

### 1-5. 왜 다른 스테이지엔 안 났나

script 오버라이드는 "템플릿과 다른 스크립트일 때만" 저장된다. 지형.gd 를 그대로 쓰는 집·숲 스테이지는 이 경로를 타지 않는다. 하수도에서 처음 나타난 이유.

## 3. 수정

### 3-1. `addons/rmsmartshape/shapes/shape.gd` (★공용 애드온 · 2 곳 · 국소)

- `set_point_array()`: 새 점배열에 `update_finished`/`material_override_changed` 를 붙이기 전에 **이 노드의 같은 콜러블이 이미 붙어 있으면 건너뛴다.**
- `_set_material()`: 새 재질의 `changed` 도 같은 방어.
- `_enter_tree()` 가 재질 재연결에 이미 쓰고 있던 것과 **정확히 같은 패턴**이다.
- 바뀌지 않은 것: 옛 리소스 해제 · null → 새 배열 대체 · null 재질 허용 · `set_as_dirty()` · `notify_property_list_changed()`. `if old == new: return` 같은 조기 반환은 넣지 않았다.
- 동작 변화는 "예전엔 ERROR 를 내며 실패하던 connect 를 안 한다" 뿐이다. 연결이 없으면 예전과 동일하게 붙는다.
