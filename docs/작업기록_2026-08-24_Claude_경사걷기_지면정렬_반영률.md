## 1. 무엇이 문제였나

도형님 제보:

> "스마트월드 씬들을 보니까 곡선인 땅에 캐릭터가 걸으면 그 각도에 맞게 휘어져서 걷더라고.
> 다리만 그 각도에 맞추는 게 아니라 **마이클잭슨의 중력 무시하는 춤**처럼 걸어."

원인은 `player_anim.gd` 의 절차적 애니메이션 ①번(지면 경사 정렬)이었다.
발밑을 레이캐스트해 얻은 지면 법선의 각도를 **100% 그대로 몸통에 먹이고** 있었다.

```gdscript
var 각 := n.angle() + PI * 0.5
목표회전 = clampf(각, -deg_to_rad(지면정렬_최대각), deg_to_rad(지면정렬_최대각))
```

`지면정렬_최대각` 이 22° 였으니, 22° 비탈에서 몸이 통째로 22° 눕는다.

### 왜 그게 이상해 보이나 — 사람은 그렇게 안 걷는다

| | 몸통 자세 | 경사를 흡수하는 곳 |
|---|---|---|
| 예전 코드 | 지면에 **수직** | 없음 (몸 전체가 회전) |
| 실제 사람 | 중력 방향으로 **곧게 섬** | 다리 (양쪽 길이 차이) |

몸통을 지면에 수직으로 세우는 건 사람의 자세가 아니라 **자석 붙은 인형**의 자세다.
그래서 "중력을 무시하는" 느낌이 났다.

방향까지 반대로 간다:

- 오른쪽 오르막에서 법선에 정렬하면 몸이 **뒤로 젖혀진다**
  (법선이 왼쪽 위를 향하므로 머리가 내리막 쪽으로 눕는다)
- 그런데 실제 사람은 오르막에서 **앞으로 숙인다**

거기다 SS2D 곡면은 법선이 매 걸음 바뀌므로, 걸을 때마다 몸이 흔들리기까지 했다.

## 2. 어떻게 고쳤나

경사각에 **반영률**을 곱해 일부만 몸통에 남긴다.

```gdscript
var 각 := n.angle() + PI * 0.5
각 *= 지면정렬_반영률          # ← 이 한 줄이 전부
목표회전 = clampf(각, -deg_to_rad(지면정렬_최대각), deg_to_rad(지면정렬_최대각))
```

새 knob: `지면정렬_반영률` (`@export_range(0.0, 1.0)`, 기본 **0.25**)

| 값 | 결과 |
|---|---|
| **1.0** | **예전과 완전히 같음** (되돌리기용) |
| 0.25 | 기본값. 20° 비탈에서 5° 만 기움 |
| 0.0 | 경사 무시, 항상 곧게 섬 |

1차 수정에서는 `지면정렬_최대각` 22° 를 일부러 안 건드렸다 — 한 값만으로 왕복하려고.
**그런데 그것만으론 부족했다.** 아래 2-2 참고.

## 2-2. 2차 수정 (2026-08-25) — 최대각 22° → 8°

도형님이 스크린샷 두 장을 보내주셨다:

- **사진 1** — 작은 둔덕의 **옆구리**에 선 캐릭터. 아직 눕는다. "여기 마이클 잭슨이 존재해."
- **사진 2** — 같은 둔덕의 **윗면**. 살짝 기운다. "이 정도 기울기는 괜찮아."

### 왜 반영률만으론 안 잡혔나

`_발밑_접촉()` 은 플레이어 원점 바로 아래로 **레이를 딱 하나** 쏜다.
작은 둔덕의 옆구리처럼 **국소 경사가 급한 자리**에서는 그 한 점의 법선이 60~80° 까지 튄다.
0.25 를 곱해도 15~20° 가 남으니, 여전히 눕는다.

실제 사람은 그 자리에서 **한 발만 둔덕에 걸칠 뿐 몸통은 그대로 서 있다.**
점 하나로는 그 사실을 표현할 수가 없다.

### 어떻게 고쳤나

`지면정렬_최대각` 기본값을 **22° → 8°** 로 낮췄다 (사진 2 의 기울기가 대략 그 정도).

| 값 | 역할 |
|---|---|
| `지면정렬_반영률` 0.25 | **비례 축소** — 완만한 경사에서 자연스럽게 |
| `지면정렬_최대각` 8° | **상한** — 둔덕 옆구리 같은 국소 급경사를 자름 |

**둘이 같이 있어야 한다.** 반영률만 있으면 급경사에서 터지고, 최대각만 있으면
완만한 경사에서도 상한까지 꽉 채워 기운다.

### ⚠ 이 2차 수정도 부족했다 — 진짜 원인은 따로 있었다. §2-3 으로.

### 아직 남은 것 — 양발 평균

근본 해법은 **발 두 개 위치에서 각각 레이를 쏴 법선을 평균내는 것**이다.
그러면 둔덕 옆구리에서 한쪽 발만 경사에 닿아도 평균이 완만해져서, 상한에 기대지
않고도 자연스러워진다. 다리를 따로 움직이는 IK 는 못 해도 **회전 계산에만은**
"양발" 개념을 넣을 수 있다.

이번엔 안 넣었다 — 최대각 하나만 바꿔서 눈으로 판정할 수 있게 두는 편이 낫다.
8° 로도 어색하면 그때 넣을 것.

## 2-3. ★진짜 원인 (2026-08-25) — 부모의 비균등 스케일이 각도를 2.16배로 뻥튀기하고 있었다

8° 로 낮췄는데도 도형님이 같은 자리 스크린샷을 다시 보내주셨다. 사진의 기울기를 재보니
**약 17°** — 8° 상한으로는 나올 수 없는 각이었다. 그래서 실제로 측정했다.

### 측정 결과

```
Player.scale = (0.79496, 0.367719)   가로/세로 비 k = 2.162

코드가 넣는 각  →  화면에 보이는 각
     1.0 도  →     2.2 도   (2.16 배)
     5.0 도  →    10.7 도   (2.14 배)
     8.0 도  →    16.9 도   (2.11 배)   ← 사진과 정확히 일치
    22.0 도  →    41.1 도   (1.87 배)   ← 원래 기본값. 이게 마이클잭슨의 정체였다
```

### 왜 이런 일이

`CharacterSprite` 는 `Player` 의 **직속 자식**이고, Player 에는 스케일 `(0.795, 0.368)` 이
걸려 있다. 월드 변환이 `부모스케일 × 회전 × 자기스케일` 로 합성되므로, 회전이 부모의
비균등 스케일에 끼여서 **각도 자체가 커진다.**

```
화면각 = atan(k · tan(코드각)),   k = 부모.scale.x / 부모.scale.y = 2.162
```

`_기준_스케일_계산()` 이 자기 scale 로 부모 배율을 되돌리고는 있지만, **그건 회전 뒤에**
곱해지므로 각도에는 아무 영향이 없다.

> ★ **이 함정은 이 저장소에서 두 번째다.** `총_받침.gd`(GunRig) 가 총구 때문에 먼저 겪고
> 풀어놨고, 그 파일 주석에 경고까지 적혀 있다:
> *"Gun 에 직접 역스케일을 걸면 안 된다. 되돌리는 배율이 회전보다 **앞에** 와야 상쇄된다."*
> `player_anim.gd` 는 그걸 모르고 똑같이 빠졌다.

### 어떻게 고쳤나

`_화면각_보정()` 을 새로 만들어, 원하는 **화면 각도**가 나오도록 코드 각을 미리 줄인다.

```gdscript
코드각 = atan(tan(원하는_화면각) / k)
```

`_변형_적용()` 의 마지막 줄을 `rotation = _화면각_보정(_목표_회전)` 으로 바꾼 것이 전부다.

**이제 `지면정렬_최대각` 은 "화면에 보이는 각"을 뜻한다.** 8 이라고 쓰면 화면에서 8° 다.

검증:

```
원하는 화면각 → 보정된 코드각 → 실제 화면각    (직교성: 90도면 안 찌그러짐)
    1.0 도  →    0.5 도  →    1.0 도       89.2 도
    3.0 도  →    1.4 도  →    3.0 도       87.6 도
    5.0 도  →    2.3 도  →    5.0 도       86.1 도
    8.0 도  →    3.7 도  →    8.0 도       83.7 도
```

전단(찌그러짐)도 덤으로 줄었다 — 8° 에서 직교성 76.8° → **83.7°**.

### 왜 GunRig 처럼 중간 노드를 안 끼웠나

그게 구조적으로는 정답이고 전단까지 완전히 없앤다. 하지만 `CharacterSprite` 는 **이름으로
찾아 쓰는 곳이 많다** — `player.gd` 의 `_분할_시트_준비()`, 자식 `색겹침`,
`proto_motion.gd`, `player_shoot_anim.gd`, 검사 도구들. 부모를 바꾸면 그게 전부 깨진다.
각도만 미리 줄이면 씬을 안 건드리고 끝나므로 이쪽을 택했다.

남는 전단은 8° 언저리에서 눈에 안 띈다. 나중에 캐릭터를 리깅할 일이 생기면 그때 같이
중간 노드로 정리하는 게 맞다.

### 곁가지 — 걷기 그림 자체는 죄가 없었다

처음엔 `Walk.png` 가 기울어져 그려진 줄 알았다(사진 1 이 걷는 중, 사진 2 가 서 있는 중이라).
픽셀로 재보니 아니었다:

| 시트 | 프레임별 기울기 |
|---|---|
| `Idle.png` | -1.8° / -1.7° / -1.5° / -1.5° |
| `Walk.png` | +0.5° / -0.1° / +0.5° / +1.4° |

걷기가 오히려 더 수직이다. 그림은 멀쩡했고, 전부 코드의 각도 증폭 탓이었다.

## 4. 아직 못 한 것 — 양발을 각각 다른 높이에 붙이기

도형님 요청 중 "양발이 두 땅에 다 붙게" 는 **이번에 못 했다. 지금 구조로는 불가능하다.**

캐릭터가 뼈대 리그가 아니라 **완성된 그림 시트**다:

- `scenes/player/Player.tscn` → `CharacterSprite` 는 `AnimatedSprite2D` 한 장
- `assets/p/player_frames.tres` → 640×640 프레임, 흑/백 12개 애니메이션 총 148프레임

`Walk.png` 의 각 프레임은 두 다리가 **이미 그려진 완성 그림**이라, 왼발만 5px 내릴 방법이 없다.

하려면 IK(역운동학)가 필요하고, 그러려면:

1. 캐릭터를 부위별로 쪼개 다시 그려야 한다 (허벅지·종아리·발·몸통·팔)
2. `Skeleton2D` + `Bone2D` + `SkeletonModification2DTwoBoneIK` 로 리그를 짠다
3. ★**그리고 색분할 셰이더를 전부 다시 설계해야 한다** ← 여기가 진짜 위험
   `player.gd` 의 `_분할_시트_준비()` 는 `AnimatedSprite2D` **정확히 2장**에 셰이더를 건다.
   리그가 되면 `Polygon2D` 조각 10~15개마다 걸어야 하고, `몸_사각형()` 기반 사망 판정도
   같이 재설계해야 한다. **이 게임의 핵심 규칙(색 다르면 즉사)이 여기 걸려 있다.**

→ 별도 작업으로 잡을 것. 이번 수정과 섞지 말 것.

## 5. 다음에 더 손본다면 — 오르막 앞숙임

"걷는 중일 때만" 오르막 쪽으로 몸을 숙이는 항을 따로 더할 수 있다.

⚠ **부호가 지면정렬과 반대다.** 지면정렬은 몸을 내리막 쪽으로 눕히는데, 사람은
오르막 쪽으로 숙인다. 그래서 **서 있을 때는 꺼야** 두 항이 서로 상쇄되지 않는다.

- 서 있을 때 → 0 (곧게 섬)
- 걸을 때 → 오르막 쪽으로 숙임 (오르막이든 내리막이든 방향은 같다)

이번엔 일부러 안 넣었다. 두 개를 한꺼번에 넣으면 **어느 knob 이 무엇을 바꿨는지
눈으로 구분할 수 없어서** 튜닝이 불가능해진다. 반영률부터 눈에 맞춘 뒤 얹을 것.

## 6. 되돌리는 법

| 방법 | 명령 |
|---|---|
| **값만 되돌리기** (권장) | Inspector → `CharacterSprite` → `지면정렬_반영률` = **1.0** **그리고** `지면정렬_최대각` = **22.0** |
| 코드까지 완전 복구 | `git checkout -- scripts/player_anim.gd` |

⚠ 2차 수정 뒤로는 **두 값을 같이** 되돌려야 한다. 하나만 되돌리면 예전 동작이 안 나온다.

⚠ 3차 수정(`_화면각_보정`)은 **값으로는 못 되돌린다.** 코드에 들어간 함수라 완전 복구는
`git checkout` 뿐이다. 다만 되돌릴 이유는 없을 것이다 — 그건 "8° 라고 쓰면 화면에서 17°"
였던 **버그를 고친 것**이지 연출 취향이 아니다.
(굳이 끄고 싶으면 `_변형_적용()` 의 마지막 줄을 `rotation = _목표_회전` 으로 되돌리면 된다)

### 지뢰 — `proto_motion.gd` 와 공존 불가

`ProtoMotion` 은 `_physics_process` 에서 `_sprite.rotation = _lean` 으로 회전을
**통째로 덮어쓴다**(달리기 기울임 4.5° 뿐, 경사와 무관). `player_anim.gd` 는 `_process`
에서 쓰므로, 둘이 같이 붙으면 매 프레임 서로 밀어내고 경사 기울기는 사실상 사라진다.

지금은 `scripts/proto/stage_lab.gd`(프로토 랩)에서만 붙으므로 **스마트월드는 안전하다.**
스마트월드에 ProtoMotion 을 붙일 일이 생기면 둘 중 하나는 꺼야 한다.

작업 시작 시점의 HEAD 는 `79327ba` 였고, `player_anim.gd` 는 그 시점에 **수정 없는 깨끗한
상태**였다. 그래서 `git checkout` 한 방이면 원상복구된다.

⚠ 이 작업은 **커밋하지 않았다.** 작업 시작 전부터 남의 미커밋 변경 7개가 있었기 때문에

즉 **버그가 아니라 사각형 히트박스의 구조적 한계**다. 다만 이 캐릭터는 발이 유난히 좁아서

# 부록 C — 플레이어 몸 치수를 재는 자를 하나로 모았다 (2026-08-25)

> 도형님이 콜리전을 `CollisionShape2D`(사각형) → 캡슐 → **`CollisionPolygon2D`** 로 바꾸는
> 과정에서 **게임의 중심 규칙이 조용히 멈췄다.** 원인과 근본 수정을 적는다.

## C-1. 무슨 일이 났나 — 두 번 터졌다

### ① 캡슐로 바꿨을 때 — 검사가 **가짜로 통과**했다

`지형규칙.gd` 의 `플레이어에서_재기()` 는 `RectangleShape2D` 만 읽었다.
캡슐이면 그 `if` 를 건너뛰고 **위에서 채운 기본값(= 상수 44/97)을 그대로 반환**한다.
그 값을 다시 상수와 비교하니 **언제나 일치**한다.

```
실제 캡슐 폭 31.0px
측정 결과   44.0px      ← 상수를 그대로 돌려준 것
test_지형규칙  PASS      ← 44 == 44, 자기 자신과 비교
```

사각형일 때 2 개 실패하던 것이 오히려 정직한 신호였고, 캡슐로 바꾸자 조용해졌다.

### ② 폴리곤으로 바꿨을 때 — **사망 판정이 멈췄다**

`CollisionPolygon2D` 는 `CollisionShape2D` 가 **아니다**(형제 클래스지 하위가 아니다).
7 곳 전부 `get_node_or_null("CollisionShape2D")` 로 찾으므로 **노드조차 못 찾았다.**

```
WARNING: player: 콜리전을 못 찾음 → 몸 크기를 기본값(44×97)으로 쓴다
WARNING: 스마트월드: 플레이어 콜리전을 못 찾음 → 발밑 레이로 대체한다

test_사망판정  24 / 25
  FAIL  ★흰 벽에 몸이 닿은 검정 플레이어 = 죽는다
```

**"몸에 닿은 지형이 내 색과 다르면 즉사"** — 이 게임의 중심 규칙이 발밑 레이 하나로
퇴화했다. 몸이 반대색 벽에 닿아도 안 죽는다. 게임은 멀쩡히 돌아가므로 눈치채기 어렵다.

## C-2. 근본 원인 — 같은 코드가 7 곳에 복사돼 있었다

| 파일 | 무엇에 쓰나 |
|---|---|
| `scripts/player.gd` `_몸_실측()` | **사망 판정 기준** |
| `scripts/스마트월드/월드.gd` `_접촉모양_준비()` | 접촉 겹침 질의 |
| `scripts/스마트월드/지형규칙.gd` `플레이어에서_재기()` | 레벨 규칙 상수 검증 |
| `tools/레벨검사.gd` | 도달 가능성 게이트 |
| `tools/지형_진단.gd` | 끼임·발뜸 진단 |
| `tools/지형_보정.gd` | 디딤돌 놓기 |
| `tools/치수_보정.gd` | 치수 보정 |

전부 따로 구현돼 있어 아는 모양도 제각각이었다(어떤 곳은 사각형만, 어떤 곳은 캡슐까지).
그래서 모양을 바꿀 때마다 **어디가 깨졌는지 하나씩 찾아다녀야** 했다.

이 저장소가 이미 같은 처방을 내린 적이 있다 — `작업기록_2026-08-19` §5-3:
*"지금 두 파일에 복사돼 있는 것이 원인이다. **자가 하나가 되면** 고리가 닫힌다."*

## C-3. 수정 — `scripts/플레이어_몸.gd` 신규

```gdscript
플레이어몸.재기(플레이어) -> { "찾음": bool, "크기": Vector2, "중심오프셋": Vector2 }
```

- **노드**: `CollisionShape2D` · `CollisionPolygon2D` — **이름이 아니라 타입으로** 찾는다
- **모양**: `Rectangle` · `Capsule` · `Circle` · `ConvexPolygon`
- **개수**: 여러 개면 **전부의 합집합** 바운딩 박스
- 자식 노드 자신의 `position`·`scale` 까지 반영한다
- 못 재면 `찾음 = false` — **부르는 쪽이 반드시 확인**한다. 조용히 기본값으로 넘어가면
  이번 사고가 그대로 반복된다. 7 곳 모두 못 쟀을 때 경고를 찍게 고쳤다.

7 곳 전부 이 함수를 부르도록 바꿨다. **이제 여기만 고치면 7 곳이 따라온다.**

> ⚠ 새 `class_name` 은 **전역 클래스 캐시에 등록돼야 헤드리스에서 보인다.**
> 파일만 만들면 `Parse Error: Identifier "플레이어몸" not declared` 로 검사가 통째로 죽는다.
> `godot --headless --path . --import` 를 한 번 돌리면 `.godot/global_script_class_cache.cfg`
> 가 갱신된다. (에디터를 한 번 열었다 닫아도 된다)
