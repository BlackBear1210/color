## 1. 먼저 잰 것 — 플레이어 능력 실측 (`tools/측정_플레이어_능력.gd` 신규)

추정하지 않고 **물리 엔진 위에서 플레이어를 실제로 움직여** 이분 탐색으로 쟀다.

### ⚠ 스테이지가 `Player.tscn` 을 덮어쓴다

집 4방의 Player 인스턴스는 전부 **`점프_거리_칸 = 15`**(기본 10) 오버라이드가 걸려 있다.
그래서 중력이 5148 → **2288**, 체공이 0.42s → **0.63s** 로 조작감이 완전히 다르다.
**설계에 쓸 숫자는 집 챕터 쪽이다.**

| 항목 | 집 챕터(실사용) | Player.tscn 기본 |
|---|---:|---:|
| 콜리전 | **44 × 95.6** | 44 × 95.6 |
| 이동 속도 | **390** | 390 |
| 중력 / 점프속도 | **2288 / −855.7** | 5148 / −1283.5 |
| 최대 점프 높이 | **167.2** | 170.7 |
| 체공 | **0.63 s** | 0.42 s |
| 건널 수 있는 간격 | **256.8** | 174.3 |
| 오를 수 있는 단차 | **160.3** | 165.3 |
| 물리 최소 통로 높이 | **96.1** | 96.1 |

### 레벨검사기가 실제로 강제하는 게이트

```
세로 도달 = 160 × 0.80 = 128px      (실측 한계 160)
가로 건널 = 240 × 0.85 = 204px      (실측 한계 257)
치명 낙하 = 900px  (집 씬 오버라이드 · 기본 520)
```

→ **설계값은 전부 128 / 204 이하로 잡았다.** 실측 한계까지 20~25% 가 남아 실수 한 번에 안 죽는다.

### 측정하다 밟은 지뢰 두 개 (기록용)

1. **`JUMP_CUT_MULTIPLIER(0.4)` 함정** — `Input.action_press()` 는 헤드리스에서 **약 2 프레임 뒤**에야
   `is_action_just_pressed` 로 보인다. "아직 안 뛰었네" 하고 떼면 그 뗌이 *막 시작된 상승 중*에
   도착해 점프를 ×0.4 로 깎는다. 첫 측정이 **167px → 36px** 로 나온 원인.
   → **공중에 뜬 뒤 정점을 지난 뒤에만** 뗀다. (`test_집_체인.gd` 도 같은 규칙을 쓴다)
2. **"좌우 벽 사이를 걸어서 통과" 시험은 성립하지 않는다** — 지면에 붙은 두 벽 사이는 애초에
   걸어 들어갈 수 없다. 좁은 폭이 실제로 문제되는 곳은 *아래로 내려가는 구멍*이라 그쪽으로 바꿔 쟀다.

## 3. `집_복도계단` — 좌표와 근거 (`tools/build_집_복도계단.gd` 신규)

```
x −1940 … −1700   왼벽            (입구통로 y −170~0 비움)
x −1700 …   520   2층 바닥(윗면 0) · 중간에 −90 문지방 턱(폭 200)
x −1780 …  −200   복도 천장 (아랫면 −600 · 실효 552)
x  −200 …   520   좁은 통로 천장 (아랫면 −200 · **실효 152**)
x   520 …  1780   계단 7 단 (폭 180 × 높이 110) → y 0 → 770
x   520 …  1240   계단실 천장 (위 4 단만)
x  1780 …  3160   1층 바닥(윗면 770) · 천장 아랫면 −30 (**실내 800**)
x  3160 …  3400   오른벽            (출구통로 y 410~580 비움)
```

### 왜 이 숫자인가

| 값 | 근거 |
|---|---|
| 계단 **180 × 110** | README_지형찍기 §7 권장. 한 칸 90px 미만이면 코너 조각(90px)이 겹쳐 뭉갠다. 110 ≤ 게이트 128 이라 **되돌아 올라올 수도** 있다(소프트락 방지) |
| 층고 **770** | 계단 7 단 × 110 |
| 좁은 통로 **시각 200 → 실효 152** | ⚠ SS2D 콜리전은 `collision_size(24)` 만큼 바깥으로 부푼다 → 마주 보는 지형은 **시각에서 48 이 깎인다.** 몸 96 이라 머리 위 56 만 남는다 = 점프하면 반드시 천장에 박힌다 |
| 복도 **600** / 1층 홀 **800** | 방(692) 보다 복도가 낮고, 1층이 가장 넓다 → "아래층이 더 크다" 가 지형으로 성립 |
| 단차 전부 **90~110** | 게이트 128 의 70~86% |
| 가구 폭 전부 **≥300** | 코너 조각이 90px 씩이라 220 이하면 모서리가 검게 파인 것처럼 보인다 |

### 게이트(유령 발판) 산수

```
바닥 770 → 출구 선반 580 = 190px  >  점프 167   → 절대 못 넘는다
바닥 770 → 유령    660 = 110px    ✔  (칠해야 밟힌다)
유령 660 → 출구 선반 580 =  80px  ✔
탁자 550(오른끝 2500) → 출구 선반(2900) = 수평 400px > 건널 204  → 우회 불가
```

## 4. 배경 — **디자이너 원화만** 쓴다 (도형님 지시)

v1 은 `실내배경.gd` 의 코드 그림(웨인스코팅·문·벽등)을 썼다. 지시는 "배경을 우리가 만든 게 아니라
**작업자들이 만든 것**으로" 였다. 그런데 **복도·계단 원화는 없다**(원화는 room / livingroom /
kitchen / chimney 넉 장뿐). 그래서 있는 원화를 **좌표를 재서** 얹었다 — 한 번도 늘리지 않았다.

### ① 2층 복도·좁은 통로·계단 왼쪽 = `room.png` 왼쪽 880px 크롭 × 5 장

- 크롭 880×1200 → 패널 660×900 = **배율 정확히 0.75, 왜곡 0**
- 0.75 는 `집_2층방` 과 **같은 배율**이라 벽지·서까래 높이가 두 씬에서 이어진다
- ⚠ 크롭을 900 이상으로 잡으면 **침대 머리판**이 딸려 들어와 "복도에 침대가 있는" 그림이 된다
- `좌우반전` 을 번갈아 켜서 "문이 마주 보는 복도" 로 읽히게 했다

### ② 계단 오른쪽 + 1층 홀 = `livingroom.png` **한 장** (배율 0.9)

원화의 바닥선(py 963)과 천장선(py 64)이 이 스테이지의 1층 바닥(770)·천장(−30)에 오도록 역산:

```
배율 0.9  →  패널 1921.5 × 1080
패널 위쪽 y = 770 − 963 × 0.9 = −96.7
패널 왼쪽 x = 1240   (계단 4 단째부터)
→ 덮는 범위 x 1240 … 3161.5   ≈  1층 홀 오른끝(3160) 과 거의 정확히 일치
```

- 그래서 **빛도 원화의 진짜 광원에서 쏜다**: 창(월드 1789~2001) · 샹들리에(월드 2010)
- 계단 한가운데(x 1240~1600)에서 방 원화 → 거실 원화로 벽지가 바뀐다 = **"층이 바뀌었다" 신호**
- 앞바닥(전경) 띠는 원화 py **975**~1200 (바닥선 963 + 12px).
  ⚠ 905 로 잡았더니 띠가 바닥선보다 위에서 시작해 **플레이어를 통째로 가렸다**(머리만 보였다).

## 5. ★★ 찾아 고친 버그 — SS2D `_meshes` (프로젝트 전체에 걸려 있었다)

### 증상

`scenes/집/스마트 매쉬 assets/TEMPLATE_*.tscn` 을 인스턴스해서 점을 바꿔도 화면에는
**Template 원래 크기**(벽돌 420×242 / 나무 340×475)로 그려졌다.
콜리전과 레벨검사는 새 점을 쓰므로 **"보이는 것과 밟는 것이 다른"** 상태.
**집 4방(2층방·거실·부엌·굴뚝)의 바닥·천장·벽이 전부 이 상태**였고, 원화 전경이 앞을 가려서
여태 안 보였을 뿐이다.

### 원인 (세 겹)

1. `_meshes` 는 부모 `SS2D_Shape` 의 `@export_storage` 라 **저장 씬에 실린다.**
   Template 이 이미 구워 둔 메시가 인스턴스에 그대로 따라온다.
2. `force_update()` 는 `if not _first_update or not _meshes:` 일 때만 다시 굽는다.
   로드 직후는 `_first_update == true` 이고 `_meshes` 가 비어 있지 않으니 **안 굽는다.**
3. 빌더에서 비우려 해도 소용없다 —
   `set("_meshes", [])` 는 **타입 있는 배열**(`Array[SS2D_Mesh]`)에 타입 없는 `[]` 를 넣는 것이라
   조용히 무시되고, 타입을 맞춰 비워도 **빈 배열은 프로퍼티 기본값**이라 `PackedScene.pack()` 이
   저장하지 않아 로드 때 Template 값으로 되돌아간다.

### 고친 곳 — `scripts/스마트월드/지형.gd` `_ready()`

```gdscript
_meshes.clear()      # ← super() 앞에서
super()
```

점 배열은 인스턴스마다 제대로 저장되므로, 비워 두면 `super()` 안의 첫 `force_update()` 가
그 점으로 새로 굽는다. 에디터에서도 비운다 — **작업자가 Template 을 복제해 점을 끌었는데
크기가 안 변하는 그 함정**(README 작업자들이 실제로 겪은 것)이 같은 원인이기 때문이다.

### 확인

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 집_거실 바닥 (점 1700×300) | 메시 **420×242** ✖ | 메시 **1790×389** ✔ |
| 집_거실 벽_왼위 (점 240×724) | 메시 **420×242** ✖ | 메시 **330×814** ✔ |
| 복도계단 1층천장 (점 2340×300) | 메시 **310×500** ✖ | 메시 **2430×390** ✔ |

## 7. 경계 = 김동현(blackbear125) 작업자의 시스템 (도형님 지시)

```
scenes/경계/color_zone.gd     다각형 색 강제 구역        (2026-07-19 · blackbear125)
scripts/스마트월드/색경계.gd   몸을 경계선으로 잘라 판정   (2026-08-23 · BlackBear1210)
```

기존 집 4방은 `빛기둥(모드=경계)` 만 썼고 ColorZone 은 한 개도 안 썼다.
이번 두 스테이지는 **ColorZone 이 경계**이고, 빛기둥은 `모드 = 연출`(판정 없음)로 낮춰
같은 자리를 그림으로만 비춘다 → 두 경계가 면으로 겹치는 사고가 원천적으로 없다.

⚠ **`color_zone.tscn` 을 인스턴스하면 안 된다.** `PackedScene.pack()` 은 owner 가 패킹 루트인
노드의 값만 저장하므로, 인스턴스 내부 `CollisionPolygon2D` 에 꽂은 폴리곤이 통째로 버려지고
Template 기본 사각형(원점 384×256)만 남는다 → 두 구역이 **정확히 98304px² 겹친다**는 오류가 났다.
→ 다른 빌더들과 같은 방식(**새 노드에 스크립트 붙이기**)을 쓴다. 클래스는 그대로 ColorZone 이다.

### 반딧불이 = 경계를 읽는 눈

`발광체(종류 = 구슬)` 무리를 **ColorZone 안쪽 둘레**에 흩는다. 가운데 뭉치면 빛이 동그란
웅덩이가 되어 "여기부터 저기까지" 가 안 읽힌다. 둘레를 따라 놓으면 겹친 빛의 바깥선이 곧
구역의 모양이 된다. `show_tint` 는 **끈다** — 켜면 인게임에 흰 사각형 + 외곽선이 나와 디버그 상자로 보인다.

좁은 통로 → 1층 홀이 **2.3 배**. 이 대비가 "좁았다가 트인다" 를 만든다.
1층 홀은 **들어갈 때(1.25s)를 나올 때(1.0s)보다 길게** 둬서 계단을 내려오는 동안 화면이 천천히 열린다.
