## 1번: 내부 무늬

별도 SS2D/콜리전을 겹치지 않는다. 기존 흑백 텍스처 짝을 같은 UV로 합성하는 표면 장식이다. 새 그림을 늘리는 방식이 아니므로 기존 벽돌 질감과 줄눈을 그대로 쓴다.

`하수도_내부벽돌.gd`의 `내부_벽돌영역`은 지형 로컬 Rect2 배열(최대 16개)이다. 한 줄마다 줄눈에 맞춘 직사각형을 넣어 불규칙한 덩어리로 만든다. `내부_바탕흰색`은 재질 색과 반드시 일치시킨다. 무늬는 반대색이다.

중요: 시작상태=0, 무색일때_통과=false, 안칠한_바탕도_색이다=true를 유지한다. 0은 초기 페인트 시드를 넣지 않는 설정이다. 이 전용 스크립트는 기본_아트색()을 재정의하므로 검정/흰색 바탕의 접촉 판정은 유지된다. 시작상태를 1/2로 바꾸면 초기 전체 페인트가 장식을 덮는다.

무늬 합성 다음에 기존 페인트 시드를 적용하므로 양쪽 색으로 덮을 수 있고, 회수 후 무늬가 다시 드러난다. 장식은 별도 사망 판정이 없다. **무늬와 모든 실제 외곽선 사이에 최소 24px 이상 여유를 둔다.** 지형 점을 줄이거나 오목하게 바꾼 뒤 반드시 다시 확인한다. 외곽까지 이어지는 무늬는 2번 방식으로 전환한다.

에디터 미리보기는 `내부무늬_black/white.tres`의 inlay_rects/inlay_count를 사용하고, 실행 시에는 노드의 내부_벽돌영역을 사용한다. **수동 변경 시 두 데이터를 같이 갱신해야 한다.** 공유 재질을 직접 수정하지 말고 해당 배치 전용으로 복제한다. 현재 자동 인스펙터 동기화 기능은 없다.

## 2번: 실제 색 경계

각 모듈에는 독립된 SS2D 지형 3개가 있다. 검–흰–검 또는 흰–검–흰이며 중간 영역은 실제 지형이다. 각 노드의 기존 명중/회수/위치별 색 판정 경로를 그대로 사용한다.

- 양쪽 접합선은 하나를 생성해 역순으로 공유한다. 별개로 그려 빈틈이나 겹침을 만들지 않는다.
- 벽돌의 실제 줄눈에 맞춰 약 반 장~두 장 깊이가 불규칙하게 바뀐다. 지퍼처럼 반 장씩 같은 패턴을 반복하지 않는다.
- 가로 경계도 같은 원칙이다. 세로 모듈을 90도 돌려 벽돌을 세워서 대체하지 않는다.
- 세 노드의 로컬 원점을 같게 유지한다. 이동은 모듈 부모를 움직인다. 자식 하나만 이동하면 접합선과 UV가 깨진다.
- Scale=(1,1) 유지. 크기 변경은 SS2D 점과 양쪽 공유선을 함께 편집한다. 텍스처를 늘려 맞추지 않는다.
- 내부 접합에는 윗면·옆면 마감을 넣지 않는다. 기존 마감 캐시의 이웃 가림을 이용한다. 세 노드는 같은 부모 아래에 둔다.
- 다른 지형과 연결할 때 모듈의 부모가 다르면 자동 이웃 가림이 작동하지 않을 수 있다. 최종 지형과 같은 부모에 배치하고 월드 좌표/UV 기준을 함께 보존해야 한다. 연결부를 눈으로 확인한다.
- 장식용 Sprite나 회색 그라데이션으로 접촉색 경계를 가리지 않는다.

## 검수와 성능

생성 도구 `tools/create_sewer_color_modules.py`는 이 신규 6종/전용 재질/비교 씬만 쓴다. 실행하면 해당 파일의 수동 편집은 덮이므로, 편집한 모듈에는 재실행하지 않는다. 기존 스테이지를 재생성하지 않는다.

정적 검사: 2번 가로/세로 영역 합계 18,644점에서 지형이 정확히 하나씩 존재함을 확인했다. 실제 Godot 파싱/렌더/물리 검사를 대신하지 않는다.

Godot 실행 허가 후 확인할 항목:
1. 비교 씬에서 여섯 조합의 줄눈·경계·내부 마감이 맞는지 확인한다.
2. 실제 플레이 시험 씬에 넣어 두 색의 명중, 페인트 회수, 초기화 후 복원을 확인한다.
3. 1번 내부 무늬가 외곽으로 노출되지 않았는지 확인한다. 바탕과 반대색 플레이어의 실제 외곽 접촉 사망도 확인한다.
4. 2번 두 색과 중간 영역 각각에 총을 쏘고, 칠한 접촉면과 사망 판정이 일치하는지 확인한다.
5. 접합선을 걸을 때 틈에 빠짐·걸림·이중 충돌이 없는지 확인한다.
6. 마감 캐시가 정지 중 계속 재생성되지 않는지, 배치 수를 늘렸을 때 프레임 시간이 어떻게 바뀌는지 측정한다.

현재 상태: 코드/씬 생성 및 정적 검사 완료. Godot 실행·플레이·실제 FPS 검증은 미실행.
