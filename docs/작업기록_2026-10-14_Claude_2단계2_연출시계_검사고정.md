## 1. 게임 코드

- 새 파일 **`scripts/스마트월드/연출시계.gd`** (`class_name 연출시계`)
  - `연출시계.밀리초()` = 예전 `Time.get_ticks_msec()` 그대로(int)
  - `연출시계.초()` = 예전 식 `fmod(float(밀리초) × 0.001, 3600)` 그대로
  - 시험 전용 `프레임_시계`(기본 false)·`프레임_기준` — 켜면 "씬을 띄운 뒤 프레임 수 ÷ 60" 으로 센다. **게임 코드는 켜지 않는다.**
- 실제 시계를 직접 읽던 **F5 3 곳**을 바꿈(계산식 동일 · 이유 주석 한 줄씩):

| 파일 | 예전 | 지금 |
|---|---|---|
| `흰물_디자인.gd` (물줄기 anim_time) | `fmod(float(Time.get_ticks_msec()) * 0.001, 3600.0)` | `연출시계.초()` |
| `하수도_자연발판.gd` (유령 일렁임 anim_time) | 같음 | `연출시계.초()` |
| `양동이.gd` (물 받을 때 출렁임) | `sin(Time.get_ticks_msec() * 0.018)` | `sin(연출시계.밀리초() * 0.018)` |

- 안 바꾼 것: `떨어지는블록`·`무너지는발판`(F5 에서 안 닿음) · `실행_기록.gd` 의 완료 날짜(연출 아님).
- 셰이더의 `TIME` 9 곳은 전부 "쓰지 말 것" 주석이었다 — 실제로 쓰는 곳 0.

**검토**: 눈 검토(3 곳) + 전후비교 전체(옛 기준과) → 로드·오류 줄·검사·경로 재생(260/0) 같음 · 화면은 옛 로비 1 장만 다름 →
버튼 글자는 같고 **버튼 강조(마우스 올림)만 달랐다** = 검사 창 위에 실제 커서가 있었던 것(아래 2).

## 2. 전후비교 화면을 완전히 고정 (`tools/전후비교/화면촬영.gd`)

찍을 때마다 달라지던 원인 둘:
1. **물결 시계** → 촬영 때 `연출시계.프레임_시계 = true` · 씬마다 `프레임_기준` = 지금 프레임(앞 씬이 몇 프레임을 썼든 0 초에서 시작).
2. **마우스** — 얼굴 방향(`player.gd:326`)·총 조준(`gun.gd`)·버튼 강조가 **OS 실제 커서**를 읽는다.
   Godot 메인 창은 `get_global_mouse_position()` 이 OS 커서를 직접 읽어서 가짜 입력으로는 못 바꾼다(실험으로 확인).
   - SubViewport 안에 띄우면 커서와 떨어지지만(실험: 커서를 옮겨도 그대로) `current_scene` 을 못 정해서(루트 자식만 가능)
     창문빛 위치 맞추기·총알 붙이기 등 **29 곳이 실제 게임과 다르게** 돈다 → 버림.
   - → 촬영하는 동안 매 프레임 `Input.warp_mouse(1500, 400)`. **⚠ 화면 단계(약 4 분) 동안 마우스가 게임 창 안에 묶인다**(실행기가 안내 문구를 찍는다).

**결과: 흔들림 마스크 3 번 표본 95 장 → 1 번 표본 0 장.** 화면 489 장이 두 번 찍어도 픽셀 하나 안 다르다.
→ 이제 물 영역도 1 픽셀 단위로 비교된다(마스크·300 픽셀 "참고" 규칙은 남겨 둠 — 다시 흔들리는 게 생기면 잡으려고).
기준을 이 도구로 새로 찍음(`기준` 전체 · 29 분 · 경로 재생 260/0 그대로).
