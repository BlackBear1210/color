## ① 올리는 순서 (이대로만 하면 충돌 안 남)

GitHub Desktop 에서:
1. **Fetch origin** → 원격에 새 커밋이 있는지 본다.
2. 있으면 **Pull origin** 먼저. (여기서 충돌이 나면 파일 단위로 해결 — 규약 8)
   - ★내 작업을 커밋하기 **전에** 당겨야 충돌이 작고 명확하다. 커밋 후 당기면 머지가 커진다.
3. 충돌 없거나 해결했으면 → 아래 ②의 변경들을 **커밋** → **Push**.

> 충돌(conflict)은 "원격과 내가 같은 줄을 동시에 고쳤을 때"만 난다. 먼저 Pull 로 원격을
> 받아 두면, 올릴 때 새로 충돌 날 일이 없다. 이 저장소는 지금 로컬이 원격보다 앞서 있지 않다
> (마지막 fetch 기준) → **Pull 만 잘 하면 깨끗하게 올라간다.**

## ⑤ 참고 — "왜 충돌이 잘 나나 / 앞으로 덜 나게"
- .tscn/.tres 는 텍스트지만 노드 id·순서가 조금만 달라도 줄이 많이 바뀐다 → 두 사람이 **같은
  씬**을 동시에 편집하면 충돌이 크다. 씬은 **사람마다 다른 파일**을 맡거나, 편집 전 Pull 하는 습관.
- 이번처럼 **인스턴스 원본 씬(장애물·템플릿)을 옮기면** 참조하는 모든 씬이 바뀌어 diff 가 커진다.
  옮긴 뒤엔 반드시 한 번에 같이 커밋(중간 상태로 올리면 남이 Pull 할 때 깨짐).
