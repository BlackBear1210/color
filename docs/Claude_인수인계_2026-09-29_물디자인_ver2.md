## 1. 지금 무엇을 하는가

2D 흑백 퍼즐 플랫폼 게임의 world_2_클로드 스테이지에 사용자가 승인한 시각 시안을 구현하는 작업이다. 기준 스테이지는 stage_2-9.tscn이다.

현재 최우선은 **떨어지는 물줄기(유체)의 디자인 품질 개선**이다. 사용자는 생성 시안의 물을 원한다. 기존 구현을 반복해서 보고 ‘평면적이다, 종이를 잘라 붙인 것 같다’고 지적했다. 단순히 셰이더가 연결됐다는 사실이나 기능 검사 통과를 디자인 완료로 보고하면 안 된다.

마지막 작업에서 검정·흰색·회색 낙수의 균일한 평행선을 제거하고 여러 크기의 물살 명암, 국소 반사, 가장자리 두께감을 넣었다. 실제2-9 캡처를 보여줬지만 **사용자가 최신 결과를 승인한 상태는 아니다.** 사용자는 토큰 소진으로 Claude에 이어서 작업하도록 인수인계를 요청했다.

**6단계 화면 효과 확인은 사용자의 지시에 따라 보류 중이다. 물 디자인을 먼저 맞춘 후 돌아간다.**

## 2. 사용자 요구와 시각 기준

### 물줄기
- 검정: 검정 본체에 불규칙하고 절제된 은빛 반사. 검정색 식별이 명확해야 한다.
- 흰색: 밝고 밀도 있는 물. 균일한 흰 종이 띠가 아니라 물살 내부의 작은 명암/흐름이 보여야 한다.
- 회색: 뒤 벽이 비치는 굴절/투과와 물살 반사. 불투명 회색 관처럼 보이면 안 된다.
- 일정 간격의 가는 선만 그려 놓은 모습은 사용자가 거절했다.
- 낙수 접점은 물보라/거품으로 자연스럽게 연결돼야 한다.
- **흰 물이 공중으로 튀는 물방울은 흰색이다.** ‘흰 거품을 본체보다 어둡게’라는 예전 기준을 모든 물보라에 적용하면 안 된다. 어두운 회색은 수면에 겹치는 얇은 잔물결/접촉 음영에만 제한한다.

### 호퍼와 웅덩이 — 유지할 규칙
- 호퍼 출구는 평면 노즐. 둥근 검정 내부가 보이면 안 된다.
- 출구 물 폭은 호퍼 폭×0.2. 현재2-9 폭320 호퍼의 실제 출구 물 폭64.
- 호퍼가 실행 중 출구 폭을 덮어쓴다. 외관을 넓히려고 출구_물줄기_폭 값을 임의로 올리지 않는다.
- 물 윗끝은 출구_포트에 붙고 아랫끝은 바닥 윗면에 맞춘다.
- 호퍼 입구 물은 검정만 공급되면 검정, 흰색만이면 흰색, 둘 다 공급되면 회색.
- 웅덩이는 다리 높이의 얕은 수심32px를 유지한다. 참고 시안의 깊은 수조를 그대로 만들겠다고 지형/판정을 바꾸지 않는다.
- 검정 웅덩이는 짙은 본체+은빛 수면 반사, 흰색은 불투명한 유백색, 회색은 뒤 벽돌과 다리가 비치는 반투명.

### ver.2 화면 효과
극소적인 빛 번짐 / 입수 순간 하단 물방울 / 느린 전경 파티클 / 미세한 필름 입자 / 약한 비네트.
입수 물방울은 작고 불규칙한3~5개, 하단 가장자리에 잠깐 튀고0.3~0.5초 내 소멸. 큰 비눗방울을 상시 표시하지 않는다.
고정 벽등은 플레이어를 따라 움직이지 않는다. 플레이어가 빛 안을 지날 때 명암/그림자가 변하는 것이 목표다.

## 7. 다음에 할 일 — 우선순위

1. **최신 실제 물 캡처와 사용자 시안을 직접 비교한다.** 최신 결과는 미승인이다. 사용자의 추가 피드백이 있으면 물줄기부터 반영한다.
2. 아직 부족하다면 균일한 띠/반복선이 남는지, 흰색 명암이 과도하게 번지는지, 검정의 반사가 충분한지, 회색이 유령/비닐처럼 보이는지 조정한다. 새 생성 시안만 보여주고 끝내지 않는다.
3. 검정·흰색·회색을 각각 같은 카메라에서 실제 실행으로 확인한다. 가능하면 움직이는 물살과 낙수 접점도 시간에 따라 관찰한다. 현재는 정지 캡처와 기능 검사가 중심이다.
4. 물 디자인이 정리된 뒤에만 보류된6단계 화면 효과를 사용자와 확인한다. 이미 코드는 있으므로 중복 구현하지 않는다.
5. 기준2-9가 안정된 뒤 나머지10개 스테이지를 실제 화면에서 검증한다. 낙수/화면효과는 공통 연결됐지만 모든 스테이지의 시각 품질까지 검증된 것은 아니다. 개선 웅덩이/실시간 벽등은2-9 전용 부분이 있으므로 무조건 전 스테이지 완료라고 말하지 않는다.
6. 필요하면 이후 성능 확인 및 전체 시각 마감. 사용자 승인을 받기 전 단계 번호만 올리지 않는다.
