# 작업기록 — 2026-10-08 Codex 실행 초기화 오류 진단

## 요청과 결론
사용자 요청: 공유한 Godot/Codex 오류 해결 정보를 바탕으로 직접 해결 시도.
현재 재현되는 실패는 Godot 실행 전의 Codex Windows 샌드박스 초기화 오류다. 기본 실행은 실패하지만 승인 검토를 거친 개별 명령 실행은 성공하여 프로젝트 파일 확인과 git pull을 수행했다. 이는 임시 작업 경로 확보이며 기본 실행의 영구 복구는 아니다.

- 기존 사망판정 검사 로그의 실패 4개는 2026-09-14 기록으로, 이번 오류의 증거로 사용하지 않음.

## 남은 복구
살아 있는 Codex 보조 프로세스들이 실행 파일을 사용 중이므로 Codex 완전 종료와 재실행 후 기본 실행을 다시 검증해야 한다. 다른 채팅의 도구 상태를 임의로 종료하거나 앱을 강제 재시작하지 않았다. 재시작 후에도 오류가 유지되면 최신 .sandbox 로그를 기준으로 추가 진단한다.

공식 문서는 elevated 초기화 실패 시 unelevated 대체 방식을 안내하지만, 이 방식은 네트워크 격리가 더 약하므로 이번 작업에서는 보안 설정을 변경하지 않았다.

## 후속 복구 — 앱 재시작 후
- 사용자 앱 재시작 후에도 동일 오류를 재현했다. 보조 프로세스 생성 시각으로 재시작이 실제로 이루어졌음을 확인했다.
- node_repl.exe 보조 프로세스를 정지하자 초기화는 다음 DLL까지 진행했다.
- 화면 제어 서비스의 VCRUNTIME140_1.dll 잠금을 확인했다. 이 서비스는 앱이 자동 재실행하므로 한시적인 잠금 해제 처리가 필요했다.
- 마지막 node.exe 잠금은 부모 실행 명령을 통해 Codex 앱 도구 MCP와 코드 검토 MCP임을 확인하고 해당 보조 서버만 정지했다.
- 화면 제어 서비스만 정확한 경로로 45초 동안 정리하는 임시 프로세스를 실행했다. 보안 설정, 권한 규칙, 설정 파일은 변경하지 않았다. 샌드박스 자체가 정상 권한 초기화를 수행했다.
- 이후 기본 실행으로 Get-Location이 종료 코드 0으로 성공했다. 이전에 필요했던 개별 명령의 샌드박스 밖 실행 없이도 프로젝트 파일 읽기와 git diff --check가 성공했다.
- 샌드박스 보호 영역인 setup_marker.json 읽기는 정상적으로 접근 거부되었다. 작업 폴더 이외 권한을 확대하지 않았다는 점을 확인했다.
- 현재 작업 폴더의 기본 실행은 복구됐지만 다른 프로젝트, 다음 앱 재시작, Godot 엔진 실행의 안정성까지 보장하는 결과는 아니다.
- Godot은 이번에도 실행하지 않았다.
- 한시적 잠금 해제 프로세스 종료 후에도 기본 명령 실행을 다시 확인했다. 제한된 샌드박스의 Win32_Process 조회는 접근 거부되어 일반 프로세스 목록으로 확인했다.
- 앱 도구 MCP 연결 검사는 Transport closed로 실패했다. 복구 과정에서 정지한 MCP 보조 서버는 앱을 다시 열어 재연결해야 한다.

- 현재 대화에서 기본 명령을 다시 실행했지만 여전히 기존 helper_unknown_error가 발생했다. 실행 중인 대화에는 이전 실행 환경이 유지되는 것으로 보이며, 변경 후 Codex 완전 종료 및 재실행이 필요하다.
