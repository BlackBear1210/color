# 2026-10-10 · Codex · 하수도 지도 입구와 소리 설정

## 요청과 확인

world_2_클로드가 로비의 챕터1처럼 연결됐는지 확인하고, 약 10개 이후에도 맵을 늘릴 수 있도록 보완했다. 전체 소리·배경음악·효과음 설정을 로비와 인게임에 추가했다.

작업 시작 시 `git pull --ff-only` 결과 Already up to date. 기존 하수도 씬·총·몬스터·효과음 관련 미커밋 변경을 보존했다. 커밋·푸시는 하지 않았다.

기존 연결은 이미 있었다. `scenes/lobby/쳅터2_지도.tscn` → `scripts/진행/하수도_지도.gd` → 집과 같은 `scripts/ui/퍼즐보드.gd`·사진카드. 기존 맵은 stage_2-1~stage_2-11, 총 11개다. 새 타이틀의 스테이지 버튼은 집 지도부터 열었고 챕터2 진입은 집 지도 마지막 마디 또는 F12 개발 로비를 거쳤다.

## 바뀐 동작

- 새 로비에서 **스테이지 → 챕터 1 · 집 / 챕터 2 · 하수도**를 바로 고른다. 각 맵의 선행 클리어 해금 규칙은 유지한다.
- 2-9·2-10 출구가 예전 개발 로비를 향하던 부분은 진행 계층에서 다음 맵으로 연결했다. 2-1부터 2-11까지 순차 진행하고 현재 마지막 출구는 새 타이틀로 간다. 하수도 씬 파일의 지형·통로 배치는 이번 작업에서 수정하지 않았다.
- `게임진행.하수도_칸들()`은 기존 갈림길 표를 유지하며 이후 `stage_2-N.tscn`을 숫자순으로 자동 추가한다. 내보낸 리소스의 `.remap`도 인식한다. 맵 수 제한은 없다. 기존 표에 없는 맵은 앞 번호 다음에 이어지고 오른쪽에 세 칸씩 배치된다.
- 챕터2 사진 지도 본문은 가로 스크롤이 가능하다. 제목·선택 정보·뒤로 버튼은 고정되며 방향키 포커스도 선택 카드를 화면 안에 보여 준다.
- 마지막 씬의 출구가 옛 로비 또는 새 타이틀로 향해 있어도 다음 맵이 생기면 자동으로 그 맵에 이어진다. 별도 목적지가 지정된 갈림길은 해당 목적지를 따른다. 전경전환은 입구통로가 있을 때 그 입구를 사용하고, 없으면 기존 시작 위치를 사용한다. 현재 2-10에는 입구통로가 없어 기본 시작 위치로 들어간다.

## 이미지

이미 집과 동일한 물감 바탕·사진 틀·실·기록·도장 UI에 연결돼 있어 생성형 이미지는 새로 만들지 않았다. 사진은 기존 `스테이지_스냅.gd`가 **실제 플레이 화면**을 찍고 클리어 시 `user://스냅/stage_2-N.png`에 저장한다. 미클리어 칸과 아직 캡처가 없는 칸은 빈 사진이다. 새 맵도 같은 경로로 자동 연결된다.

이번에 확보한 새 실제 엔진 전후 PNG는 **없다**. 새 챕터 선택 창·하수도 스크롤은 **수정 완료·시각 검증 대기**이며 생성형 이미지나 정적 검사로 실제 게임 화면이 검증됐다고 판단하지 않는다.

## 소리 설정

`scripts/ui/소리설정.gd`가 세 볼륨 행을 공통으로 만든다. 새 타이틀 설정, F12 개발 로비 설정, 인게임 Esc → 설정에서 동일하게 사용한다. 0~100%, 1% 단위, 현재 퍼센트 표시, 즉시 반영·저장, 0% 음소거와 다시 올릴 때 음소거 해제를 지원한다.

설정은 기존 `user://settings.cfg`의 `[audio] master`를 그대로 사용하고 `bgm`, `sfx`를 추가한다. 설정 저장 전에 파일을 읽어 전체화면과 다른 볼륨 값을 보존한다. 기존 개발 로비가 숨긴 옛 master 슬라이더 값을 저장하면서 새 설정을 덮어쓰지 않도록 수정했다.

`default_bus_layout.tres`에 BGM·SFX 버스를 추가하고 둘 다 Master로 보낸다. 전체 소리는 두 종류에 함께 곱해진다. 각 재생기의 기존 음량·거리 감쇠·전환 페이드는 유지한다.

| 분류 | 연결 |
|---|---|
| 배경음악 BGM | 타이틀 음악, 챕터 합성 드론, 실제 챕터 음원 |
| 효과음 SFX | 플레이어 걷기·점프·착지·사망, 페인트/몬스터 발사·명중·발걸음, 하수도 입수·물 발소리·물줄기 |

로비뿐 아니라 재생기 생성과 일시정지 메뉴 준비에서도 초기 설정을 읽어 F6로 스테이지를 직접 열 때도 저장한 소리가 적용되게 했다.

## 새 맵 추가 방법

1. `scenes/world_2_클로드/stage_2-12.tscn`처럼 다음 번호로 실제 씬을 만든다. 번호를 문자열이 아닌 숫자로 정렬한다.
2. 출구통로에 다음 목적지를 명시하거나 로비 목적지를 둔다. 로비 목적지면 뒤 맵이 생길 때 자동 연결된다. 걷기 입장을 원하면 입구통로 노드를 둔다.
3. 새 게임 실행 시 목록·선행 해금·기록·사진 경로·지도 크기가 자동 확장된다. 이름을 별도로 붙이려면 `게임진행.gd`의 `하수도_이름`에 추가한다. 원하는 갈림길·위치는 `하수도_지도` 표에 추가한다.
4. 실제 게임에서 통로 진입·복귀·클리어 기록과 캡처를 확인한다. 자동 등록이 씬 자체의 플레이 가능성을 검증하지는 않는다.

## 검사와 제한

- `docs/다음작업_프롬프트.md`가 없어서 원본 13개 검사 명령·지뢰밭 본문을 읽지 못했다. 사용자 규약대로 Godot·헤드리스·빌더는 실행하지 않았다.
- 작업 전 13개 정적 점검을 시도한 임시 스크립트는 Python 괄호 오류로 실행되지 않았다. 따라서 작업 전 13개 통과로 보고하지 않는다. 초기 Git 상태·지도·씬·설정 구조는 읽기 작업으로 확인했다.
- `python tools/검사_로비소리_정적.py --parser-path tmp/lobby_audio_validation`: **13개 정적 계약 통과**. 집 지도, 하수도 등록·해금 도달, 실제 출구의 정적 이동 모델, 모든 오디오 재생기의 버스 지정, 설정 보존, 캡처 계약, 리소스 경로, 문법, 삭제 목록을 검사한다. 결과는 `docs/visual_review/로비소리_20261010/정적_검사.json`.
- gdtoolkit으로 수정 GDScript 13개 파싱. 개발 로비의 기존 일반 따옴표 다중행 셰이더는 파서 제한 때문에 메모리에서만 삼중 따옴표로 바꿔 확인했다. 파일 원본은 보존했다. Godot 타입 검사·렌더링 성공을 의미하지 않는다.
- Git 파일 삭제 없음. 기존 사용자 작업 전체 diff를 이번 작업으로 간주하지 않는다.
- `graphify query`로 먼저 관련 구조를 조회했다. `graphify update .`도 실행했으나 34,472개 기존 노드 대비 AST 결과 14,681개라 축소 방지 장치가 graph.json 덮어쓰기를 거부했다. 강제로 축소하지 않았다. 엔진이나 외부 API는 실행하지 않았다.
- 실행 허용 질문을 전달했지만 아직 답이 없어 실제 화면·클릭·타입 검사·청취·설정 재실행 검증은 **대기**다.

실행 허용 뒤 확인할 사항: 로비 챕터 선택, 챕터2 모든 카드와 작은 해상도/스크롤, 2-9→2-10→2-11 이동과 되돌아오기, 사진 클리어 저장, 세 볼륨 독립 조절·0%/복구, 일시정지 중 조작, 로비 왕복과 게임 재실행 뒤 값 유지.
