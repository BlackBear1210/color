## 2. 원인 1 — 에디터가 GPU 를 계속 쓴다

- Windows 성능 카운터: 에디터(PID 20764, `stage_2-5.tscn` 열림, 조작 없음) **3D 엔진 41%**.
- Godot 는 `TIME` 을 읽는 셰이더가 화면에 있으면 에디터 뷰포트를 매 프레임 다시 그린다. 하수도 물 셰이더 5 종이 전부 `TIME` 을 읽었다
  (`animate` 가 꺼져 있어도 코드에 `TIME` 이 있으면 똑같다).
- @tool `_process` 에서 매 프레임 `queue_redraw()` 하던 곳: `연결통로.gd`(모든 하수도 씬에 있음) · `움직이는발판.gd`(에디터에서만 일부러) · `페인트분사기.gd`(동일) · `유체.gd`.

**고친 것**
- 셰이더 5 종(`sewer_pool_29` · `sewer_pool_shallow` · `white_water_modular_v2` · `water_stream_reference` · `water_stream_v3`):
  `TIME` → `uniform float anim_time`. 값은 `흰물_디자인.gd._process` 가 **게임 중에만** `Time.get_ticks_msec()` 기준(3600 초 되돌림 = TIME 과 같은 시계)으로 넣는다.
  → 게임에서는 예전과 똑같이 흐르고, **에디터에서는 물이 멈춰 보인다**(의도).
  `white_water_modular.gdshader`(v1)는 어디서도 안 써서 그대로 둠.
- 새 도우미 `scripts/스마트월드/에디터_다시그리기.gd` — 인스펙터 값 + 변환의 해시. 위 4 스크립트는 에디터에서 **값이 바뀐 프레임에만** 다시 그린다.
  연결통로의 맥동·유체의 흐름은 에디터에서 멈춘다.

## 3. 원인 2 — 2-9 스크립트 스파이크

사슬: `압력버튼._대상_이동()` 이 `대상.position = move_toward(...)` 를 **도착한 뒤에도** 매 틱 대입 →
Godot 는 같은 값이어도 `NOTIFICATION_TRANSFORM_CHANGED` 를 보냄 → `하수도_자연발판._notification` 이 `마감_배치변경` 신호 →
형제 지형 **27 개 전부**가 `_접합_갱신()`(이웃 26 개의 점을 전부 변환 + 해시, 한 바퀴 ≈10ms). 호출 스택으로 확인(임시 추적, 원복함).

**고친 것**
- `압력버튼.gd` — 새 위치가 지금과 같으면 대입하지 않는다.
- `하수도_자연발판.gd`
  - `_notification`: `global_transform` 이 **실제로 바뀐 때만** 반응(어떤 스크립트가 같은 값을 다시 넣어도 무시).
  - `마감_배치변경(보낸이)` 로 신호에 보낸 지형을 싣고, 받는 쪽 `_이웃_배치변경` 은 보낸이의 **지금/옮기기 전 월드 경계**가
    내 경계 + 24px(배율 반영) 에 닿을 때만 재계산. 경계는 `월드경계()` 로 캐시.
  - `_접합_갱신` 도 이웃 점을 변환하기 전에 캐시 경계로 먼저 거른다(기존 bounds.grow(24) 와 같은 기준이라 결과 동일).

## 4. 원인 3 — 2-9 로드 3 초

- `instantiate()` 만 3,095ms(준비·첫 프레임은 0.1 초). 지형 묶음을 빼면 1.8ms, 지형 하나당 64~188ms. 속성 setter 는 0ms.
- 정체: `[node name="@ColorRect@19684" parent="지형/G_천장" index="0"]` + `metadata/__ss2d_click_rect__ = true` 블록 27 개.
  SS2D `_setup_click_rect()` 가 에디터에서만 만드는 클릭 영역인데, 지형이 `[editable path=...]` 인스턴스라 에디터 저장 때 덮어쓰기로 남았다(HEAD 커밋에도 27 개).
  게임에선 노드가 없어 `WARNING: ... modified from inside an instance, but it has vanished` 가 하나씩 나오고 그게 느리다.
- 제거본 instantiate **10ms**. 2-2(9 개) · 2-3(10 개)에도 있었다.

## 8. 앞으로 프레임 드랍을 막는 규칙 (재발 방지)

1. **셰이더에 `TIME` 금지(하수도·물·장식 전부).** 움직임이 필요하면 `uniform float anim_time` 을 두고 스크립트가 게임 중에만 넣는다(`흰물_디자인.gd` 가 본보기).
   검사: `G -s res://tools/진단_에디터_계속그리기.gd` → 전 스테이지 "쉼 ✔".
2. **@tool 스크립트의 `_process` 에서 조건 없이 `queue_redraw()` 금지.** 에디터 분기는 `에디터_다시그리기.서명(self)` 이 바뀐 때만.
3. **같은 값을 `position`/`rotation`/`scale` 에 다시 넣지 말 것.** 같은 값이어도 변환 알림이 가고, 그걸 듣는 쪽(하수도 지형 마감)이 일을 한다.
4. **"형제 전부에게 알림" 구조 금지.** 알림은 경계가 닿는 이웃에게만(`_이웃_배치변경` 이 본보기). n 이 27 이면 n² 가 700 이다.
5. **에디터에서 씬을 저장한 뒤** `python tools/정리_SS2D_클릭사각형_흔적.py` — 종료코드 1 이면 `--적용`. (지형을 `[editable]` 로 두는 한 저장 때마다 다시 생길 수 있다.)
6. 새 스테이지·장치를 넣으면 창 모드로 `G -s res://tools/측정_하수도_프레임.gd -- <씬> --칸=60` 을 돌려
   **16.7ms 초과 0 · 스크립트 최대 < 5ms · 로드 < 300ms** 를 확인한다. 스파이크는 SPIKE 줄이 GPU/스크립트/기타 중 어디인지 말해 준다.
7. 성능 측정은 **에디터를 끄고**(또는 에디터 GPU 사용량 확인 후) 한다. 에디터가 켜진 채 잰 값은 2~3 배까지 흔들린다(이번 첫 측정 30ms vs 두 번째 9.6ms).
8. (권고 · 미적용) `project.godot` 의 `window/vsync/vsync_mode=0` 은 9-25 Codex 측정 때 넣은 미커밋 값이다. 모니터가 60Hz 라
   VSync 를 켜면 GPU 가 프레임 사이 쉬어 발열·다른 프로그램과의 경쟁이 줄고 찢어짐이 없어진다. 끄고 싶다면 물리 60Hz 와 화면 프레임이 어긋나
   움직임이 떨려 보이지 않게 `physics/common/physics_interpolation` 을 켜는 것을 권한다. 도형님 결정 사항이라 건드리지 않았다.
9. (권고 · 미적용) GPU 는 1080p 에서 평소 8~9ms(예산의 절반). 지형 메시 3.3ms 의 정체(§6)를 밝히면 여유가 더 생긴다 —
   후보는 텍스처 밉맵/크기(`sewer_masonry_v02/*/fill.png` 1536×1024) · `내부벽돌`(2 개에 1.5ms) · `그림` 스프라이트(1ms).
