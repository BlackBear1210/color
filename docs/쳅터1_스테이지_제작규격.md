## 2. 설계 규칙 (편하게 되는 값 · 괄호 = 한계)

| 규칙 | 칸 | 왜 |
|---|---|---|
| 한 번에 오르기 | 4 (5) | 5칸은 정점에서 딱 닿는다 — 실수 여지가 없다 |
| 같은 높이 틈 | 처음 6 · 최대 8 (9) | 10칸은 픽셀 단위로 맞아야 한다 |

| 발판 두께 · 최소 폭 | 2 · 4 | 1칸 판은 데크 윗면(28.8px)만 보여 납작하다 |
| **머리 위 여유** | 점프하는 판 위로 8칸 | 정점 5 + 몸 3. 6칸이면 출발하자마자 머리를 박는다 |
| 검정판 ↔ 흰판 | 사이에 구조 3칸 | 몸이 둘 다 닿으면 죽는다. ★[10-10] 구조도 이제 **검정**이라 흰 판 옆 구조는 "검정" — 건너는 건 공중 색 전환으로(검사기가 본다) |

| ★[10-10] 갇힘 금지 | 닿을 수 있는 바닥에서는 반드시 길목 하나에 닿는다(`tools/쳅터1/갇힘검사.py`) | 체크포인트 없이 죽으면 입구에서 부활 — 죽지도 못하는 구덩이는 게임을 다시 켜야 한다 |
| ★[10-10] 입구·체크포인트는 빛 밖 | 길목 안쪽 자리 · 촛불등이 고정 빛 · 반딧불 반경(200px) 밖 | 부활하자마자 또 죽는다(`tools/검사_체크포인트_빛.gd` 가 입구까지 본다) |
| 길목 앞 | 길목 안쪽 6칸은 비운다 | 도착 자동 걷기가 부딪힌다 |
| ★색 비율 (2차 · 도형님) | 칠할 수 있는 판 넓이 중 **검정 ≤ 70% · 흰 ≤ 30%** (나머지 유령) | 검사기가 실패로 잡는다 |
| ★흰 판 머리 위 (2차 · 도형님) | 흰 판 위 **8칸 · 좌우 2칸** 안에 아무것도 없다 | "점프하며 색을 바꾼다고 가정" — 머리 박으면 색 전환 실패 |
| ★3칸 틈 금지 | 판 아래 지나가는 길은 4칸 이상 | 3칸 = 96px < 몸 97px — 1px 차이로 못 지나간다(거실에서 실제로 걸림) |
| ★연결 높이 (3차 · 도형님) | 나가는 길목과 들어오는 길목의 **화면 높이 차 ≤ 96px(3칸)** | "캐릭터가 걸어 나오니까 높이를 맞춰 줘" — 카메라는 발-60px 를 가운데로 잡고 방 밖으로 안 나가므로 바닥 길목 = 화면 856px, 방 중간 길목 = 600px. 검사기가 쌍마다 잰다 |
| ★큰 지형 부피 (2차) | 테두리 위5·아래7·좌우5칸 · 선반·덩어리 두께 4~6칸 | 도형님: "큰 지형들의 부피를 더 키워 줘" |

> ⚠ 2026-10-04 검사기가 실제로 잡은 실수: ① 굴뚝 지그재그에서 다음다음 판이 비행 경로 바로 위(6칸)에 있어 매번 머리를 박음 ② 복도 흰 디딤판이 되돌아갈 때 6칸 위라 일방통행 ③ 굴뚝 첫 선반이 문 길을 막음 ④ 서재 장식 덩어리가 입구 문을 막음.

## 3. 방 크기표 (칸)

모든 방은 가장 넓은 화면(67×38)보다 커야 카메라가 방 안에서 움직인다.

| 종류 | 칸 | px | 화면 장수 | 쓰는 곳 |
|---|---|---|---|---|
| 방_S | 80 × 44 | 2560 × 1408 | 1.3 × 1.3 | 수납실 · 재봉실 |
| 방_M | 112 × 56 | 3584 × 1792 | 1.9 × 1.7 | 시작방 · 침실 |
| 방_L | 144 × 72 | 4608 × 2304 | 2.4 × 2.1 | 서재 · 음악실 |
| 복도 | 192 × 38 | 6144 × 1216 | 3.2 × 1.1 | ★모든 일반 복도는 같은 크기·벽지·문 자리(PPT 7쪽) |
| 계단 | 72 × 112 | 2304 × 3584 | 1.2 × 3.3 | 2층→1층 중앙 계단 |
| 거실 | 224 × 72 | 7168 × 2304 | 3.7 × 2.1 | 1층 거실 |
| 굴뚝 | 44 × 176 | 1408 × 5632 | 0.7 × 5.2 | 화덕 → 굴뚝(화면보다 좁다 — 양옆은 바깥 지형) |

**카메라 밖 배경이 절대 안 보이게** (도형님 지시): 카메라 리밋 = 도안 전체(벽 포함) **그리고** 생성기가 도안 밖으로 구조 지형을 가로 36칸·세로 21칸(가장 넓은 화면의 반 + 2칸) 더 깐다 — 같은 목재 지형이 이어지므로 카메라가 밖으로 나가도 어색하지 않다(엔진 촬영 `_엔진_새스테이지_전체.png` 로 확인). 길목 자리만 12칸짜리 굴로 이어진다.

**스테이지 흐름(2차)**: 나가는 방향 = 다음 스테이지에 들어오는 방향(오른쪽으로 나가면 다음 스테이지 왼쪽에서 걸어 들어온다).
01 → 02 복도A(→) → 03 서재(↘) → 04 복도B(→, 높은 출구) → 05 침실(같은 왼쪽 벽 아래로 들어와 위로 나감) → 06 복도C(← 역방향) → 07 수납실(같은 오른쪽 벽, S자) → 08 계단(↓) → 09 거실(→) → 10 굴뚝(↑, 지붕 길목은 닫힘).

## 4. 도안 → 씬 (Dungeon Scrawl 대신)

Dungeon Scrawl 은 위에서 내려다보는 던전용이라 횡스크롤 방을 찍기 불편했다. 그래서 **같은 모눈 도면 느낌**을 JSON 한 장에서 그린다.

```
scenes/쳅터1/도안/<이름>.json        ← 사람이 고치는 유일한 파일
scenes/쳅터1/도안/<이름>.png         ← 도면(양피지·모눈 · 5칸/10칸 굵은 선 · 검사 결과 표시)
scenes/쳅터1/도안/미리보기/          ← 배경+지형 합성(엔진 아님) · 연결도 · 예시 비교판  (.gdignore)
scenes/쳅터1/스테이지/<이름>.tscn     ← 플레이 씬(생성물 — 손으로 고치지 않는다)
```

```bash
python tools/쳅터1/만들기.py           # 검사 → 도면 → 씬 → 미리보기 (전부, 약 30초)
python tools/쳅터1/검사.py --유령없이   # 칠하기 없이도 지나가지나(유령판을 꼭 칠해야 하는 곳 찾기)
python tools/쳅터1/씬검사.py           # 생성된 씬의 참조·경로·문 연결 정적 검사
python tools/쳅터1/배경_만들기.py       # 임시 배경 그림 다시 굽기
python tools/쳅터1/예시_목재윗면.py     # 목재 윗면·모서리 예시판
```

JSON 형식은 `tools/쳅터1/도안.py` 머리말에 있다. 요점:
- 좌표는 전부 **칸**, (0,0) = 방 왼쪽 위. `"바닥"` = 발이 닿는 칸의 y.
- `"지형"`: `["구조"|"검정"|"흰"|"유령"|"빈", x, y, w, h]` 를 **순서대로** 칠한다. `"빈"` 은 판다.
- `["계단", 종류, x, y, 단수, 방향(+1/-1), 단폭, 단높이, 틈]` — 두께 2칸 발판 계단.
- `"연결"`: `{"이름","쪽":"왼|오른","바닥","높이","연결":[씬,연결이름],"되돌아가기","문장식"}` — 벽을 파고 **연결구**(길목)를 놓는다. 문 그림은 `"문장식": true` 일 때만(길 안내 장식).
- `"가구"`: `[이름, 가운데x, y]` — 배경 레이어(밟을 수 없음). 이름·크기는 `규격.가구표`.
- `"큰틀": true` = 지형 미배치(임시 길) 표시.

**구조(테두리·선반)의 색** ★[2026-10-10 도형님 결정 = 검정]: 05 침실 "흰색인데 안 죽는 버그" → 구조는 **검정 판정**(흰 몸이 닿으면 죽는다 · 칠은 여전히 안 됨).
엔진 = `지형.gd` `구조_판정색`(그림은 안 바뀜 — `시작상태` 를 쓰면 물감이 맞물림 무늬를 덮는다) · 생성기 `만들기.py` `구조_색 = "검정"` · 검사기 `검사.py` `구조_검정`(환경변수 `쳅터1_구조_중립=1` 이면 예전처럼).
- `"흰구조"` (격자 5): 칠 못 하는 **흰** 지형 = 달빛 깔개. 판정 흰색 · 색 비율에 안 셈(칠할 판이 아니다). 흰 빛이 검은 바닥에 떨어지는 자리에 깐다.
- `"추가지형"` · `"추가가시"` · 기믹의 `"추가": true` (빛줄기·도약대·움직이는발판): 손으로 고친 씬에 **새 것만** 끼운다(`tools/쳅터1/추가기믹.py` — 같은 판은 글자 하나 안 건드리고 새 판만 붙인다 · 생성기 표식 씬은 이미 구운 판을 건너뛴다).
- 설계 도구: `tools/쳅터1/글지도.py <스테이지>`(글자 지도 + 닿는 바닥 ~ / 못 닿는 바닥 !) · `경로보기.py`(검사기가 찾은 길) · `갇힘검사.py`(빠지면 못 나오는 바닥).

## 5. 레벨 디자인 원칙 (참고 링크 2개를 이 게임에 맞춘 것)

devmag「How to design levels for a platformer」 — 순서대로 한다:
1. **아이템 목록**: 이 방에서 처음 배우는 것(특정) · 몇 번 반복되는 것(일반, 개수). 예) 서재 = "가시 바닥 위 디딤판"(특정) · 검정판 3 · 흰판 3 · 유령판 2(일반).
2. **거친 배치**: 길만 그린다(도시의 길, 건물 무시). 너무 곧고 긴 줄 = 지루함 → 접기(U자)·갈래·하강.
3. **특정 아이템 스케치** → 4. **상세 배치**(도안 JSON) → 5. **블록아웃**(임시 그림 · 비슷한 명도) → 6. **플레이 후 고치기** → 7. **장식**(아스트라 그림).

significant-bits「SMB3 level design lessons」 — 적용한 것:
- **안전하게 먼저 가르친다**: 새 요소는 떨어져도 안 죽는 곳에서 처음 나온다(시작방 흰 바닥 앞 체크포인트 · 중2층 구덩이는 바닥으로 떨어질 뿐).
- **보이는 목표**: 시작하자마자 출구 문이 보이지만 바로 못 간다(접힌 U자) → 탐험 동기.
- **선택 길**: 복도 A ③ 선반, 서재 윗길(안전·김)/아랫길(위험·짧음).
- **리듬**: 디딤판 간격을 6칸으로 맞추고 높이만 ±2칸 흔든다(복도 B ③).
- **끝이 분명한 경계**: 방 테두리는 두꺼운 구조 + 문은 어두운 전경으로 "여기가 출구"가 읽힌다.
- **벌이 고문이 되지 않게**: 체크포인트 간격 = 방 하나에 4~5개, 위험 구간 바로 앞.

## 6. 스테이지 전환 — 연결구 (2차: 문 없이 길목만)

`scripts/쳅터1/연결구.gd`(길목) + `scripts/쳅터1/반딧불이.gd`(길 안내) + `scripts/쳅터1/전경전환.gd`(진행). 기존 `연결통로`·`장면전환`(암전)과 별개.

도형님 2차 지시: "문을 통과해야만 넘어가는 게 아니야 — 문은 길을 알려 주는 표시일 뿐. 한 부분은 타일셋보다 가까운 전경이 그라데이션으로 명암을 보여 주고, 근처에 반딧불이가 깜빡이며 돌아다니게. 어두운 벽은 너무 두껍지 않게, 들어가면 줌인 → 다음 스테이지에서 자동으로 걸어 나오며 천천히 줌아웃."

1. **가까운 전경 띠**: 길목 위에 타일보다 앞(z 60)으로 얇은 그라데이션 — 바깥(다음 스테이지 쪽)으로 갈수록 진하고 방 안쪽 96px 에서 투명, 구멍 위로는 세로로 옅어진다(각진 상자 없음).
2. **반딧불이**: 길목 바로 안쪽에 7마리 — 사인 두 개로 헤매고 (사인)^3 로 짧게 반짝. 광원 없이 가산 혼합(광원 한계 15 를 아낌) · 화면 밖이면 안 그림.
3. **판정**: 몸이 벽 안쪽 면을 56px 넘으면 시작 — 조작 잠금 · **자동으로 바깥쪽 걷기** · 카메라 줌인 1.0→1.35(0.55초) · 비네트 조임 · 0.30초부터 0.25초 동안 짧게 어두워짐.
4. **교체**: 어두운 순간 스테이지 교체. **떠나는 스테이지는 보관**(최대 3개).
5. **나옴**: 새 스테이지는 줌인된 채 밝아지고(0.35초) 길목에서 자동으로 걸어 나와 방 안 2칸에서 조작 반환 · 카메라는 **1.8초 동안 천천히** 1.0 으로.
6. **되돌아가기**: 들어온 길목으로 다시 나가면 보관된 이전 스테이지로 — 떠날 때 그대로(엔진 시험: 같은 인스턴스 복원 ○).
7. 닫힌 길목(`다음_씬` 없음/`되돌아가기` 끔): 투명 벽 + 짙은 전경, 반딧불이 없음.

## 9. 기믹 · 색 전환 시뮬 (2026-10-05)

도안 JSON 의 `"기믹"` 목록 → 검사(시뮬)·씬·도면·미리보기가 `tools/쳅터1/기믹.py` 한 곳의 해석을 같이 쓴다. 엔진 장면은 공용 키트 `scenes/집/스마트월드_장애물/` 그대로(경로 바꾸지 말 것).

| 종류 | 도안에 적는 법 | 엔진 | 규칙 |
|---|---|---|---|
| 빛줄기 | `{"종류":"빛줄기","근원":"창문","x":40,"y":10,"각도":70,"두께":3}` (x,y = 빛이 나오는 점 · 길이 생략 = 처음 닿는 지형까지) | `scenes/쳅터1/기믹/창문빛.tscn`(색레이저.gd 상속) | 근원 **창문**(비스듬한 달빛, 창문 그림 자동) · **천장틈**(빛 기둥) · **그을음**(검정, 재 기둥). 빛 안에서 몸 색 ≠ 빛 색이면 즉사. `"점멸":true,"주기":2.5` = 구름. **벽을 뚫으면 안 된다**(검사가 잡는다). 옛 형식(`"방향":"아래"`)도 읽는다 |
| 도약대 | `{"종류":"도약대","x":88,"바닥":49,"폭":4,"오름":9}` | 도약대.tscn | 오름(칸)으로 도약속도 자동 계산(√(2·1287·오름·32)). `"색":"검정"` = 그 색일 때만 튐. 머리 위 `오름+3칸` 비울 것 |

지형을 기믹 자리로 바꿀 때는 `"지형"` 끝에 `["빈",x,y,w,h]` / `["구조",…]` 를 덧칠한다(순서대로 칠하므로 뒤가 이긴다).

**통과 기준 (2차)**: ① 모든 길목 ② **모든 바닥(폭 24px↑)** 이 **'편한 손'**(점프 최고 95% = 152px · 색 전환 틈 ≥ 15프레임)으로 닿아야 한다. 밟을 것처럼 보이는데 못 가는 판은 실패다(도형님 "점프로도 못 올라가" — 02 의 9칸 위 장식 판).

**지형 모양**: 씬의 지형은 `tools/쳅터1/모양.py` 가 칸 다각형을 **안쪽으로만** 깎아 불규칙하게 만든다(윗면 평평 + 양끝 8px 모따기 · 옆 0~7px · 밑 0~16px). 도안은 그대로 칸으로 그리면 된다.

**시뮬(검사기) 규칙 — 엔진 재생 시험으로 맞춘 값**
- 몸: 벽·머리 = 허리 너비 사각형(원점 −18 … +26px, 키 97) · **서기 = 발 가운데 ±6px + 모따기 8px 가 전부 판 위** · 엔진 재생용 경로의 착지는 ±18px 로 더 안쪽. 실제 충돌 모양이 위아래가 좁은 육각형(발바닥 17px)이라, 판 끝 몇 px 걸침은 엔진에서 미끄러진다.
- 색: 비행마다 몸(±3px = 월드.gd `접촉_여유`)에 닿는 색을 프레임별로 적는다. 두 색 동시 = 죽음 · 색이 바뀌는 틈 < **8프레임**(0.13초) = 못 감 · < 15프레임 = '빠듯' 경고. 먼저 15프레임 이상만으로 길을 찾고, 없을 때만 8프레임까지 허용.
- 벽에 막히면 벽에 딱 붙는다(move_and_slide 처럼) — 안 붙이면 검정 판 옆면 접촉을 놓친다.
- 길목 굴(방 밖)은 서는 자리로 안 친다(연결구 판정 자리). 닫힌 길목도 시작에서 닿아야 한다(다음 도안 자리).
- 움직이는 발판 = 위상 5곳의 윗면을 착지 판으로 보고 발판 하나를 노드 하나로(기다려 맞춘다고 가정). 주기·점멸 빛은 막지 않는다.

**확인 3단계** (전부 통과해야 끝)
1. `python tools/쳅터1/만들기.py` → 검사 실패 0 (경로가 `tools/_진단/경로/<이름>.json` 에 남는다)
