## 1. 왜 새 층이 필요했나

카메라 값을 정하는 주인이 이미 **세 개** 있었다.

| 주인 | 언제 | 무엇을 |
|---|---|---|
| `월드.gd` | 씬 시작에 한 번 | 스테이지 전체 리밋 · 줌 |
| `카메라_연출.gd` | **매 물리 프레임** | x 구역을 섞어 리밋 · 줌 · 시선 |
| `장면전환.gd` / `월드._등장_연출` | 전환할 때 | 줌 트윈 ("짜잔") |

여기에 "굴뚝에 들어가면 조인다"를 그냥 얹으면 **다음 프레임에 연출가가 덮어쓴다.**
한 프레임 조였다 풀렸다 하며 떨린다. (실제로 `장면전환` 의 줌 트윈은
구역 연출이 붙은 씬에서 **첫 프레임에 지워져 아무 일도 안 하고 있었다.**)

→ 값을 서로 덮어쓰지 않도록 **곱셈 3층**으로 나눴다.

```
zoom = 기준 줌        ×  공간 혼합            ×  연출 배수
       (월드/구역)       (굴뚝 = 카메라공간)      (전환 "짜잔")
       0.82              lerp(0.82→1.10)         1.14 → 1.0

리밋 = lerp(기준 리밋, 공간 리밋, smoothstep(혼합))
시선 = lerp(구역 시선, 공간 시선, 혼합)
```

`공간 혼합` 은 0~1 하나뿐이고, **그것만 트윈한다.**
기준값이 매 프레임 바뀌어도 싸우지 않는다.

## 2. 왜 여기서는 "시간 트윈" 이 맞나

`카메라_연출.gd` 머리말에는 **"전환은 시간이 아니라 플레이어 위치로 굴러간다"** 고
못박아 두었다 (Vane 2019 이 "카메라가 플레이를 방해한다" 는 혹평을 받은 이유).
이 문서의 카메라 공간은 그 규칙을 **의도적으로 어긴다.** 이유:

| | x 구역 전환 | 굴뚝 진입 |
|---|---|---|
| 사건 성격 | 경계 없는 **연속 이동** | 문을 통과하는 **이산 사건** (Area2D 1회) |
| 진행도 축 | x 하나로 명확 | 아래로도 옆으로도 들어올 수 있어 축이 안 정해진다 |
| 맞는 방법 | 위치 보간 | **시간 트윈** |

대신 Vane 식 실패(화면이 혼자 흘러가 조작과 어긋남)를 두 가지로 막았다.

1. **되돌아 나오면 즉시 반대로 트윈한다** (`공간_나감`). 화면이 계속 조여들지 않는다.
2. **남은 거리에 비례해 시간을 줄인다.** 절반 들어갔다 나올 때 전체 시간을 다시 쓰면
   화면이 몸보다 한참 늦게 따라와 "끌려가는" 느낌이 난다.
   → `시간 × max(남은거리, 0.15)`

## 3. 연출 시퀀스 (실제 구현된 순서와 숫자)

굴뚝 = `스마트월드_4` 의 x 5120~5440 · y 770~1850 (안쪽 306×1080)

| # | 시점 | 카메라 | 시간 | 왜 |
|---|---|---|---|---|
| ① | 하층 수로를 걷는다 | 줌 0.82 · 리밋 = 스테이지 전체 | — | 방 전체가 보인다 = 경로 계획 |
| ② | 굴뚝 판정 영역에 **몸이 들어간 순간** | 혼합 0 → 1 시작 | **0.65s** | 첫 선반에 닿을 무렵 완성된다 |
| ③ | 조여드는 중 | 리밋이 좌우 벽으로 좁혀진다 | ↑ | 리밋 306px < 화면 1747px → **x 중앙 고정** |
| ④ | | 줌 0.82 → **1.10** | ↑ | 화면 폭 2341 → 1747px |
| ⑤ | | 룩어헤드 → 0 · 플랫폼 스냅 해제 | ↑ | 좁은 통로에서 좌우 흔들림 제거 |
| ⑥ | 등반 중 | 세로 반응 6 → **11 (1/s)** | 즉시 | 오르는 몸을 화면이 바로 따라온다 |
| ⑦ | 등반 중 | 시선이 진행도에 비례해 위로 (0 → −150px) | 연속 | 출구를 **도착 전에** 보여준다 |
| ⑧ | 등반 중 | 틈새빛이 위로 갈수록 강해진다 (u² 곡선) | 연속 | 흑백 게임에서 "출구는 위" 를 명암으로 말한다 |
| ⑨ | 굴뚝을 완전히 벗어난 순간 | 혼합 1 → 0 | **1.15s** | 들어갈 때보다 **길게** = 전경이 읽힌다 |

★ ⑨ 가 도형님이 말한 "다음 스테이지의 전경을 보여주는 줌 아웃" 이다.
스테이지가 바뀌는 전환(`연결통로` → `장면전환`)과 **층이 다르다** — 아래 §6 참고.

## 4. 배치법

### 4-1. 자동 (권장)

지형 노드 이름을 `○○벽_좌` / `○○벽_우` 로 지으면 끝이다.
`카메라공간배치.gd` 가 두 벽의 **콜리전을 실측**해서 그 사이에 공간을 만든다.

```bat
Godot --headless --path . -s res://tools/카메라공간_배치.gd -- --조사   :: 어디에 생기나만 본다
Godot --headless --path . -s res://tools/카메라공간_배치.gd            :: 실제로 놓고 저장
```

- 안쪽 폭 120px 이상 · 높이 400px 이상만 통로로 인정한다(그보다 작으면 문틀이다).
- **멱등** — `카메라공간_*` 노드를 먼저 다 지우고 다시 계산한다. 몇 번 돌려도 같다.
- `tools/스마트월드_체인.gd` 도 **같은 함수**를 부른다 → 스테이지를 다시 구워도 살아남는다.

좌표를 손으로 적지 않는 이유는 `장식배치.gd` 와 같다:
벽을 1px 만 옮겨도 어긋나고, **어긋난 것을 눈으로는 알 수 없다**
(카메라가 벽을 조금 넘겨 비추는 정도라 "왜 좀 이상하지?" 로만 느껴진다).

### 4-2. 손으로

에디터에서 `카메라공간` 노드를 굴뚝 안쪽 한가운데에 놓고 `크기` 를 맞춘다.
초록 사각형(판정) · 노란 사각형(카메라 리밋) 가이드가 2D 뷰에 그려진다.

| 인스펙터 값 | 기본 | 뜻 |
|---|---|---|
| `크기` | 320×1100 | 판정 영역 = 카메라 리밋의 바탕. **굴뚝 안쪽 폭**으로 잡을 것 |
| `리밋_여유` | (0, 260) | 리밋만 세로로 넓힌다. 없으면 굴뚝 끝에서 플레이어가 화면 가장자리에 붙는다 |
| `줌_배수` | 1.34 | 기준 줌에 곱한다. **1보다 크면 조여든다** |
| `시선_오프셋` | (0, −60) | 등반 공간은 위를 더 보여준다 |
| `수직모드` | on | 룩어헤드 끄고 몸을 바로 따라간다. 가로로 긴 공간이면 끌 것 |
| `오를수록_위로` | 150 | 위로 갈수록 시선을 더 올린다 (출구 예고) |
| `들어갈때` / `나올때` | 0.65 / 1.15 | 나올 때가 길어야 "짜잔" 이 된다 |
| `틈새빛_*` | on · 6개 | 벽 틈에서 새는 빛. 위로 갈수록 강해진다 |

## 5. ⚠ 튜닝할 때 알아야 하는 한계

**`줌_배수` 를 1.34 보다 크게 올리지 말 것.**

화면 세로 = 1080 / (0.82 × 배수). 배수 1.34 에서 **982px** 이 보인다.
굴뚝 선반 간격은 110px 이므로 위아래로 8~9 장이 보인다 — 다음 발판을 보고 뛸 수 있다.
배수를 2.0 으로 올리면 658px 만 보이고, 화면 위쪽 절반이 벽에 가려지면
**다음 선반이 화면 밖에 있는 상태로 점프**하게 된다. 그건 도박이지 실력이 아니다.

**"굴뚝 벽 바깥을 절대 안 비춘다" 의 정확한 의미**

- 가로: **완전히 보장된다.** 리밋(306px) < 화면(1747px) 이므로 카메라 x 가
  굴뚝 중심에 못박힌다. 플레이어가 좌우 선반을 오가도 화면은 **0.0000px** 움직인다
  (자동 검사로 측정한 값이다).
- 세로/구석: 화면 폭 1747px 중 굴뚝은 306px 이다. 나머지 1441px 에 무엇이 보이는지는
  **지형이 결정한다.** 스마트월드_4 는 굴뚝 좌우가 이미 암반 덩어리라
  (왼쪽 = `천장_수로` y 420~1250, 오른쪽 = `바닥_상2` y 900~2760) 대부분 암반이 채운다.
  단 굴뚝 **바닥 부근의 왼쪽**(y 1250~1800)은 하층 수로가 열려 있다 —
  이건 "내가 올라온 곳이 보인다" 라서 오히려 두는 게 맞다.
- 새 굴뚝을 만들 때: 벽 두께를 화면 반폭(≈874px) 만큼 줄 필요는 없다.
  **굴뚝 좌우에 암반 매스가 어차피 있는 자리**에 굴뚝을 파면 저절로 해결된다.

## 6. 이 시스템과 "스테이지 전환" 의 차이 (섞지 말 것)

| | 카메라 공간 (이 문서) | 스테이지 전환 |
|---|---|---|
| 담당 | `카메라_공간.gd` | `연결통로.gd` + `장면전환.gd` |
| 씬 | **안 바뀐다** | 바뀐다 (`change_scene_to_file`) |
| 화면 | 안 어두워진다 | 검정(같은 챕터) / 흰색(챕터 전환) 페이드 |
| 범위 | 한 스테이지 **안의** 공간 | 스테이지 ↔ 스테이지 |
| 연출 시간 | 0.65s / 1.15s | 암전 0.85 + 정적 0.22 + 점등 1.35s |

둘 다 "포탈이 아니다" 라는 같은 원칙에서 나왔지만 **층이 다르다.**
거실 → 굴뚝은 카메라 공간, 굴뚝 → 다음 스테이지는 연결통로다.
굴뚝 위쪽 끝에 연결통로를 두면 두 연출이 이어져 하나처럼 읽힌다
(굴뚝에서 조여든 화면 → 통로로 걸어들어가며 암전 → 다음 스테이지에서 풀리며 전경).
