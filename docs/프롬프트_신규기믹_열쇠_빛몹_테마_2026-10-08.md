## 0. 작업 루프 — 디자인 하나를 게임 오브젝트로 만드는 방법

```
① Claude: 작업 카드(§5)를 준다 — 목적 · 원하는 느낌 · 시안 프롬프트 · 확정 프롬프트 · 저장 위치
② 도형 → 아스트라: 카드 0(공통 스타일)을 대화 처음에 한 번 붙이고, 해당 카드의 [시안 프롬프트] + 첨부 그림
③ 아스트라: 시안 3~4장 → 도형이 고른다(고르는 기준은 카드에 있다). 마음에 안 들면 [고칠 때 쓰는 말]로 다시
④ 도형 → 아스트라: 고른 시안을 붙인 채 [확정 프롬프트] → 부품 시트 / 프레임 시트
⑤ 도형: 파일을 카드의 저장 위치에 넣고 Claude 에게 [Claude 에게 보낼 말] 양식으로 알린다
⑥ Claude: 배경 제거·자르기·바닥선 맞춤·명도 검수 → 게임 시스템에 연결(사물의 움직임은 대부분 코드로) → 시험 → 실제 게임 화면 캡처
⑦ 도형: 화면 보고 컨펌 / 수정 요청 → 필요하면 ③으로
```

**왜 "부품 시트 + 코드 애니메이션"을 기본으로 하나** — GPT 이미지는 한 장 안의 프레임끼리 모양·크기·바닥선이 조금씩 어긋난다(게임에서 떨림으로 보인다).
그래서 **스프링·열쇠·문 같은 사물은 부품으로 받고 Claude 가 코드로 움직인다**(늘이기·탄성·트윈·파티클). 프레임 시트는 **모양 자체가 변하는 것**(이펙트 번짐·몹 동작)에만 쓰고, 그때도 Claude 가 칸마다 중심·바닥선을 다시 맞춘다.

**아스트라 출력 규칙(매번 확인)**: 캔버스 1024×1024 · 1536×1024 · 1024×1536 중 하나. 투명 배경이 안 되면 **단색 크로마키 초록(#00FF00)** — 이 게임은 흑백이라 Claude 가 깨끗하게 지운다.

## 3. 게임 정체성 · 분위기 · **2.5D 문법** (모든 작업의 기준)

- **2D 흑백 다크판타지 퍼즐 플랫포머.** Godot 4.6.3 · SmartShape2D 지형 · 브랜치 dev_4.
- 핵심 규칙: **몸에 닿은 지형이 내 색과 다르면 즉사.** 안 칠한 지형은 검정. 회색만 안전. Shift = 내 색 전환. 물감총으로 칠한다.
- 세계관(「수정된 세계」): 신이 "색은 오류"라며 **표백**했다. 소년은 색이 봉인된 페인트 건을 든다 → 이펙트 재료 = **잉크·물감**, 적 재료 = **그을음·표백**.
- 쳅터1 = 밤의 빅토리아풍 저택 15 스테이지(연결구, 체크포인트 = 촛불등). 쳅터2 = 하수도 11 스테이지(거미줄 지도, 장치는 주철).
- 레퍼런스 톤: LIMBO · INSIDE · Little Nightmares · Rain World. **포탈 금지**, UI 아이콘보다 세계 안의 사물로 알린다.
- **2.5D 문법(지금 게임이 실제로 쓰는 것)**
  - 지형 = **정면 + 위에서 살짝 내려다본 얇은 윗면**. 쳅터1 목재 = 윗면 30px(판자 결이 앞쪽으로 뻗음) + 앞면 판자 줄 36px · 못 머리 · 판자 이음 틈 · 모서리 마감판·쇠 꺾쇠. 하수도 = 거친 벽돌 앞면 + 갓돌 윗면 한 줄 + 사다리꼴 끝 마감.
  - 빛은 **왼쪽 위**에서. 윗면은 앞면과 구분되는 명도, 앞면 위쪽에 얇은 그늘(윗면 아래 입술선), 모서리·틈에 어두운 그늘(AO).
  - 소품(촛불등·옷장·책상)도 **입체 조형 + 결 + 낡음**이 있다. 평면 아이콘·만화 외곽선과 섞이면 바로 튄다.

## 4. 기능 기획 상세

### A. 반반 열쇠 (v3 확정)

**쓰는 곳**: **중간중간 특정 스테이지만**(도안 JSON / 하수도 진행 표에 "열쇠 스테이지" 표시). 그 스테이지의 출구는 **잠긴 문**(B).

**모양** — 도형님 레퍼런스(하트 머리 열쇠가 세로로 갈라진 한 쌍)의 구조:
- **하나의 열쇠를 위에서 아래로 한가운데를 따라 세로로 반 쪼갠다.** 손잡이/날로 나눈 게 아니다 — 머리와 날이 **둘 다** 반씩 나뉜다.
- 머리(손잡이) 부분의 쪼갠 면은 **지그재그 톱니**로 서로 맞물린다. 날 부분의 쪼갠 면은 곧게 붙어, **두 반쪽의 날이 합쳐져야 한 개의 온전한 날**이 된다.
- **왼쪽 반 = 검정 조각, 오른쪽 반 = 흰 조각.** 둘을 붙이면 누가 봐도 하나의 열쇠 실루엣.
- 머리 모양: 레퍼런스의 하트처럼 **좌우 대칭의 둥근 장식 머리**(하트 · 물방울 · 둥근 방패 중 시안에서 고름) + 위에 고리 구멍(쪼개면 반원씩) + 덩굴 무늬 양각. 우리 세계에 맞게 **물감 방울 / 덩굴** 모티프 권장.
- 2.5D: 얇은 금속판 두께가 옆에서 살짝 보이고, 양각 무늬에 왼쪽 위 빛.

**규칙**
1. 열쇠 스테이지에 들어오면 HUD(페인트 게이지 오른쪽)에 **열쇠 전체 외곽선만 점선**으로 뜬다(안쪽 금선 없음) → "잠긴 스테이지" 신호.
2. 검정 조각은 **플레이어가 검정일 때만 보이고 주울 수 있다.** 흰 조각은 흰색일 때만. (기준 = `선택색()`)
3. **줍는 순간**: 그 자리에서 **조각 색의 빛이 짧게 퍼진다**(0.35초 · 반경 약 3칸) — 흰 조각 = 부드러운 흰빛 원이 퍼졌다 사라짐 / 검정 조각 = 어두운 잉크 고리가 퍼지며 **가장자리만 밝게 빛나는 테**(검정 화면에서도 보이게). 조각은 HUD 로 날아간다(0.35초 곡선).
4. HUD 점선 외곽선 안이 **주운 조각의 실제 모양 그대로** 채워진다(왼쪽 반 검정 / 오른쪽 반 흰색, 0.4초 잉크가 차오르듯).
5. 두 조각이 다 차면 HUD 에서 지그재그 면이 **맞물리며 붙는 연출**(0.6초) → 점선이 실선 = 완성된 열쇠.
6. 보이는 순간 연출: Shift 할 때 0.15초 페이드 · 보일 때 은은한 후광 + 가는 밝은 테두리.
7. 죽어도 주운 조각은 유지(추천 · §7). 스테이지별 "열쇠 얻음"은 `user://진행.cfg` 에 저장 → 쳅터2 지도 칸에 열쇠 표식.
8. 공중 Shift 줍기: 흰 조각이 검정 지형 위 허공에 있으면 검정으로 점프 → 공중에서 흰색으로 바꿔 줍기 → 착지 전 검정.

**레벨 디자인 규칙**: 조각은 그 색 몸으로 살아서 닿는 자리(공중 줍기 의도 제외) · 주 경로에서 한 갈래 벗어난 곳 · 문 바로 앞 금지 · 두 조각은 서로 다른 갈래에 · 근처에 세계 안 단서(빈 열쇠걸이·먼지 자국·반딧불이).

### B. 잠긴 문 — 다음 스테이지로 가는 길목 (v3)

- 열쇠 스테이지의 출구 길목(쳅터1 연결구 · 쳅터2 출구 통로) 입구에 **잠긴 문**.
  - 집 = 길목에 맞춘 **낡은 나무 문(쇠띠·징)** + 문을 가로지른 쇠사슬 + **놋쇠 자물쇠**(열쇠 구멍 = 반반 열쇠 머리 모양).
  - 하수도 = 통로 입구의 **주철 격자문** + 맹꽁이 자물쇠(같은 열쇠 구멍).
- **열쇠 없이 다가가면**: 막혀 있고 자물쇠가 덜컥 흔들림 + HUD 점선 열쇠가 흔들림 → "열쇠가 필요하다". 반딧불이는 문 앞에서 맴돈다.
- **완성된 열쇠를 가지고 다가가면**(자동, E 불필요): HUD 열쇠가 자물쇠로 날아가 꽂혀 돌아감(0.4초) → 사슬이 풀려 떨어짐 → 문이 안쪽으로 열림(0.6초) → 콜리전 해제 → 걸어가던 그대로 쳅터1 전환으로 이어진다.
- 조각 하나만 있으면 안 열린다(HUD 의 빈 반쪽이 깜빡여 무엇이 모자란지 알린다).
- 문이 놓일 자리가 없는 길목은 **잉크 막**(반투명 검·흰 소용돌이) 대안.
- 원칙: 잠금은 **출구 한 곳에만**. 스테이지 안의 새 길은 빛 장치(G)로 연다.

### F. 부서지는 발판 (v3 규칙 확정)

- 기존 3종(`무너지는발판.gd` · `무너지는바위.gd` · `SS2D_붕괴발판.gd`)을 **`SS2D_붕괴발판.gd` 하나로** 통일, 외관만 집(썩은 마루판)/하수도(녹슨 철망).
