## 1. 코너 후광의 정체 — 추측을 버리고 알파를 셌다

새로 만든 진단 도구 `tools/진단_코너_고스트.gd` 로
**grass_v4(승인된 LOCK 에셋)** 와 나란히 놓고 쟀다. 절대 수치가 아니라 **대조군 대비**로 본다.

### (1) 엣지 안쪽 알파 페이드가 뒤집혀 있었다 — 진짜 버그

`_엣지마감()` 의 마스크가 `0.5*(1+cos(PI*(1-t)))` 였다.
이건 **가장 안쪽 행에서 1, 페이드 시작 지점에서 0** 이다. 주석에 적힌 의도와 정반대다.

실측 (1024×256 엣지의 안쪽 76행 알파):

```
grass_v4 (파이썬으로 구움)  … 251 → 서서히 → y=253 에서 0        ← 의도한 모양
brick/sewer/wood (GDScript) … 255 → y=200 에서 0 → 다시 → y=255 에서 255
```

결과: 지형 안쪽 78% 지점에 **완전히 투명한 가로줄**이 생기고 맨 안쪽 행은 불투명.
그 줄이 코너 합성에서 apex 둘레 고리로 감겨 유령이 되었고,
실제 렌더에서는 지형 내부에 **옅은 사각 테두리**로도 보였다(5배 확대 스샷에서 확인).

→ `0.5*(1 - cos(PI * d/n))` 으로 수정.

### (2) miter 코너의 각도 블렌드가 너무 넓었다

45도에서 TOP/SIDE 를 섞는 폭이 90도의 70%(= ±31.5도)라
**SIDE 실루엣 바깥**인 지점에서도 TOP 이 26% 섞였다.
TOP 은 그 깊이에서 불투명이므로 **알파 60짜리 반투명 덩어리**가 실루엣 밖에 얹혔다.

→ 색은 넓게(0.70) · 알파는 좁게(`--코너알파폭=0.16`) 로 **분리**했다.
   `_블렌드2(a, b, wc, wa)` 를 새로 만들었고, `wa == wc` 면 기존 `_블렌드()` 와 동일하다(하위호환).

### (3) 덤 — 512 코너가 그림을 가로로 2배 압축하고 있었다

코너 쿼드의 월드 크기는 캐리어(`투명_256`) × 0.35 = **89.6px 고정**인데
u 매핑이 `float(코너변)` 을 그대로 써서, 코너크기 512 에서는
엣지 그림 **179 월드px 분량**을 89.6px 에 밀어 넣고 있었다.
코너에서만 벽돌이 좁아지고 코너 쿼드 경계가 **사각 자국**으로 드러났다(하수에서 가장 심함).

→ `코너캐리어(256)` 기준으로 u 를 계산하도록 수정.
고친 뒤 **256 과 512 의 렌더가 구분되지 않는다**(512 는 단순 업샘플).
512 는 확정값이라 그대로 두었고, 파일 크기 외에 이득은 없다.

> 지난 기록의 "512 채택 근거(볼록 디테일 0.56→0.66)"는 사실 **이 압축을 재고 있었다.**
> 압축하면 같은 면적에 무늬가 더 들어가므로 '디테일 비율'이 올라간다.

### 채택하지 않은 안

| 안 | 왜 안 썼나 |
|---|---|
| 코너 PNG 외곽 알파 trim(원호로 자르기) | 벽돌의 **사각 코너 실루엣이 둥글게 깎인다**. 원본 실루엣을 잘라먹지 말라는 조건에 걸린다 |
| `polar` 로 전환 | 잔상은 비슷하게 줄지만 **벽돌 줄눈이 부채꼴로 휘어** 아치처럼 보인다 (렌더로 확인) |
| `--코너알파폭=0.08` | 0.16 대비 개선이 2.26%→2.08% 뿐. 45도에서 더 급하게 끊어 이음매 위험만 커진다 |

## 3. 안쪽 그림자 (SOLID 가 벽처럼 보이게)

구조는 그대로 두었다 — **FILL 이 아니라 엣지에 굽는다.**
FILL 은 내부를 반복 타일링하므로 그라데이션을 구우면 그게 반복돼 줄무늬가 된다.

페이드 버그를 고친 뒤 실측 (엣지 v: 바깥 0 → 안쪽 1, 알파가중 휘도):

```
벽돌   45.6 → … → 28  | FILL 30.5
하수   62.5 → … → 21  | FILL 29.7
나무   45.5 → … → 28  | FILL 30.4
```

바깥에서 안쪽으로 어두워지고, **FILL 평균이 엣지 안쪽 톤과 맞아** 경계에 단이 없다.
코너·taper 는 이 엣지 단면에서 합성되므로 그림자를 자동으로 물려받는다.
GRASS v4 에는 그림자가 없다(LOCK). 통일하려면 `grass_v5` 를 따로 만들어야 한다.


## 6. 흑/백은 여전히 '머티리얼'이 아니라 '상태'다

`BRICK_BLACK` / `BRICK_WHITE` 같은 색 전용 머티리얼은 **만들지 않았다.**
만들면 그 지형은 반대 색으로 칠할 수 없게 되어
"내 색과 다른 지형에 닿으면 즉사" 규칙이 그 지형에서만 깨진다.

새로 만든 `tools/검증_런타임색_타일셋.gd` 가 재질 4종 × 채움/속빔에 대해
**지형 노드를 실제로 세워서** 확인한다:

- 4방향 엣지에 페인트 셰이더가 붙고 `alt_tex` 가 `/white/` 를 가리키는가
- 코너 캐리어(투명_256)에는 셰이더가 **안** 붙는가 (경고 폭탄 방지)
- 채움은 fill 셰이더가 있고, 속빔은 없는가
- 머티리얼 하나로 **무색 → 검정 → 흰색 → 다시 검정** 이 전부 되는가
- `shape_material` 이 인스턴스마다 깊은 복사되는가 (공유 오염 방지)

→ **168 통과 / 0 실패 · 경고 0**
