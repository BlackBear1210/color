- 처음 문장의 하강 표현은 후속 답변 **아래 중앙 → 위 중앙으로 상승**으로 확정했다.
- 세로로 긴 직사각형, 중앙 직통 금지, 반복되는 좌우 선택.

- 기존 사전 질문 규칙과 `맵 기본 구조 틀.pptx` 반영 내용은 유지했다. 이번 시작·도착·방향·외곽은 이미 답변받아 다시 묻지 않았다.

## 배치와 진행

안쪽 외곽은 x=-128~6272, y=1024~12672인 6400×11648 직사각형이다. 시작은 (3072,12288), 최종 목적지는 (3072,2048)이다. 좌우·위아래에 2048px 두께의 외곽 마감을 두고 카메라 줌은 0.85로 설정했다.

| 구역 | 출발 y | 합류 y | 구성 |
|---|---:|---:|---|
| 1 | 12288 | 10496 | 좌우 상승 회랑, 오른쪽 지형 변색 분사기 |
| 2 | 10112 | 8576 | 오른쪽 회전톱, 급수·양동이 작업장, 필수 중앙 문 |
| 3 | 8192 | 6400 | 오른쪽 가시, 좌우 우회 |
| 4 | 6016 | 4224 | 오른쪽 지형 변색 분사기 |
| 5 | 3840 | 2048 | 오른쪽 가시·회전톱, 최상단 중앙 출구 |

각 구역은 중앙에서 왼쪽 흰 회랑 또는 오른쪽 검정 회랑으로 나간 뒤 바깥의 반환 발판을 통해 위쪽 회랑으로 돌아온다. 중앙에는 두꺼운 기둥을 내려 중앙 점프만으로 다음 합류점에 갈 수 없게 했다. 합류 후 짧은 격자 계단을 올라 다음 좌우 선택에 진입한다. 이번에는 사용자의 반복 선택 요구에 맞춰 양쪽이 모두 이어지는 분기 다섯 곳을 두었다. 기존 예시의 F1 막다른 길을 그대로 복제한 구성은 아니다.

연속 회랑은 20개이며 각각 SS2D 하나다. 반환 발판 30개는 실제로 서로 떨어진 점프 발판이므로 별도 노드다. 중앙 기둥·외곽·독립 이동 문을 합해 SS2D는 61개다. 승강기는 0대다. 단순 점프용 격자 계단은 기존 통과플랫폼 부품을 사용하고, 아래에서 머리가 걸리지 않게 충돌 자식에 단방향 충돌을 명시했다.

## 양동이 퍼즐

1. 두 번째 합류점 오른쪽 작업장에 진입한다. 검정색 상태에서 양동이를 민다.
2. 양동이 시작 x=4256에서 왼쪽으로 밀어 x=4128의 검정 유체 아래에서 물을 받는다.
3. x=3712 압력발판까지 계속 밀어 물 찬 양동이를 놓는다.
4. 중앙 SS2D 덮개가 위로 640px 이동한다. 열린 격자 계단으로 다음 구역에 올라간다.

버튼은 `양동이` 그룹만 감지한다. 기존 스크립트는 빈 양동이를 제외한다. `채운뒤_밀수없음=false`, `작동방식=0`으로 설정해 물을 채운 뒤 운반할 수 있고, 양동이가 올라가 있는 동안만 문이 열린다. 버튼 대상은 타입이 명시된 `Array[NodePath]`, 이동량은 `Array[Vector2]`다.

작업장의 평지는 x=3584~4352, 양끝 턱은 96px다. 턱도 같은 SS2D의 편집 점으로 만들었다. 양동이를 옆 구역으로 떨어뜨리는 상황을 막기 위한 구조다. 바로 위 회랑은 해당 구간만 144px 두께로 줄여 왼쪽 턱 위에 144px의 머리 공간을 확보했다.

## 장애물과 출구

분사기 2대는 아래로 발사하고 탄낙차가 0이다. 3.2초 간격으로 쏘며 6.4초마다 색을 바꾼다. 각 분사기의 발사선과 전체 지형 변을 교차 계산하여 해당 구역 오른쪽 상행 회랑을 먼저 맞는 것을 확인했다.

톱 2개는 반지름 36px, 이동거리 160px, 왕복 3.2초다. 가시 2개는 각각 2칸·높이 20px다. 분사기와 톱은 서로 다른 구역에 있다. 양동이·급수·버튼·문을 포함하면 주요 장치는 10개이며, 점프용 격자 계단·배관·체크포인트·출구는 이 수에서 제외했다.

기존 연결통로는 오른쪽으로 들어가는 가로 터널이다. 이를 최상단 중앙에 놓았다. 마지막 왼쪽 길은 입구로 연결되고, 오른쪽 길은 출구 지붕으로 합류한 뒤 왼쪽 회랑으로 내려가 입구로 들어간다. 지붕 위 추가 장식 암반을 0으로 설정해 보행자를 가리지 않게 했다. 후속 씬은 로비다. 메인 캠페인의 챕터표와 기존 스테이지 연결은 변경하지 않았다.

## 정적 확인 결과

- 61개 SS2D 폴리곤 내부 겹침 0개. 오목 폴리곤 삼각분할 후 삼각형 교차로 확인했다. 공유 경계 접촉은 내부 겹침에 포함하지 않는다.
- 시계 방향, 16px 격자, 변 길이 90px 이상, 직접 리소스 파일과 내부 리소스 참조 확인.
- 연속 회랑 20개/출구 1개/승강기 0대, 노드 경로 중복 없음, 메타데이터 키 ASCII 확인.
- 반환 발판 높이 차 96px·틈 128px. 현재 설정의 연속 점프 수식상 96px 높은 곳의 수평 도달 거리 약 273.9px. 입력·충돌·색 전환을 포함하는 실제 주행 판정은 아니다.
- 최대 경사 약 31.61도. 기존 가이드 예시의 30도보다 조금 크며 일반 45도 보행 한계 안에 둔 설계다. 실제 보행은 미확인이다.
- 외곽 마감을 제외한 플레이 지형의 검정 면적 65.43%. 외곽 포함 전체 검정 면적은 96.00%다. 전체가 60~70%라고 보고하지 않는다.
- 외곽 2048px는 기준 1920×1080·줌 0.85 시야와 카메라 오프셋을 포함하도록 계산했다. 실제 모서리 화면 및 다른 화면비는 미확인이다.
- Godot 편집기·콘솔·headless·빌더·레벨검사·주행검사·저장소 엔진 회귀검사는 모두 **미실행**. 사용자 안전 예외를 준수했다. 정적 검사를 엔진 검사 통과로 간주하지 않는다.
- 최종 `node --check`와 작성 도구의 읽기 전용 `--check` 통과. `git diff --check` 오류 없음. Git의 삭제 변경 및 실제 누락 추적 파일 목록은 모두 비어 있었다.

## 작업 보존과 환경

기존 2-9 씬, 2-8 씬, PPT를 재작성하지 않았다. 최종 2-9 SHA256은 보존 기준 `83D35215A0D936F4421287E523C8744D40D406D23E3D69762D21FF1D3CE732B5`와 일치했다. PPT SHA256도 `C0BAF28C5CC54F149F74AC5F48A4AD10A1EC97120996B05B926BB2BBAD0DFAFC`로 기존 값과 일치했다.

이전 작업 시작 시 `git pull`은 권한 문제 뒤 승인된 재시도에서도 응답 없이 대기하여 중단했다. 동기화 완료로 보고하지 않는다. 이번 작업에서는 커밋·푸시하지 않았다.

`graphify-out/graph.json`이 없어 그래프 질의 대신 원본 파일을 읽었다. 코드 변경 후 `graphify update .`를 시도했으나 `uv trampoline failed to canonicalize script path`로 실패했다. 그래프 갱신은 완료하지 못했다.
