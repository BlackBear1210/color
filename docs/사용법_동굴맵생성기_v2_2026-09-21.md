(`벽_껍데기`, `칠하기_방식 = 2`), 발판·관문도 전부 SS2D Template 인스턴스다.

# ■ 관문 — 이 도구의 핵심

관문은 **띠를 가로질러** 놓여서 우회할 수 없다. 우회되면 장식이지 관문이 아니다.

| 종류 | 생김새 | 플레이어가 배우는 것 | 통과 방법 |
|---|---|---|---|
| **J 도약** | 2칸(192px) 구덩이 + 바닥에 가시 | **점프** | 뛴다 (건널 수 있는 거리 272px 안) |
| **C 색바닥** | 통로를 막는 5칸(480px) 색 슬래브 | **색 반전 / 칠하기** | ① Shift 로 내 색을 바꾸거나 ② 총으로 슬래브를 내 색으로 칠한다 |
| **G 유령다리** | 4칸(384px) 구덩이 + 안 칠하면 없는 유령 발판 | **쏴서 길을 만든다** | 유령 발판을 쏘면 굳어서 다리가 된다 (점프로는 절대 못 건넌다) |

**죽어서 배우되 억울하지 않게** — 관문 바로 앞(왼쪽 3칸)에 체크포인트를 자동으로 놓는다.

난이도 순서: 아래층(시작 쪽)은 `J → C → J → G`, 위층은 `C → G → C → J`.
무작위로 고르면 종류가 쏠려서(실측: 16개 중 유령다리 1개) **순번으로 돌려 가며** 배정한다.

# ■ 새 관문 종류를 추가하려면

`tools/생성기/관문.gd` 에 함수 하나를 더하면 끝이다.

1. `_새관문(동굴, out, x, 바닥y, 폭, 번호)` 를 만든다 (기존 `_도약`·`_색바닥` 을 복사)
2. 격자를 고치려면 `_파기(동굴, x, y)` 를 쓴다 (구덩이 등)
3. 발판을 놓으려면 `out["플랫폼"].append({이름, 사각, 종류, 색, 칠방식, 일방통행, 의도형태})`
4. **쏴서 여는 기믹이면** `out["사격"].append({자리, 목표, 대상})` 도 넣는다 —
   그래야 "포물선이 실제로 닿는가" 를 검증기가 봐 준다
5. `세우기()` 의 `match` 와 `_종류_고르기()` 에 글자 한 개 추가

관문이 지켜야 할 계약: **통로 폭 전체를 덮을 것**(우회 불가) · **앞뒤 3칸은 평평할 것**(도움닫기).

# ■ 손댈 때 조심할 것 (전부 실제로 한 번씩 터진 것)

1. **SS2D 는 콜리전을 스스로 굽고, 점 200개 오목 폴리곤에서 볼록 분해가 실패한다.**
   `Convex decomposing failed!` 가 뜨면 그 지형은 **콜리전이 통째로 사라진다.**
   → 껍데기는 `CollisionPolygon2D.build_mode = SEGMENTS`.
2. **그 설정은 `set_editable_instance()` 없이는 저장이 안 된다.** Template 인스턴스 내부 노드라서다.
3. **윤곽 단순화가 동굴을 파고들 수 있다.** 그래서 단순화 뒤 "빈칸이 폴리곤 밖으로 나갔나" 를 직접 세고,
   나가면 오차를 절반으로 줄여 다시 한다. 자기교차도 본다.
4. **"공간이 이어졌다" ≠ "플레이어가 갈 수 있다".** 계단은 **디딤을 채워야** 오를 수 있고,
   채운 디딤은 **보호 마스크에 넣어야** 천장 흔들기가 안 깎는다.
5. **격자 BFS 의 `건넘칸` 은 구덩이 칸 수가 아니라 칸 인덱스 차이다.** 2칸 구덩이는 인덱스 3.
6. **노드 메타 이름에 한글을 쓰면 조용히 실패한다** → `gen_seed` 등 ASCII.
7. **이 PC 에는 파이썬이 없다.**

# ■ [2026-09-23 추가] 발판은 **반드시 사이가 벌어져 있어야 한다**

도형님 지적: *"발판이 이어지면 그냥 점프 기믹 없이 스페이스만 누르면서 가는거야."*

그때까지 `배치.gd` 는 발판 폭이 2 칸(192 px)인데 **1 칸(96 px)씩** 전진하며 놓았다.
발판끼리 가로로 겹쳐서 **이어 붙은 경사로**가 됐고, 겹친 발판은 발판이 아니라 바닥이다.

`진단_플랫폼겹침` 으로 잰 전/후 (집 씨앗 1):

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 실제 침투(FAIL) | 4 | **0** |
| 규칙 3 근접 경고 | 25 | 5 |
| 겹친 예 | `디딤10 ↕ 디딤11 간격 96 · x겹침 192` | 없음 |
| 격자 BFS 닿는 칸 | 402 | **446** |

고친 값은 `배치.gd` 맨 위 상수 3 개다:

```gdscript
const 체인_발판칸: int = 2      ## 발판 폭 192 px (= 규격.최소_착지폭)
const 체인_틈칸: int = 2        ## 발판 사이 빈 공간 192 px (판정선 272 안)
const 체인_보폭칸: int = 4      ## = 발판칸 + 틈칸
```

- `_계단_체인()` — 가로로 갈 자리가 있으면 **징검다리**(4 칸씩 나아가며 1 칸씩 오른다)
- `_엇갈린_사다리()` — 거의 수직인 자리는 **좌우 288 px 엇갈린 사다리**(112 px 씩 올린다)
- **가로 공간이 모자라 틈을 못 만들면 아예 안 놓는다.** 억지로 메우면 "닿는 칸" 숫자는
  좋아지지만 화면에는 겹친 램프가 남는다 — 숫자를 위해 게임을 버리는 셈이다.

## 같이 고친 것

- `배치.채우기(…, 기존발판)` — 관문 슬래브·징검다리 **위에 방 발판을 겹쳐 놓던 버그**.
  관문은 배치보다 먼저 놓이는데 배치가 그걸 몰랐다(집 s1 에서 `발판03` 이 `관문14_색바닥` 을
  32 px 파고들었다). 겹친 두 발판은 색이 다를 수 있어 **밟는 순간 죽는 자리**가 된다.
- `조립2._체크포인트_솎기()` — 체크포인트 하나 = 광원 하나인데 바닥이 전부 `벽_껍데기`
  노드 하나라 **모든 빛이 한 캔버스 아이템에 겹친다**. 2층 방이 24 개로 엔진 한계(15~16)를
  넘고 있었다(적용본에 이미 들어 있던 버그). 1,600 px 안의 것을 합치고 10 개로 맞춘다.
- `--진단칸=x,y` — 미리보기 PNG 에서 이상한 자리를 칸 좌표로 들여다본다(PNG 픽셀 ÷ 10 = 칸).
- `--적용` 의 대상이 **설정마다 다르다**(`생성_동굴.gd _기본_대상`). `--설정=복도계단` 으로
  만들고 `--대상` 을 안 줘도 2층 방을 덮어쓰지 않는다.

새로 생긴 **내려가는 계단 모드**는 `docs/사용법_복도계단_생성기_2026-09-23.md` 참고.
