## 2. ★ 실측 — 그림과 콜리전이 얼마나 어긋나 있었나

`tools/진단_콜리전대_그림.gd` 를 작업자 Template 9 종 전부에 돌렸다.
**양수 = 그림이 콜리전보다 튀어나옴 · 음수 = 콜리전이 그림보다 큼.**

| Template | 손대기 전 | 손댄 뒤 |
|---|---:|---:|
| BRICK SOLID / HOLLOW | +0.0 ✔ | +0.0 ✔ |
| **BRICK STAIRS** | **−44.8** ✖ | **+0.0 ✔** |
| WOOD SOLID / HOLLOW / STAIRS | +0.0 ✔ | +0.0 ✔ |
| GRASS SOLID / HOLLOW / STAIRS | **+44.8** ✖ | +44.8 (§7-3 · 안 고침) |

**44.8 이라는 숫자의 정체**: taper 128×256 × `texture_scale 0.35` = 44.8 월드px.
구형 재질(방향별 엣지 + taper)은 이 taper 조각이 도형 밖으로 걸쳐 나간다.
**얇은 사방 재질은 `offset = -1.0` 으로 테두리를 안쪽에 그리므로 0.0 이 된다.**
"사방 미터 조인이 0.0px 까지 일치한다" 는 기존 기록은 BRICK SOLID/HOLLOW 와
WOOD 3 종에서 **그대로 재현 확인**했다.

## 3. 고친 것 ① — BRICK 테두리가 흰색으로 전환되지 않았다

### 증상

`test_사방재질_칠하기` 가 **12 통과 / 3 실패**. BRICK 3 종 전부 실행 중 경고:

```
스마트지형(TEMPLATE_BRICK_SOLID): '.../brick_v2_opaque/black/edge_top_thin.png' 의 흰색 짝을 못 찾음
```

흰색으로 칠하면 **채움만 하얘지고 얇은 테두리는 검은 채로 남는다.**
이 게임의 핵심 규칙("내 색과 다른 지형에 닿으면 즉사")에서 지형의 색이 반쪽만 바뀌는 것은
미술 문제가 아니라 **판정을 오독하게 만드는 문제**다.

### 원인

`scripts/스마트월드/지형.gd::_짝_텍스처()` 는 `.../black/x.png → .../white/x.png` 로
**폴더 이름만 바꿔** 짝을 찾고, 없으면 경고 한 줄 남기고 **조용히 건너뛴다**
(그 메시에는 페인트 셰이더가 안 꽂힌다).

`brick_v2_opaque/white/` 에 `edge_top_thin.png` 가 **아예 없었다.**
WOOD 는 `wood_v2/{black,white}/edge_top_thin.png` 양쪽 다 있어 정상이었다.

```
brick_v2_opaque/black/   edge_bottom · edge_left · edge_right · edge_top · edge_top_mid · edge_top_thin
brick_v2_opaque/white/   edge_bottom · edge_left · edge_right · edge_top          ← 두 장이 없다
```

### 고친 방법 — 새로 그리지 않고 **기존 흰색 원본을 검정과 똑같이 잘랐다**

`tools/파생_흰색짝_생성.gd` (신규 · 멱등) 가 두 단계로 한다.

1. 큰 검정(`black/edge_top.png` 1024×159) 안에서 작은 검정(`black/edge_top_thin.png` 1024×38)이
   **몇 번째 행부터 픽셀 단위로 완전히 일치**하는지 찾는다 → **y = 0…37** (완전일치)
2. 그 오프셋을 **큰 흰색**(`white/edge_top.png` 1024×159)에 그대로 적용해 잘라낸다

즉 얇은 띠는 원본의 **맨 위 38 행**이었고, 흰색 짝도 같은 38 행이다.
새 픽셀아트를 만들지 않았고, 해상도·감마·Texture Filter 를 건드리지 않았다.
`.import` 파라미터는 검정 짝과 **완전히 동일**함을 diff 로 확인했다.

| | |
|---|---|
| 만든 파일 | `assets/textures/smartshape/brick_v2_opaque/white/edge_top_thin.png` (1024×38) |
| 결과 | `test_사방재질_칠하기` **12/3 → 15 통과 / 0 실패** · 흰색 짝 경고 0 |

> `edge_top_mid.png` 는 흰색 짝이 여전히 없지만, **어떤 재질도 참조하지 않으므로** 만들지 않았다.

## 4. 고친 것 ② — BRICK 계단 콜리전이 그림보다 사방 44.8px 컸다

### 증상

Template 9 종 중 `TEMPLATE_BRICK_STAIRS` 만 `collision_offset = 44.8` 이 있었고,
저장된 폴리곤도 44.8px 바깥으로 확장돼 있었다(±494.8 / y −264.8…456.8 · 점은 ±450 / −220…412).

플레이어가 **계단 위 44.8px 에 떠서 걷고, 계단에 닿기 44.8px 전에 보이지 않는 벽에 막힌다.**

### 원인 — 보정이 두 번 걸렸다

2026-08-27 커밋에서 두 가지가 **같이** 일어났다.

1. 구형 재질의 "그림이 +44.8 튀어나옴" 을 보정하려고 **콜리전을 44.8 키웠다**
2. 같은 커밋에서 재질을 **얇은 사방(`offset = -1.0`, 안쪽 그리기)** 으로 바꿨다 → 튀어나옴이 0 이 됐다

1 번이 그대로 남아 부호가 뒤집힌 것이다. `TEMPLATE_WOOD_STAIRS` 는 `collision_offset` 자체가
없어서 정상이었고, 두 템플릿의 **점 배열은 13 개가 완전히 동일**하다.

> 당시 기록에 "Godot 헤드리스 검사가 signal 11 로 죽어 정적 검증만 했다" 고 적혀 있다.
> 이번에는 Godot 4.6.3 이 정상 실행되어 실측으로 잡혔다.

### 고친 방법

`TEMPLATE_BRICK_STAIRS.tscn` 에서

- `collision_offset = 44.8` **줄 삭제**
- `CollisionPolygon2D.polygon` 을 점 좌표 그대로(= `TEMPLATE_WOOD_STAIRS` 와 동일)로 되돌림

재질 · 텍스처 · 점 배열 · `collision_size(24)` 는 건드리지 않았다.

| | |
|---|---|
| 결과 | BRICK STAIRS **−44.8 → +0.0** · BRICK/WOOD 6 종 전부 0.0 |
| 육안 증거 | `tools/_shots/템플릿점검_BRICK_수정후.png` (초록 = 콜리전. 그림에 정확히 붙었다) |

|---|---:|---:|
| 콜리전 | **44 × 95.63** | 44 × 95.63 |

그대로 유효하다. 이 씬의 설계값은 전부 **상승 ≤ 110 · 간격 ≤ 180 · 단차 ≤ 110** 이다.

### 좌표 (진행은 −x → +x · 지상 윗면 y = 0)

### 왜 이 숫자인가

| 값 | 근거 |
|---|---|
| 계단 **180 × 110** | 폭은 코너 조각(90px)의 두 배 · 높이는 게이트 128 의 86% → **되돌아 올라올 수 있다**(소프트락 방지) |
| 공중 발판 **두께 200** | 엣지 띠 한 장이 38px. 위아래가 겹치면 FILL 이 사라져 검은 막대가 된다 (README §11) |
| 좁은 발판 **폭 360** | 코너 쿼드가 사방 90px 씩 먹는다. 300 미만은 모서리가 검게 파인 것처럼 보인다 → **폭으로 "좁다" 를 더 밀어붙이면 지형 결함과 구분이 안 된다** |
| ㄷ자 깊이 **110** | 한 단차. 들어갔다 나올 수 있다 |
| ㄱ자 천장 **시각 220** | 실효 = 220 − 48 = **172**. 몸 96 + 머리 위 76 → 안 끼이지만 "여긴 뛸 수 없다" 가 몸으로 읽힌다 |
| 치명_낙하거리 **900** | 계단 + 공중 발판 총 낙차 620. 기본 520 이면 한 번 떨어지는 것만으로 죽어서 원인을 못 가린다 |

### ★ 이번에 밟은 함정 — 높이가 같은 단이 연달아 오면 콜리전이 통째로 죽는다

계단 꼭대기에 착지 발판을 붙이면 마지막 단과 발판이 **같은 높이**라, 경계 x 에서
똑같은 점이 **두 번** 들어간다. 그 0 길이 변 때문에 `Geometry2D.offset_polygon()` 이
빈 배열을 돌려주고 `Convex decomposing failed!` 와 함께 **밟을 수 없는 지형**이 조용히 만들어진다.
**그림은 멀쩡하게 나오므로 눈으로는 절대 못 찾는다.**

→ `_계단덩어리()` 가 **높이가 같은 이웃 단을 먼저 합친다.** 같은 실수를 다시 안 하도록
   빌더 안에 주석으로 근거를 남겼다.

이 검사는 결과를 안 찍고 매번 멈췄다. "그냥 오래 걸리네" 로 보였을 뿐 **실패로도 안 잡혔다.**

원인: `_씬목록()` 이 재질 폴더를 통째로 훑는데, 2026-08-29 커밋 `ab7770f` 이
`벽돌 계단.tscn` · `벽돌 테스.tscn` 을 `BRICK_벽돌/` 안으로 옮기면서 그 둘까지 집었다.
두 씬의 루트는 스마트지형이 아니라 `시작상태` 가 없고,
131 줄의 `int(n.get("시작상태"))` 가 `int(null)` 이 되어 스크립트가 죽는다.

→ 이름 규칙(`TEMPLATE_*.tscn`)은 이 파일 머리말에 이미 적혀 있었다.
   **목록을 만들 때부터 그 규칙을 걸도록** 고쳤다. 이제 9 개만 보고 끝까지 돈다.

## 7. ★ 아직 안 고친 것 (지시 없이 건드리지 않았다)

### 7-1. BRICK 테두리의 무늬 주기가 채움과 2.86 배 어긋난다 — **Severity 2**

`검증_작업자씬` 의 실패 3 건이 이것이다: `texture_scale 이 0.35 가 아니다 (1.000)`.

| | 테두리 원본 | edge texture_scale | 월드 두께 | 월드 반복 주기 | 채움 주기 |
|---|---|---:|---:|---:|---:|
| WOOD | 1024×**109** | **0.35** | 38.15 | **358** | 358 ✔ |
| BRICK | 1024×**38** | **1.0** | 38.0 | **1024** | 358 ✖ |

`texture_scale` 은 가로·세로에 **같이** 곱해진다. BRICK 은 원본을 38px 로 잘라 두께를 맞췄기
때문에 배율을 1.0 으로 둘 수밖에 없었고, 그 결과 **테두리 무늬만 가로로 2.86 배 늘어났다.**
육안으로 확인된다 — `tools/_shots/프로토_테두리주기_BRICK_WOOD.png` 에서 WOOD 테두리는 잔결이
촘촘하고 BRICK 테두리는 같은 화면 폭에서 균열 무늬가 3~4 개뿐이다.

**올바른 고침**은 WOOD 와 똑같이 만드는 것이다:
`brick_v2_opaque/{black,white}/edge_top.png` 를 **38 이 아니라 109 행**으로 잘라
`texture_scale = 0.35` 를 준다 (109 × 0.35 = 38.15 = WOOD 와 동일 두께 · 주기 358).

> ⚠ **하지만 이건 테두리에 들어가는 그림 자체가 바뀐다**(갓돌만 있던 띠에 벽돌 켜가 들어온다).
> 타일셋 소유자(성진 / Codex)의 판단이 필요해서 **손대지 않았다.**
> 원본은 159 행이므로 109 행 크롭은 가능하다.

### 7-2. 되돌아간 수정 1 건 — WOOD `fill_mesh_offset`

`docs/작업기록_2026-08-28_..._나무_얇은테두리_채움인셋.md` 가 넣은
`fill_mesh_offset = -0.0375` 가 커밋 `ab7770f` 에서 **사라졌다.**
`fill_mesh_offset` 은 애드온에 실재하는 속성이다(`shape_material.gd:30` · `shape.gd:869`).

AABB 측정으로는 차이가 안 잡히는 **미세 코너 문제**라 육안 확인이 필요하다.
되돌린 것이 의도인지 아닌지 몰라서 **지시 없이 되살리지 않았다.**

### 7-3. GRASS 는 아직 구형 구성 (+44.8px) — **Severity 2**

`지형_잔디_v4_black_detail.tres` 는 방향별 엣지 4 + 코너 메타 + taper 8 장 구성이고
`offset` 이 없어 그림이 밖으로 +44.8px 나간다.
**GRASS 로 만든 발판은 보이는 윗면보다 44.8px 아래를 밟게 된다.**

이번 프로토타입에서 **GRASS 를 뺀 이유가 이것이다.** BRICK/WOOD 와 같은
얇은 사방 구조의 `.tres` 를 새로 만들면 되고(PNG 는 안 건드려도 된다),
`grass_v4` 는 LOCK 자산이라 별도 STEP 으로 분리했다.

### 7-4. 실제 스테이지는 아직 구형 재질을 쓴다

집 4 방 + 복도계단은 전부 `지형_벽돌v2_black_detail.tres` / `지형_나무v2_black_detail.tres`(구형)를
쓴다. `집_복도계단` 지형 17 개 중 **16 개가 +44.8px 상태**다(계단 1 개만 0.0).
키트만 갱신됐고 스테이지는 이관되지 않았다. **지시가 없어 건드리지 않았다.**

### 7-5. `assets/tileset/brick_black_seamless_341x307.png` 도 흰색 짝이 없다

`지형_벽돌v2_opaque_black_사방.tres` 의 채움으로 쓰이고, 그 재질을
`벽돌 계단.tscn` · `벽돌 테스.tscn` 이 참조한다. `black/` 폴더 안이 아니라
파일명 규칙에도 안 걸려 **칠해도 흰색으로 안 바뀐다.** 두 씬은 Template 이 아니라
이번 검증 범위 밖이라 손대지 않았다.
