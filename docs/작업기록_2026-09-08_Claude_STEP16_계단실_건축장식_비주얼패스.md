## 1. 왜 계단실이 계단실로 안 보였나 — 원인 3 가지

실화면을 찍어 재 보고 원인을 셋으로 갈랐다.

### ① 카메라가 아래층을 **25px 차이로** 못 보여줬다  ← 제일 큰 원인
플레이어가 FL1(윗면 220)에 서면 화면은 y −455~895 를 본다.
아래층 FL2 의 윗면이 **920**. 25px 차이로 화면 밖이다.
그래서 한 화면에 층이 하나만 들어오고, 위/아래의 공간 관계가 아예 안 보였다.

→ `카메라_계단` 의 `시선_오프셋` 을 **(190, 110) → (0, 300)**.
화면이 300px 아래를 보게 되어 **아래층 tread 가 화면에 들어온다.**
(x 오프셋 190 은 좌↔우로 왕복하는 지그재그 구간에서 방향이 안 맞아 0 으로 지웠다)

### ② tread 가 난간도 기둥도 없는 맨 판이었다
2950~3200px 짜리 판 하나만 덩그러니 있으니 "떠 있는 발판" 으로 읽힌다.

→ `장식_계단실` 이라는 **별도 부모** 밑에 SS2D 장식 **26 개**를 넣었다.
  · 수직 기둥 2 (왼쪽은 홀~1층 3140px 관통 · 오른쪽은 1층 천장에서 끊음)
  · 난간 4 조 (가로 손잡이 + 기둥 4 개씩) — FL1 · FL2 · FL3 · 2F 홀 가장자리
  · 소핏 6 (tread 끝에 매달리는 짧은 벽) — tread 가 "널빤지" 가 아니라 **바닥 슬래브**로 읽힌다

### ③ 계단실 위/아래 밝기가 거의 같았다
FL1 0.45 · FL2 0.42 · FL3 0.42 — 수직 방향이 안 느껴졌다.

→ **FL1 0.55 → FL2 0.42 → FL3 0.38** 로 등급을 줬고, FL2 에 없던 납작한 빛
(`계단FL2_단차빛` 종류 2)을 더했다. 어둡게 하되 tread 윗면을 **스치는** 빛이라
단차·가시·낙사 경계는 어느 층에서도 남는다(지시서 §17 1순위).

## 2. ★장식이 gameplay 에 개입하지 못하게 한 방법 (2 차 수정)

처음에는 StaticBody2D 의 layer/mask 를 0 으로 두고 CollisionPolygon2D 를 `disabled` 로 껐다.
**런타임에 되살아났다.** 통행 시험이 26/26 → **17/26** 으로 떨어졌고 플레이어가 난간에 걸려 멈췄다.

원인은 두 군데였다.

- `지형.gd::_충돌레이어_갱신()` 이 `_ready` 에서 `collision_layer` 를 **1 로 다시 쓴다**
- SS2D 가 `collision_update_mode` 에 따라 폴리곤을 **다시 굽는다**

**여기서 두 번 더 틀렸다. 세 번째에 맞았다.**

| 차수 | 시도 | 결과 | 왜 안 됐나 |
|---|---|---|---|
| 1 차 | layer/mask 0 + `CollisionPolygon2D.disabled = true` | 17/26 | `_충돌레이어_갱신()` 이 layer 를 1 로 되돌리고 SS2D 가 폴리곤을 다시 굽는다 |
| 2 차 | **StaticBody2D 를 통째로 제거** | 17/26 | 장식이 템플릿 씬의 **인스턴스**라, 인스턴스에서 자식을 지운 것은 .tscn 에 저장되지 않는다. 로드할 때 원본 PackedScene 이 다시 펼쳐지며 **되살아난다** |
| 3 차 | `지형.gd` 에 **`장식_전용` 스위치** 신설 · 노드 자신의 속성으로 켬 | **26/26** | 노드 자신은 owner 가 있어 .tscn 에 저장된다. `_충돌레이어_갱신()` 이 그 값을 보고 판정을 끈다 |

2 차가 왜 실패했는지가 이번 STEP 에서 제일 값진 발견이다 —
**인스턴스 씬은 자식을 지워도, 자식 속성을 덮어써도 저장되지 않는다.**
(자식에 owner 를 박으면 저장되지만 그건 CLAUDE.md §6 의 "노드가 두 벌" 사고를 부른다)
→ 인스턴스에 무언가를 남기려면 **노드 자신의 export 속성**이어야 한다.

`지형.gd` 에 더한 것은 export 하나뿐이고 **기본값이 false** 라, 기존 지형 122 개의 동작은
한 글자도 안 바뀐다(STAGE 1 회귀로 확인).

검증:
- 씬에 `"장식_전용" = true` 가 **26 개** 저장됨
- `진단_공간감.gd`(물리 point query 로 잰다) 결과가 장식 전/후 **완전히 동일**
  — 채움 11.1%% · 발판 18 개 · 화면 채움 24.4%% → 장식은 물리적으로 존재하지 않는다
- `진단_노멀맵_적용` : STAGE 2 지형 28 → **54** · 노멀맵 54 · 짝실패 0
  → 장식 26 개도 **노멀맵이 붙어 빛에 반응한다**(지시서 §9)

★장식을 `지형` 이 아니라 **별도 부모**에 둔 것도 의도다 —
`진단_플랫폼겹침.gd` 는 `지형` 의 자식만 센다. 그래서 검사 대상은 **28 개 그대로**,
겹침도 **0 / 378 그대로**다(지시서 §15 · §16).

그러면서도 SS2D 라서 **텍스처와 노멀맵을 그대로 쓴다** → 빛에 반응한다(지시서 §9).
`z_index −10` : 배경(−60)보다 앞, gameplay 지형(0)보다 **뒤** → 발판을 가리지 않는다.

### 낙하 경로를 막지 않는다 (설계 검산)
소핏은 전부 지그재그의 **안쪽**에 둔다.

| 낙하 | 경로 x | 소핏 | 관계 |
|---|---|---|---|
| 홀 6400 → FL1 | 6400→6600 | 6500~6660 (y 380~) | tread **아래**라 무관 |
| FL1 9450 → FL2 | 9450→9650 | 9290~9450 | 낙하선 **왼쪽** |
| FL2 6700 → FL3 | 6700→6490 | 6700~6860 | 낙하선 **오른쪽** |
| FL3 9450 → 1F | 9450→9660 | 9290~9450 | 낙하선 **왼쪽** |

→ 플레이어는 늘 구조물의 바깥면을 스치며 **계단실 빈 통로로** 떨어진다.

## 3. ★EXIT_GHOST 소프트락 — 검증 결과 **소프트락 아님**

STEP 15 에서 "잘못 칠하면 죽는다. 되돌릴 수 있는지 확인 못 했다" 로 남겨 둔 건이다.
전용 검사 `tools/진단_유령_되돌리기.gd` 를 만들어 실제로 돌렸다.

```
HALL_GHOST  검정→흰색 PASS (색 0→1 · 밟기 true) · 흰색→검정 PASS
FL2_GHOST   검정→흰색 PASS                        · 흰색→검정 PASS
EXIT_GHOST  검정→흰색 PASS                        · 흰색→검정 PASS
낙사 후 리스폰 지점  PASS  섰던 곳 (11000,2520) → 리스폰 (11000,2520) · 맵 처음으로 갔나=false
7 / 7 PASS
```

- 유령 3 장 전부 **양방향으로 다시 칠할 수 있다.** 잘못 칠해도 반대색으로 덮으면 복구된다.
- 죽어도 **맵 처음이 아니라 직전 안전지점**에서 다시 시작한다
  (`월드.gd` 의 `안전지점_자동저장 = true` — 마지막으로 안전하게 서 있던 땅).

⚠ 다만 **탄약**은 유한하다. 유령 3 장에 9 발이 들고 탄창은 12 발이라, 한 장을 잘못 칠하면
(3 발 낭비) 12 발을 넘긴다. 이때는 `E 회수` 로 칠한 물감을 되찾아야 한다
(`test_paint_system` 이 회수·재칠하기를 검증한다). **자원 순환으로 설계된 것**이지 막다른 길이 아니다.

```
✖ SS_WOOD_FLOOR_01 ↔ 벽_왼아래_BRICK_01   교집합 90000 px² · 파고듦 300 px
```

## 7. 네 번째로 틀린 것 — owner 재지정 세그폴트

멱등성(3 회 반복) 검사를 돌리다 `그림자_가림막.gd` 가 씬을 인스턴스했다 지울 때
**세그폴트**가 났다. 원인은 이 도구가 마지막에 부르던 `공통.주인_지정(루트, 루트)` 였다.

STEP 15 패치는 지형을 **새로 짓는** 도구라 새 노드에 owner 를 줘야 했다.
그런데 STEP 16 도구는 **이미 다 지어진 씬을 읽어서 손보는** 도구다.
이미 owner 가 있는 노드에 owner 를 다시 박는 것이 되고, 그게 정확히
CLAUDE.md §6 이 경고하는 사고다.

→ 블랭킷 owner 재지정을 **없앴다.** `PackedScene.instantiate()` 는 원래 씬이 소유하던
노드에 owner 를 이미 제대로 넣어 준다. 이 도구가 owner 를 줘야 하는 것은
**새로 만든 장식 노드뿐**이고 그건 `_장식()` 에서 하나씩 직접 준다.
제거 후 3 회 반복에서 세그폴트 없음.

★규칙으로 남길 것: **씬을 새로 짓는 도구와 읽어서 손보는 도구는 owner 처리가 다르다.**
읽어서 손보는 도구는 `주인_지정` 을 부르면 안 된다.

⚠ `patch_STAGE2_STEP16_계단실.gd` 는 씬을 instantiate → pack 하는 **빌드 도구**라
돌릴 때마다 SS2D 가 `_meshes` 를 다시 구워 부동소수점이 미세하게 달라진다(md5 변동).

평소에는 돌리지 않는 도구다(§4 와 같은 부류).

## 10. 남은 문제

1. **계단실이 아직 "계단"은 아니다.** 층·난간·기둥·소핏으로 **회랑(gallery)이 있는
   계단실**로는 읽히지만, 실제로 계단을 **걸어 내려가지는** 않는다(700~800px 낙하다).
   플레이어 점프 한계(높이 160 · 거리 240)상 걸어 내려가는 계단은 tread 를 잘게
   쪼개야 하는데, 그러면 STEP 15 에서 없앤 "촘촘한 발판" 으로 되돌아간다.
   → 지금은 **의도적 트레이드오프**다. 정말 계단을 걷게 하려면 플레이어 이동
     파라미터(`점프_거리_칸`)를 손대야 하고, 그건 gameplay 변경이라 이번 범위 밖이다.
2. **계단실 배경이 코드 벽지 하나**다. 층마다 다른 벽지/창문이 있으면 층 구분이 더 뚜렷해진다.
3. **`patch_STAGE2_STEP16_계단실.gd` 는 md5 가 매번 달라진다**(§8). 커밋할 때 diff 가 크게 잡힌다.
4. STEP 14 의 P0(**Stage 3 씬 참조 불일치** · git D 파일)은 이번에도 손대지 않았다.
   `챕터.gd` 는 `스테이지_3_거실.tscn` 을 가리키는데 그 씬이 없고, 출구는 `집_거실.tscn`
   으로 이어져 게임은 안 깨진다. STEP 13 작업기록 §10 상태 그대로다.
5. Stage 1 겹침 1 건은 §5 의 근거로 **일부러 안 고쳤다**.
