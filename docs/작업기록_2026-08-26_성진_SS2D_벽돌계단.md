## 계단 치수와 점

문서의 확정값을 그대로 사용했다.

| 항목 | 값 | 이유 |
|---|---:|---|
| 한 단 폭 | 180px | 엣지·코너가 겹치지 않는 검증값 |
| 한 단 높이 | 110px | 현재 128px 점프 안전 범위 안 |
| 상승 횟수 | 4 | 작업자 템플릿 확정값 |
| 꼭대기 발판 | 180px | 꼭대기를 실제로 밟을 수 있게 함 |
| 밑동 두께 | 192px | 공중 발판 권장 두께 |
| 전체 외곽 | 900×632px | x -450~450, y -220~412 |

폐곡선의 고유점 12개:

```text
(-450,  220) → (-270,  220)
              → (-270,  110) → ( -90,  110)
                              → ( -90,    0) → (  90,    0)
                                               → (  90, -110) → ( 270, -110)
                                                                 → ( 270, -220) → ( 450, -220)
                                                                                   → ( 450,  412)
                                                                                   → (-450,  412)
                                                                                   → 닫기
```

오른쪽으로 올라가며, 오른쪽은 긴 외벽, 아래는 막힌 밑동이다.

## 씬 구조

```text
벽돌계단 (SS2D_Shape)
└ StaticBody2D
  └ CollisionPolygon2D
```

`CollisionPolygon2D`도 렌더 도형과 같은 12점을 사용한다. 따라서 보이는 계단과
플레이어가 밟는 면 사이에 빈 공간이나 위치 차이가 없다.

처음에는 게임용 `scripts/스마트월드/지형.gd`를 붙였지만 이 재질은 검정 전용이라
런타임 페인트 시스템이 흰색 짝 텍스처를 요구하는 경고가 났다. 요청은 페인트 지형이 아니라
`벽돌 테스` 디자인을 사용하는 SS2D 계단이므로, 최종본은 **순수 `SS2D_Shape`**로 만들었다.
콜리전은 그대로 있어서 플레이어가 밟는 데는 문제가 없다.

## 재질에서 반드시 유지할 값

계단은 90° 안쪽·바깥쪽 모서리가 많아서 아래 값이 빠지면 바로 깨진다.

```text
normal range: 0~360° 한 런
edge texture: edge_top_thin.png (1024×38)
fit_mode: CROP
uniform_width: true
weld: true (기본값)
offset: -1.0
fill: brick_black_seamless_341x307.png
```

- 각도별로 엣지 머티리얼을 나누면 계단 모서리마다 런이 끊겨 겹친다.
- `CROP`을 빼면 180px 짧은 계단 변에 1024px 텍스처가 압축된다.
- `uniform_width`를 빼면 모서리 각도에 따라 테두리 두께가 달라진다.
- `offset=-1`을 빼면 테두리 절반이 도형 밖으로 튀어나온다.

## Codex에서 Godot 4.6.3이 접근 위반으로 죽었던 원인

작업 중 `Choose Just-In-Time Debugger`, `0xC0000005`, `signal 11`이 떴다.

### 첫 사고

PowerShell에서 GUI 서브시스템 `godot.exe`를 `&`로 연속 호출하니 종료를 기다리지 않고
반환되어 검사 14개가 동시에 실행됐다. 여러 프로세스가 같은 `.godot` 캐시를 건드렸다.

### 최소 재현으로 확정한 실제 환경 차이

- `C:\Users\Public\godot46\godot.exe --headless --version` → 정상, 4.6.3 확인
- 샌드박스 안 `-s res://tools/_codex_min.gd` → 접근 위반
- 같은 4.6.3·같은 스크립트를 샌드박스 밖에서 실행 → `exit=0`

즉 Godot 버전 문제가 아니라 **Codex 샌드박스의 사용자 설정·캐시 경로 권한과
Godot 스크립트 모드의 충돌**이었다. Claude Code에서 안 났던 이유도 실행 권한 환경 차이다.

이후에는 승인된 `C:\Users\Public\godot46\godot.exe`를 샌드박스 밖에서
`Start-Process -Wait -WindowStyle Hidden`으로 한 번에 하나씩 실행했다.

## 편집 방법

`벽돌 계단.tscn`을 열고 루트 `벽돌계단`을 선택하면 SS2D 점 편집 도구가 나온다.

- 단을 늘릴 때: 수평점과 그 다음 수직점을 **한 쌍**으로 추가한다.
- 단 폭은 180px 이상을 권장한다.
- 단 높이는 현재 플레이어 기준 128px 이하로 둔다.
- 마지막에는 꼭대기 수평 발판을 남긴다.
- 재질의 Edge Meta를 4방향으로 쪼개지 않는다. 0~360° 한 런을 유지한다.
