# ■ 동굴 모드(`--설정=집`)와 무엇이 다른가

|  | `--설정=집` (동굴층.gd) | `--설정=복도계단` (계단층.gd) |
|---|---|---|
| 생김새 | 평평한 **띠**가 여러 겹 | 뱀처럼 꺾이며 **내려가는 한 줄기** |
| 바닥 높이 | 층마다 **고정** | **x 마다 다르다**(계단) |
| 층 잇기 | 지그재그 세로 갱도 | 다리 끝의 **큰 계단** |
| 비율 | 232 × 60 칸 (가로로 김) | 160 × 90 칸 (세로로 김) |
| 주 난이도 | 관문 + 방 발판 | 관문 + **징검다리 구덩이** |

```
     ┌──복도──┐▄▖                                    ← 다리 0 (오른쪽으로)
              ▝▚▄▖ 복도 ┌──복도──┐▄▖
                   ▝▀▀▀▀▀        ▝▚▄▖
          ▗▄▞▘ ┌──복도──┐ ▗▄▞▘                       ← 다리 1 (왼쪽으로)
     ┌──복도──┐▄▖                                    ← 다리 2 (오른쪽으로)
```

- **다리(leg)** = 한 방향으로 쭉 가는 구간. 방향이 번갈아 바뀐다.
- 다리 안은 `[평평한 복도] → [작은 계단 2~5 단] → [복도] → …` 의 되풀이.
- 다리 끝에서 **큰 계단**으로 다음 다리 높이까지 내려간다.
- 시작은 **왼쪽 위**, 출구는 **오른쪽 아래**.

# ■ 징검다리 구덩이 — 이 맵의 진짜 난이도

복도 한가운데를 뚫고 발판으로 건너게 한다. 도형님 지적(2026-09-23)을 그대로 구현한 것:

> "발판이 이어지면 그냥 점프 기믹 없이 스페이스만 누르면서 가는거야.
>  한 칸씩 뛰어서 발판을 배치하면 점프를 실수했을 때 떨어져 다시 올라가야 하니까 어려움을 주는 거지."

```
  바닥 ▓▓▓▓▓█  ▄▄  ▄▄  ▄▄  █▓▓▓▓▓        ▄▄ = 발판 2 칸(192 px)
            ╲  ░░  ░░  ░░  ╱             ░░ = 빈 공간 2 칸(192 px)
             ╲▲ ▲ ▲ ▲ ▲ ▲╱               ▲  = 가시(구덩이 바닥)
```

- 발판 윗면이 **복도 바닥과 같은 높이** → 달려와서 그대로 뛴다
- 발판 사이 192 px 는 판정선 272 px 안 → **뛰면 반드시 건너지고, 안 뛰면 반드시 빠진다**
- 구덩이 깊이 3 칸(288 px) → 오르기 한계 128 px 를 넘어 **못 나온다** → 가시로 죽이고
  **구덩이 바로 앞 체크포인트**에서 다시 시작한다
- ⚠ 가시를 성능 때문에 듬성듬성 깔면 **빠져도 안 죽는 소프트락**이 된다. 덮는 면적은 절대 줄이지 말 것

| `진단_절차생성_예산` | 예산 안 | 아래 두 가지가 제일 먼저 터진다 ↓ |

**제일 먼저 터지는 두 가지 (실측으로 둘 다 한 번씩 터졌다)**

1. **한 지형에 겹친 광원** — 체크포인트 하나가 PointLight2D 하나인데, 바닥·벽이 전부
   `벽_껍데기` **노드 하나**라 맵 안 모든 체크포인트 빛이 같은 캔버스 아이템에 겹친다.
   Godot 4 의 한계는 캔버스 아이템당 15~16 개(하드코딩). 19 개에서 터졌다.
   → `조립2.gd _체크포인트_솎기()` 가 1,600 px 안의 것을 합치고 10 개로 맞춘다.
2. **hazard 순회 수** — `월드.gd _사망_판정()` 이 매 물리 프레임 hazard 노드마다
   `get_overlapping_bodies()` 를 부른다. 가시를 칸마다 놓았더니 86 개(권고 60)가 됐다.
   → `가시.gd` 의 `칸수`(1~20 · 한 칸 32 px)로 6 칸씩 묶어 24 개로 줄였다. **덮는 면적은 그대로.**

# ■ 손댈 때 터지는 것 (계단 맵 고유)

1. **한 단을 2 칸(192 px)으로 키우면 안 된다.** 내려가는 건 공짜지만 **되돌아 못 올라온다**
   (오르기 한계 128 px). 체크포인트로 돌아가거나 관문을 다시 시도할 수가 없어진다.
2. **큰 계단은 다음 다리 방향으로 내려가야 한다.** 가던 방향 그대로 내려가면 다음 다리가
   큰 계단 **바로 밑**을 되돌아 지나가면서 사이 바위가 2~3 칸밖에 안 남아 천장이 뚫린다.
3. **세로 예산을 먼저 나눈다**(`계단층.gd _예산()`). "내려가고 싶은 만큼" 두면 마지막 다리가
   맵 바닥을 뚫거나 다리끼리 겹친다.
4. **관문은 평평한 바닥만 고른다**(`관문.gd _바닥_평평`). 그래서 계단 위가 아니라 복도에 선다.
   복도를 짧게 하면 관문이 한 개도 안 선다.
5. **층의 바닥 y 가 x 마다 다르다.** `관문.gd` 는 `동굴["바닥줄"]`(다리마다 길이 W 인 배열,
   −1 = 이 x 에 이 다리 없음)에서 읽는다. 평평한 맵에는 이 키가 없고 층선을 그대로 쓴다.

# ■ 지금의 한계 (다음 작업)

- 다리 안이 **한 줄기**다. 갈림길이나 되돌아오는 고리가 없어서 탐험 요소가 없다.
- 복도 천장이 랜덤 높이일 뿐, 기둥·벽감 같은 **실내 구조물**이 없어 아직 "복도" 보다는 "굴" 에 가깝다.
- 재질이 전부 WOOD 다. 집 챕터 규칙(나무 = 방 안 / 벽돌 = 벽·기둥)대로라면
  껍데기는 `TEMPLATE_BRICK_SOLID`, 발판만 WOOD 여야 한다. `설정.gd 구조_템플릿` 한 줄이다.
- `레벨검사.gd` 는 이 씬을 못 읽는다 — 바닥이 전부 `벽_껍데기`(구조물)라 도달성 그래프에서 빠진다.
  **v2 씬은 생성기 자체의 `연결` 줄과 `진단_플랫폼겹침` 으로 판단할 것.**
