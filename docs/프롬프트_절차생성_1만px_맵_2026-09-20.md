# ■ 받은 프롬프트에서 **틀린 값** (그대로 다른 AI 에 넣으면 안 된다)

실제 코드와 대조한 결과다. 나머지 경로(`색규칙.gd`·`빛기둥.gd`·`조명표준.gd`·`하수도_빌더_공통.gd`)와 노멀 세기(WOOD 1.6 · GRASS 0.9 · IRON 1.4)는 **맞다.**

| 받은 프롬프트 | 실제 | 왜 치명적인가 |
|---|---|---|
| "점프 높이 20칸(320px) / 수평 거리 약 240px" | **높이 10칸 = 160 px · 거리 20칸 = 320 px** (하수도) · 집은 거리 15칸 = 240 px | 높이와 거리가 **뒤바뀌어 있다.** 320 높이를 믿고 생성하면 **올라갈 수 없는 맵**이 대량 생산된다 |
| "SS2D `Path2D` 노드 포인트 배열로 변환" | SS2D 는 Path2D 를 안 쓴다. **`SS2D_Point_Array` + `add_points()` + `close_shape()`** | 그대로 구현하면 컴파일도 안 된다 |
| "Bresenham 직선으로 사격 경로(LoS) 검증" | 총알은 **포물선**이다 — 탄속 1150 px/s · 중력 900 · 수명 3 초 | 1,000 px 앞을 직선으로 쏘면 실제로는 **약 340 px 아래**에 맞는다. 직선 LoS 는 거짓말 |
| "치명 낙하 1500 · 줌 1.0" | 맞다. 단 **하수도 한정**. 집은 900(복도계단)·520(옛 기준) | 챕터마다 다르다. 상수로 박지 말고 씬에서 읽어라 |
| "Collision 을 핵심 지형만 켜고 Simplify" | 이 저장소 규약은 **`collision_offset = 0` · 외곽선 그대로**. 깎으면 이웃 사이에 48 px 슬롯이 생긴다 | 단순화하면 2-8 때 났던 "플레이어가 낀다" 사고가 재발 |

# §1. 네 가지 질문에 대한 답

## 1-1. 지형을 랜덤으로 만들 수 있나 — 된다, 단 "조립기" 로

이 저장소는 이미 **맵을 코드로 짓고 있다.** `tools/build_하수도_2-1.gd` ~ `2-4.gd` 는 좌표표를 들고 `tools/하수도_빌더_공통.gd` 를 불러 씬을 통째로 찍어낸다. 즉 **"좌표를 어디서 가져오는가" 만 사람 → 알고리즘으로 바꾸면 절차 생성이 된다.** 새 파이프라인을 만들 필요가 없다.

그런데 **완전 무작위 지형은 이 게임에서 작동하지 않는다.** 이유가 세 가지다.

1. **모양 어휘가 이미 정해져 있다.** `가이드라인_스테이지2_분기형맵_2026-09-12.md` §5 는 S1(직사각형)·S3(역사다리꼴)·S5(경사로)·S6(ㄱ자) 같은 어휘와 각각의 최소 치수를 못 박아 놨다. 펄린 노이즈로 언덕을 뽑으면 이 어휘 밖으로 나가고, 그 순간 **이 챕터처럼 안 보인다.**
2. **색이 지형보다 먼저다.** 지형을 먼저 뽑고 색을 칠하면 "흰 바닥 위에서 검정으로 시작" 같은 즉사 배치가 나온다. 색 구간을 먼저 정하고 그 안에 지형을 채워야 한다.
3. **풀 수 있다는 증명이 필요하다.** 랜덤 맵에는 공략이 없다. 그런데 이 저장소의 검사기 `하수도_주행검사.gd` 는 **사람이 적은 공략표를 태워 보는** 도구다. → **생성기가 맵과 공략을 같이 뱉어야 한다.**

> **결론: 생성기는 "지형을 상상하는 기계" 가 아니라 "합법적인 조각을 규칙대로 잇고, 그 정답 경로를 같이 적어 내는 기계" 다.**

## 1-2. 공중 발판·장애물·기믹을 오류 없이 놓을 수 있나 — 생성만으로는 안 된다

"오류 없이" 를 보장하는 것은 생성 알고리즘이 아니라 **검사**다. 이 저장소에는 이미 두 개가 있다.

| 도구 | 무엇을 보나 | 못 보는 것 |
|---|---|---|
| `tools/레벨검사.gd` | 실제 물리로 표면을 훑어 **도달 불가 · 소프트락 · 치명 낙하**를 잡는다 | **색·탄약을 전혀 안 본다.** 통과해도 흰 바닥에 검정으로 내려서면 죽는다 |
| `tools/하수도_주행검사.gd` | 공략표대로 **진짜로 태워 본다.** 지형·색·물·탄약이 한 번에 걸린다 | 공략표를 **사람이 적어야 한다** |

→ 파이프라인은 이렇게 된다.

```
씨앗(seed) → 골격 생성 → 검산(겹침·격자·변) → 레벨검사(도달성) → 공략 자동 생성 → 주행검사(색·탄약)
   ↑                                                                                    │
   └──────────────── 하나라도 실패하면 씨앗을 버리고 다음 씨앗 ─────────────────────────┘
```

**생성기의 성공률은 10~30 % 로 잡는 것이 정상이다.** 씨앗 100 개를 돌려 20 개가 살아남고 그중 사람이 5 개를 고르는 식이다. 이게 손으로 짓는 것보다 빠른 이유는, 검사가 **헤드리스로 자동**이기 때문이다(스테이지 하나 로드 1 초 미만 — §5 실측).

## 1-3. 월드마다 SS2D 디자인이 다른데 — 된다, 이미 그렇게 갈려 있다

테마 교체는 **이미 `하수도_빌더_공통.gd` 가 하고 있는 일**이다. `재질_검`·`재질_흰`·`재질_선반_검`·`재질_선반_흰` 네 칸만 갈아 끼우면 같은 좌표표로 다른 외관이 나온다.

| 층 | 집 | 하수도 | 도시(예정) |
|---|---|---|---|
| 지형 프리팹 | `스마트 매쉬 assets/` Template 26종(WALL·WOOD·BRICK·GRASS·METAL·CEMENT·GHOST) | `scenes/지형/하수도/` 기본지형·공중선반 각 흑/백 | **새로 만들어야 한다** |
| 재질(.tres) | brick_v2 · wood_v2 · grass_v4 · metal_v1 | sewer_masonry_v02 · sewer_ledge_v03 | 신규 |
| 노멀 세기 | WOOD 1.6 · GRASS 0.9 · IRON 1.4 · BRICK 수제 | 벽돌 수제 | 신규 측정 |
| 배경 | `실내배경.gd` + 원화 PNG | `하수도_다층배경_v02.tscn` | 신규 |
| 모양 어휘 | 방·벽·기둥·계단 (건축) | S1~S6 · 직각 · 곡선 0 | **여기부터 정해야 함** |

**주의 — 갈아끼우면 안 되는 것이 하나 있다.** 재질은 교체해도 되지만 **`지형.gd` 가 붙이는 페인트 셰이더는 교체하면 안 된다.** 하수도 v01 재질을 집 지형에 꽂았더니 칠이 안 먹었던 사고가 이미 있다(메모리: 집월드 플랫폼·배경 공통가이드). 테마팩은 **"재질 + 프리팹 + 배경 + 어휘"** 까지만 바꾸고 스크립트는 공용으로 둔다.

**진짜 어려운 부분은 기하가 아니라 어휘다.** 집은 "방과 복도", 하수도는 "수로와 갱도", 도시는 "건물과 옥상" 이라 **같은 생성 알고리즘으로 세 개가 다 그럴듯해지지 않는다.** 권장: 생성기 코어(경로 그래프·도달성·색 구간)는 하나, **방 배치 규칙만 월드별 테이블**로 분리.

## 1-4. 조명·노멀맵이 CPU/GPU 를 잡아먹나 — CPU 는 아니다, GPU 는 "총량" 이 아니라 "한 덩어리" 가 문제

§5 에 실측을 전부 적었다. 요약하면:

- **CPU: 전혀 문제 없다.** 1.7만 × 8.7천 px 맵(화면 74 장)도 물리 60 틱이 정확히 1,000 ms = 실시간 유지. 노드 400~600 개는 Godot 에게 아무것도 아니다.
- **GPU: 총 광원 수는 문제가 아니다.** 화면 밖 광원은 엔진이 알아서 빼고, 이 프로젝트 스테이지의 광원은 12~48 개다.
- **진짜 위험은 광원 개수 한계 하나다.** Godot 4 의 2D 라이트는 **캔버스 아이템 하나당 15~16 개**까지만 먹는다(엔진에 하드코딩·프로젝트 설정으로 못 바꾼다). **SS2D 지형 한 덩어리 = 캔버스 아이템 하나**이므로, 지형을 길게 뽑을수록 그 하나가 광원을 다 물게 된다.

> **실측: `스테이지_2_복도계단.tscn` 의 `선반_1층_SS_BRICK` 한 노드에 광원 13 개가 겹쳐 있다.** 한계 15 까지 2 개 남았다. 여기에 광원을 더 놓거나 지형을 더 길게 이으면 그 지형만 빛이 끊긴다. **자동 생성 이전에 이미 있는 문제다.**

# §2. 적용 아키텍처 — 3 층으로 나눈다

```
┌─ 3층 · 테마팩 (월드마다 하나)  ──────────────────────────────┐
│  프리팹 경로 · 재질 .tres · 배경 씬 · 장식 키트 · 모양 어휘 표 │
└───────────────────────────────────────────────────────────────┘
┌─ 2층 · 생성기 (월드 공용) ────────────────────────────────────┐
│  씨앗 → 청크 그래프 → 경로/갈림길 → 색 구간 → 방 채우기        │
│  출력: ① 좌표표(Array)  ② 공략표(Array)  ③ 씨앗·설정 기록     │
└───────────────────────────────────────────────────────────────┘
┌─ 1층 · 기존 빌더 (손대지 않는다) ─────────────────────────────┐
│  tools/하수도_빌더_공통.gd — b.지형()·b.유령()·b.공중선반()   │
│  b.검산() · 색비율_보고() · GEN_EDIT_STATE_INSTANCE 저장       │
└───────────────────────────────────────────────────────────────┘
```

**핵심: 생성기는 씬을 직접 만들지 않는다. 좌표표만 만들어 기존 빌더에 넘긴다.**
이유 — 빌더에는 이미 1 년치 사고 대응(편집상태 인스턴스·일방통행 owner·콜리전 offset 0·무늬 재적용)이 들어 있다. 생성기가 씬을 직접 조립하면 그 사고를 **전부 다시 겪는다.**

## 생성 단계 (씨앗 하나가 맵이 되기까지)

| 단계 | 하는 일 | 검사 |
|---|---|---|
| G1 | 씨앗으로 청크 격자(1,024 px 단위) 위에 **주경로** 를 그린다 — 상승/하강/수평 중 하나 | 경로 길이 ≥ 목표 |
| G2 | 주경로에 **갈림길 3 종**(F1 막다른 길·F2 고리·F3 지름길)을 붙인다 | 각 1 개 이상 |
| G3 | 경로를 **색 구간**으로 자른다(검정 구간 / 흰 구간, 경계마다 80 px 틈) | 검정 65 ± 5 % |
| G4 | 각 청크를 **어휘(S1~S6)로 채운다** — 방 하나 = 바닥·벽·천장 + 발판 | 점프 도달성 |
| G5 | 장애물·기믹을 **갈래마다 1 개 이상** 놓는다 | 6~10 개 · 4 종 이상 |
| G6 | **공략표를 같이 뱉는다** — G1~G5 가 경로를 알고 있으니 적을 수 있다 | 주행검사 통과 |

**G6 이 이 설계의 전부다.** 경로를 알고 있는 생성기만이 공략을 적을 수 있고, 공략이 있어야 "이 맵은 깰 수 있다" 가 증명된다. 나중에 붙이려 하면 못 붙인다.

## 도달성 판정은 이렇게 (직선 LoS 아님)

```gdscript
## 발판 A 의 가장자리에서 발판 B 에 올라설 수 있나 — 레벨검사.gd 와 같은 잣대.
## ⚠ 여유(0.80 / 0.85)를 빼면 "이론상 가능" 한 자리가 나오는데, 사람 손으로는 못 한다.
static func 갈_수_있나(a_끝: Vector2, b: Rect2, 점프높이: float, 점프거리: float) -> bool:
	var 올라갈_높이 := 점프높이 * 0.80       # 조작 오차 20 % 여유
	var 건널_거리 := 점프거리 * 0.85         # 조작 오차 15 % 여유
	var 수직 := a_끝.y - b.position.y        # 위로 갈수록 양수(y 는 아래로 증가)
	if 수직 > 올라갈_높이:
		return false
	var 수평: float = maxf(b.position.x - a_끝.x, 0.0)
	# 내려가는 점프는 더 멀리 간다 — 떨어지는 동안에도 수평 속도가 유지되기 때문.
	# 단 700 px 낙하에 197 px 가 한계다(CLAUDE.md "플레이어는 160px 밖에 못 뛴다").
	if 수직 < 0.0:
		건널_거리 += minf(absf(수직) / 700.0 * 197.0, 197.0)
	return 수평 <= 건널_거리


## 서 있는 자리 p 에서 목표 t 를 **쏴서 맞출 수 있나** — 직선이 아니라 포물선이다.
## 총알: 탄속 1150 px/s · 중력 900 · 수명 3 초 · 단단한 레이어 1|8 (총알.gd·총.gd 와 같은 값)
static func 쏠_수_있나(공간: PhysicsDirectSpaceState2D, p: Vector2, t: Vector2) -> bool:
	# 조준각을 훑으면서 총알을 그대로 시뮬레이션한다. 총.gd 의 궤적 미리보기와 같은 계산이라
	# "조준선에 보이는 대로 맞는다" 가 유지된다.
	for 각도 in range(-70, 71, 5):
		var 속도 := Vector2.RIGHT.rotated(deg_to_rad(각도)) * 1150.0
		if t.x < p.x:
			속도.x = -속도.x
		var 자리 := p
		for _i in int(3.0 * 60.0):              # 수명 3 초 = 180 프레임
			속도.y += 900.0 * (1.0 / 60.0)      # ★속도를 먼저 더하고 위치를 옮긴다(총알.gd 순서)
			var 다음 := 자리 + 속도 * (1.0 / 60.0)
			if 다음.distance_to(t) < 48.0:
				return true
			var q := PhysicsRayQueryParameters2D.create(자리, 다음, 1 | 8)
			if 공간.intersect_ray(q):
				break                            # 지형에 먼저 막혔다 → 이 각도는 실패
			자리 = 다음
	return false
```

# §3. 적용 시 주의할 점 — 이 저장소 고유의 지뢰

## 3-1. 생성기를 **두 번 돌리면 안 된다**

`CLAUDE.md` §4: *"씬을 통째로 다시 만드는 도구(`tools/build_*.gd`)는 평소에 돌리지 않는다. 에디터에서 손본 값이 전부 날아간다."*

생성기도 똑같다. **"생성은 한 번, 그 뒤로는 손 편집"** 이 원칙이다.
→ 생성기 출력에 **씨앗과 설정을 파일로 같이 남긴다**(`stage_3-7_생성정보.json`). 나중에 "왜 이렇게 생겼지" 를 추적할 수 있고, 같은 맵을 다시 뽑을 수도 있다. 다시 뽑으면 **손본 것이 날아간다는 것만 기억**하면 된다.

## 3-2. 인스턴스는 반드시 `GEN_EDIT_STATE_INSTANCE`

그냥 `instantiate()` 로 만들면 서브씬과 다른 값이 **스크립트 기본값과 같다는 이유로 저장에서 빠진다.** 흰 물이 회색으로 되살아난 사고가 이미 있었다(2-2 주행검사에서 발견). 빌더를 쓰면 자동으로 지켜진다 — **직접 씬을 조립하지 말아야 하는 이유이기도 하다.**

## 3-3. 읽어온 씬 노드에 owner 를 다시 박지 않는다

`CLAUDE.md` §6. 어기면 다음 로드 때 노드가 두 벌이 되고 **씬 교체 시 세그폴트**다. 새로 만든 노드에만 owner 를 준다.

## 3-4. 셰이더에 한글 금지

`.gdshader` 안에 한글이 들어가면 **조용히 셰이더가 안 나온다**(에러도 안 뜬다). 생성기가 셰이더를 건드릴 일은 없지만, 국소 색반전을 새로 만들려 한다면 반드시.

## 3-5. 국소 색반전은 **이미 있다** — 새로 만들지 말 것

받은 프롬프트의 [STEP 3](탄환 명중 지점 주변만 셰이더 마스크로 반전)은 **이미 구현되어 있다.**
`shaders/지형_페인트.gdshader` 의 `seeds[24]` 가 정확히 그것이다. 노드 로컬 좌표 + 반지름 + 색 + 흘러내림 + 젖음까지 들어 있다. 새로 설계하면 **HUD·탄약 환급·연결 페인트·유령 발판이 전부 끊어진다.**

다만 **한계를 알고 써야 한다**:
- 한 노드에 **얼룩 24 개**까지. 25 번째가 생기면 가장 오래된 것이 **조용히 사라진다.**
- 탄창이 12 발이라 사람이 혼자 쏴서는 잘 안 넘지만, **페인트 분사기·호퍼·연결 페인트**가 같은 노드를 계속 찍으면 넘는다.
- **긴 바닥을 노드 하나로 뽑으면 그 한 노드가 시드 24 개를 전부 쓴다.** → 규칙 20.

## 3-6. 색 판정에 참여하는 것과 아닌 것을 섞지 말 것

`색규칙.gd` 머리 주석: *"칠할 방법이 없는 것까지 죽이면 흰색으로는 방을 지나갈 수가 없다."*
생성기가 벽·천장을 `칠하기_방식 = 안칠해짐` 으로 두지 않고 전부 칠 가능으로 뱉으면, **흰색 플레이어가 지나갈 수 없는 방**이 대량 생산된다.

| 역할 | `칠하기_방식` | `무색일때_통과` |
|---|---|---|
| 밟는 바닥·발판 | 전체칠_가능 (긴변 ≤ 576) | false |
| 큰 바닥·수로 바닥 | **부분칠만** | false |
| 유령(칠해야 생기는) 발판 | 전체칠_가능 | **true** |
| 벽·천장·기둥 (구조물) | **안칠해짐** | false |
| 장식 | 안칠해짐 + `장식_전용 = ON` | — |

## 3-7. 빛기둥 모드를 연출용으로 쓰지 말 것

`빛기둥` 모드 1(경계)·2(발판)는 **`색경계` 그룹에 들어가 색 판정에 관여한다.** 분위기용으로 뿌리면 플레이어 색이 제멋대로 강제된다. 연출은 **모드 0** 만.

## 3-8. 스테이지마다 기준값이 다르다 — 상수로 박지 말 것

| 값 | 하수도 | 집(복도계단) |
|---|---|---|
| 점프 거리 | 320 (20칸) | 240 (15칸) |
| 치명 낙하 | 1500 | 900 |
| 카메라 줌 | 1.0 | 1.0 (2층방) / 0.85 (STEP15) |

생성기는 **이 세 값을 인자로 받아야 한다.** 하드코딩하면 "같은 폭의 틈이 한 판에서는 건너지고 다른 판에서는 못 건너는" 사고가 재발한다.

# §4. 성능 — 실측 (2026-09-20 · `tools/진단_절차생성_예산.gd`)

## 4-1. 실측 표

| 스테이지 | 크기 | 화면 | 노드 | SS2D 지형 | 광원 | 로드(메시·콜리전까지) | 실시간 유지 | **한 지형에 겹친 광원 최대** |
|---|---|---|---|---|---|---|---|---|
| `stage_2-4` | 9,600 × 4,096 | 19.0 장 | 613 | 43 | 12 | 763 ms | 998 ms **여유** | 4 ✔ |
| `stage_2-11` | 17,664 × 8,704 | 74.1 장 | 431 | 25 | 12 | 794 ms | 1000 ms **여유** | 3 ✔ |
| `스테이지_2_복도계단` | 19,600 × 5,400 | 51.0 장 | 403 | 54 | **48** | 842 ms | 980 ms **여유** | **13 ✖** |

(지형 점은 각각 288 / 195 / 270 점, 콜리전 정점 245 / 170 / 216 개. "실시간 유지" = 물리 60 틱의 벽시계 시간. 정확히 1,000 ms 면 CPU 가 여유롭다는 뜻이다.)

## 4-2. 읽는 법

**① CPU 는 걱정할 일이 아니다.**
1.7만 px 맵도 1,000 ms 를 그대로 지켰다. 노드 600 개·콜리전 정점 245 개는 Godot 2D 물리에게 아무것도 아니다. **맵을 1만 px 로 키우는 것 자체는 CPU 문제를 만들지 않는다.**

**② 로드 시간은 800 ms 근처다.**
전부 SS2D 가 메시·콜리전을 굽는 시간이다. 지형 수에 비례한다. 1만 px 맵 하나 = 0.8 초. **스테이지 30 개를 검사기로 자동 순회해도 30 초 미만**이라 생성→검사 루프가 현실적이다.

**③ 진짜 위험은 광원 한계 하나.**
Godot 4 의 2D 라이트는 캔버스 아이템 하나당 **15~16 개**가 하드코딩 한계다. 엔진 메인테이너가 *"셰이더를 최대한 빠르게 돌리기 위해 하드코딩해야 한다"* 고 못 박았고, **프로젝트 설정으로 못 늘린다.**
→ SS2D 지형 하나 = 캔버스 아이템 하나이므로, **긴 지형일수록 위험**하다. `복도계단` 의 `선반_1층_SS_BRICK` 이 이미 13/15 다.

**④ 노멀맵은 공짜에 가깝다.**
노멀맵은 **광원이 이미 계산하는 픽셀에 텍스처 한 장을 더 읽는 것**이다. 광원 수를 늘리지 않으므로 ③ 과 무관하다. `조명표준.height = 128` 을 지키는 한 그림만 좋아진다.

**⑤ 이 프로젝트는 `gl_compatibility` 렌더러다.**
`project.godot` 에 `renderer/rendering_method="gl_compatibility"` 로 박혀 있다. OpenGL 백엔드라 드로우콜이 Vulkan 보다 비싸다. 그래서 **광원보다 "화면에 동시에 보이는 SS2D 조각 수"** 를 관리하는 편이 낫다. 지형을 쪼갤 때 **무한정 잘게 쪼개면 안 되는 이유**이기도 하다 — 규칙 20 이 "한 화면 + 광원 6 개" 라는 조건을 단 건 이 균형 때문이다.

**⑥ 헤드리스로는 GPU 를 못 잰다.**
위 표에 GPU 수치가 없는 이유다. **실제 화면으로 확인해야 하는 것**: 빛이 끊기는 지형, 흰 지형 위 과노출(세기 1.0 초과 광원 금지), 페인트 얼룩의 오버드로.

## 4-3. 그래서 1만 px × 30 스테이지가 가능한가

**가능하다.** 지금 저장소에 이미 9,600~19,600 px 맵이 12 개 있고 전부 실시간을 유지한다. 목표(3 월드 × 10 판)는 **성능 문제가 아니라 제작량 문제**다. 바로 그래서 자동 생성이 의미가 있다.

단 — **생성이 늘리는 것은 지형이지 재미가 아니다.** `docs/맵분석_2026-09-07` 이 이미 지적한 것(*"단면이 일곱 판 내내 똑같다"*)은 자동 생성으로 **더 나빠질 수 있다.** 그래서 생성기에 **갈림길 3종·모양 3종·장애물 4종** 을 강제 조건으로 넣어야 한다(규칙표에 이미 반영).

# §5. 다른 작업자가 맵을 만들거나 고칠 때

## 5-1. 자동 생성된 맵을 손보기 전에

1. **씨앗 기록(`*_생성정보.json`)을 먼저 본다.** 이 방이 왜 여기 있는지가 적혀 있다.
2. **생성기를 다시 돌리지 않는다.** 손본 것이 전부 날아간다(§3-1).
3. 고치고 나면 **검사 3 종을 다시 돌린다** — 특히 주행검사. 발판 하나를 16 px 옮겨도 공략이 깨진다.

## 5-2. 지형을 옮기거나 늘릴 때

| 하려는 것 | 반드시 같이 할 것 |
|---|---|
| 발판을 옮긴다 | `하수도_주행검사.gd` 의 **공략표 좌표도 같이 고친다** |
| 발판을 길게 늘인다 | 긴변 > **576** 이 되면 전체칠이 안 된다 → 나누거나 `부분칠만` 명시 |
| 지형 두 개를 합친다 | 겹치는 광원이 **12** 를 넘지 않는지 `진단_절차생성_예산` 으로 확인 |
| 지형을 쪼갠다 | 꼭짓점을 **공유**해야 한다(겹침 0 · 틈 0). 색 경계·층 경계에서만 자른다 |
| 광원을 추가한다 | `tools/조명_배치.gd` 의 **배치표**를 고친다(씬 직접 편집 금지 · 멱등) |
| 흰 지형 위에 광원 | **세기 1.0 넘기지 말 것** — 순백으로 뭉갠다 |

## 5-3. 절대 하면 안 되는 것

- ❌ 에디터에서 인스턴스 **자식 노드의 속성만** 바꾸기 → 저장 때 버려진다. **노드 자신의 export** 로 켤 것
- ❌ 지형 콜리전 offset 을 0 이 아닌 값으로 → 이웃 사이 48 px 슬롯에 플레이어가 낀다
- ❌ `공통.주인_지정()` 을 읽어온 씬 노드에 호출 → 세그폴트
- ❌ 새 Template 을 만들고 `tools/생성_템플릿_점독립.gd` 를 안 돌리기 → 점 배열이 공유돼 한 곳을 고치면 전부 바뀐다
- ❌ 커밋 전 `git status` 확인 안 하기 → 2026-08-07 에 남의 작업 55 개가 사라진 적 있다

```markdown
## 3. 만들 것
generator = **조립기**다. 지형을 상상하지 말고, 모양 어휘(S1~S6)를 규칙대로 잇는다.
출력은 씬이 아니라 **① 좌표표 ② 공략표 ③ 씨앗·설정 기록** 세 가지.
씬 조립은 반드시 `tools/하수도_빌더_공통.gd` 의 b.지형()·b.유령()·b.공중선반()·b.검산() 에 맡긴다.

[STEP 1] 청크 그래프 + 도달성 — 1,024 px 청크 격자에 주경로/갈림길(F1 막다른길·F2 고리·F3 지름길)
[STEP 2] 색 구간 분할 — 구간 경계마다 80 px 틈. 안 칠한 지형은 **검정**이다(무색 아님). 검정 65±5 %
[STEP 3] 방 채우기 — 어휘 S1~S6 조합. 한 화면에 모양 3종 이상
[STEP 4] 장애물 배치 — 갈래마다 1 개 이상 · 스테이지당 6~10 개 · 4 종 이상
[STEP 5] **공략표 자동 생성** — 주행검사 문법(가/뛰기/뛰기색/색/칠)으로. 정답 + 헛걸음 두 벌
[STEP 6] 검사 루프 — 검산 → 레벨검사 → 주행검사. 하나라도 실패하면 씨앗을 버리고 다음 씨앗

## 4. 저장소 규약 (어기면 조용히 깨진다)
1. 코드를 고치면 **왜 그렇게 했는지 한글 주석**을 붙인다
2. 인스턴스는 `instantiate(PackedScene.GEN_EDIT_STATE_INSTANCE)` 로만 만든다
3. 읽어온 씬 노드에 **owner 를 다시 박지 않는다**(세그폴트)
4. `.gdshader` 안에 **한글 금지**(조용히 셰이더가 사라진다)
5. 도구는 **멱등**. "기존 값 + 여유" 같은 누적 금지
6. 콜리전은 외곽선 그대로(`collision_offset = 0`) — 깎으면 플레이어가 낀다
7. 국소 색반전 셰이더를 **새로 만들지 말 것** — `지형_페인트.gdshader` 의 seeds[24] 가 이미 그것이다
```
