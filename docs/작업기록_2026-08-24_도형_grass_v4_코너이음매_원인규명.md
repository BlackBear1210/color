| ① 실루엣의 축정렬 직선 길이 | 코너가 대조군보다 **짧게** 나옴 | 바깥 윤곽은 원래 깨끗하다. 문제는 안쪽이다 |

## 2. 원인 — 볼록과 오목이 다르다

같은 도형을 구성만 바꿔 나란히 구워서 갈랐다 (`tools/진단_grass_v4_코너합성.gd`).

| 구성 | 볼록 단차 | 오목 단차 |
|---|---|---|
| 대조군 (그냥 직선 엣지) | 3.00 | 3.00 |
| **A. 코너 없음 (4방향만)** | **16.24** | **4.09** |
| C. 현재 구성 | 13.25 | 8.96 |
| D. 코너를 배열 맨 앞으로 | 13.25 | 8.56 |
| E. 코너 z_index = −1 | 13.64 | 8.93 |
| F. 층 명시 (필 −1 < 코너 0 < 엣지 1) | 13.64 | 8.56 |

읽는 법:

- **볼록 = 원인 E (띠가 꼭짓점에서 그냥 끊긴다).**
  코너를 아예 빼도 16.24 다. 코너는 오히려 13.25 로 **줄여 준다**.
  4방향 띠는 외곽선을 따라 ±45 월드px 폭으로 깔리는데,
  TOP 은 x=꼭짓점에서, RIGHT 는 y=꼭짓점에서 끝난다.
  그래서 꼭짓점 바깥쪽 45×45 월드px 이 **아무 띠도 없는 구멍**이 된다.
  코너 타일이 그 구멍을 덮지만, 코너는 u=0.31 로 고정된 그림이고
  띠는 타일링 위상이 제각각이라 경계에서 그림이 안 맞는다.

- **오목 = 원인 A/B (코너 타일이 멀쩡한 접합을 덮는다).**
  코너를 빼면 4.09 로 거의 대조군이다. 코너를 얹으면 8.96 이 된다.
  단차가 나는 자리는 화면 x 로 코너 꼭짓점 **+44.8 월드px** — 코너 쿼드의 경계다.

- **원인 D(그리는 순서)는 아니다.** z_index 를 어떻게 바꿔도 13.2~13.6 이다.
  코너를 엣지 아래로 내리면 경계가 x=꼭짓점−45 에서 x=꼭짓점으로 **옮겨갈 뿐**이다.

### 코드에서 확인한 구조 (추측 아님)

```
shape.gd:1596  new_quads.push_front(q)     # 코너 쿼드를 앞에 끼울 뿐,
                                           # 옆 엣지 쿼드를 줄이지 않는다
shape.gd:1024  build_quad_corner(...)      # 코너 쿼드는 꼭짓점 중심 ±(256*0.35*0.5)
shape.gd:962   build_quad_from_two_points  # 일반 쿼드는 외곽선 중심, pt~pt_next 전 구간
shape.gd:1734  quad.pt_d = taper_quad.pt_a # taper 는 원 쿼드를 **실제로 줄인다**
```

즉 코너가 겹쳐 그려지는 것은 하이브리드 구성 때문이 아니라 **SS2D 의 원래 동작**이다.
같은 머티리얼 안에서도 코너는 엣지를 줄이지 않는다.

## 3. taper — 수치는 넘겼는데 곡선이 깨진다

### 3-1. 만든 방식 (AI 생성 없음 · LOCK PNG 는 읽기만)

`tools/생성_grass_v4_taper.gd` 로 기존 엣지 텍스처에서 파생한다. 세 판 만들어 봤다.

| 방식 | 볼록 | 오목 | 판정 |
|---|---|---|---|
| `fade` (행 평균 단면 + 알파 페이드) | 3.53 | 4.38 | 수치는 통과인데 **뭉갠다** — 그림이 평균나서 사라지고, taper 시작점에 세로 직선이 생긴다 |
| `slice` (u∈[0.31−N/주기, 0.31] 실제 그림) | 8.10 | 3.06 | 디테일은 살지만 볼록이 안 잡힌다 (알파를 안 내려서 띠가 여전히 뚝 끊긴다) |
| **`slicefade`** (slice 그림 + 바깥 55%만 알파 페이드) | **2.60** | **3.06** | 수치·디테일 둘 다 통과 |

`slicefade` 는 대조군 3.00 보다도 낮다. 목표(6/255)를 확실히 넘겼다.

※ `fade` 의 실패가 지표 ④ 를 만든 이유다. 단차 3.53 으로 **PASS 인데 화면은 더 나빴다.**

### 3-2. 그런데 곡선이 깨진다

작은원 · 큰언덕 · 복합폐곡선에 taper 를 걸면 각 방향 호의 경계마다
**검은 슬래브/가시가 실루엣 밖으로 튀어나온다.** 이건 이음매보다 훨씬 나쁜 결함이다.

원인 두 가지, 둘 다 애드온 안에 있다.

**(a) taper 길이가 텍스처 크기에 성분곱으로 묶여 있다**

```
shape.gd:1730  var offset: Vector2 = delta_normal * taper_size
```
`delta_normal` 은 정규화된 방향이라 **가로 엣지는 taper_size.x, 세로 엣지는 taper_size.y**
가 길이가 된다. `texture_scale` 은 곱해지지 않는다 → **텍스처 1px = 월드 1px**.

세로 엣지에서 길이 45 를 얻으려면 텍스처 **높이**가 45 여야 하는데,
높이는 곧 띠 단면(월드 90px)의 해상도다 → **0.5 텍셀/월드**.
엣지 본체는 256px ÷ 90월드 = **2.84 텍셀/월드** 다. **5.7배 저해상도.**
비스듬한 쿼드에서 이게 가로 줄무늬로 번진다.

실제로 확인했다: 가로 엣지만 45×256(단면 풀해상도)으로 구워 봤더니
곡선의 결함이 **더 커졌다**(길이가 방향마다 달라져 가시가 길어짐). 비대칭은 답이 아니다.

**(b) 안 맞으면 쿼드 전체를 taper 로 덮는다**

```
shape.gd:1724  var fit: bool = absf(taper_size.x) <= quad.get_length_average()
shape.gd:1744-1747  # 안 맞으면 quad.texture = taper_texture  (쿼드 전체 교체)
```
실측한 끝쿼드 최소 길이:

| 도형 | 끝쿼드 최소 길이 |
|---|---|
| 사각 | 470.4 |
| L자 | 260.0 |
| 짧은직선 | 140.4 |
| 복합 | 73.4 |
| 작은원 | 58.5 |
| **큰언덕** | **39.2** ← 45 보다 짧다 |

레벨 디자이너가 더 조인 곡선을 그리면 언제든 재발한다. 값을 낮춰도 근본 해결이 아니다
(길이를 줄이면 단면 해상도가 같이 줄어 (a) 가 악화된다).

### 3-3. 그래서 멈췄다

지시받은 규칙이 명확했다 — **taper 로 해결되지 않으면 억지로 적용하지 말 것.**
이음매 수치만 보면 채택 조건을 만족하지만, **곡선 회귀는 회귀 목록에 명시된 항목**이고
고칠 수단이 전부 `addons/rmsmartshape` 안에 있다. 그래서 `.tres` 에 연결하지 않았다.

## 4. 다음 최소 수정안 (승인 필요 — 애드온 1줄)

```gdscript
# addons/rmsmartshape/shapes/shape.gd:1730
- var offset: Vector2 = delta_normal * taper_size
+ var offset: Vector2 = delta_normal * (taper_size.x * quad.texture_scale)
```

이 한 줄이 두 문제를 동시에 푼다.

1. **네 방향이 같은 성분(.x)을 쓴다** → 텍스처를 정사각으로 만들 필요가 없어진다.
2. **texture_scale 이 곱해진다** → 128×256 taper 를 배율 0.35 로 쓰면
   길이 **44.8 월드px**(코너 반너비와 정확히 일치), 단면 256px ÷ 90월드 = **2.84 텍셀/월드**,
   가로 128px ÷ 44.8월드 = **2.86 텍셀/월드** — **엣지 본체와 해상도가 완전히 같아진다.**
   `slicefade` 텍스처를 128×256 으로 다시 구우면 된다 (생성기에 `--길이` `--높이` 인자 이미 있음).

곁들여 필요할 수 있는 두 번째 줄 (곡선 안전장치):

```gdscript
# addons/rmsmartshape/shapes/shape.gd:1744-1747
# fit 이 아니면 쿼드 전체를 갈아끼우지 말고 taper 를 그냥 건너뛴다
```

**검증 기준은 이미 준비돼 있다.** 수정 후 아래를 그대로 돌리면 된다:

```bat
Godot --headless --path . -s res://tools/생성_grass_v4_taper.gd -- --길이=128 --높이=256 --방식=slicefade
Godot --headless --path . --import
Godot --headless --path . -s res://tools/진단_grass_v4_코너합성.gd
Godot --headless --path . -s res://tools/측정_실루엣_단차.gd -- --줌=3.0 --평범창=60,400 --관심창=505,700 --그림=<볼록.png>
```
합격선: 볼록·오목 열평균 단차 **< 6/255**(대조군 3.00), 디테일 비율 하락 없음,
그리고 **작은원·큰언덕·복합에 슬래브가 없을 것.**

⚠ 애드온을 고치면 `test_ss2d_해상도분리` 88/88 과 기존 머티리얼 바이트 단위 하위호환을
다시 증명해야 한다 (P0 때 했던 것과 같은 방식).

## 6. 지뢰밭 (이번에 새로 밟은 것)

1. **비교 렌더는 배경이 같아야 한다.** 일부 도형이 배경 사각형 밖으로 나가면
   반투명 술이 다른 색과 섞여서 수치가 통째로 뒤집힌다. 두 번 당했다.
2. **`_edge_meta_materials` 배열 순서는 그리는 순서를 정하지 않는다.** z_index 가 정한다.
   (D 변형이 C 와 완전히 같은 수치가 나와서 알았다)
3. **정규화 상관·연속길이 같은 지표는 잔디 붓질에 오염된다.** 열 평균을 써야 한다.
4. **단차 지표만 믿으면 "뭉갠 것"을 놓친다.** 고주파 에너지를 같이 봐야 한다.
5. `c_extends`(shape.gd:1485)도 `c_scale` 과 똑같이 **리터럴 0.0 으로 죽어 있는 손잡이**다.
   띠를 꼭짓점 너머로 늘려 구멍을 메우는 길도 애드온 수정 없이는 막혀 있다.
6. 새 PNG 를 만들면 `--headless -s` 실행만으로는 import 가 안 된다.
   `Godot --headless --path . --import` 를 한 번 돌려야 `load()` 가 된다.
   import 설정(mipmap off / compress 0)도 기존 정책에 맞춰 줘야 한다.
