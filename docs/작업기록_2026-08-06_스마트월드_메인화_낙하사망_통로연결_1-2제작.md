## 3. 낙하 사망 — 좌표가 아니라 "떨어진 거리"

### 파일
- [scripts/스마트월드/낙하_감시.gd](../scripts/스마트월드/낙하_감시.gd) — **신규**
- [scripts/스마트월드/월드.gd](../scripts/스마트월드/월드.gd) — 연결 · 자동 체크포인트

### 왜 바꿨나
기존은 `낙사_y = 1500` 처럼 **절대 좌표 한 줄**이었다. 그러면
- 구멍에 빠져도 낙사선까지 한참 떨어져야 죽고(지루함),
- 낙사선을 올리면 **깊은 방을 아예 못 만든다**.

거리로 재면 둘 다 해결된다. 깊은 갱도도 만들 수 있고(계단식으로 내려가면 안전),
한 번에 쭉 떨어지면 죽는다.

### 규칙
| # | 내용 |
|---|---|
| 1 | 바닥에 닿아 있는 동안 기준 높이를 계속 갱신한다 (완만한 내리막은 낙하가 아니다) |
| 2 | 공중에 뜨면 **가장 높이 올라간 지점**부터 거리를 센다 (점프 꼭대기 기준) |
| 3 | 낙하 거리 > `치명_낙하거리`(기본 520px) → **착지를 기다리지 않고 즉시 사망** |
| 4 | 위험 구간(55% 지점)부터 **화면 가장자리 비네트**가 조여든다 — 예고 없는 죽음은 없다 |

### 520px 은 어디서 나온 숫자인가
점프 높이 = 10칸 × 16px = **160px**. 520 = 점프 높이의 **3.25 배**.
- 130px 단차(기존 레벨디자인 안전 수치)는 당연히 안전
- 발판 3~4단(약 400px)을 실수로 놓쳐도 산다
- 그보다 깊은 구멍은 **"여긴 내려가면 안 되는 곳"** 으로 읽힌다 = 지형만으로 규칙이 전달된다

스테이지마다 `월드.gd` 의 `치명_낙하거리` 로 조절할 수 있다. 0 이면 낙하 사망을 끈다.

### 같이 들어간 자동 체크포인트
긴 스테이지에서 낙사할 때마다 처음으로 돌아가면 벌칙이 아니라 고문이 된다.
**마지막으로 안전하게 서 있던 땅**(0.45초 이상 유지)을 기억했다가 거기로 되돌린다.
레인월드의 셸터와 같은 역할. `안전지점_자동저장` 으로 끌 수 있다.

### ⚠ 함정 2가지 (둘 다 자동 테스트가 잡아냄)

1. **셰이더에는 한글 식별자를 못 쓴다.**
   ```
   SHADER ERROR: Tokenizer: Unknown character #49464: '세'
   ```
   GDScript 는 `var 세기` 가 되지만 GDShader 는 거부한다. 그러면 셰이더가 통째로
   컴파일 실패하고 **비네트가 조용히 안 나온다**(게임은 안 죽어서 더 찾기 어렵다).
   → 셰이더 안은 전부 ASCII, 설명만 한글 주석.

2. **`is_on_floor()` 는 마지막 `move_and_slide()` 결과가 그대로 남아 있다.**
   플레이어를 코드로 순간이동시키면 다음 물리 프레임까지 "아직 땅에 서 있다"고 답한다.
   그 한 프레임에 체크포인트가 찍히면 **허공이 안전지점으로 저장**되고,
   죽을 때마다 그 허공으로 돌아가 무한 낙하한다.
   → `월드.gd._발밑에_땅있나()` 로 레이를 한 번 더 쏴서 확인한다.

## 4. 통로 연결 — 포탈을 없앴다

### 파일
- [scripts/스마트월드/연결통로.gd](../scripts/스마트월드/연결통로.gd) — **신규**
- [scripts/스마트월드/장면전환.gd](../scripts/스마트월드/장면전환.gd) — **신규**

### 왜 기존 `stage_transition.gd`(잉크 와이프)를 안 썼나
잉크가 화면을 덮고 걷히는 건 **"장면이 바뀌었다"는 게임적 신호**다.
도형님이 싫다고 한 포탈 감각과 같은 종류다. 우리가 원한 건 VINE 처럼 **공간이 그냥 이어진** 느낌.

### 어떻게 했나 — 화면 효과가 아니라 조명이다
```
플레이어가 어두운 굴 안으로 걸어 들어간다
   → 굴 안이라 자연스럽게 화면이 까매진다     (전환이 아니라 '조명')
   → 다음 스테이지의 같은 굴 안에서 시작
   → 눈이 적응하듯 서서히 밝아지며 밖이 보인다
```
효과 자체는 검정 페이드지만, **통로 안에서만 일어나기 때문에** 플레이어에게는
전환이 아니라 "터널을 통과했다" 로 읽힌다. 이게 전부다.

| 구간 | 시간 | 이징 | 이유 |
|---|---|---|---|
| 암전 | 0.85초 | SINE / EASE_IN | 입구는 밝고 깊이 들어갈수록 급격히 어두워지는 실제 감각 |
| 암흑 유지 | 0.22초 | — | 0 이면 툭 끊긴 느낌이 난다 |
| 점등 | 1.35초 | SINE / EASE_OUT | 암전보다 **길어야** "눈이 적응하는" 것으로 읽힌다 |

### 통로는 스스로 굴을 짓는다
`연결통로` 노드가 **바닥 · 천장 · 막다른 뒷벽**을 StaticBody2D 로 직접 만든다.
- 지형 폴리곤을 정교하게 파낼 필요가 없다 — 지면 끝에 툭 놓기만 하면 된다
- **천장이 있어서 뛰어넘어 갈 수 없다** = 반드시 통로를 지난다

### 바이옴이 이어진다
출구 통로의 `속빛` = **다음 지역의 하늘색**이다. 통로 저 끝에서 그 색 빛이 새어나오므로
지나가기 전에 이미 다음 지역의 분위기가 보인다.
`StageBackdrop` 이 원래부터 "각 스테이지의 끝 바이옴 = 다음 스테이지의 시작 바이옴" 구조라
통로를 나오면 하늘이 그대로 이어진다.

```
1-1  자연 ─────────→ 물가      출구 속빛 = 물가 하늘색
1-2  물가 ─────────→ 판자촌    출구 속빛 = 판자촌 하늘색
```

### ⚠ 함정 3가지

1. **페이드 판은 `get_tree().root` 에 붙여야 한다.** `current_scene` 에 붙이면 씬이 바뀔 때
   같이 사라져 화면이 한 번 번쩍인다.
2. **한 노드가 암전·점등을 다 해야 한다.** 새 씬이 자기 페이드를 따로 하면 두 페이드가 겹쳐
   한 번 깜빡인다.
3. **스폰할 통로는 `get_tree()` 전체가 아니라 자기 스테이지 안에서 찾아야 한다.**
   스테이지마다 입구 이름이 똑같이 `"입구통로"` 라서, 이전 씬이 트리에 남아 있으면
   **엉뚱한 스테이지의 통로**를 집어 플레이어가 화면 밖에 스폰된다.
   (`월드.gd._내_통로들()` — test_통로전환 이 실제로 잡아냈다)

### 통로 그림 — 스크린샷 보고 두 번 고쳤다
1. 처음엔 콜리전만 만들고 그림을 안 그렸다 → 화면에서 **허공에 뜬 검은 상자**로 보였다.
   "지형에 파인 굴" 이 전혀 안 읽히면 결국 포탈처럼 보인다. → 암반 사각형을 직접 그린다.
2. 두께(90px)만큼만 그렸더니 이번엔 **지면에 얹힌 콘크리트 상자**였다.
   → `암반_위` / `암반_아래` 로 위아래를 늘려 천장 매스와 이어 붙이고 바닥에 파묻었다.

### 5-3. 스마트월드 1-2 (물가 → 판자촌) — 신규

**도형님 지시 3 가지를 그대로 옮겼다.**

1-1 의 바닥은 사인 3 개를 겹친 굽이치는 자연 지형이다.
1-2 는 `지형공통.평바닥_점들()` 로 **완전한 수평 바닥**(요철 ±2.5px)을 깐다.
인공 구조물(수로)이라는 성격에도 맞고, 수평선이 길게 이어지면 **길이감**이 산다.

#### ② stage_1-1(동현 테스트월드 제작)의 지형 배치·길이 느낌
실제로 `scenes/world_1/stage_1-1.tscn` 의 타일 데이터를 풀어서 재봤다.

| 항목 | stage_1-1 실측 | 스마트월드 1-2 |

| 전체 높이 | 152칸 × 16px = 2,432px | 약 3,000px |
| 핵심 구조 | y=87~90 행에 **542칸(8,672px) 통짜 수평 바닥** | 상층 y=900 통짜 수평 바닥 |

| " | y=-18~-17 에 225칸 천장 슬래브 | 구간별 천장 매스 6 개 |

**타일 데이터를 복사한 게 아니라 구조의 비례만 옮겼다** (타일맵이 아니라 SS2D 라서).
참고로 기존 스마트월드는 4,300px 이었으므로 **2.1 배 길어졌다.**

#### ③ "내가 만든 타일을 써서 지형을 새롭게 구축"
`assets/textures/smartshape/` 의 도형님 픽셀 타일로 SS2D 재질을 새로 조립했다.

| 재질 | 쓰는 타일 | 쓰는 곳 |
|---|---|---|
| `검정_지형.tres` (기존) | center / left / right / bottom_center | 1-1 지형 |
| **`지형_거친암반.tres` (신규)** | **center2 / left2 / right2** / bottom_center | 1-2 지형 |
| **`지형_덩어리.tres` (신규)** | **allaround** 한 장으로 사방 | 작은 공중 발판 · 선반 |

★`center2` · `left2` · `right2` · `allaround` 는 **도형님이 그려두고 한 번도 안 쓰인 타일**이었다.
같은 엔진·같은 시스템인데 1-1 과 지형 룩이 확실히 다르다.

> ⚠ **변형 타일을 한 재질에 몰지 말 것.** SS2D 의 `randomize_texture` 로 한 슬롯에 여러 장을
> 섞을 수 있지만, `지형_페인트.gdshader` 는 **텍스처 한 장당 흰색 짝 한 장**(`alt_tex` 유니폼이
> 하나)이라 섞으면 칠했을 때 엉뚱한 흰 무늬가 나온다. → 변형은 **재질을 나눠서** 쓴다.

#### 구성

```
⓪ −460~   0  입구 통로     1-1 에서 걸어 나온다
①    0~1400  넓은 홀       천장 650px. 아무것도 안 죽인다 — 공간 스케일만 보여준다
② 1400~2500  좁은 굴       천장 200px. ★색 레이저 2 개 (위상 엇갈림)
③ 2500~3300  수직 갱도     상층 900 → 하층 1800. 선반 110px 간격 좌우 엇갈림
④ 3300~5100  하층 수로     저장고→배관→호퍼→물줄기 / 통과플랫폼이 '길의 일부'
⑤ 5100~5560  굴뚝          전용 벽 2 장 사이(폭 320px = 점프 1회분)를 선반으로 오른다
⑥ 5560~7300  상층 배관실   갈래 물줄기 + 직선 레버 + 도약대로 상단 진입
⑦ 7300~8900  구멍 다리     ★밑이 없는 구멍(660px). 유령 발판 2 개를 칠해야 건넌다
⑧ 8900~9200  출구 통로     (1-3 이 없어 지금은 1-1 로 순환)
```

**레인월드 지형 문법 5가지를 실제로 썼다**
1. 방은 늘 "덩어리에서 파낸 공간" → 바닥만큼 **천장 매스**를 깐다
2. 넓은 홀 ↔ 기어가는 좁은 굴이 **번갈아** 나온다 (650 / 200 / 550px)
3. 수직 이동은 **벽에서 튀어나온 선반**을 좌우로 엇갈려 밟는다
4. 아래로 가는 길은 **위험**하다 — 선반을 무시하고 뛰어내리면 낙하 즉사
5. 배경이 지형 뒤로 계속 이어져 방이 세계의 일부로 보인다 (StageBackdrop 재사용)

## 6. ★레벨 검사기 — 이번 작업에서 가장 쓸모 있던 것

[tools/레벨검사.gd](../tools/레벨검사.gd) — **신규**

```bash
Godot --headless --path . -s res://tools/레벨검사.gd -- <씬경로> [--지도] [--상세]
```

### 무엇을 하나 (추정이 아니라 실측이다)
1. 씬을 **진짜로 띄우고** 물리 프레임을 돌린다
2. 32px 마다 세로 레이캐스트를 반복해 **모든 층의 발판 윗면**을 찾는다
3. 이웃한 표면점을 **선반(segment)** 으로 묶는다
4. `player.gd` 의 export 값에서 **실제 점프 수치를 역산**해 도달 가능성 그래프를 만든다
5. 시작 지점에서 BFS

### 무엇을 보고하나
| 항목 | 뜻 |
|---|---|
| `[도달불가]` | 시작 지점에서 갈 수 없는 발판 = 죽은 콘텐츠거나 배치 실수 |
| `[소프트락]` | 들어갈 순 있는데 **출구까지 못 가는** 곳 |
| `[치명낙하]` | 가장자리에서 걸어 나가면 치명 거리를 넘게 떨어지는 곳 (오류 아님 — **정보**) |
| `--지도` | 스테이지 단면 ASCII 지도 |
| `--상세` | 선반 하나하나와 그 이웃 전부 |

**"조금만 낮췄으면 닿았을" 이웃도 알려준다:**
```
선반_6   x 1188~1284  y 870
     → 갈 수 있는 곳이 하나도 없다
     ⓘ 바닥_1 로 갈 뻔했다 — 가로 288px (한계 272 · 16 초과)
```

### 이번에 실제로 잡아낸 것 (전부 눈으로는 안 보이는 종류였다)

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 1-1 스테이지 전체가 도달 불가 | 구덩이 첫 발판 단차 **133px** = 점프(160)의 83% — 판정선(128) 초과 | 발판 655/560/590 으로 재배치 |
| 2 | 갱도 아래 선반 4 개가 소프트락 | 선반 바로 9px 위에 **통과플랫폼**이 있어 **설 머리 공간(52px)이 안 나옴** | 갱도를 물길 실험실로 재설계 + 도약대 탈출로 |
| 3 | 구덩이 턱에서 못 올라옴 | 단차 144px | 830 으로 올림 |
| 4 | 1-2 홀 징검다리 도달 불가 | 일자 바닥(900)에서 단차 288px | 815 / 705 로 재배치 |
| 5 | 선반 간격 125px 이 실측 131px | 선반 두께가 서로 다르고 윗면이 기울어 **명목보다 커진다** | 전 스테이지 110px 로 통일 |

> **명목 간격은 판정선(128px)보다 15px 이상 여유를 둘 것.** 이게 이번에 얻은 규칙이다.

## 8. 신규 장애물 3종

`docs/장애물_아이디어_정리.md` 에서 **낙하 사망·수직 레벨과 짝이 되는 것**만 골랐다.

### 8-1. 도약대 ([도약대.gd](../scripts/스마트월드/도약대.gd))
밟으면 위로 튄다. 상승 **418px** = 점프의 2.6 배.

낙하 사망을 넣으면서 **아래로 가는 길이 위험**해졌는데, 올라가는 수단이 점프뿐이면
레벨이 옆으로만 길어진다. 도약대가 있어야 수직으로 쌓인 방을 만들 수 있다.

> ⚠ **도약대 위에는 반드시 받아줄 발판을 둘 것.** 세기를 치명 거리(520px)보다 크게 잡으면
> 도약대 자체가 자살 장치가 된다. 기본값 −1500 은 418px 라 그 아래에 뒀다.
> 상승 높이 = 속도² / (2 × gravity × 상승_배수). `레벨검사.gd` 가 실제로 계산해 준다.

### 8-2. 무너지는 바위 ([무너지는바위.gd](../scripts/스마트월드/무너지는바위.gd))
밟으면 0.7초 흔들리다 부서진다. 4초 뒤 재생.

**칠하면 단단해져 무너지지 않는다.** 물감을 "보강재"로 쓰는 셈이라
색칠에 새 용도가 하나 생겼다 (레벨디자인_가이드 §2 물감 이코노미).

### 8-3. 색 레이저 ([색레이저.gd](../scripts/스마트월드/색레이저.gd))
빔 안에서 빔과 **다른 색**이면 사망. 주기마다 흑↔백 전환, 전환 전 깜빡여 경고.

스마트월드 오브젝트 11 종은 전부 물감을 쓰는 것들이라 **물감이 떨어지면 할 게 없어진다.**
색 레이저는 **물감 0 발로도 통과**할 수 있어서, 레벨에
`물감 구간 ↔ 반사신경 구간` 리듬을 만들 수 있다.

판정은 몸 전체가 닿는 방식이라 `월드.gd._사망_판정()` 이 그룹 `"색레이저"` 를 한 줄로 물어본다.
