## 1. 왜 그런가

Godot 은 씬에 박힌 **서브리소스를 그 씬의 모든 인스턴스가 공유**한다
(`resource_local_to_scene` 이 꺼져 있을 때). 이게 기본 동작이다.

SS2D 의 점 배열이 바로 그 서브리소스다:

```
TEMPLATE_CEMENT_SOLID.tscn
  [sub_resource type="Resource" id="Resource_y14av"]   ← SS2D_Point_Array
  script = ExtResource("3_hebbq")
  _points = { 0: SubResource("Resource_apyxx"), ... }  ← SS2D_Point 12 개
  ...
  [node name="TEMPLATE_CEMENT_SOLID" ...]
  _points = SubResource("Resource_y14av")              ← 여기를 모든 인스턴스가 같이 본다
```

`resource_local_to_scene` 이 이 파일에 **한 줄도 없다**(20 개 템플릿 전부 그렇다).

### 실측으로 확인

```
════ TEMPLATE_CEMENT_SOLID.tscn 을 두 번 인스턴스
  점배열 같은 객체 = true
  점(SS2D_Point) 같은 객체 = true
  A 점id=-9223372000313997845   B 점id=-9223372000313997845   ← 같다
  A 의 점 하나를 (+500,+300) 옮긴 뒤
    A=(-140.0, -924.0)
    B=(-140.0, -924.0)                                       ← B 도 같이 움직였다
```

★ **다른 씬에 있는 것까지 같이 움직인다.** 리소스 캐시는 프로젝트 전체에서 하나라,
stage_2-1 의 CEMENT 점을 끌면 stage_2-2 의 CEMENT 도 같이 끌린다.

## 2. 고치는 법 (둘 다 실측으로 확인)

### ① Template 파일을 **복제**해서 쓴다 — 평소엔 이게 기본

`README_지형찍기.md` §3 이 원래 이렇게 시켜 왔다:
"FileSystem 에서 그 씬을 **복제**한다 (우클릭 → Duplicate)".
복제본은 **자기 파일에 자기 서브리소스**를 갖는다 → 처음부터 독립이다.

이번 건은 그 단계를 건너뛰고 Template 을 바로 꽂아서 생긴 일이다.
README 에 그 이유가 안 적혀 있었다 → **이번에 적어 넣었다.**

### ② 이미 꽂았다면 → SS2D 의 **Make Unique**

지형 노드 선택 → 인스펙터 **Geometry** 그룹 → `Make Unique` 의 **Execute** 버튼
→ 대화상자 "Make shape point geometry unique (not materials). Proceed?" → **Proceed**

속으로 `point_array.clone(true)`(깊은 복제)를 한다
(`addons/rmsmartshape/actions/action_make_shape_unique.gd`).

```
[Make Unique (clone(true)) 를 B 에 적용]
  B 새 id=-9223371997226990024  (A 와 같은가 = false)
  A 를 다시 옮김 → A=(-111,-111)  B=(9999,9999)
  → 이제 독립인가 = true
```

⚠ **새로 꽂자마자 누르는 것이 안전하다.** 모양을 고친 뒤에 누르면 그때는 이미
옆에 있던 것까지 바뀐 뒤다.

## 3. 세 번째 방법과 그 대가 — `resource_local_to_scene`

템플릿 .tscn 을 고쳐서 **자동으로** 독립하게 만들 수도 있다. 실측 결과:

| 무엇에 `resource_local_to_scene = true` 를 주나 | 결과 |
|---|---|
| 점 배열에만 | ❌ **부족하다.** 배열은 갈라지는데 안의 `SS2D_Point` 는 그대로 공유 → 점이 같이 움직인다 |
| 점 배열 **+ 점 12 개 전부** | ✅ 완전히 독립 |

즉 템플릿 하나당 **13 줄**을 넣어야 하고, 템플릿이 20 개다.

**대가**: 인스턴스마다 엔진이 복사본을 만들므로, 맵 씬을 저장할 때 그 복사본이
**전부 씬 파일에 저장된다.** 실측으로 인스턴스 2 개짜리 테스트 씬이
139 줄 → 236 줄(서브리소스 17 → 30)로 늘었다.
**모양을 안 고칠 인스턴스까지** 전부 불어난다는 뜻이다.

→ 그래서 기본은 ①·② 로 두는 게 맞다고 본다.
   ②(Make Unique)는 **따로 가져가고 싶은 것만** 골라서 저장하므로 낭비가 없다.

### 검사 — `tools/test_템플릿_점독립.gd` (통과 130 · 실패 0)

**앞부분** — Template 26 개를 각각 두 번 인스턴스해서:

1. 점 배열이 서로 다른 객체인가
2. **점(`SS2D_Point`) 하나하나도** 서로 다른 객체인가 ← 여기가 진짜다
3. 한쪽 점을 옮겨도 다른 쪽이 안 움직이는가 ← 이게 증상이다

2 번이 없으면 §3 의 함정(배열만 갈라지고 점은 공유)이 그대로 통과해 버린다.

**뒷부분** — 성진님 질문 그대로: *"인스턴스를 독립적으로 수정해도 원본을 안 해치지?"*
에디터가 하는 일을 그대로 흉내 낸다.

1. `GEN_EDIT_STATE_INSTANCE` 로 꽂고 ← 에디터가 씬에 인스턴스를 놓을 때 쓰는 모드
2. 점을 끌어 모양을 바꾸고
3. 맵 씬을 저장하고(`pack()` + `ResourceSaver.save()`)
4. **Template 파일 내용을 바이트로 대조**한다 + 맵 씬에 `_points` 덮어쓰기가 담겼나 본다

결과: **26 개 전부 Template 파일이 바이트 하나 안 바뀐다.** 수정은 맵 씬 쪽에 담긴다.
검사를 두 번 돌려도 `스마트 매쉬 assets` 전체 md5 가 `5c73ccd1…` 로 동일했다.

### ⚠ 곁다리로 찾은 것 — 껍데기가 있는 Template 5 개

`벽돌 테스` · `벽돌 테스_흰색` · `TEMPLATE_METAL_SOLID` · `TEMPLATE_METAL_SOLID_WHITE` ·
`TEMPLATE_PIPE_OPEN_GRAY` 는 SS2D 가 **인스턴스 뿌리가 아니라 껍데기 안의 자식**이다.

```
[node name="철판_SOLID" type="Node2D"]              ← 인스턴스 뿌리(껍데기)
[node name="SS2D_Shape_Closed" parent="."]          ← 진짜 지형은 여기
```

Godot 은 인스턴스 **안쪽** 노드의 수정을 **Editable Children 을 켰을 때만** 저장한다.
안 켜면 에디터에서 그 지형은 선택조차 안 되고, 스크립트로 고쳐도 저장이 안 된다
(검사에서 실제로 `_points` 덮어쓰기가 안 남는 걸로 걸렸다).

**이번 수정과 무관한 원래부터 있던 구조 문제**다. README 에 적어 뒀다.
나머지 21 개는 SS2D 가 인스턴스 뿌리라 그냥 고치면 된다.

## 7. 다음 사람이 알아야 할 것 (지뢰 추가)

**"씬에 박힌 서브리소스는 그 씬의 인스턴스 전부가 공유한다"** 는 이 저장소에서
**세 번째로 물린 함정**이다.

| 언제 | 무엇을 공유했나 | 증상 |
|---|---|---|
| 2026-09-02 오전 | 유체의 `RectangleShape2D` | 물 14 개가 판정 사각형 하나를 나눠 씀 |
| 2026-09-02 오후 | SS2D 의 `SS2D_Point_Array` | Template 인스턴스끼리 모양이 같이 움직임 |
| (주의) | `SS2D_Material_Shape`, 그 밖의 `.tres` | 아직 안 물림 — 재질은 원래 공유가 맞다 |

확인하는 법은 늘 같다: **`노드.속성.get_instance_id()` 를 인스턴스별로 찍어 본다.
같으면 공유 중이다.**
